# web

화면 파일이다. FastAPI가 `public/`만 `/ui/`에 정적 파일로 내준다(`app/main.py`). 빌드가 없고 Python 코드도 없다. 로그인은 `/ui/login/`, 이용자 화면은 `/ui/librarian/`, 관리자 화면은 `/ui/admin/`이다. 이 README와 CLAUDE.md는 `public/` 밖이라 내주지 않는다.

## 구성

| 위치 | 내용 |
| --- | --- |
| `public/shared/` | 화면들이 함께 쓰는 모듈: `api.js`(화면별 토큰, 역할 확인, 경로 함수, 오류 구분), `sse.js`(fetch 스트림을 사건으로), `card.js`(책 카드, `safeUrl`), `dom.js`(글자만 넣는 요소 도우미), `phone.js`(휴대폰 번호 하이픈: 보이기와 입력칸), `base.css` |
| `public/login/` | 로그인 화면: `index.html`, `login.css`, `login.js`(응답 역할로 행선지) |
| `public/librarian/` | 이용자 화면: `index.html`, `librarian.css`, `suggest.js`(자동완성), `chat.js`(턴 흐름, 두 단계 검색 결과 블록), `basket.js`(담은 책: 서버 보관 `/basket`을 불러오고 담기·빼기·비우기, 사본은 메모리), `member.js`(회원 로그인 상태와 토큰 한 칸), `actions.js`(로그인·대출·반납·희망도서 입력칸), `idle.js`(두 시계), `main.js`(조립) |
| `public/admin/` | 관리자 화면(한 페이지, 탭 여덟): `index.html`, `admin.css`, `main.js`(조립·탭·로그아웃), `chat.js`(운영 대화와 결과 표·[초안 보기]), `approvals.js`(승인 목록), `requests.js`(희망도서), `overdue.js`(오늘의 연체), `imports.js`(장서 가져오기), `collection.js`(장서), `members.js`(회원), `closures.js`(휴관일) |

## 규칙

- **기존 API만 쓴다.** 화면 전용 API를 만들지 않는다. 필요해 보이면 먼저 묻는다. 부르는 경로는 `shared/api.js`에 모은다(로그인·내 정보·로그아웃, 회원 로그인 `/auth/member-login`·로그아웃 `/auth/member-logout`, 담은 책 `/basket`, 자동완성, 검색, 주제 검색 `/catalog/topic`, 비슷한 책, AI 사서 대화, 대화 종료, 도서관 안내, 대출 `/loans`, 반납 `/loans/return`, 희망도서 `/book-requests`, 기관 정보 `/library`, 운영 에이전트 대화, 큐레이션·연체 안내문 틀·구매 요청서의 목록·상세·승인·반려·내리기, 오늘의 연체 `/overdue-notices/today`, 장서 가져오기 `/holding-imports`의 올리기·목록·단건·행 목록·적용·미리 보기 삭제, 사본 `/holdings`·`/holdings/{id}`, 기관 도서 `/library-books`, 회원 `/members`·`/members/{id}`, 임시 휴관일 `/library/closures`·`/library/closures/{id}`). 테스트가 부르는 경로·메서드가 서버 OpenAPI에 있는지 맞춰 본다.
- **기관은 토큰으로 정한다.** 화면은 `library_id`를 보내지 않는다.
- **브라우저에는 토큰만 저장한다. 화면마다 키 하나다.** 키오스크(이용자 화면)는 `localStorage`의 `chaekbang.kiosk.token`(PC를 다시 켜도 이어짐), 관리자 화면은 `sessionStorage`의 `chaekbang.admin.token`(탭을 닫으면 사라지고 키오스크 토큰을 덮어쓰지 않음)이다. 저장소 접근은 `api.js`에만 있고 화면은 처음에 `useScreen`으로 정한다. 대화, 검색어, 회원 토큰, 관리자 목록은 메모리에만 두고 새로 고치거나 비우면 사라진다(공용 PC). 새로 고치면 회원은 로그아웃된다. 담은 책도 화면에는 사본만 메모리에 두고(브라우저 저장소에 쓰지 않음), 서버가 회원별로 3시간 보관한다.
- **서버 값은 글자로만 넣는다.** `textContent`, `setAttribute`를 쓰고 `innerHTML` 계열, `eval`은 쓰지 않는다. 주소(표지, 상품 링크)는 `card.js`의 `safeUrl`을 거쳐 `http`·`https`만 쓴다.
- **책 값은 `book.필드` 형태로만 읽는다.** 필드 이름은 `BookSummary`·`BookCard`·`RelatedBook`에 있어야 한다. 테스트가 `card.js`를 검사한다.
- **표지는 원본 URL로만 보이고 출처(`cover_source`)를 함께 보인다.** 외부 대출 기관은 대출 상태의 갱신 시각(`status_synced_at`)을 보인다. 표지가 없으면 자리 표시를 둔다.
- **이용자 화면은 두 시계로 비운다**(`public/librarian/idle.js`): 무입력 1분(45초에 알림, 입력하면 다시 셈, 답을 받는 동안에는 세지 않음), 이용 상한 3분(**회원이 로그인한 순간부터** 센다. 2분 30초에 알림, 입력해도 늘지 않고 답을 받는 중에도 멈추지 않음). 시계가 하는 일은 로그인 여부로 갈린다.
  - 로그인하지 않았을 때: 무입력 1분이면 화면을 비우고 시작 화면("화면을 눌러 시작하세요")이 보이며 누르면 대화 화면으로 간다(처음 열 때도 시작 화면). 이용 상한은 없다.
  - 로그인 중: 무입력 1분과 상한 3분 모두 **회원만 로그아웃하고 바로 시작 화면**으로 간다(로그아웃 문구 없음). 서버 회원 세션을 끊고(`/auth/member-logout`) **대화, 화면의 담은 책, 입력칸을 모두 비운다**(받는 중인 답은 끊긴다. 서버에 보관한 담은 책은 지우지 않는다. 다시 로그인하면 나온다). [로그아웃] 버튼도 같다. 시작 화면에서는 시계가 세지 않고, 시작 화면을 누른 뒤 첫 입력부터 익명 무입력 시계가 센다. 서버 회원 세션 오류(403)만 시작 화면 없이 화면을 로그아웃하고 로그인 칸을 연다.
  - 어느 쪽도 키오스크는 로그아웃하지 않는다. [새 대화]와 대화 세션 끝은 시작 화면 없이 대화만 비우고 로그인과 담은 책은 남긴다(`main.js`의 `resetChat`). 서버 회원 세션 수명(`member_session_minutes`, 3분)은 이용 상한과 같고 AI 사서 세션 한도(5분)보다 짧다. 테스트가 본다. 확인용으로 `?idle_seconds=N`, `?cap_seconds=N`이 시계를 줄인다(알림은 15초·30초 앞).
- **로그인과 역할 확인.** 화면은 열 때 `requireRole`로 `GET /auth/me`를 불러 역할을 확인한다(이용자 화면은 `kiosk`, 관리자 화면은 `admin`). 토큰이 없거나 401이거나 역할이 다르면 그 화면의 키만 지우고 `/ui/login/`으로 간다. 이용자 화면에는 직원 로그아웃 버튼이 없다(키오스크를 끌 사람이 없다). 위 띠의 [로그아웃]은 회원 로그아웃이다. 위 띠의 [직원 로그인]은 `/ui/login/`으로 가는 링크 하나다(키오스크·관리자 직원이 다른 계정으로 들어가는 길). 이동만 하고 키오스크 토큰을 지우거나 직원 로그아웃을 부르지 않는다. 관리자 화면에는 [로그아웃]이 있고 뒤로 가기 캐시로 돌아오면 토큰을 다시 확인한다. 로그인 화면은 로그인한 상태로 열려도 넘기지 않는다(같은 PC에서 관리자가 새 탭으로 로그인하는 길).
- **Enter는 서명·저자 찾기를 먼저 한다**(`librarian/chat.js`의 `submitText`, `main.js`의 `submit`). 1권 이상이면 AI 사서 대화를 보내지 않고 두 단계 결과를 보인다: 위 단 "이 책을 찾으시나요?"(찾기 결과 앞 2권), 아래 단 "'질의'와 관련된 책"(`/catalog/topic` 결과에서 위 단 책을 뺀 것, 비거나 실패하면 제목째 숨김), [사서에게 물어보기](같은 글을 대화로 한 번). 0권이거나, 입력이 100자(`suggest.js`의 `MAX_QUERY`, 서버 질의 상한과 같음)를 넘거나, 찾기가 실패하면(401은 로그인 화면) 지금처럼 AI 사서 대화로 간다. 자동완성 후보 고르기와 "모두 찾기"는 그대로다. 두 단계 결과는 서버 세션을 만들거나 바꾸지 않고 [새 대화]·무입력으로 지워진다.
- **관리자 화면은 보고 승인·반려한다.** 승인 목록(큐레이션·연체 안내문 틀·구매 요청서)은 상세 보기, 승인(확인 한 번), 반려(사유 필수), 게시 내리기만 하고 만들기·고치기 양식은 없다(초안은 운영 대화로 만든다). [오늘의 연체] 탭, 틀 묶음, [장서] 탭은 `loan_mode`가 `internal`일 때만, [장서 가져오기] 탭은 `external`일 때만 보이고 [회원]·[휴관일]은 두 방식 모두 보인다(`admin/main.js`의 `loadLibrary` 한 곳, 못 읽으면 운영 방식에 따른 것은 모두 숨김, 숨긴 탭의 주소는 운영 대화, 서버 409가 방어선).
- **운영 대화의 표와 [초안 보기]**(`admin/chat.js`): SSE `result`는 모아 두었다가 `answer`가 온 뒤 답 말풍선 아래에 받은 순서대로 그리고, `answer` 없이 끝나면 버린다. `kind`가 `table`이면 제목·설명 줄·표이고 모르는 종류는 건너뛴다. 막대 열은 그 열의 가장 큰 값을 100%로 한 CSS 막대(라이브러리 없음)이고 빈 칸은 `-`, 숫자 칸은 오른쪽 맞춤, 잘린 표는 "전체 N건 중 M건"을 보인다. 넓은 표는 `.result-table`만 가로로 스크롤한다. `draft`는 답 아래 [초안 보기] 버튼이고, 누르면 승인 목록 탭에서 그 초안을 펼친다(`main.js`의 `openDraft` → `approvals.js`의 `reveal`: 승인 대기에 없으면 전체 보기, 그래도 없으면 "그 초안을 찾지 못했어요"). 초안 종류 이름은 `DRAFT_KINDS`가 승인 목록 묶음에 맞춘다. 표와 대화는 메모리에만 있고 탭을 바꿔도 남으며 [새 대화]가 함께 비운다.
- **장서 가져오기**(`admin/imports.js`): 파일 올리기 → 미리 보기 요약(행 수, 빠진 사본 수, 인식한 열)과 확인할 행(건너뜀과 표기 넷, 20줄씩) → [적용]. 파일 내용은 화면이 읽지 않고 서버로 보내기만 한다. 필수 열을 못 찾은 422는 응답의 `missing`·`headers`로 열을 고르게 하고 `column_mapping`으로 같은 파일을 다시 보낸다(머리글이 없으면 서버 문구만). [적용]은 가장 최근 기록이 미리 보기일 때 그 기록에만 만든다(옛 미리 보기를 서버는 막지 않는다). 확인 한 번 뒤 적용하고, 대량 제적 409는 문구의 `confirm_withdraw`로 알아봐 서버 문구 대신 화면 문장으로 한 번 더 묻는다. 성공은 알리지 않고 목록·요약을 다시 읽는다. 미리 보기가 생기면 파일 선택을 비운다(같은 파일 중복 방지, 열 고르기 422는 남김). [삭제]는 미리 보기에만 있고 확인 한 번 뒤 지운다. 목록은 적용한 기록과 미리 보기를 색으로 나누고 연 기록을 표시한다. 기증처와 회원 값은 보이지 않는다. 열 이름·표기 이름 표는 서버 값과 같아야 하고, `record.`는 `HoldingImportRead`, `row.`는 `HoldingImportRow` 필드만 읽는다(테스트).
- **장서**(`admin/collection.js`, 자체 대출 기관): 들어오면 최근에 등록한 사본부터 보이고(`GET /holdings`), 서명·저자·등록번호 한 칸으로 `GET /holdings?q=`를 불러 사본 표(20줄씩)를 보인다. 찾은 동안에만 [전체 보기]가 있어 처음 목록으로 돌아간다(빈 칸으로 [찾기]도 같다. `status`는 보내지 않아 분실·제적도 나온다). 상태는 이용 가능·분실·훼손·제적에서 고르고 제적만 한 번 더 묻는다. 실패·취소면 고르기를 되돌린다. 대출 중 줄은 [반납](확인 뒤 `/loans/return`, 그 줄을 다시 읽음). [책 등록]은 ISBN으로 있는 책인지 확인하고(`/library-books?isbn=`) 없으면 기관 도서를 만든 뒤 사본을 등록한다. 만든 책의 id를 칸이 들고 있어 사본 등록이 실패해도 다시 누르면 사본만 보내고, 같은 ISBN이 그사이 생겼으면(409) 다시 찾아 잇는다. 성공은 알리지 않고 그 등록번호로 찾는다. `holding.`은 `HoldingRead` 필드만 읽는다.
- **회원**(`admin/members.js`): 첫 20명(회원번호 순)과 이름·회원번호 찾기, 등록(회원번호·이름·휴대폰 번호 모두 필수), [고치기](이름·휴대폰 번호. 번호는 지울 수 없고, 번호 없던 기존 회원만 비운 채 이름을 고친다), [삭제](확인 뒤, 대출 중이면 서버 문구). 입력칸은 `autocomplete="off"`다.
- **휴대폰 번호의 하이픈**은 `shared/phone.js` 한 곳이다: 회원·연체 목록은 `formatPhone`, 번호 칸(관리자 회원 등록·고치기, 이용자 회원 로그인)은 `attachPhoneInput`(치는 대로 하이픈, 13자). 서버는 하이픈을 지워 저장한다.
- **휴관일**(`admin/closures.js`): 오늘부터 365일의 임시 휴관일, 날짜·사유(100자)로 더하기, 확인 뒤 삭제. 날짜는 브라우저의 오늘이다.
- **회원 값은 세 탭에서만 보이고 들어올 때마다 다시 읽는다.** 희망도서·오늘의 연체·회원 목록의 회원번호·이름·전화·문안은 그 탭에 들어올 때마다 서버에서 다시 읽는다(떠날 때 지우지는 않는다. 숨긴 패널은 보이지 않고 DOM을 볼 수 있는 사람은 이미 로그인한 탭을 쥔 사람이다). 복사·출력·내려받기 버튼과 `console` 출력이 없다. 관리자 무입력 자동 로그아웃은 하지 않는다(개선 사항).
- **회원 토큰은 대출·희망도서·담은 책·회원 로그아웃 요청의 `X-Member-Token` 헤더에만 붙인다**(`api.js`의 `borrow`, `requestBook`, `basket`·`addBasket`·`removeBasket`·`clearBasket`, `memberLogout`). 이용자 화면에는 `member_number`가 없고, 대화·검색·자동완성 요청에는 회원 값이 없다. 대화 요청 본문의 키는 `session_id`, `message`, `selected_library_book_id`뿐이다. 이용자 화면은 응답의 회원번호·이름을 보이지 않고, 위 띠에는 "로그인 중"만 보인다. 관리자 화면은 희망도서·연체 목록(`requests.js`, `overdue.js`)과 회원 탭(`members.js`)에서만 회원 값을 읽는다. 회원 값이 요청에 실리는 곳은 회원 등록·고치기·찾기뿐이다. 테스트가 소스를 검사한다.
- **403은 회원 세션 오류다**(`api.js`의 오류 종류 `member_required`). 이용자 화면은 직원 토큰 오류(401)와 구분해, 대출·신청이 403이면 화면도 회원만 로그아웃하고 로그인 칸을 연다. 키오스크 토큰과 로그인 화면은 건드리지 않는다.
- **회원 로그인**(`member.js`, `actions.js`): 휴대폰 번호로 `POST /auth/member-login`을 부른다. 토큰은 `member.js`의 변수 한 칸에만 있다. 검색·대화·반납은 로그인 없이 되고, 담기·빌리기·희망도서는 로그인이 필요하다. 빌리기·희망도서를 로그인 전에 누르면 로그인 칸을 열고, 성공하면 그 동작을 이어서 한다(기다리는 동작 하나: 빌리기는 등록번호를 남긴 채 빌리기 칸으로, 희망도서는 신청 칸으로). 담기는 로그인 전에는 버튼이 없다(바깥 `.app`의 `logged-in` 클래스 하나로 카드의 [담기]를 보이고 숨긴다). 외부 대출 기관도 로그인 칸은 같고 [대출·반납]만 숨는다.
- **담은 책**(`basket.js`): 로그인하면 `GET /basket`으로 불러오고(문구 없음, 실패해도 빈 목록, 401은 로그인 화면·403은 회원 로그아웃과 로그인 칸), 담기·빼기·[모두 빼기]는 서버가 성공한 뒤에 사본을 바꾼다. 실패 문구는 둘뿐이다(10권 상한 409 "담은 책은 10권까지예요", 그 밖 "잠시 뒤 다시 눌러 주세요"). 로그아웃(버튼·무입력·상한·403)은 사본만 비우고 서버를 부르지 않는다. 담은 책 줄에는 서명·서가·대출 상태가 있고 외부 대출 기관은 "대출 상태 … 기준"을 함께 보인다. 요청하는 사이 로그아웃했으면(토큰이 바뀜) 응답으로 비워 둔 사본을 채우지 않는다.
- **대출·반납·희망도서·로그인 입력칸**(`actions.js`)은 칸 하나에 모드 넷(로그인, 빌리기, 반납하기, 희망도서)이다. [대출·반납] 버튼은 HTML에서 `hidden`으로 시작하고, 도서관 안내의 `loan_mode`가 `internal`일 때만 보인다(`main.js`의 `loadGuide`, 안내를 못 읽으면 숨김). 외부 대출 기관은 서버가 409로 막는다. [희망도서 신청]은 두 방식 모두 보이고, AI 사서가 희망도서를 안내한 답(`suggest_book_request`)에도 같은 버튼이 붙는다.
- **입력은 칸이 열린 동안만 둔다.** 칸을 닫거나 화면을 비우면(`resetAll`: 익명 무입력, `memberLogout`: 로그아웃) 모든 입력을 지운다. 입력칸은 `autocomplete="off"`다. 로그인이 성공하면 휴대폰 번호를, 빌리기·반납이 성공하면 등록번호만 지우고(연속 대출) 희망도서가 성공하면 모두 지운다. 서버 문구(404·409)는 글자로만 칸 안에 보인다.
- 최신 크롬·엣지를 가정한다(`fetch` 스트림, `TextDecoderStream`, ES 모듈).
- 대화 요청은 POST에 토큰 헤더가 필요해서 `EventSource`가 아니라 `fetch` 스트림으로 읽는다.

## 로그인

`/ui/login/`에서 아이디·비밀번호로 로그인하면 역할(`kiosk`·`admin`)에 따라 이용자 화면이나 관리자 화면으로 간다. 입력칸은 `autocomplete="off"`이고 공용 PC에서는 비밀번호를 저장하지 말라고 안내한다. 크롬이 자동 완성을 무시할 수 있으니 **키오스크 PC의 크롬 설정에서 "비밀번호 저장 제안"을 꺼 두기를 권한다**(운영 안내). 개발용 `#token=`은 없앴다. 개발 계정은 `.env`의 `SEED_ADMIN_PASSWORD`·`SEED_KIOSK_PASSWORD`로 만든 `sunny-admin`·`sunny-kiosk`(햇살, 자체 대출)와 `forest-admin`·`forest-kiosk`(푸른숲, 외부 대출) 등이다.

## 시험

`tests/platform/test_web_ui.py`가 세 화면의 서빙, 경로(서버 OpenAPI와 대조), 기존 API만 쓰기, 저장 규칙, 안전한 표시, 카드 필드 계약, 회원 토큰의 행선지, 회원 로그인(시계·표시·저장), 대출 버튼 조건, 입력칸 자동 완성, 로그인·역할 확인, 시간 값, 관리자 화면 규칙, 운영 대화의 결과(`answer` 뒤에만 그림, 읽는 필드, 초안 종류 이름 맞춤, [초안 보기]), 장서 가져오기 화면(필드 계약, 열·표기 이름, 확인 순서, [적용] 조건), 장서·회원·휴관일 화면(보내는 값과 읽는 필드가 스키마에 있음, 상태 고르기, 확인 순서, 책 등록의 확인·이어 하기, 휴관일 조회 기간)을 본다. 화면 동작은 change `design.md`의 브라우저 확인 항목으로 본다(`add-librarian-web-ui`, `add-librarian-actions`, `add-web-ui`, `add-two-step-search`, `add-member-login`, `add-admin-import-ui`, `add-admin-analytics-ui`). 브라우저 자동화 테스트(Playwright)는 승인 흐름이 화면으로 생겼으니 `add-admin-analytics-ui` 뒤에 다시 본다.
