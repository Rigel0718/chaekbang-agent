## Why

지금 AI 사서 평가(`evals/librarian`, 표본 87권)는 규칙 위반과 기대 일치만 본다. 추천이 요청에 어울리는지는 재지 못해, `add-topic-search-tool`의 전후 비교도 "나빠지지 않음"까지만 말할 수 있었다. MVP 전에 대화 추천의 품질을 한 번 숫자로 재고, 뒤의 change(프롬프트·tool 변경)가 같은 표로 비교할 수 있게 한다. MVP를 빨리 내는 것이 우선이라 기능 평가에 필요한 만큼만 한다(2026-11-17 사용자 결정).

## What Changes

- **대화 추천 평가**(새 평가, LLM 포함): 실험 장서 525권을 테스트 DB에 넣고, 추천 실험의 세 세트(주제 30, 비슷한 책 20, 최근 기록 10) 항목을 실제 대화로 돌린다. 카드로 나온 책을 기존 어울림 라벨(같은 항목 id × 책 키)로 채점한다.
  - 지표: Hit@5, Recall@5, nDCG@5, 카드 없음 수, 라벨 없음 수. 묶음별(주제어, 상황, 어린이, 비슷한 책, 아무거나)로 낸다.
  - 같은 턴 tool 결과의 앞 5권도 같은 라벨로 채점해, LLM이 고른 효과를 함께 본다.
  - 라벨 없는 카드는 실행 뒤 Claude가 보충하고(`pool` 단계), 사용자는 고정 표본만 본다.
  - 실행 사이 비교: 두 실행의 카드를 지금 라벨로 다시 채점한다(버전별 점수표).
- **실제 LLM 낱말 확인**(LLM 없음): 대화 평가가 검색 tool에 넘어간 낱말을 평가 안에서만 받아 둔다(제품 실행 기록은 그대로 남기지 않는다). 그 낱말로 주제로 찾기를 돌려, 벡터 질의가 낱말인 제품 기본(`hybrid-best`)과 이용자 문장인 `hybrid-k60`을 같은 라벨로 짝 비교한다.
- **`related-anything` 검사 판정**: "아무거나" 요청에서 관련 책 tool을 비워 부른 뒤 같은 턴에 검색도 했다면, 검색 결과에서 고른 추천도 맞음으로 센다. 스펙 문장을 그에 맞춘다.
- 키워드 순위가 빈 검색과 `note` 횟수는 대화 평가 요약에 적기만 한다. 빈 결과 규칙은 바꾸지 않는다.

**넣지 않는 것**(MVP 뒤로 옮김, 2026-11-17 사용자 결정): 어린이 지표 둘(책 분류, 요청 판단)과 섞인 기록의 어린이 조건, 모델 비교, 사람만 단 라벨과의 일치도, 없는 주제 세트와 빈 결과 규칙, 비슷한 책 API 노출 기록의 출처 칸, 평가 표본 87권의 세 출처 전환. LLM 채점도 하지 않는다(최종 서비스 테스트에서).

## Capabilities

### New Capabilities

- `platform/conversation-recommendation-evals`: 실제 대화로 낸 추천 카드를 어울림 라벨로 채점하는 평가. 실험 장서 적재, 세트 항목을 대화로 바꾸기, 지표와 묶음, 라벨 보충, 실행 사이 비교, tool 입력을 평가 안에서만 받기.

### Modified Capabilities

- `platform/recommendation-experiments`: 주제 세트의 낱말을 대화 평가가 받은 실제 LLM 낱말로 바꿔 돌리는 실행을 더한다.
- `agent/librarian`: "관련 책 요청에 답함"의 "아무거나" 시나리오에서, 같은 턴의 검색 결과로 답해도 된다.

## Impact

- 새 평가 패키지 `evals/conversation/`(`uv run python -m evals.conversation`). `evals/librarian`의 시나리오 실행기·되돌리는 세션, `evals/recommendation`의 라벨·지표·책 키·보충 도구, `scripts/seed_experiment.py`의 적재를 다시 쓴다.
- `evals/librarian/checks.py`의 `related_met`. 이미 있는 실행 결과를 다시 채점할 수 있다.
- `evals/recommendation/__main__.py`(주제 실행에 실제 낱말 넣기).
- 제품 코드(`app/`)는 바꾸지 않는다. DB 스키마도 바꾸지 않는다.
- 외부 도서 API 호출 없음. LLM은 대화 평가 두 실행(`gpt-6-luna`, 사용자 승인 뒤). 임베딩 서버는 실험 장서 문서 벡터를 처음 캐시할 때와 평가 실행 동안만 띄운다.
- 받은 응답과 평가 결과는 `evals/conversation/data/`(저장소에서 뺌)에 둔다.
