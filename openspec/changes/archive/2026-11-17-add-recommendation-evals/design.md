- **MVP 우선**(2026-11-17 사용자 결정): 대화 추천을 기능 평가만 하고 다음 change(`add-admin-agent`)로 넘어간다. 범위 후보 일곱 개 중 이번에 넣는 것은 1(어울림 라벨·지표), 3(실제 LLM 낱말), 5(`related-anything`)다. 4(빈 결과)는 횟수를 적기만 한다. 나머지는 MVP 뒤다(아래 Non-Goals).
- **지금 AI 사서 평가**(`evals/librarian`): 시나리오 32개, YES24 표본 87권을 테스트 DB의 가상 기관에 넣고 되돌린다. 표본에는 잡지·수험서가 섞여 있고 라벨이 없다. 마지막 실행은 32개에 턴 35개, LLM 호출 약 73회, 입력 약 23만 토큰이었다(`add-topic-search-tool` 결과).

- **tool 입력**: 검색 tool(`SearchInput.keywords`)은 `record_fields`가 없어 낱말이 실행 기록에 남지 않는다. 관련 책 tool은 `library_book_id`만 남긴다.
- **`related-anything`**: 네 실행 모두 관련 책 tool을 비워 부른 뒤 `search_collection`도 불러 그 결과에서 추천했다. 검사(`related_met`)는 "추천이 모두 관련 책 결과 안"이라 틀림으로 셌다. 스펙 문장도 "결과에 나온 책으로 답한다"였다.

## Goals / Non-Goals

**Goals:**

- 실제 대화의 카드가 요청에 어울리는지를 기존 라벨로 한 번 잰다. 묶음별 점수표가 나오고, 뒤 change가 같은 명령으로 비교할 수 있다.
- 제품 코드와 DB 스키마는 바꾸지 않는다. 평가 코드만 더한다.
- 새 라벨은 대화가 낸 책 중 라벨 없는 것만 단다. 새 세트는 만들지 않는다.

**Non-Goals (MVP 뒤, 2026-11-17 사용자 결정):**

- 어린이 지표 둘(책 분류의 정밀도·놓친 비율, 요청 판단의 맞은 비율·오판 비율)과 섞인 기록의 어린이 조건(보고서 OQ3)
- 모델 비교(`LLM_PRICES`의 다른 모델), 사람만 단 라벨과 Claude 라벨의 일치도
- 소장 도서가 없는 주제 세트와 빈 결과 규칙(보고서 OQ1)
- 비슷한 책 API 노출 기록의 출처 칸, 평가 표본 87권의 세 출처 전환(보고서 OQ6)
- LLM 채점(최종 서비스 테스트에서)

## Decisions

### 1. 실험 장서를 테스트 DB에 넣는다

**제안:** 대화 추천 평가는 87권 표본이 아니라 실험 장서 525권에서 돈다. 장서는 `scripts/seed_experiment.py`의 적재(`seed_experiment`, 세 출처 합침)를 테스트 DB의 되돌리는 세션(`evals/librarian/__main__.py`의 `rollback_session`)에서 부른다.

- 라벨을 그대로 쓰려면 같은 장서여야 한다. 87권에 라벨을 새로 다는 것보다 훨씬 적게 든다.
- 키 일치는 테스트로 확인한다(개발 DB 없이, 적재 규칙에서 나온 등록번호와 ISBN).
- 시드 비밀번호는 평가용 고정 값을 넘긴다. 계정은 되돌릴 때 함께 사라진다.
- 벡터는 `load_catalog`과 같은 두 층 적재를 쓴다. 문서 벡터는 `CachedEmbedder`로 `evals/conversation/data/doc_vectors.json`에 캐시한다. 처음 한 번만 임베딩 서버로 인코딩한다(87권이 115초였으니 525권은 약 12분, 백그라운드). 질의 캐시는 `data/query_vectors.json`이다.
- 안:
  - (a) 개발 DB의 실험 기관에서 되돌리는 세션으로 돌린다. 적재와 벡터가 이미 있지만 "LLM 평가는 테스트 DB" 규칙을 깨고 개발 DB에 쓰기가 생긴다.
  - (b) 87권 표본에 라벨을 새로 단다. 표본 성격이 작은도서관과 다르고 라벨 양이 많다.

### 2. 세트 항목을 대화로 바꾸는 법

| 세트 | 대화 | 묶음 |
| --- | --- | --- |
| `topic` 30 | 이용자 문장 한 턴 | 어린이(12) / 일반은 결로 주제어·상황 |
| `similar` 20 | 기준 책을 고른 턴(LLM 없음) → `이 책이랑 비슷한 책 있어요?` | 비슷한 책 |
| `history` 10 | 기록의 책을 오래된 것부터 고른 턴들(LLM 없음) → `아무거나 추천해 줘` | 아무거나 |

- 어린이 기준 책(비슷한 책 8권)이나 책이 모두 어린이 도서인 기록(3개)은 어린이 요청 문장을 쓴다(예 `아이랑 같이 볼 건데 이 책이랑 비슷한 책 있어요?`, `아이가 읽을 거 아무거나 추천해 줘`). 실험이 이 항목에 어린이 조건을 걸었기 때문이다. 문장이 어린이 요청 판단 규칙에서 어린이로 나오는지 테스트한다.
- 고른 턴은 `chat.prepare_turn(selected_id=…)`로 보낸다(`run_scenario`의 `Picked`와 같은 길). 최근 기록은 고른 순서대로 세션 메시지에 쌓여 `session_books`의 최신 3권이 기록과 같다.
- 실행기는 `evals/librarian/runner.py`의 `run_scenario`를 넓혀 쓴다. 새 시나리오 종류를 더하지 않고, 평가 패키지가 항목에서 `Scenario`를 만들고 고를 책 id 목록을 넘긴다. 규칙 검사(`score`)도 그대로 쓴다. 검사가 쓰는 표본 정보(`SampleCatalog`의 추천 가능, 어린이, 서지 글)는 실험 장서에서 같은 모양으로 만든다.

### 3. 지표

- 카드는 최대 5권이고 순서가 있다. 항목마다 Hit@5, Recall@5, nDCG@5를 낸다. 계산은 `evals/recommendation/metrics.py`의 함수를 쓰고, Recall만 깊이 5다(카드가 5권까지라 실험의 Recall@10은 맞지 않는다).
- **tool 결과 앞 5권**: 마지막 턴에서 처음 부른 추천 tool(검색 또는 관련 책)의 결과 앞 5권도 같은 지표로 낸다. 카드가 tool 순서보다 나은지(LLM이 고른 효과) 본다. 이것도 라벨 보충 대상이다.
- 요약: 전체와 묶음별 평균, 카드 없음, 라벨 없는 카드, 규칙 위반, 턴·호출·토큰·비용(`LLM_PRICES`), 키워드 순위가 빈 검색과 `note` 수. 실행 폴더는 `evals/conversation/data/runs/<시각>-<모델>/`이다. 항목별 JSON, `results.json`(보충 도구 형식), `summary.md`를 쓴다.
- 요약 머리에 모델, 프로필 버전(`PROFILE_VERSION`), 세트 해시, 라벨 수(단계·단 쪽별)를 적어 버전별 점수표의 한 줄이 되게 한다.
- 채택 규칙은 두지 않는다. 이번에는 점수표를 내는 것이 목표다. 뒤 change가 이 표와 비교한다.

### 4. tool 입력은 평가 안에서만 받는다

- 평가가 프로필의 tool handler를 감싼다. 감싼 handler가 입력(검색 낱말, 관련 책 id)과 결과의 책 id를 메모리 목록에 적고 원래 handler를 부른다. 제품의 `Tool` 정의, `record_fields`, 실행기는 바꾸지 않는다.
- 받은 값은 평가 결과 파일(저장소 밖)에만 쓴다. 평가 문장은 사람이 쓴 세트 문장이라 개인정보가 없다.
- 관련 책 결과를 같은 service로 다시 구하는 지금 방식(`runner._related`)은 그대로 둔다. 감싼 기록과 같아야 하며 테스트로 확인한다.

### 5. 실제 LLM 낱말로 벡터 질의 입력 다시 보기 (LLM 없음)

- `uv run python -m evals.recommendation topic --keywords-from <대화 실행 폴더> --split all --variants hybrid-k60,hybrid-best`. 항목마다 마지막 턴의 첫 검색 호출 낱말로 세트의 낱말을 바꾼다. 검색 tool을 부르지 않은 항목은 빼고 수를 적는다.
  - `hybrid-k60`: 키워드는 LLM 낱말, 벡터는 이용자 문장
  - `hybrid-best`: 둘 다 LLM 낱말(제품)
- 개발 DB 실험 기관에서 읽기만 한다(기존 실험과 같다). 새 낱말의 질의 벡터는 임베딩 서버로 인코딩하고 캐시한다.
- 상위 5권의 라벨 없는 책은 실행 뒤 보충한다(라벨 파일 백업 → Claude 초안 → 고정 표본).
- **미리 정한 읽기**(조정 세트, `hybrid-best` − `hybrid-k60`):
  - 나쁨(차이 < 0이고 95% 구간 상한 < 0)이면 결과를 적고 멈춰 사용자에게 알린다. 문장 입력은 대화 코드가 문장을 tool에 넘기는 제품 변경이라 이 change에서 하지 않는다.
  - 그 밖이면 낱말을 그대로 둔다. `docs/roadmap.md` 근거 칸에 실제 LLM 낱말 결과를 더한다.
- 낱말은 첫 실행의 것을 쓴다. 두 실행의 낱말이 다른 항목 수를 함께 적는다.

### 6. `related-anything` 판정

- 스펙을 "아무거나 요청은 같은 턴의 검색 결과로도 답할 수 있다"로 고친다. 검색 결과에서 고른 것이 틀린 답은 아니다. 품질은 아무거나 묶음의 어울림 점수가 본다.
- `related_met`: 기대가 `EMPTY`이고 그 턴에 검색 tool(`search_collection`, `search_children_books`)도 불렀으면, 추천이 관련 책 결과 안에 있는지 묻지 않는다. 비워서 불렀는지는 그대로 본다. 추천할 수 있는 책인지는 `not_held`가 따로 본다.
- 프롬프트는 고치지 않는다.
- 이미 있는 네 실행(`add-topic-search-tool`)의 JSON을 새 검사로 다시 채점해 `related-anything`이 맞음으로 바뀌는지 확인한다(LLM 없음).

### 7. 라벨

- 실행 전 라벨은 이미 있다. 이번 대화는 기존 라벨을 본 뒤 만든 변형이 아니라 제품 그대로라 치우침이 없다.
- 보충: 첫 실행 뒤 라벨 파일 셋을 `/home/pollux/chaekbang-backups/labels-<시각>-before-chat/`에 백업한다. 그다음 `draft dump <세트> --pool <대화 실행>`, Claude 초안, `draft apply --pool`, 사용자 `review <세트> --sample --since <백업>` 순서다. 표본의 30% 이상을 고치면 멈춘다. 둘째 실행 뒤에도 라벨 없는 카드가 있으면 같은 순서로 한 번 더 한다.
- `draft`의 `--pool`이 대화 실행 폴더를 읽게 한다. 대화 평가의 `results.json`은 실험 실행과 같은 형식(세트 → 변형 이름 `chat` → 항목 → 책 키 목록)이고, 카드와 tool 결과 앞 5권을 합친 목록을 둔다.

### 8. 실행과 비용

- 두 번 돌린다(`gpt-6-luna`). 실행 사이 흔들림을 보려는 것이다. 그 뒤 `compare`로 지금 라벨에서 두 실행을 나란히 낸다.
- **추정**(실행 1회): 항목 60개, LLM 턴 60개(고른 턴은 LLM 없음). 지난 실행의 턴당 입력 약 6,600, 출력 약 140, 호출 약 2.1회로 잡는다.
  - 입력 약 40만, 출력 약 8.4천 토큰, 호출 약 126회
  - 캐시 없이 약 $0.044
  - 두 번이면 입력 약 80만, 출력 약 1.7만, 호출 약 250회, **약 $0.09**
  - **상한 $0.15로 승인을 요청한다.** 실제 사용량이 추정을 넘으면 결과에 그대로 적는다.
- 걸린 시간: 턴당 약 4~5초라 실행당 약 5분이다.
- 평가가 도는 동안 pytest를 돌리지 않고 앱 코드를 고치지 않는다. 임베딩 서버는 문서 캐시를 만들 때와 두 실행 동안만 띄우고 끝나면 내린다.
- 테스트 DB에 525권을 넣고 되돌리므로 실행 뒤 `VACUUM ANALYZE`를 한다.

### 9. 테스트

- 적재: 실험 장서 적재 뒤 책 키가 적재 규칙과 같음(작은 가짜 장서 파일), 되돌린 뒤 기관이 없음, 문서 캐시 적중이면 인코더를 부르지 않음
- 대화 바꾸기: 세 세트의 턴 모양, 어린이 문장이 어린이 요청 판단 규칙에서 어린이, 기록 순서와 `session_books`
- 지표: 스펙의 계산 예, 카드 없음, tool 결과 앞 5권, 묶음 나누기, 보충 전 표시, 비용 계산
- tool 감싸기: 두 번 부른 낱말과 결과, 실행 단계에 낱말 없음, 관련 책 결과가 다시 구한 결과와 같음
- 비교: 지금 라벨로 다시 채점, 세트 해시가 다르면 멈춤
- 실험: `--keywords-from`의 낱말 바꾸기, 검색 없는 항목 빼기
- 검사: `related_met`의 아무거나 뒤 검색, 비슷한 책은 그대로 엄격
- 가짜 LLM으로 대화 평가 한 항목씩 끝까지(세트마다)

## Risks / Trade-offs

- **[라벨이 Claude 판단에 기댐]** 수치는 같은 라벨에서 버전끼리 비교할 때만 쓴다. 요약에 라벨 단 쪽 수를 적는다. 사람 라벨과의 일치도는 MVP 뒤다.
- **[실험 장서는 작은도서관 장서가 아님]** YES24 스테디셀러 525권이고 기관·사본이 가상이다. 실제 서비스 성능으로 쓰지 않는다고 요약에 적는다.
- **[두 번으로 흔들림을 다 가르지 못함]** 이번에는 기준 점수표를 내는 것이 목표라 채택 규칙을 두지 않는다. 뒤 change가 비교할 때 같은 두 번 규칙을 쓴다.
- **[보충 라벨이 보고한 실행 쪽으로 기움]** 보충은 카드와 tool 앞 5권만이고, 어느 실행이 낸 책인지 보지 않고 단다(실험과 같은 방식).
- **[처음 문서 인코딩 약 12분]** 한 번뿐이고 캐시 뒤에는 서버 없이 적재된다.
- **[어린이 요청 문장]** 고정 문장이 어린이로 판단되지 않으면 어린이 항목이 일반 결과로 채점된다. 테스트로 막는다.

## Migration Plan

- 제품 동작·스키마 변경이 없다. 되돌리기는 평가 패키지와 검사 변경을 빼면 된다.
- 순서: 평가 코드와 테스트 → 문서 벡터 캐시(임베딩 서버) → 승인 → 첫 실행 → 라벨 보충과 표본 검수 → 둘째 실행 → 비교 → 실제 LLM 낱말 실행과 보충 → 문서.
