# Spec Delta

## MODIFIED Requirements

### Requirement: 브라우저 저장
화면은 브라우저에 직원 토큰 말고 아무것도 MUST NOT 저장한다. 토큰은 화면마다 키 하나다. 키오스크 토큰은 `localStorage`에, 관리자 토큰은 `sessionStorage`에 둔다. 관리자 토큰은 탭을 닫으면 사라지고 키오스크 토큰을 덮어쓰지 않는다. 대화, 검색어, 회원 토큰, 관리자 화면의 목록은 화면 메모리에만 두고, 새로 고치거나 화면을 비우면 사라진다. 담은 책도 화면에는 메모리의 사본만 두고 브라우저 저장소에는 두지 않는다(회원별 보관은 서버가 맡는다. `circulation/member-basket`). 회원 토큰은 새로 고치면 로그아웃된다는 뜻이다. 공용 PC에서 다음 사람이 앞사람의 기록을 보지 않게 하기 위해서다.

#### Scenario: 저장소 사용
- **WHEN** 화면 스크립트에서 브라우저 저장소(`localStorage`, `sessionStorage`, `indexedDB`, 쿠키)를 쓰는 곳을 모두 모으면
- **THEN** `localStorage`의 키오스크 토큰 키 하나와 `sessionStorage`의 관리자 토큰 키 하나를 읽고 쓰고 지우는 곳뿐이다

#### Scenario: 회원 토큰은 저장소에 없음
- **WHEN** 회원 로그인에 성공한 뒤 브라우저 저장소를 보면
- **THEN** 회원 토큰이 어느 저장소에도 없고, 새로 고치면 로그아웃된 상태다(브라우저 확인)

#### Scenario: 두 토큰이 섞이지 않음
- **WHEN** 같은 브라우저에서 키오스크로 로그인해 둔 뒤 새 탭에서 관리자로 로그인하면
- **THEN** 키오스크 토큰 키는 그대로이고, 관리자 토큰은 다른 키에 있다

#### Scenario: 옛 토큰 키
- **WHEN** 화면 스크립트를 검사하면
- **THEN** 옛 키 `chaekbang.token`과 주소의 `#token=`을 읽는 곳이 없다

#### Scenario: 담은 책은 저장소에 없음
- **WHEN** 책을 담은 뒤 브라우저 저장소를 보면
- **THEN** 담은 책이 어느 저장소에도 없고, 새로 고친 뒤 다시 로그인하면 서버에서 불러와 나온다(브라우저 확인)

### Requirement: 기존 API만 사용
화면은 화면 전용 API 없이 기존 API만 MUST 쓴다. 화면이 부르는 경로는 다른 클라이언트도 쓰는 일반 API이고, 화면 때문에 `/ui` 아래에 API 경로를 두지 않는다.
- 로그인 화면: 로그인, 내 정보
- 이용자 화면: 내 정보, 자동완성, 검색, 주제 검색, 비슷한 책, AI 사서 대화, 대화 종료, 도서관 안내, 회원 로그인·로그아웃, 담은 책(불러오기·담기·빼기·비우기), 대출, 반납, 희망도서 신청
- 관리자 화면: 내 정보, 로그아웃, 기관 정보, 운영 에이전트 대화와 대화 종료, 큐레이션·연체 안내문 틀·구매 요청서의 목록·상세·승인·반려(큐레이션은 내리기도), 희망도서 목록과 닫기, 오늘의 연체 안내 목록

#### Scenario: 서버 경로
- **WHEN** 서버의 경로 목록을 읽으면
- **THEN** `/ui` 아래에는 정적 파일 경로 하나만 있고 API 경로가 없다

#### Scenario: 화면이 부르는 경로
- **WHEN** 화면 스크립트에서 서버에 요청하는 경로를 모두 모으면
- **THEN** 모두 `/auth/login`, `/auth/me`, `/auth/logout`, `/auth/member-login`, `/auth/member-logout`, `/catalog/suggest`, `/catalog/search`, `/catalog/topic`, `/catalog/books/{id}/similar`, `/librarian/messages`, `/librarian/sessions/{id}`, `/library`, `/library/guide`, `/basket`, `/basket/{id}`, `/loans`, `/loans/return`, `/book-requests`, `/book-requests/{id}`, `/admin-agent/messages`, `/admin-agent/sessions/{id}`, `/curations`, `/curations/{id}`, `/curations/{id}/approve`, `/curations/{id}/reject`, `/curations/{id}/unpublish`, `/overdue-notice-templates`, `/overdue-notice-templates/{id}`, `/overdue-notice-templates/{id}/approve`, `/overdue-notice-templates/{id}/reject`, `/purchase-requests`, `/purchase-requests/{id}`, `/purchase-requests/{id}/approve`, `/purchase-requests/{id}/reject`, `/overdue-notices/today` 중 하나다

#### Scenario: 부르는 경로가 서버에 있음
- **WHEN** 화면 스크립트가 요청하는 경로와 메서드를 서버의 경로 목록과 맞춰 보면
- **THEN** 모두 서버에 있는 경로와 메서드다

### Requirement: 이용자 화면의 무입력·이용 상한 비우기
이용자 화면은 두 시계로 화면을 MUST 비운다. 시계가 하는 일은 로그인 여부에 따라 다르다.
- **무입력**: 마지막 입력에서 1분이다. 45초에 알림을 띄우고, 입력하면 알림을 닫고 다시 센다. 답을 받는 동안에는 세지 않는다. 로그인하지 않았으면 화면을 비우고 시작 화면을 보인다(대화 종료, 담은 책·입력칸 지움). 로그인 중이면 **회원만 로그아웃하고 바로 시작 화면**을 보인다(키오스크 토큰은 그대로).
- **이용 상한**: **로그인한 순간부터** 3분이다. 2분 30초에 알림을 띄운다. 입력해도 늘어나지 않고, 답을 받는 중에도 멈추지 않는다. 끝나면 회원만 로그아웃하고 바로 시작 화면을 보인다. 로그인하지 않았으면 이용 상한은 없다.

회원 로그아웃은 서버 회원 세션을 끊고 **대화(대화 종료, 검색 결과, 자동완성), 화면의 담은 책, 입력칸을 모두 비운다.** 서버에 보관한 담은 책은 지우지 않는다(다시 로그인하면 나온다). 그리고 **바로 시작 화면**을 보인다(로그아웃을 알리는 문구도, 대화 화면으로 돌아오는 일도 없다). 버튼, 무입력, 이용 상한이 모두 같다. 서버 회원 세션 오류(403)만 시작 화면 없이 화면을 로그아웃하고 로그인 칸을 연다. 답을 받는 중이었으면 그 답은 끊긴다. 시작 화면에서는 어떤 시계도 세지 않는다(시작 화면을 누른 뒤 첫 입력부터 익명 무입력 시계가 센다). 알림은 화면 아래 띠에 문구와 남은 초를 글자로 보인다. 로그인 중의 문구는 "N초 뒤 로그아웃해요"와 "N초 뒤 이용 시간이 끝나 로그아웃해요"다. 두 시계 모두 서버 AI 사서 세션의 무입력 시간(5분)보다 짧다.

익명 상태에서 시간이 다 돼 비우거나 회원이 로그아웃하면 **시작 화면**("화면을 눌러 시작하세요")을 보이고, 누르면 대화 화면으로 간다. 시작 화면은 화면을 처음 열 때도 보인다. 두 시계 모두 키오스크 토큰은 그대로 두고 로그아웃하지 않는다(다음 이용자가 직원 계정 없이 쓸 수 있어야 한다). [새 대화]와 세션 끝(404)은 시작 화면 없이 대화만 비운다.

#### Scenario: 시간 값
- **WHEN** 이용자 화면 스크립트의 시간 값을 읽으면
- **THEN** 무입력은 60초·알림 45초, 이용 상한은 180초·알림 150초이고, 둘 다 서버 설정 `librarian_session_idle_minutes`(5분)보다 짧다. 서버 회원 세션 수명은 이용 상한과 같은 3분이다

#### Scenario: 무입력 비우기
- **WHEN** 로그인하지 않은 채 45초 동안 입력하지 않으면 알림이 뜨고, 입력 없이 1분이 되면
- **THEN** 화면이 비워지고 시작 화면이 보인다(브라우저 확인)

#### Scenario: 익명은 이용 상한이 없음
- **WHEN** 로그인하지 않은 채 3분이 넘도록 계속 입력하며 쓰면
- **THEN** 화면은 비워지지 않고 이용 상한 알림도 뜨지 않는다(브라우저 확인)

#### Scenario: 무입력 알림과 연장
- **WHEN** 이용 중 45초 동안 입력하지 않으면 알림이 뜨고, 그때 화면을 누르면
- **THEN** 알림이 닫히고 다시 1분을 센다. 로그인 중의 알림 문구는 "N초 뒤 로그아웃해요"다(브라우저 확인)

#### Scenario: 로그인 중 무입력 로그아웃
- **WHEN** 로그인한 뒤 알림에도 입력하지 않아 1분이 되면
- **THEN** 회원만 로그아웃되어 대화와 화면의 담은 책과 입력칸이 비고, 바로 시작 화면이 보인다(로그아웃 문구 없음). 같은 번호로 다시 로그인하면 담은 책이 나온다(브라우저 확인)

#### Scenario: 이용 상한
- **WHEN** 로그인한 뒤 계속 입력하며 쓰다가 2분 30초가 되면 알림이 뜨고, 입력을 이어 가도 3분이 되면
- **THEN** 회원만 로그아웃되어 대화가 비워지고 바로 시작 화면이 보이며, 답을 받는 중이었으면 그 답은 끊긴다(브라우저 확인)

#### Scenario: 쓰지 않는 화면
- **WHEN** 비운 화면에 아무도 입력하지 않으면
- **THEN** 어떤 시계도 시작하지 않고 알림도 뜨지 않는다(브라우저 확인)

#### Scenario: 로그아웃 뒤 익명 시계
- **WHEN** 회원 로그아웃으로 시작 화면이 보이는 채 아무도 입력하지 않으면
- **THEN** 시계가 다시 시작하지 않고 시작 화면 그대로다. 시작 화면을 눌러 입력하면 그때부터 익명 무입력 시계가 센다(브라우저 확인)

#### Scenario: 시작 화면
- **WHEN** 시작 화면을 누르면
- **THEN** 시작 화면이 사라지고 대화 화면이 보인다(브라우저 확인)

#### Scenario: 처음 열 때
- **WHEN** 이용자 화면 HTML을 읽으면
- **THEN** 시작 화면이 숨김이 아닌 상태로 있다

#### Scenario: 로그아웃하지 않음
- **WHEN** 시간이 다 돼 비우거나 회원을 로그아웃하는 길(시계가 부르는 함수와 시작 화면을 보이는 함수)을 검사하면
- **THEN** 키오스크 토큰을 지우거나 로그인 화면으로 보내거나 `/auth/logout`을 부르는 곳이 없다

#### Scenario: 새 대화는 시작 화면 없이
- **WHEN** [새 대화]를 누르면
- **THEN** 대화가 비워지고 시작 화면은 보이지 않는다(브라우저 확인)

### Requirement: 회원 토큰의 행선지
이용자 화면은 회원 토큰을 대출(`POST /loans`), 희망도서 신청(`POST /book-requests`), 담은 책(`/basket`) 요청, 회원 로그아웃(`POST /auth/member-logout`) 요청의 `X-Member-Token` 헤더에만 MUST 붙인다. 대화, 대화 종료, 검색, 자동완성, 안내 요청에는 붙이지 않는다. 이용자 화면은 요청 본문에 회원번호를 넣지 않고, 어떤 응답의 회원번호·이름·전화번호도 표시하지 않는다. 관리자 화면은 회원 값을 읽어 보이기만 하고 어떤 요청에도 넣지 않는다.

#### Scenario: 회원 토큰을 보내는 곳
- **WHEN** 화면 스크립트에서 `X-Member-Token` 헤더를 붙이는 곳을 모두 모으면
- **THEN** 대출, 희망도서 신청, 담은 책, 회원 로그아웃 요청을 만드는 곳뿐이다

#### Scenario: 이용자 화면의 회원번호
- **WHEN** 이용자 화면 스크립트에서 `member_number`를 쓰는 곳을 모두 모으면
- **THEN** 없다

#### Scenario: 대화 요청의 본문
- **WHEN** 화면 스크립트에서 AI 사서 대화 요청 본문을 만드는 곳을 검사하면
- **THEN** 본문의 키는 `session_id`, `message`, `selected_library_book_id`뿐이다

### Requirement: 이용자 화면의 회원 로그인
이용자 화면은 휴대폰 번호로 `POST /auth/member-login`을 불러 회원으로 SHALL 로그인한다. 검색·대화·반납은 로그인 없이 되고, 담기·빌리기·희망도서 신청은 로그인한 회원만 할 수 있다.
- 로그인 칸은 입력칸의 한 모드다. 번호 칸 하나(숫자 키패드)이고 성공하면 번호를 지운다. 실패하면 서버 문구를 글자로 보인다.
- 로그인 중에는 위 띠에 이름·번호 없이 "로그인 중"과 [로그아웃]만 보이고, 담은 책 표시와 카드의 [담기]는 로그인한 동안에만 보인다.
- 운영 방식과 상관없이 로그인 칸을 보인다. 외부 대출 기관에서는 대출·반납이 지금처럼 숨겨진다.

#### Scenario: 익명의 띠
- **WHEN** 이용자 화면 HTML을 읽으면
- **THEN** [회원 로그인]은 숨김이 아니고 담은 책 표시와 [로그아웃]은 숨김 상태로 시작한다

#### Scenario: 로그인 중 표시
- **WHEN** 로그인에 성공하면
- **THEN** 위 띠에 "로그인 중"이 보이고 이름·번호는 어디에도 보이지 않는다(브라우저 확인)

#### Scenario: 로그아웃 버튼
- **WHEN** [로그아웃]을 누르면
- **THEN** 대화와 화면의 담은 책과 입력칸이 비고 바로 시작 화면이 보이며(그 위 띠의 [회원 로그인]이 다시 보인다), 서버의 담은 책은 남는다(브라우저 확인)

#### Scenario: 외부 대출 기관
- **WHEN** 외부 대출 기관에서 이용자 화면을 열면
- **THEN** [대출·반납]은 숨겨지고 [회원 로그인]은 보이며, 로그인한 뒤 담기와 희망도서 신청이 된다(브라우저 확인)

### Requirement: 로그인이 필요한 동작은 로그인 뒤에 이어서 함
이용자 화면은 로그인이 필요한 동작을 로그인 전에 누르면 로그인 칸을 열고, 성공하면 그 동작을 MUST 이어서 한다(기다리는 동작 하나만 기억한다). 빌리기·희망도서는 그 칸으로 돌아오며 이미 적은 등록번호·서명은 남긴다. 빌리기·희망도서 칸에는 회원번호 칸이 없다.

#### Scenario: 로그인 전 담기
- **WHEN** 로그인하지 않은 채 카드를 보면
- **THEN** [담기]가 없어 로그인 칸을 여는 담기 동작이 없다(브라우저 확인)

#### Scenario: 로그인 전 빌리기
- **WHEN** 로그인하지 않은 채 등록번호를 적고 [빌리기]를 눌러 로그인하면
- **THEN** 빌리기 칸으로 돌아오고 등록번호는 남아 있다(브라우저 확인)

#### Scenario: 회원번호 칸 없음
- **WHEN** 이용자 화면 HTML의 입력칸을 읽으면
- **THEN** 회원번호를 받는 입력 요소가 없고 휴대폰 번호를 받는 입력 요소 하나가 있다

## ADDED Requirements

### Requirement: 담은 책 화면
이용자 화면은 로그인한 회원의 담은 책을 서버(`/basket`)에 MUST 보관하고 불러온다. 카드의 [담기]는 로그인한 동안에만 있고, 로그인하면 담은 책을 자동으로 불러온다. 담기·빼기·비우기는 서버가 성공한 뒤에 화면에 반영한다. 로그아웃(버튼, 무입력, 이용 상한, 403)은 화면의 담은 책만 비우고 서버에는 남긴다. 성공이나 불러오기에는 문구를 띄우지 않고, 실패 문구는 둘뿐이다.
- 10권 상한(409): "담은 책은 10권까지예요". 그 밖의 실패(404, 연결 오류): "잠시 뒤 다시 눌러 주세요".
- 401은 키오스크 로그인 화면으로, 403은 회원 로그아웃과 로그인 칸으로 간다. 불러오기가 실패하면 문구 없이 빈 목록으로 시작한다.
- 담은 책 칸에 [모두 빼기]가 있고(담은 책이 없으면 숨김), 줄에는 서명·서가·대출 상태가 있으며 외부 대출 기관에서는 "대출 상태 … 기준"을 함께 보인다.
- [새 대화]는 담은 책을 건드리지 않는다.

#### Scenario: 로그인 전에는 담기가 없음
- **WHEN** 로그인하지 않고 카드를 보면
- **THEN** 카드에 [담기]가 없고 위 띠에 담은 책 표시가 없다(브라우저 확인)

#### Scenario: 로그인·로그아웃이 카드에 바로 적용됨
- **WHEN** 카드가 떠 있는 채 로그인하면, 이어서 로그아웃하면
- **THEN** 이미 떠 있던 카드에 [담기]가 바로 나타나고, 로그아웃하면 바로 사라진다(브라우저 확인)

#### Scenario: 담고 빼기
- **WHEN** 카드의 [담기]를 누르면
- **THEN** 서버에 저장된 뒤 버튼이 [담김]으로 바뀌고 담은 책 숫자가 늘며, 다시 누르거나 줄의 ×를 누르면 빠지고 버튼이 [담기]로 돌아온다(브라우저 확인)

#### Scenario: 모두 빼기
- **WHEN** 담은 책 칸에서 [모두 빼기]를 누르면
- **THEN** 담은 책이 모두 비고 카드 버튼은 [담기]로 돌아오며, 담은 책이 없으면 [모두 빼기]는 보이지 않는다(브라우저 확인)

#### Scenario: 로그아웃하고 다시 로그인
- **WHEN** 책을 담고 로그아웃한 뒤 같은 번호로 다시 로그인하면
- **THEN** 담은 책이 문구 없이 숫자와 목록으로 그대로 나온다. 이 확인은 버튼, 이용 상한, 무입력, 새로 고침 네 경우에 한다(브라우저 확인)

#### Scenario: 10권 상한
- **WHEN** 10권을 담은 뒤 다른 책의 [담기]를 누르면
- **THEN** 담지 않고 "담은 책은 10권까지예요"를 보인다(브라우저 확인)

#### Scenario: 실패하면 화면이 바뀌지 않음
- **WHEN** 담기 요청이 연결 오류로 실패하면
- **THEN** 버튼은 [담기]로 남고 "잠시 뒤 다시 눌러 주세요"를 보인다(브라우저 확인)

#### Scenario: 외부 대출 기관의 담은 책 줄
- **WHEN** 외부 대출 기관에서 책을 담으면
- **THEN** 담은 책 줄에 대출 상태 기준 시각이 보인다(브라우저 확인)

#### Scenario: 회원 토큰 헤더와 저장소 검사
- **WHEN** 화면 스크립트에서 담은 책 요청을 만드는 곳을 검사하면
- **THEN** 모두 회원 토큰 헤더를 붙이고, 담은 책을 브라우저 저장소에 쓰는 곳이 없다
