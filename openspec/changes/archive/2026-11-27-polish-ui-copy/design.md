# Design

## Context

- 화면 문구는 `app/web/public/`의 파일마다 상수와 글자로 흩어져 있다. 문구를 한곳에 모으는 층(i18n)은 없다.
- 서버 오류 문구는 `app/core/errors.py`의 오류(`NotFoundError`, `ConflictError`, `AuthenticationError`, `InvalidRequestError`, `LimitExceededError`, `UnavailableError`)와 `HTTPException`으로 나가고, `app/main.py`의 처리기가 `detail`로 돌려준다. 화면은 404·409·401·429·503의 `detail`을 그대로 보이고 422는 보이지 않는다(`shared/api.js`).
- 공통 "찾을 수 없음"(`app/core/tenancy.py`의 `get_owned`)과 승인 흐름 문구(`app/library/approval.py`)는 REST와 에이전트 tool이 함께 쓴다. 그래서 tool 오류로 LLM에도 간다.
- 운영 대화의 표(결과 사건)는 `analytics_tools.py`의 `present_*`가 만든다. 화면에만 가고 LLM에는 가지 않는다.
- 장서 가져오기 열 이름은 서버 `importing/columns.py`의 `LABELS`와 화면 `FIELD_LABELS`가 같아야 한다(테스트가 비교한다).

## Goals / Non-Goals

**Goals:**
- 화면과 화면에 나오는 서버 문구가 proposal의 용어와 문장 규칙을 따르고, 테스트가 되돌아가지 않게 지킨다.

**Non-Goals:**
- 문구를 모으는 층이나 다국어 지원
- 프롬프트와 tool 설명·입력 고치기, DB에 저장된 값(연체 안내 양식 본문, `{서명}` 자리표시) 옮기기
- 스펙·용어집·코드 주석의 도메인 용어(서명, 사본, 장서, 틀, 운영 에이전트) 바꾸기. 요구사항 이름도 그대로 둔다

## Decisions

### 1. 문구는 제자리에서 고치고, 실패 문구만 공통 상수 하나로
- 화면 파일마다 있는 문구 상수를 그 자리에서 고친다.
- 일반 실패 문구는 `shared/api.js`에 `GENERIC_ERROR = "잠시 뒤 다시 해 주세요."` 하나를 내보낸다. 각 화면이 이것을 가져다 쓰고, 문구 없는 실패의 기본 메시지도 이 값을 쓴다.
- 다른 안으로 모든 문구를 `shared/messages.js` 한곳에 모으는 방법이 있다. 손대는 파일과 위험이 커서 MVP 뒤로 미룬다.

### 2. 받침으로 조사를 고르는 함수를 새로 만든다
- `app/core/text.py`에 `with_particle(word, pair)`를 새로 만든다. `pair`는 "을/를", "이/가", "은/는", "과/와", "으로/로"이다.
- 마지막 글자가 한글 음절이면 받침을 보고 고른다. "으로/로"는 받침이 없거나 ㄹ이면 "로"를 쓴다.
- 한글이 아닌 끝 글자는 받침 없는 쪽을 쓴다. 대상 이름은 모두 고정된 한글이라 이 경우는 생기지 않는다.
- 쓰는 곳은 `get_owned`("{대상}을 찾을 수 없어요.")와 승인 흐름의 충돌 문구다.
  - 승인 흐름의 동작 이름은 동사 꼴로 따로 둔다: 제출할, 승인할, 반려할, 내릴.
  - 예: "구매 요청서가 승인 상태라 반려할 수 없어요."
- 다른 안으로 대상마다 문구를 손으로 쓰는 방법이 있다. 대상 이름(LABEL)이 열 개 가까이 되고, 새 대상이 생길 때마다 다시 써야 해서 고르지 않았다.

### 3. 대상 이름(LABEL)은 화면 말로
| 지금 | 바꾼 뒤 |
|---|---|
| "도서" | "책" |
| "사본" | "책" |
| "연체 안내문 틀" | "연체 안내 양식" |

나머지("큐레이션", "구매 요청서", "회원", "휴관일", "희망도서 신청", "가져오기 기록")는 그대로 둔다.

### 4. LLM이 보는 오류 글자는 함께 바뀌는 것을 받아들인다
- `get_owned`와 승인 흐름 문구는 tool 오류로도 LLM에 간다. 이 둘만은 새 문구가 LLM에도 간다(예: "기관 도서을(를) 찾을 수 없습니다: 12" → "책을 찾을 수 없어요.").
- 프롬프트, tool 설명, tool 결과의 구조는 바꾸지 않는다. 에이전트는 이미 자기가 보낸 id를 알고 있어 문구에서 id가 빠져도 할 일이 같다.
- 다른 안으로 REST와 tool이 문구를 따로 갖는 방법이 있다. 두 벌을 관리해야 해서 고르지 않았다.
- tool 전용 모듈의 오류 문구는 바꾸지 않는다: `*_tools.py`, `tools.py`, `app/library/analytics/`, `services/analytics.py`, `recommendation/`, `features/*/checks.py`

### 5. 검사 테스트로 되돌아가는 것을 막는다
`tests/platform/test_ui_copy.py`를 새로 만든다.

- **화면 검사**: `app/web/public/`의 HTML·JS에서 주석(`//`, `/* */`, `<!-- -->`)을 뺀 글자를 모아 다음을 본다.
  - 쓰지 않는 말과 사라진 버튼 글자
  - 실패 문구의 꼴
  - `confirm(` 문구의 첫 문장
  - "니다"
- **서버 검사**: `app/core`, `app/library`에서 위 오류 클래스와 `HTTPException`에 넘기는 글자와 그 상수를 읽어 다음을 본다.
  - 겸용 조사
  - "니다"
  - "주세요" 아닌 "세요"
  - 결정 4의 tool 전용 모듈은 빼고 본다.
- 정규식으로 읽는 단순한 검사다. 잘못 걸리면 검사 목록에 이유와 함께 예외를 적는다.

### 6. 가져오기 열 이름과 결과 표 머리글
- **가져오기 열 이름**: `LABELS["title"]`을 "도서명"으로 바꾸고, 인식하는 머리글 목록에는 "서명"을 남긴다. 필수 열이 빠졌을 때의 문구는 "필수 열을 찾지 못했어요: 도서명"이 된다.
- **결과 표 머리글**

| 표 | 바꾼 뒤 |
|---|---|
| 장서 현황 | 권수, 종수 |
| 분야별 대출 | 대출, 권수, 권당 대출 |
| 많이 빌린 책 | 순위, 도서명, 저자, 대출 |
| 상태별 목록 | 도서명, 저자, 등록번호, 청구기호 |
| 안 빌린 책 | 도서명, 저자, 권수 |

  "종수"는 서명 수(책 종류 수)를 말한다. 구매 요청서 목록의 "N종"과 같은 말이다.
- 결과 사건의 개인정보 검사(`test_admin_results_privacy.py`)가 허용하는 열 이름도 같이 고친다.

### 7. 같은 안내가 두 번 나오는 곳
- **[승인 목록]**: 503 갈래가 서버 문구 뒤에 글을 붙이지 않는다.
- **[오늘의 연체]**: 서버는 "승인한 연체 안내 양식이 없어요."까지만 말하고, 화면이 "[AI 도우미]로 양식을 만들어 승인해 주세요."를 한 번 붙인다.

### 8. 대량 제적 표시는 그대로
- 서버의 대량 제적 409 문구에는 화면이 알아보는 낱말 `confirm_withdraw`가 계속 있다. 화면은 이 문구를 보이지 않고 자기 확인창을 띄운다.
- 문구의 다른 부분도 화면에 나오지 않으니 그대로 둔다. 응답 값으로 바꾸는 일은 미룬다.

## Risks / Trade-offs

- **에이전트가 받는 오류 글자가 바뀐다** → 결정 4의 두 곳뿐이고, 상태 코드와 결과 구조는 같다. tool 테스트(`test_librarian.py`, `test_related_tool.py`)의 글자 검사를 고친다. LLM 평가는 돌리지 않는다.
- **에이전트의 답이 화면 말과 다를 수 있다** → 답 문장에 "장서", "틀"이 나올 수 있다. 프롬프트 정비(MVP 뒤)에 미룬 일로 적는다.
- **검사 테스트가 정상 문구를 잡을 수 있다** → 예외 목록에 이유와 함께 둔다. 예외가 늘면 규칙을 다시 본다.
- **스펙 인용이 빠질 수 있다** → 화면 문구를 인용한 요구사항은 delta에 모았다. 빠진 인용이 구현 중에 보이면 delta를 먼저 고치고 알린다.

## Migration Plan

- 스키마, API 경로, 저장된 데이터는 바뀌지 않는다. 배포는 코드 교체뿐이고 되돌리기도 코드 되돌리기다.
- 브라우저 확인은 확인용 DB(`chaekbang_check`)에서 하고, 개발 DB는 읽기만 한다.

## 확인 결과와 미룬 일

- 2026-11-27 확인용 DB `chaekbang_check`에서 브라우저 확인 B1~B24(`check-samples/polish-ui-copy.md`)를 했다. 사용자가 모두 정상이라고 알렸고 고칠 것은 없었다. YES24 키를 끈 채 확인해 외부 API와 LLM 호출은 없었다.
- 브라우저 확인에서 뺀 것: 다른 기관 id의 404, 담은 책 10권 상한, "비슷한 책이 없어요."(임베딩 서버 필요). 셋 다 테스트(`tests/platform/test_ui_copy.py`, `test_member_basket.py`, 화면 소스 검사)로 확인했다.
- 미룬 일(archive 때 `docs/roadmap.md`에 적는다)
  - 연체 안내 양식의 자리표시 `{서명}` → `{도서명}`(프롬프트, 저장된 양식, 스펙)
  - 운영 에이전트 프롬프트·tool 설명의 "장서", "안내문 틀"(답 문장이 화면 말과 다를 수 있음)
  - 대량 제적 표시 `confirm_withdraw`를 서버 문구 대신 응답 값으로
  - 화면 문구를 한곳에 모으기(`shared/messages.js`, design 결정 1의 다른 안)
