# Proposal

## Why

데모 영상과 배포(`add-observability-deploy`) 전에 화면 문구를 정리한다. 지금은 같은 것을 여러 이름으로 부르고(서명/책 제목/책 이름, 책/도서/사본, 사서/AI 사서), 화면은 해요체인데 화면에 그대로 나오는 서버 문구는 대부분 합니다체이며, 같은 실패 안내가 네 가지 꼴이다. 내부 id와 영어 값("상태: lost", "…: 42")과 겸용 조사("을(를)")도 화면에 나올 수 있다. 작은도서관 담당자는 사서가 아니어서 "장서", "사본", "틀" 같은 업무 말도 낯설다.

## What Changes

- 화면 용어를 하나로 맞춘다.
  - 책 제목: 관리자 화면은 "도서명", 이용자 화면은 칸 이름만 "도서명"이고 문장 속은 "책 제목"
  - 책 단위는 "책"과 "권"이고 "사본"·"소장"은 화면에서 쓰지 않는다. 도서관이 가진 책 전체는 "책 목록"
  - 탭 [장서] → [책 목록], [장서 가져오기] → [책 가져오기], [운영 대화] → [AI 도우미]
  - "연체 안내문 틀" → "연체 안내 양식", 사본 상태 "이용 가능" → "대출 가능", 로그인 화면 제목 → "직원 로그인"
  - "제적"은 그대로 둔다
- 버튼을 고친다: [더하기] → [등록], [반려하기] → [보내기], 희망도서 [닫기] → [처리 완료], [사서에게 물어보기] → [AI 사서에게 묻기], [고치기] → [수정]. [대출·반납]·[희망도서 신청]은 그대로(AI 사서 프롬프트가 안내한다).
- 문장 규칙 여덟 가지를 화면 문구와 화면에 나오는 서버 문구에 적용한다: 해요체, 짧은 버튼, 한 줄 빈 화면, 실패 안내 하나("잠시 뒤 다시 해 주세요."), 내부 id·영어 값·겸용 조사 없는 서버 문구, 질문 먼저인 확인창, 마침표, 성공은 알리지 않음.
- 같은 안내가 두 번 나오는 곳 둘(정가 조회 503, 연체 안내 양식 없음)을 한 번으로 줄이고, 서버가 문구를 주지 않을 때 상태 번호를 보이지 않는다.
- 받침을 보고 조사를 고르는 함수를 `app/core/text.py`에 새로 만든다.
- 운영 대화 결과 표의 머리글(코드가 만드는 값)을 화면 말로 바꾼다.

배치와 동작, AI 사서·운영 에이전트 프롬프트와 tool 설명, 화면에 나오지 않는 문구(422 검증, 실행기·검사, seed·스크립트)는 바꾸지 않는다. 다만 공통 "찾을 수 없음"·승인 흐름 문구는 tool 오류로 LLM에도 가므로 LLM이 보는 오류 글자가 함께 바뀐다(design 참고).

## Capabilities

### New Capabilities

없음

### Modified Capabilities

- `platform/web-ui`: 화면 문구 규칙과 화면에 나오는 서버 문구 규칙을 더하고, 탭·버튼·문구를 인용한 요구사항을 새 문구로 고친다
- `circulation/member-login`: 로그인 실패와 회원 세션 오류 문구를 해요체로
- `circulation/member-basket`: 회원 세션 오류와 10권 상한 문구를 해요체·마침표로
- `circulation/book-requests`: 중복 신청과 소장 도서 신청 거부 문구에 마침표
- `agent/admin`: 분석 결과 표(화면에 그리는 결과 사건)의 열 이름을 화면 말로(사본 → 권수, 서명 → 도서명·종수)

## Impact

- 화면: `app/web/public/`의 login, librarian, admin, shared 스크립트와 HTML
- 서버 문구: `app/core/`(tenancy, 조사 함수), `app/library/`(approval, deps, services, importing, analytics_tools의 표 머리글, overdue_tools의 진행 문구)
- 테스트: `tests/platform/test_web_ui.py`, 서버 문구를 비교하는 API·tool 테스트, 새 문구 검사 테스트와 조사 함수 테스트
- 문서: `docs/glossary.md`에 화면 말 한 줄씩, archive 때 `docs/roadmap.md`
- API 경로·스키마·DB는 바뀌지 않는다. 장서 가져오기 파일의 "서명" 머리글은 계속 인식한다
