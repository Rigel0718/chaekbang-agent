## Context

가져오기 REST(`app/library/api/holding_imports.py`)는 올리기, 기록 목록·단건, 행 목록(`outcome`·`flag`), 적용(`confirm_withdraw`)을 이미 가진다. 관리자 화면(`app/web/public/admin/`)은 탭 넷이고 `main.js`의 `loadLibrary`가 `loan_mode`에 따라 숨김을 푼다. `shared/api.js`의 `request`는 JSON 본문만 보내고, 오류에서 `detail`만 남긴다.

## Goals / Non-Goals

**Goals:** 외부 대출 기관 관리자가 화면에서 파일을 올리고, 열을 맞추고, 확인할 행을 보고, 적용한다.

**Non-Goals:** 스키마 변경, 삭제 말고의 서버 API 변경, 적용한 가져오기 되돌리기, 선택 열 고치기, 새로·바뀜 행 목록, 자체 대출 기관의 장서 관리, 회원 탭, 분석 표·차트(24b), Playwright.

## Decisions

### 1. 서버는 삭제 하나만 더한다
올리기·목록·단건·행 목록·적용은 있는 API를 그대로 쓴다. 미리 보기 삭제만 새로 만든다(결정 8). 대신 아래 3·4처럼 서버 문구·값에 기대는 곳은 pytest로 서버와 맞춰 본다.

### 2. `shared/api.js`
- `request`에 `form`(FormData) 갈래를 더한다. 이때 `Content-Type`을 붙이지 않는다(브라우저가 경계값을 붙인다).
- `ApiError`에 응답 본문(`body`)을 남긴다. 422의 `missing`, `headers`를 읽기 위해서다.
- 항목: `importUpload(file, mapping)`, `importList(limit)`, `importGet(id)`, `importRows(id, filter, offset, limit)`, `importApply(id)`, `importApplyConfirmed(id)`. 적용을 둘로 나눠 `confirm_withdraw=true`는 두 번째 확인 뒤의 항목에만 있게 한다(소스에서 보인다). 경로 검사 테스트가 읽을 수 있게 각 항목은 `request`에 경로를 바로 쓴다.

### 3. 열 고르기
- 422의 `missing`은 한국어 이름(`저자`)이고 `column_mapping`의 키는 표준 열(`author`)이다. `imports.js`에 표준 열 → 이름 표(15개)를 두고, 필수 열은 이름으로 거꾸로 찾는다. 테스트가 `importing/columns.py`의 `LABELS`와 같은지 본다. "인식한 열" 표시도 같은 표를 쓴다.
- `headers`가 비면(빈 파일 등) 고를 것이 없으므로 서버 문구만 보인다.
- 다시 올리기는 같은 `<input type=file>`의 파일을 다시 보낸다. 파일 내용은 화면이 읽지 않는다. 파일을 새로 고르면 열 고르기를 지운다.

### 4. 적용과 409
- 409는 대량 제적 말고도 "이미 적용", "다른 작업과 겹침", "외부 대출 기관만"이 있다. 응답에 종류 값이 없으므로 문구에 `confirm_withdraw`가 있는지로 대량 제적을 알아본다. 테스트가 service 문구에 그 낱말이 있는지 본다.
- 대량 제적일 때는 서버 문구를 보이지 않고 화면의 문장으로 확인을 묻는다. 서버 문구에는 담당자가 알 수 없는 `confirm_withdraw=true`가 들어 있기 때문이다. 빠진 권수는 위 요약에 이미 있다. 그 밖의 409는 서버 문구를 그대로 보인다.
- 대안(서버 응답에 종류 값 더하기, 문구 고치기)은 서버 변경이라 하지 않는다. 문구를 고칠 일이 생기면 테스트가 먼저 깨진다.

### 5. 어느 기록에 [적용]이 있나
목록은 id 내림차순이다. 첫 줄이 `preview`일 때 그 기록에만 [적용]을 둔다. 적용 직전에 목록을 다시 읽어 여전히 첫 줄인지 확인하지는 않는다(관리자 한 명을 가정). 옛 미리 보기의 적용을 서버에서 막는 것은 미룬다.

### 6. 화면 규칙
- 탭 `imports`. 순서는 운영 대화, 승인 목록, 희망도서, 오늘의 연체, 장서 가져오기. 숨긴 탭의 hash는 운영 대화로 간다.
- `show()`는 열린 요약과 열 고르기를 지우고 기록 목록(최근 20건)을 다시 읽는다.
- 올리기·적용 동안 버튼을 잠근다. 401은 로그인 화면.
- 서버 값은 `dom.js`의 `el`로만 넣는다. 변수 이름 `record`는 `HoldingImportRead`, `row`는 `HoldingImportRow`에만 쓴다(필드 계약 테스트가 읽는다).
- 성공 문구는 없다. 확인 창은 적용 때 한 번, 대량 제적 때 한 번 더.

표기 이름: `invalid_isbn` ISBN 형식 오류, `unknown_status` 대출 상태를 모름, `purchased_without_isbn` 매입인데 ISBN 없음, `purchased_without_price` 매입인데 가격 없음.

### 7. 견본 파일 `scripts/make_import_samples.py`
고정된 가상 값으로 파일을 만든다. **DB를 읽지 않는다.** 탐색에서는 푸른숲의 지금 사본으로 만들기로 했으나, 시드 사본은 출처가 `manual`이라 파일에서 빠져도 제적 대상이 아니다. 그래서 견본을 먼저 가져와 `imported` 사본을 만든 뒤, 거기서 절반 넘게 뺀 파일로 대량 제적을 확인한다.

| 파일 | 내용 | 확인 |
| --- | --- | --- |
| `normal.csv` | 등록번호 `IMP-…` 약 40행. 가격 없는 매입 25행 이상, ISBN 형식 오류, 모르는 상태, 서명 없는 행 | B3, B6~B8 |
| `renamed.csv` | 저자 머리글이 `책임표시` | B4 |
| `half.csv` | `normal.csv`의 등록번호 중 절반 미만만 | B9 |
| `donor.csv` | 기증처 열에 눈에 띄는 값 | B11 (적용하지 않음) |
| `old.xls`, `empty.csv` | 예전 형식 머리 바이트, 빈 파일 | B5 |

폴더를 주지 않으면 저장소의 `import-samples/`에 쓴다. 이 폴더는 `.gitignore`에 넣어 만든 파일이 저장소에 들어가지 않는다.

### 8. 브라우저 확인에서 더한 것(2026-11-25)
- **파일 선택 비우기**: 올린 뒤에도 파일이 남아 [올리기]를 다시 누르면 같은 파일의 기록이 또 생겼다. 미리 보기가 생기면 비운다. 422 열 고르기는 같은 파일을 다시 보내야 해서 남긴다.
- **미리 보기 삭제**: `DELETE /holding-imports/{id}`. 미리 보기는 장서를 바꾸지 않았으므로 행을 지운다. 적용한 기록은 이력이라 409. 적용과 겹치지 않게 적용처럼 기관 행을 잠근 뒤 판단한다. 참조하는 테이블이 없어 마이그레이션은 없다.
- 최신 미리 보기를 지우면 그 앞 기록이 가장 최근이 된다. 미리 보기면 [적용]이 생긴다. 적용한 기록은 지워지지 않아, 더 새로 적용한 파일보다 옛 미리 보기가 최근이 되는 일은 없다.
- **구분**: 목록의 상태 표시에 색을 달리하고(적용함 / 미리 보기) 연 기록 줄을 표시한다.

## 브라우저 확인

사용자가 직접 본다. 서버는 `chaekbang_importcheck` DB로 띄운다(아래 위험 참고). 계정은 `forest-admin`(외부 대출), `sunny-admin`(자체 대출).

| B | 하는 일 | 기대 |
| --- | --- | --- |
| B1 | `forest-admin`으로 연다 | [장서 가져오기] 탭이 보인다 |
| B2 | `sunny-admin`으로 `#imports`를 연다 | 탭이 없고 운영 대화가 열린다 |
| B3 | `normal.csv`를 올린다 | 요약 수, 빠진 사본 수, 인식한 열 |
| B4 | `renamed.csv`를 올리고 `책임표시`를 골라 다시 올린다 | 저자 열 고르기 → 요약 |
| B5 | `old.xls`, `empty.csv`를 올린다 | 서버 문구만, 열 고르기 없음 |
| B6 | `normal.csv` 요약에서 확인할 행을 누른다 | 행 목록, 20줄이 넘는 종류는 [더 보기] |
| B7 | `normal.csv`를 다시 올려 [적용] 후 취소 | 요청 없음, 미리 보기 그대로 |
| B8 | [적용] 후 확인 | 문구 없이 "적용함", [적용] 사라짐. `forest-kiosk`에서 견본 서명이 찾아진다 |
| B9 | `half.csv`를 올려 적용한다 | 두 번째 확인. 취소하면 그대로, 다시 확인하면 적용 |
| B10 | 미리 보기를 두 개 만들고 앞의 것을 연다 | [적용] 없음 |
| B11 | `donor.csv`를 올려 요약과 행 목록을 본다 | 기증처 값이 어디에도 없다 |
| B12 | `normal.csv`를 올린 뒤 [올리기]를 다시 누른다 | 파일 선택이 비어 있고 새 기록이 안 생긴다 |
| B13 | 미리 보기의 [삭제] → 취소, 다시 [삭제] → 확인 | 취소하면 그대로, 확인하면 목록에서 사라진다. 적용한 기록에는 [삭제]가 없다 |
| B14 | 적용한 기록과 미리 보기를 눌러 본다 | 상태 색이 다르고 연 줄이 표시된다 |

## Risks / Trade-offs

- 문구의 낱말로 409를 가른다 → 서버 문구를 맞춰 보는 테스트로 지킨다.
- 옛 미리 보기를 API로는 적용할 수 있다 → 화면에서만 막고 미룬다.
- 개발 DB의 푸른숲에는 이미 가져온 사본이 200권 있다(2026-11-06 `export.xlsx`, 2026-11-25 확인). 거기에 `normal.csv`를 적용하면 200권이 모두 제적된다 → 브라우저 확인은 **따로 만든 DB `chaekbang_importcheck`**(마이그레이션 + 시드, `imported` 사본 0)로 서버를 띄워서 한다. 개발 DB는 바꾸지 않는다. 확인이 끝나면 이 DB는 지워도 된다.

## 확인 결과와 미룬 일

브라우저 확인 B1~B14를 사용자가 통과로 확인했다(2026-11-25, 확인용 DB `chaekbang_importcheck`).

미룬 일(archive 때 `docs/roadmap.md`에 옮긴다):
- 화면에 대한 사용자의 나머지 피드백은 핵심 기능이 끝난 뒤에 받는다
- 적용한 기록 지우기: 지금은 미리 보기만 지운다(2026-11-25 B10 때 이야기). 넣는다면 "기록만 지움, 장서는 그대로"이고, 적용 되돌리기는 따로 큰 일이다
- 잘못 인식한 선택 열 고치기, 새로·바뀜 행 목록, 서버에서 옛 미리 보기 적용 막기, 열 지정 기억, 큰 파일 진행 표시·끌어다 놓기, 기증처 보기
- Playwright(기존 "24b 뒤에 다시 본다"에 합침)
- 자체 대출 기관의 책 등록·사본 상태 처리·회원 탭은 따로 change(가칭 `add-admin-collection-ui`)
