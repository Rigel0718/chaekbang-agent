## MODIFIED Requirements

### Requirement: 쓰기 tool 없음
AI 사서의 tool은 두 운영 방식 모두 조회뿐이다. 대출, 반납, 희망도서 신청은 이용자 화면의 입력칸이 REST로 처리하고, 대화로는 MUST NOT 처리한다. 회원번호가 LLM과 대화 기록을 거치지 않게 하기 위해서다.

#### Scenario: 대화 후 데이터 변화 없음
- **WHEN** 대화가 끝나면
- **THEN** 사본, 대출, 회원, 희망도서 신청 행은 바뀌지 않는다

#### Scenario: 운영 방식별 tool 목록
- **WHEN** 자체 대출 기관과 외부 대출 기관의 프로필 tool 목록을 읽으면
- **THEN** 둘 다 같고, 대출·반납·희망도서 신청을 하는 tool이 없다

#### Scenario: 대화 요청의 회원번호 칸
- **WHEN** `POST /librarian/messages`에 문장과 함께 `member_number` 칸을 보내면
- **THEN** 422이고 LLM을 부르지 않는다

## ADDED Requirements

### Requirement: 화면 기능 안내 문구
프로필은 화면의 대출·희망도서 기능을 운영 방식에 맞게 SHALL 안내한다. 자체 대출 기관의 시스템 프롬프트는 대출·반납을 화면 위의 [대출·반납]으로 안내하고, 외부 대출 기관의 시스템 프롬프트는 대출·반납을 데스크로 안내하며 [대출·반납]을 말하지 않는다. 두 방식 모두 희망도서는 화면의 [희망도서 신청]으로 안내한다. 프로필 버전은 v8이다.

#### Scenario: 자체 대출 기관의 안내 문구
- **WHEN** 자체 대출 기관의 시스템 프롬프트를 읽으면
- **THEN** [대출·반납]과 [희망도서 신청] 안내가 있다

#### Scenario: 외부 대출 기관의 안내 문구
- **WHEN** 외부 대출 기관의 시스템 프롬프트를 읽으면
- **THEN** 데스크 안내와 [희망도서 신청] 안내가 있고 [대출·반납]은 없다

### Requirement: 대출 요청에 화면 기능을 안내함
이용자가 대화로 빌리기·반납을 요청하면 에이전트는 자체 대출 기관에서는 화면의 [대출·반납]을, 외부 대출 기관에서는 대출 데스크를 SHALL 안내한다. 회원번호를 묻지 않고, 이용자가 말한 회원번호를 답에 다시 쓰지 않는다. 이 요구사항은 평가로 확인한다.

#### Scenario: 자체 대출 기관의 대출 요청
- **WHEN** 자체 대출 기관에서 `이 책 빌리고 싶어요`라고 하면
- **THEN** 답이 [대출·반납]을 안내하고 회원번호를 묻지 않는다

#### Scenario: 외부 대출 기관의 대출 요청
- **WHEN** 외부 대출 기관에서 `여기서 책 빌릴 수 있어요?`라고 하면
- **THEN** 답이 데스크를 안내하고 [대출·반납]을 말하지 않는다

#### Scenario: 회원번호를 말한 대출 요청
- **WHEN** 자체 대출 기관에서 `회원번호 A-0042로 이 책 빌려 줘`라고 하면
- **THEN** 답에 그 회원번호가 없고 [대출·반납]을 안내하며 회원번호를 묻지 않는다

### Requirement: 희망도서 요청에 화면 기능을 안내함
이용자가 없는 책을 어떻게 구하는지 물으면 에이전트는 화면의 [희망도서 신청]을 SHALL 안내한다. 이름·연락처·회원번호를 묻지 않는다. 이 요구사항은 평가로 확인한다.

#### Scenario: 희망도서 방법 질문
- **WHEN** `읽고 싶은 책이 도서관에 없으면 어떻게 해요?`라고 하면
- **THEN** 답이 [희망도서 신청]을 안내하고 회원번호를 묻지 않는다
