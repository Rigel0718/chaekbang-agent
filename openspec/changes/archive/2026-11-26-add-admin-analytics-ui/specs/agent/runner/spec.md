## MODIFIED Requirements

### Requirement: 진행 사건
실행기는 실행 중 사건을 순서대로 SHALL 내보낸다. tool을 실행하기 전에 그 tool의 진행 문구를, 끝날 때 최종 답이나 고정 답을 한 번 내보낸다. tool 입력과 결과, 검사를 통과하지 못한 답은 사건에 MUST NOT 넣는다. 다만 tool이 고른 화면용 값(화면용 변환 요구사항)은 실행이 검사를 통과한 답이나 정리한 답으로 끝날 때만, 호출 순서대로 최종 답 바로 앞에 결과 사건으로 내보낸다. 고정 답, 실패, 중단으로 끝나면 결과 사건을 내보내지 않는다.

#### Scenario: 사건 순서
- **WHEN** tool 하나를 거쳐 최종 답이 나오면
- **THEN** 사건은 진행 문구, 최종 답, 끝 순서로 나온다

#### Scenario: 위반한 답은 사건에 없음
- **WHEN** 최종 답이 위반한 뒤 고친 답이 통과하면
- **THEN** 사건에는 고친 답만 있다

#### Scenario: 결과 사건의 순서
- **WHEN** 화면용 값을 돌려주는 tool 두 개를 차례로 거쳐 검사를 통과한 답이 나오면
- **THEN** 사건은 진행 문구, 진행 문구, 첫 tool의 결과, 둘째 tool의 결과, 최종 답, 끝 순서로 나온다

#### Scenario: 정리한 답의 결과 사건
- **WHEN** 화면용 값을 돌려주는 tool을 거친 뒤 검사 재시도를 넘겨 정리한 답으로 끝나면
- **THEN** 정리한 답 바로 앞에 그 tool의 결과 사건이 나온다

#### Scenario: 고정 답이면 결과 사건 없음
- **WHEN** 화면용 값을 돌려주는 tool을 거친 뒤 호출 한도를 넘거나 LLM 호출이 실패하거나 예상하지 못한 예외로 고정 답으로 끝나면
- **THEN** 결과 사건은 나오지 않는다

#### Scenario: 중단이면 결과 사건 없음
- **WHEN** 화면용 값을 돌려주는 tool을 거친 뒤 사건을 받던 쪽이 최종 답 전에 멈추면
- **THEN** 결과 사건은 나오지 않고 실행 상태는 `cancelled`다

## ADDED Requirements

### Requirement: tool의 화면용 변환
tool은 실행 결과를 화면에 보일 값으로 바꾸는 변환을 SHALL 고를 수 있다. 변환은 그 호출의 입력과 결과를 받아 화면용 값이나 없음을 돌려주고, DB나 외부를 부르지 않는다. 실행기는 값의 뜻을 모른 채 그대로 전한다. 변환을 고르지 않은 tool, 없음을 돌려준 호출, 도메인 오류나 입력 검증 오류로 끝난 호출은 결과 사건을 만들지 않는다. 화면용 값은 실행 기록에 MUST NOT 남는다.

#### Scenario: 값을 돌려준 변환
- **WHEN** 변환이 값을 돌려주는 tool을 거쳐 검사를 통과한 답이 나오면
- **THEN** 결과 사건에 그 값이 그대로 실린다

#### Scenario: 없음을 돌려준 변환
- **WHEN** 변환이 없음을 돌려주는 tool을 거쳐 답이 나오면
- **THEN** 결과 사건은 나오지 않는다

#### Scenario: 변환을 고르지 않은 tool
- **WHEN** 변환을 고르지 않은 tool만 거쳐 답이 나오면
- **THEN** 사건은 지금처럼 진행 문구, 최종 답, 끝뿐이다

#### Scenario: 오류로 끝난 호출
- **WHEN** 변환을 고른 tool이 도메인 오류를 내거나 입력 검증에 실패한 뒤 다른 호출을 거쳐 답이 나오면
- **THEN** 오류로 끝난 호출의 결과 사건은 나오지 않는다

#### Scenario: 변환 입력
- **WHEN** 변환을 고른 tool이 실행되면
- **THEN** 변환은 그 호출의 검증한 입력과 tool 결과를 받는다

#### Scenario: 실행 기록에 없음
- **WHEN** 결과 사건이 나온 실행의 실행 행과 단계 기록을 읽으면
- **THEN** 화면용 값은 어디에도 없다
