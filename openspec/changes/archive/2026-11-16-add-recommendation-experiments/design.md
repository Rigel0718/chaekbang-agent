## Goals / Non-Goals

**Goals:**

- 실험 틀 하나로 같은 평가 세트에서 변형을 나란히 재고, 같은 명령이면 같은 수치가 나온다. LLM을 부르지 않는다.
- 요청 세 종류의 평가 세트(질의·기준 책·최근 기록)와 주제 질의의 어울림 라벨을 결과를 보기 전에 만든다.
- 주제로 찾기의 단계(키워드 → 벡터 → 합치기 → 시리즈 묶기 → 다양화)별 점수표와 기본 설정.
- 임베딩 텍스트 종류(`full`, `with_author`, `description`, 필드별) 비교와 기본 결정.
- 실험이 재는 코드가 제품에 나갈 코드와 같다(기관 범위·추천 가능·어린이 조건이 같은 함수에서 강제된다).

**Non-Goals:**

- 비슷한 책·아무 조건 없음의 신호와 비교(`add-related-book-experiments`). 평가 세트(기준 책·최근 기록)와 라벨 도구만 이번에 만들고, 두 세트의 라벨은 그 change에서 단다.
- REST, AI 사서 tool, 찾은 책 카드 아래 비슷한 책(`add-related-books`). AI 사서는 지금처럼 `search_collection`을 쓴다.
- 어린이 요청 판단. 질의마다 사람이 정한 값을 쓴다. 판단 지표는 `add-recommendation-evals`.
- 결과를 비울 유사도 문턱(소장 도서가 없는 요청), 벡터 인덱스, 옛 종류 벡터 정리.

### 1. 둘로 나누기 (2026-11-15 사용자 결정)

| 안 | 내용 |
| --- | --- |
| **A. 요청 종류로 둘 (선택)** | 이번: 틀, 평가 세트 셋(라벨 포함), 주제로 찾기, 텍스트 종류. 다음 `add-related-book-experiments`: 비슷한 책·아무 조건 없음 |

- 라벨은 세 종류 모두 이번에 단다. 어떤 변형의 결과도 보기 전에 한 번에 다는 것이 치우침이 가장 적다.

- 순서는 `add-recommendation-experiments` → `add-related-book-experiments` → `add-bibliographic-sources` → `add-related-books` → `add-recommendation-evals`가 된다. CLAUDE.md와 `docs/design.md`의 순서를 고친다.

### 3. 임베딩 텍스트 종류

- 텍스트 버전은 2 그대로 두고 종류(`kind`)만 더한다. `full`의 규칙은 바뀌지 않으므로 버전을 올릴 이유가 없다(`add-official-book-embeddings` 결정 3: 버전은 조립 규칙의 판, 종류는 넣은 필드).
- "저자 넣기"는 텍스트 버전 1을 되살리지 않고 종류 `with_author`로 둔다. 필드와 순서(서명, 다음 줄 저자 원문, 분류, 소개)는 v1과 같다. v1과 다른 점은 공식 서지 텍스트가 공식 값만 쓴다는 것(KDC 주류 이름이 비는 것)뿐이고, 지금 실험 장서에는 KDC가 없어 차이가 없다.

| 종류 | 필드 | 쓰는 곳 |
| --- | --- | --- |
| `full` | 서명(: 부제), 분류, 소개 | 지금 기본 |
| `with_author` | 서명(: 부제), 저자 원문, 분류, 소개 | 저자 넣기 비교 |
| `description` | 소개 | 소개만 비교, 필드별 벡터의 하나 |
| `title` | 서명(: 부제) | 필드별 벡터 |
| `category` | 분류 원문, KDC 주류 이름 | 필드별 벡터 |

- 필드별 벡터는 `title`·`category`·`description` 세 종류를 조회에서 가중 평균한다(결정 5). 따로 "fields" 종류를 저장하지 않는다.
- `compose`에 `author` 인자를 더하고 종류마다 줄을 고른다. 저자는 공식 서지 `Book.author`, 기관 도서 `LibraryBook.author` 원문이다(기여자 이름을 다시 잇지 않는다. 원문이 표시 값과 같다).
- `category` 텍스트는 18가지 값뿐이라 같은 분야 책의 벡터가 똑같다. 그래서 단독 변형으로는 재지 않고 필드별 합치기 안에서만 쓴다.

### 4. 빈 텍스트

- `description`은 소개 없는 공식 서지 10건과 기관 도서 몇 권에서 빈 문자열이 된다. 빈 문자열을 인코딩하면 모든 빈 책이 같은 벡터를 갖고 질의와의 유사도가 엉뚱하게 같아진다.
- `run_layer`가 빈 텍스트를 인코딩하지 않고 `EmbeddingRun.blank`로 센다. 출력: `… 인코딩 410, 건너뜀 0, 빈 텍스트 10`. `full`은 서명이 늘 있어 빈 텍스트가 없다.
- 이미 있던 그 종류의 벡터는 지우지 않는다(조회가 해시를 보지 않으므로 소개가 지워진 책의 옛 벡터가 남을 수 있다. 실험 장서에서는 일어나지 않는다. 정리 명령은 실험 뒤에 정한다는 이전 결정 그대로).

### 5. 유사도 조회 넓히기

```python
async def similar_books(session, embedder, *, library_id, query, limit=5,
                        kind=TextKind.FULL, weights: Mapping[TextKind, float] | None = None,
                        within: Select | None = None) -> list[SimilarBook]
```

- `weights`가 없으면 `{kind: 1.0}`이다. 지금 호출은 그대로 같은 결과다(스펙 "종류 하나는 지금과 같음").
- 종류마다 지금의 두 갈래(`UNION ALL`)를 만들고, 바깥에서 `library_book_id`로 묶어 `sum(w × (1 − 거리)) / sum(w)`로 점수를 낸다. 지정한 종류의 벡터가 하나도 없는 책은 묶음에 없다.
- `within`은 두 갈래 모두의 `LibraryBook.id IN (…)`에 건다. 순위를 매기기 전이다. 어린이 질의에서 상위 30권을 뽑은 뒤 거르면 일반 도서에 밀려 어린이 도서가 몇 권 안 남는다.
- 속도: 종류 셋을 합쳐도 473권이라 지금(약 45ms)의 세 배 안쪽으로 본다. 실험 실행이 질의마다 걸린 시간을 적는다(결정 13). 인덱스는 두지 않는다.
  - **잰 값** (2026-11-15, 테스트 DB 트랜잭션, 5,000권 = 공식 4,500 + 기관 500, 무작위 벡터, `ANALYZE` 뒤 다섯 번씩 두 차례): `full` 5권 약 48ms(첫 조회 84ms), `full` 30권 약 49ms, 종류 셋 가중 평균 30권 약 70ms(한 번 157ms). 넓힌 조회가 한 종류일 때 이전(약 45ms)과 같고, 종류 셋도 100ms 안쪽이다.

### 6. 주제로 찾기의 흐름

```python
@dataclass(frozen=True)
class TopicSettings:
    keyword_weight: float = 1.0  # 0이면 키워드 신호를 쓰지 않는다
    vector_weight: float = 1.0  # 0이면 벡터 신호를 쓰지 않는다
    vector_input: Literal["text", "keywords"] = "text"
    weights: Mapping[TextKind, float] = {FULL: 1.0}
    depth: int = 30  # 신호마다 가져올 순위 깊이
    rrf_k: int = 60
    series_cap: int | None = None
    mmr_lambda: float | None = None  # None이면 다양화하지 않는다
    limit: int = 5
```

1. 신호마다 범위(그 기관, 추천 가능, `within`)를 먼저 걸고 깊이 30까지 순위를 만든다.
   - 키워드: `search_collection`의 `_score`를 그대로 쓰고 상한만 푼다. 낱말은 평가 세트의 `keywords`다(AI 사서에서 LLM이 tool에 넘길 낱말에 해당한다).
   - 벡터: 질의 입력은 이용자 문장(`text`) 또는 낱말을 띄어쓰기로 이은 것(`keywords`). 둘 다 변형으로 잰다.
2. RRF로 합친다. `score = Σ w_s / (k + rank_s)`. 같으면 가장 좋은 신호 순위, 기관 도서 id.
3. 시리즈 묶기(상한이 있으면): 위에서부터 보며 시리즈 키마다 상한까지 남긴다. 빠진 권수는 남은 같은 시리즈 책 중 가장 위 책에 적는다(카드에 "같은 시리즈 2권 더"로 쓸 수 있다).
4. MMR(λ가 있으면): 합친 상위 30권 안에서 고친다. 관련도는 합친 점수를 후보 안에서 최소-최대로 0~1에 맞춘 값, 책 사이 유사도는 `full` 벡터의 코사인이다. 1024차원 30권이라 순수 Python으로 질의마다 1ms 안쪽이다. 의존성을 더하지 않는다.
5. 앞의 `limit`권을 돌려준다. 결과마다 점수, 신호별 순위, 빠진 같은 시리즈 권수를 준다.

- **RRF를 고른 이유**: 키워드 점수(가중치 합의 정수)와 코사인 유사도는 척도가 달라 바로 더할 수 없다. RRF는 순위만 쓰므로 척도를 맞출 필요가 없고 매개변수가 k 하나다.
- **시리즈 묶기를 MMR 앞에 두는 이유**: 같은 시리즈는 확실한 중복이라 규칙으로 처리하고, MMR은 그 밖의 "결이 비슷한 책" 쏠림만 맡는다.

### 7. 변형 (단계별, 앞 단계의 승자 위에 다음 단계를 얹는다)

| 단계 | 변형 | 내용 |
| --- | --- | --- |
| 0 기준 | `current` | 지금 제품: `search_collection(keywords)` 상위 5권 |
| | `current-split` | 같은 함수에 낱말 대신 이용자 문장을 띄어쓰기로 나눠 넣음(낱말을 사람이 써 준 이점을 빼고 보기) |
| 1 벡터 | `vec-text`, `vec-kw` | 벡터만, `full`, 질의 입력 문장 / 낱말 |
| 2 텍스트 종류 | `vec-author`, `vec-desc`, `vec-fields`, `vec-fields-desc2` | 1의 승자 입력으로 `with_author`, `description`, 필드별(1:1:1), 필드별(1:1:2) |
| 3 합치기 | `hybrid-k60`, `hybrid-k10`, `hybrid-kw0.5`, `hybrid-kw2` | 키워드 + 벡터(2의 승자) RRF. k ∈ {10, 60}, 키워드 가중치 ∈ {0.5, 1, 2} |
| 3' 종류 다시 | `hybrid-<종류>` | 3의 승자 설정에서 텍스트 종류 넷을 다시 비교(제품은 합친 순위를 쓰므로 최종 결정은 여기서) |
| 4 시리즈 | `+series1`, `+series2` | 상한 1, 2 |
| 5 다양화 | `+mmr0.7`, `+mmr0.5` | λ 0.7, 0.5 |

- 격자를 작게 둔다(k 두 값, 가중치 세 값, λ 두 값). 질의 20개로 촘촘히 고르면 조정 세트에 맞춰질 뿐이다.
- 변형은 `variants.py`에 이름 → `TopicSettings`(와 `current`처럼 함수가 다른 것)로 둔다. 단계의 승자는 실행 결과를 보고 사람이 정해 `variants.py`에 적는다. 결정 근거는 이 문서의 "결과"에 남긴다.

| **A. Claude가 장서를 보지 않고 이용 장면으로 초안, 사용자가 고침 (선택)** | LLM API 호출이 없다(이 대화에서 쓴다). 장서의 소개 문구를 보지 않아 질의가 소개 표현을 베끼지 않는다(벡터 쪽으로 기울지 않음). 사용자가 실제 이용 장면에 맞게 고친다 |
| B. 사용자가 모두 씀 | 편향은 가장 적지만 시간이 든다 |
| C. 규칙으로 생성(분류·서명에서) | 질의가 서명 낱말이 되어 키워드 쪽으로 기운다 |
| D. LLM API로 책에서 질의 생성 | 소개를 보고 만들어 벡터 쪽으로 기운다. 호출 비용과 승인이 필요하다 |

- 구성(실제 이용 빈도 순, design.md의 예시 기준. 임베딩을 정당화하려고 짜지 않는다)
  - 어린이 12 / 일반 18(작은도서관 어린이 비중 약 40%)
  - 결: 주제어 요청 18("공룡 책", "우주 그림책") / 상황·기분 요청 12("퇴근 후 30분 읽을", "잠자리에서 읽어 줄"). design.md의 "키워드가 약한 요청과 잘하는 요청을 나눠" 본다. 결은 질의를 쓸 때 정하고 결과를 보고 바꾸지 않는다.
  - 분야: 남겨 둔 넷(종교·예술·건강 취미·여행)은 쓰지 않는다. 나머지 15분야에 고루, 질의마다 관련 분야 1~2개. 어린이 질의는 유아나 어린이 하나를 기본으로 한다(라벨 양 때문).
- 형식:

```json
{"version": 1, "queries": [
  {"id": "t01", "text": "일곱 살 아이가 공룡을 정말 좋아해요", "keywords": ["공룡"],
   "children": true, "style": "topic", "fields": ["children"], "split": "tune"}
]}
```

- `keywords`는 AI 사서의 LLM이 tool에 넘길 법한 낱말 1~3개를 질의를 쓸 때 함께 쓴다. 결과를 보고 고치지 않는다.
- 저장소에 ISBN·등록번호·서명이 들어가지 않게 검사한다(스펙 "질의 파일의 ISBN"). 질의 문장은 사람이 쓴 것이라 YES24 값이 아니다.

**비슷한 책 기준 책 20권, 최근 기록 10개** — `data/seeds.json`, 저장소 밖(책 키가 실험 장서를 가리킨다)

- `uv run python -m evals.recommendation.pick`이 규칙으로 고른다. 난수 대신 책 키의 SHA-256 순서로 뽑아 늘 같다. 남겨 둔 분야의 책은 뽑지 않는다. 사용자가 바꿀 수 있고, 바꾼 파일이 기준이다.
  - 기준 책: 어린이 8(시리즈·같은 지은이가 장서에 있는 책 4, 없는 책 4), 일반 12(6, 6). ISBN 없는 책 2권 이상.
  - 최근 기록: 책 2~3권 목록 10개. 같은 분야 4, 분야가 섞인 것 3, 어린이 3. 이 대화에서 찾은·고른 책을 흉내 낸다(익명. 회원 대출 기록은 2단계).

### 9. 어울림 라벨

- **기준**(design.md: "받으면 납득할 책")
  - 주제: 2 = 이 요청에 이 책을 받으면 바로 납득(주제와 대상이 모두 맞음), 1 = 관련은 있으나 일부만 맞음(주제는 맞고 대상·결이 다르거나, 결은 맞고 주제가 넓음), 0 = 맞지 않음.
  - 비슷한 책·최근 기록: 2 = 이 책(들)을 좋게 읽은 사람에게 권하면 납득, 1 = 같은 갈래지만 결이 다름, 0 = 아님. 같은 시리즈 다음 권도 사람이 판단한다(자동 2가 아니다).
- **다는 사람**(2026-11-16에 바꿈): 초안은 Claude, 검수는 사용자. 처음에는 사용자가 모두 달기로 했으나(LLM 판단이 정답이 되지 않게) 카드 방식 4시간, 목록 방식도 소개가 잘려 판단하기 어렵고 오래 걸려 사용자가 멈췄다.
  - Claude가 이 대화에서 후보 전체(서명·저자·분류·소개)를 읽고 0·1·2 초안을 단다. 외부 LLM API 호출은 없다. 어떤 변형도 돌리기 전에 단다.
  - 사용자는 검수 화면(`uv run python -m evals.recommendation.review topic`, 로컬 웹 페이지)에서 초안이 1 이상인 책을 소개 전문과 함께 보고 확인하거나 고친다. 0인 책은 접은 목록으로 두고 빠진 책을 올린다. 누를 때마다 라벨 파일에 쓴다.
  - 실행 뒤 보충도 같은 방식이다(2026-11-16). 전체 변형의 상위 10권 중 라벨 없는 책이 583건(책 294권)이라 Claude가 초안을 달고(`draft apply --pool`), 검수 화면의 "보충 라벨만 보기"로 사용자가 확인한다. 보충 초안은 어느 변형이 낸 책인지 보지 않고 단다.
  - 라벨마다 단 쪽(`by`: `claude`/`user`)을 적고 요약에 수를 적는다. `by`가 없는 옛 라벨은 `user`다.
  - 한계: 0은 대부분 Claude의 판단이고 사람이 다 보지 않는다. 정답이 LLM 판단에 기댄다. 다만 판단자가 비교 대상(키워드 검색, 임베딩 모델)과 달라 특정 변형 쪽으로 기우는 정도는 작다. 결과에 "초안 Claude, 검수 사용자"를 밝히고, 사람만 단 라벨이 필요하면 `add-recommendation-evals`에서 표본으로 일치도를 본다.
- **단계**
  1. 실행 전: 질의의 관련 분야(어린이 질의는 어린이 도서만), 기준 책의 분야 + 같은 지은이·같은 시리즈 책. 어떤 변형도 돌리기 전에 끝낸다.
  2. 실행 뒤 보충: 보고할 변형들의 상위 10권 중 라벨 없는 책만. 다른 분야에 있던 어울리는 책을 잡기 위해서다. 단계를 기록해 요약에 단계별 수를 적는다.
- **양**(2026-11-16에 고침): 실제 후보는 주제 1,384건(어린이 질의 12개가 68~84권씩 약 910건, 일반 18개가 14~46권씩 약 470건), 비슷한 책 821건, 최근 기록 599건이다. 한 권씩 묻는 카드 방식은 주제만 4시간쯤이라 사용자가 멈췄다. 그래서 둘을 바꿨다.
  - 실행 전 단계는 **목록 방식**으로 단다. 질의 하나의 후보를 한 화면에 번호 목록으로 보고 2인 번호와 1인 번호만 넣는다. 나머지는 0이다. 화면 30개, 질의당 1~3분.
  - 비슷한 책·최근 기록의 라벨은 이번에 달지 않는다. 이번 비교가 주제로 찾기뿐이라 쓰이지 않는다. `add-related-book-experiments`에서 같은 도구로 단다.
  - 분야의 책을 모두 보는 것은 그대로라 결과를 보고 고르는 치우침은 생기지 않는다. 목록은 소개가 짧아(80자) 카드보다 근거가 적다. `?번호`로 그 책의 카드(소개 300자)를 볼 수 있다.
- **라벨 도구** `uv run python -m evals.recommendation.label topic|similar|history [--cards] [--pool <실행> --variants a,b]`
  - 목록(실행 전 기본): 책마다 번호, 서명, 저자, 분류 원문, 서가 위치, 소개 앞 80자. `2인 번호`, `1인 번호`를 공백이나 쉼표로 받고, 확인(Enter)하면 그 항목을 한 번에 쓴다. `r`은 다시, `q`는 끝내기(그 항목은 기록하지 않는다). 범위 밖 번호나 2·1에 겹친 번호는 다시 묻는다.
  - 카드(보충 단계, 또는 `--cards`): 서명, 저자, 분류 원문, 서가 위치, 소개 앞 300자. 답마다 파일에 쓴다. Enter는 0.
  - 다시 열면 라벨 없는 책부터 이어 간다.
  - 파일 `data/labels/<세트>.json`: `{"t01": {"isbn:978…": {"grade": 2, "stage": "before", "by": "user"}}}`.
  - 라벨 파일은 다시 만들 수 없다. 저장소 밖이라 사용자가 따로 백업한다(README에 적는다).
- 분야는 실험 장서 파일에서 읽는다(ISBN, 또는 등록번호의 순서 번호). 파일이 없으면 라벨 도구와 `pick`은 받기 명령을 알리고 멈춘다. 기준 책·최근 기록 세트를 읽을 때도 파일로 남겨 둔 분야를 검사한다. 주제 실행(`__main__ topic`)은 분야를 질의 파일에서 읽어 실험 장서 파일 없이 돈다.

### 10. 책 키

- `isbn:<13자리>` 또는 `acc:<등록번호>`(그 책 사본 중 가장 앞선 등록번호, 예 `acc:EX00004`).
- id 대신 쓰는 이유: 실험 장서를 다시 넣거나 DB를 백업에서 되돌리면 id가 바뀐다. 등록번호는 적재 규칙(ISBN 순서)으로 늘 같고, ISBN 키는 `add-bibliographic-sources`에서 출처를 바꿔도 같은 책을 가리킨다.

### 11. 지표와 흔들림 읽기

| 지표 | 정의 | 왜 |
| --- | --- | --- |
| **nDCG@5** (주 지표) | 라벨 0·1·2, 이상적 순위는 그 질의의 라벨로 | AI 사서가 최대 5권을 낸다. 등급과 순위를 함께 본다 |
| Hit@5 | 라벨 2인 책이 상위 5권에 하나라도 있음 | design.md의 Hit Rate. "바로 납득할 책이 하나는 있나" |
| Recall@10 | 라벨 1 이상 중 상위 10권에 든 비율, 분모 min(R, 10) | design.md의 Recall. 합치기·다양화 전 후보 폭 |
| 겹침 | 상위 5권의 같은 지은이 쌍 + 같은 시리즈 쌍 | design.md의 다양성(쏠림) |
| 라벨 없음 | 상위 5권 중 라벨 없는 책 수 | 보충 라벨 뒤 0이어야 결과를 읽는다 |
| 위반 | 추천 불가·다른 기관·어린이 요청의 일반 도서 | 0이 아니면 실행 실패 |
| 걸린 시간 | 질의당 평균·최대 ms | 비교하지 않고 기록만(흔들림 10~20%, 두 번 재서 평균) |

- 질의 20개면 질의 하나가 평균을 0.05 움직인다. 평균만 보지 않는다.
- **짝 비교**: 기준 변형(그 단계의 앞 승자)과 질의별 nDCG@5 차이 → 이김·비김·짐, 부트스트랩 95% 구간(2,000번, `random.Random(0)` 고정).
- **채택 규칙**: 조정 세트에서 평균 차이 > 0, 이김 > 짐, 구간 하한 > 0이면 채택한다. 하한이 0 이하면 "차이 없음"으로 보고 더 단순한 쪽(앞 단계)을 둔다. 단, 위반은 언제나 0이어야 하고 겹침이 크게 줄면 근거로 적는다.
- 어린이·일반, 주제어·상황 묶음별 표도 낸다. 한 묶음에서만 지면 이유를 적는다.

### 13. 실행·기록·재현

- `uv run python -m evals.recommendation topic [--variants a,b,…] [--split tune|check|all] [--reference <이름>]`
  - 개발 DB(`DATABASE_URL`)의 실험 기관에서 읽기만 한다. 실험 기관이 없으면 `scripts/seed_experiment.py`를 알리고 종료 코드 1.
  - 질의 인코딩만 임베딩 서버를 쓴다. 질의 벡터는 `data/query_vectors.json`(모델 이름 + 질의 문자열의 해시 → 벡터)에 캐시한다. 캐시가 다 차 있으면 서버 없이 돈다.
- 기록 `data/runs/<시각>/`: `summary.md`(표), `results.json`(질의·변형별 상위 10권의 책 키, 점수, 근거, 라벨). 책 키가 실험 장서를 가리켜 저장소 밖이다. design.md에는 숫자만 옮긴다.
- 요약 머리(지문): 평가 세트 해시, 라벨 해시와 단계별 수, 실험 기관 이름·id, 모델·텍스트 버전·종류별 벡터 수(실험 기관 범위), `git rev-parse HEAD`와 고친 파일 여부, 변형 설정, 찾지 못한 키 수.
- **같은 수치**: 정렬은 모두 id로 끝을 맺고 난수는 고정 시드뿐이다. 벡터 조회는 인덱스 없는 정확한 거리라 같은 DB에서 같다. 질의 벡터는 캐시로 고정된다. 시각과 걸린 시간 줄만 빼고 요약이 같아야 한다(테스트가 가짜 인코더로 두 번 돌려 비교한다).

### 15. 인기 신호가 없는 문제

| 안 | 내용 |
| --- | --- |
| A. 실험 기관에 대출 행을 만든다 | 누가 무엇을 빌렸는지를 지어내면 "인기" 단계는 만든 규칙을 잴 뿐이다 |
| B. YES24 판매 순위(파일의 `rank`)를 인기로 | 판매 순위는 대출 인기가 아니고, 서비스에 쓰지 않는 출처다 |
| **C. 이 단계를 비워 둔다 (선택)** | 코드는 대출 행으로 만들고 테스트 DB로 확인한다. 실험 장서에서는 0건으로 지나가고, 실제 평가는 정보나루 인기 대출 연동 뒤 |

- 이것도 `add-related-book-experiments`의 일이다. 이번에 만드는 최근 기록 세트는 책이 1권 이상 있는 경우만 담는다(빈 기록의 "아무거나"는 인기 신호가 있어야 잴 수 있다).

### 16. 공식 소개가 없는 책 (이전 Open Questions 2)

- 보완하지 않는다. 10건(2%)이고 기관 소개가 있는 경우가 0건이라 B안(기관 도서 벡터를 따로)으로 얻을 것이 없다.
- 소개 없는 책도 `full`(서명·분류)과 필드별의 `title`·`category`로 벡터가 있다. `description` 단독 변형에서는 그 10권이 결과에 오를 수 없다. 결과를 읽을 때 적는다.

### 17. 남겨 둔 분야

- 질의의 관련 분야, 기준 책, 최근 기록에 쓰지 않는다(세트 검사가 거부).
- 후보에서는 빼지 않는다. 실제 장서처럼 다른 질의의 방해 후보로 남는다(`add-official-book-embeddings` 결정 12). 보충 단계에서 그 책이 상위에 오르면 라벨을 단다. 그런 라벨 수를 요약에 따로 적는다.

### 18. 적재

- 실험 기관만: `uv run python scripts/embed_books.py --full --library-id 3 --kind <종류>`를 `with_author`, `description`, `title`, `category` 차례로(두 층). 책당 약 0.88초 × 473권이라 `with_author`·`description` 약 7분씩, `title`·`category` 약 2~3분씩(짧다), 모두 약 20분. 백그라운드로 돌린다.
- 그 전에 개발 DB를 `pg_dump`로 백업하고 경로를 알린다. 끝나면 임베딩 서버를 내린다.
- 시드 기관의 Faker 책에는 적재하지 않는다(`--library-id`).

### 19. 테스트

- 가짜 인코더(`tests/embedding_helpers.py`)와 테스트 DB의 작은 장서(지어낸 서지 10~40권)로 모든 스펙 시나리오를 돌린다. 임베딩 서버와 실험 장서 파일이 필요 없다. 테스트 docstring에 "요구사항 / 시나리오"를 적는다.
- 실험 틀은 작은 세트(질의 3, 기준 책 2, 기록 2)와 라벨로 실행·지표·재현·위반·캐시를 확인한다. 라벨 도구는 입력을 넘겨 받는 함수로 확인한다(대화형 입력 없이).
- 에이전트 동작 시나리오가 없어 `evals/librarian`에 더할 것이 없다.
- 기존 동작 확인: `similar_books`·`search_collection` 기존 테스트 그대로, `uv run python -m evals.catalog_search` 결과가 기준과 같은지.

### 채택한 설정과 근거

- **채택: 키워드 순위와 벡터 순위를 RRF로 합친다(`hybrid-k60`).** k 60, 키워드:벡터 1:1, 벡터 질의는 이용자 문장, 텍스트 종류 `full`, 시리즈 묶기와 MMR은 끔. `TopicSettings`의 기본값이 이미 이 값이라 코드를 바꾸지 않았다(`variants.py`의 `BEST_*`도 그대로).
  - 조정 세트에서 채택 규칙(차이 > 0, 이김 > 짐, 구간 하한 > 0)을 넘었고(+0.107, 14·3·3, +0.049 ~ +0.167) 확인 세트에서도 같은 방향이다(+0.128, 8·2·0, +0.072 ~ +0.182).
  - 벡터만(`vec-text`)은 평균은 올랐지만 구간이 0을 걸쳐 단독으로는 채택 규칙을 넘지 못했다. 합친 순위와 벡터만의 직접 비교도 차이 없음이다(+0.031, 8·4·8, -0.060 ~ +0.130). 키워드가 주제어 질의에서, 벡터가 상황 질의(0.168 → 0.31)에서 받쳐 주어 합친 쪽이 질의별로 덜 진다(짐 3 대 6).
  - 문장을 띄어쓰기로 나눈 키워드 검색(`current-split`)은 크게 나쁘다(-0.290). 지금 제품처럼 LLM이 낱말을 뽑아 넘기는 것이 키워드 신호의 전제다.
- **단계 1 벡터 질의 입력: 문장.** 낱말과 차이 없음(조정 +0.007, 7·4·9, -0.092 ~ +0.115). 확인 세트에서는 낱말이 높았지만(0.570 대 0.442) 10개라 조정 결과를 뒤집지 않는다. 낱말 입력은 `add-recommendation-evals`에서 실제 LLM 낱말로 다시 본다.
- **단계 3 RRF 격자: k 60, 가중치 1:1.** k 10은 같다(-0.000, 2·15·3). 키워드 가중치 0.5는 평균이 조금 높지만 차이 없음이다(+0.019, 7·9·4, -0.019 ~ +0.056). 2는 조금 낮다(-0.014).
- **단계 4·5 시리즈 묶기와 MMR: 끔(규칙대로).** nDCG는 그대로다(`series1` -0.001, 0·19·1 / `mmr0.7` -0.004, 4·12·4). 겹침은 줄었다(조정 0.35 → 0.20 / 0.15, 확인 1.00 → 0.70 / 0.60). 품질을 잃지 않고 같은 시리즈·같은 지은이가 덜 겹치므로, 제품에 내보낼 때(`add-related-books`) 시리즈 상한 1을 켤지 다시 정한다. `mmr0.5`는 조정 세트에서 품질이 내려간다(-0.024, 2·9·9).

## Risks / Trade-offs

- **[라벨 양과 피로]** 주제 1,384건 → 목록 방식(2·1인 번호만 고르고 나머지는 0)으로 단다. 훑어보다 어울리는 책을 놓치면 0이 된다 → 보충 단계가 상위 결과의 라벨 없는 책만 다시 묻지만, 이미 0으로 적힌 책은 다시 묻지 않는다. 결과 표에서 0인데 상위에 자주 오르는 책은 7.1에서 눈으로 확인한다. 한 세트는 하루 안에 끝내 기준이 흔들리지 않게 한다. 실행 전 단계를 끝낸 뒤에만 실행한다.
- **[분야로 좁힌 후보의 구멍]** 다른 분야의 어울리는 책은 실행 전 라벨에 없다 → 보충 단계. 보충은 보고한 변형의 상위만 보므로 그 변형들에 조금 유리하다(풀링 치우침). 단계별 라벨 수를 적는다.
- **[낱말을 사람이 써 준다]** 실제 LLM이 넘길 낱말보다 좋거나 나쁠 수 있다 → `current-split`으로 낱말 없이도 본다. 실제 LLM 낱말은 `add-recommendation-evals`에서.
- **[Claude가 쓴 질의 초안]** 내 말투로 치우칠 수 있다 → 장서를 보지 않고 쓰고, 사용자가 고친다. 상황·기분 질의를 따로 묶어 본다.
- **[질의가 적다]** 조정 20, 확인 10 → 짝 비교·구간·채택 규칙(결정 11). 작은 차이는 "차이 없음"으로 적는다.
- **[스테디셀러 장서]** 유명한 책에 몰려 있다 → 결과를 실제 작은도서관 성능으로 쓰지 않는다. 카카오·정보나루 일반화에서 다시 본다.
- **[라벨은 저장소 밖]** 잃으면 다시 달아야 한다 → README에 백업을 적고, 실행 요약에 라벨 해시를 남긴다.
- **[실험이 개발 DB를 읽는다]** 실험 중 실험 기관을 바꾸면 수치가 바뀐다 → 지문의 벡터 수와 세트·라벨 해시로 알아챈다.
- **[키워드 동점의 서명 순서]** DB collation이 `en_US.utf8`이라 서명 정렬이 가나다순이 아니다(2026-11-15 확인). `current`와 합친 순위의 키워드 신호가 같은 점수의 책을 이 순서로 둔다 → 실험 중에는 바꾸지 않고 결과에 적는다. 수정은 이 change 뒤의 `fix-korean-title-order`에서 한다.
- **[1주 분량]** 텍스트 종류·조회 넓히기 1일, 순위 함수 1일, 틀·라벨 도구·지표 1.5일, 세트·라벨(사용자 시간과 겹침) 1일, 적재·실행·기록 0.5일.

## Migration Plan

1. 기준 수치: `uv run pytest` 통과 수, `uv run python -m evals.catalog_search` 결과.
2. 구현과 테스트(마이그레이션 없음).
3. 질의 초안 → 사용자 수정 → `pick` → 사용자가 라벨(실행 전 단계).
4. 개발 DB 백업(경로를 알린다) → `docker compose --profile embedding up -d embedder` → 종류 넷 적재(약 20분, 백그라운드) → `--incremental --kind <종류>`가 0건인지 → 단계별 실행 → 보충 라벨 → 최종 실행 두 번(같은지) → 임베딩 서버를 내린다.
5. 결과를 이 문서에 쓰고 기본 종류를 정한다.
6. 되돌리기: 코드는 커밋 되돌리기, 벡터는 `DELETE FROM official_book_embeddings WHERE kind <> 'full'`(기관 도서 벡터도 같다) 또는 4의 백업.

## Open Questions

1. **소장 도서가 없는 요청**: 벡터는 늘 무언가를 돌려준다. 결과를 비울 문턱은 실제 이용과 LLM 답과 함께 봐야 해서 `add-related-books`나 `add-recommendation-evals`에서 정한다.
2. **책→책 유사도의 텍스트 종류**: 이번 결정은 질의→책이다. 비슷한 책의 벡터 이웃에서 다른 종류가 낫게 나오면 `add-related-book-experiments`에서 종류를 신호별로 둘지 정한다.
3. **질의 결 분류**(주제어·상황): 쓸 때 정하는 값이라 경계가 애매한 질의가 있다. 나중에 실제 대화 기록(2단계)으로 다시 나눌지.
