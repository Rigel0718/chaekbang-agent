## Context

- 화면은 `app/web/public/`의 빌드 없는 정적 파일이다. `app/main.py`가 `/ui`에 `StaticFiles(html=True)`로 내주므로, 폴더를 더하면 `/ui/login/`, `/ui/admin/`이 서버 변경 없이 열린다.
- 공용 모듈은 `shared/api.js`(토큰 `chaekbang.token` 하나, 경로 함수, `ApiError`), `shared/sse.js`(fetch 스트림을 사건으로), `shared/card.js`(책 카드, `safeUrl`), `shared/base.css`다. 이용자 화면은 `librarian/`이고, `main.js`가 `#token=`으로 토큰을 받고 `idle.js`(4분 30초, 답 받는 동안 멈춤, 개발용 `?idle_seconds=`)로 비운다.
- 관리자 화면에 필요한 REST는 모두 있다(탐색 결정 7).
  - 큐레이션·틀·요청서 목록은 `?status=` 거르기가 있다. 틀은 `in_use`를 준다.
  - 구매 요청서 상세는 `estimate`(`estimated_total`, `missing_price_count`, `priced_at`, `unavailable`)를 준다. 확정본은 `estimate`가 null이고 항목에 기록한 `unit_price`·`amount`가 있다.
  - 희망도서 목록은 페이지 나눔과 회원번호를 준다.
  - `/overdue-notices/today`는 회원 값이 든 줄을 주고, 확정한 틀이 없으면 409를 준다.
  - 외부 대출 기관에서는 연체 안내 경로(틀 목록 포함)가 모두 409다.
- 서버 토큰 수명은 관리자 12시간, 키오스크 720시간이다. 서버 세션 무입력 한도는 AI 사서 5분, 운영 에이전트 30분이다. `GET /auth/me`는 `role`, `login_id`, `library_name`을 준다.

## Goals / Non-Goals

**Goals:**
- 서버·서버 스펙을 바꾸지 않고 화면만으로 로그인부터 승인까지 닫는다.
- 공용 PC에서 키오스크 토큰과 관리자 토큰이 섞이지 않게 한다.
- 지금의 소스 검사 방식(`tests/platform/test_web_ui.py`)을 관리자·로그인 화면까지 넓힌다.

**Non-Goals:**
- 화면 프레임워크, 번들러, 외부 CDN, 차트 라이브러리
- 관리자 화면의 편집 양식(초안 만들기·고치기)
- 브라우저 자동화 테스트

## Decisions

### 1. 나누기

이번 change는 서버를 바꾸지 않는 화면만 맡는다. 분석 답의 표·차트 사건과 분석 REST, 장서 가져오기 화면, 답에서 초안으로 가는 링크, 운영 평가 전체 회귀는 24b(가칭 `add-admin-analytics-ui`)로 간다. 담은 책 이어 보기는 24c(가칭 `add-basket-resume`)로 간다. 이어 보기는 불러오기 코드로 3시간, 책 id만 서버에 두는 방향이다(회원번호를 쓰지 않음, 공용 PC라 브라우저에 두지 않음).

대안: 장서 가져오기 화면까지 넣기. 서버 변경은 없지만 단계가 많아(올리기, 열 지정, 확인 요청 행, 대량 제적 확인) 1주를 넘길 수 있어서 뺐다.

### 2. 화면별 토큰 키

`shared/api.js`는 화면이 처음에 고르는 저장소 하나를 쓴다.

| 화면 | 저장소 | 키 |
| --- | --- | --- |
| 이용자 | `localStorage` | `chaekbang.kiosk.token` |
| 관리자 | `sessionStorage` | `chaekbang.admin.token` |

- `useScreen("kiosk" | "admin")`이 저장소와 키를 정한다. `getToken`·`setToken`·`clearToken`은 그 키만 다룬다. 로그인 화면은 응답 역할로 `useScreen`을 부른 뒤 저장한다.
- 저장소 접근은 `api.js`의 이 함수들에만 있다. 소스 검사가 이것을 고정한다.
- 대안: 키 하나에 역할을 함께 저장하기. 같은 PC에서 관리자 로그인이 키오스크 토큰을 덮어써서 뺐다.
- 대안: 관리자도 `localStorage`. 공용 PC에서 탭을 닫아도 관리자 토큰이 12시간 남아서 뺐다.

### 3. 역할 확인과 401

- `requireRole(role)`(`api.js`)은 토큰이 없으면 바로 로그인 화면으로 보낸다. 있으면 `GET /auth/me`를 부르고, 401이거나 역할이 다르면 그 키를 지우고 `location.replace("/ui/login/")`를 한다.
- 이용자·관리자 화면은 그 결과를 받은 뒤에 화면을 그린다. 관리자 화면 머리에는 `library_name`과 `login_id`를 보인다.
- 쓰는 중의 401은 지금 이용자 화면의 `onUnauthorized`처럼 한 곳에서 받아 같은 일을 한다.
- 로그인 화면은 이미 로그인한 상태로 열려도 자동으로 넘기지 않고 양식을 보인다. 키오스크 PC에서 관리자가 새 탭으로 로그인하는 길이기 때문이다.
- 관리자 화면은 `pageshow`의 `persisted`(뒤로 가기 캐시)에서 화면을 비우고 `requireRole("admin")`을 다시 한다.
- 대안: 화면이 토큰 만료 시각을 저장해 미리 판단하기. 저장 값이 늘고, 서버가 401로 알려 주므로 뺐다.

### 4. 이용자 화면의 두 시계

`idle.js`의 `createIdleTimer`를 두 시계로 바꾼다.

```
상수: IDLE_MS 60s, IDLE_WARN_MS 45s, CAP_MS 180s, CAP_WARN_MS 150s

비운 직후 ----(첫 입력)----> 이용 중
                             |  무입력 시계: 입력마다 처음부터, 답 받는 동안 멈춤
                             |     45s onWarn("idle") -> 60s onClear
                             |  상한 시계: 첫 입력에서 시작, 멈추지 않음
                             |     150s onWarn("cap") -> 180s onClear
                             v
                          onClear -> 진행 중인 답 abort -> resetAll -> 비운 직후
```

- 알림 띠 `#clear-warning`(`role="status"`, `aria-live="polite"`)는 하나다. 두 알림이 겹치면 먼저 끝나는 쪽 문구와 남은 초를 보인다. 남은 초는 1초마다 `textContent`로 바꾼다.
- 무입력 알림에는 [계속 쓰기]가 있다(누르는 것도 입력이다). 상한 알림에는 버튼이 없다.
- 입력이 들어오면 무입력 알림은 닫히고, 상한 알림은 남는다.
- 상한에서 비울 때 답을 받고 있으면 `chat.js`의 진행 중 요청을 abort한 뒤 `resetAll`한다. `resetAll`은 지금처럼 대화 종료(`DELETE /librarian/sessions/{id}`)를 부르고, 담은 책·입력칸·회원번호를 지운다.
- 개발용 주소값: `?idle_seconds=N`은 그대로 둔다(알림은 N-15초, 최소 1초). `?cap_seconds=N`을 더한다(알림은 N-30초, 최소 1초). B 목록 확인용이다.
- 대안: 상한에서 답을 끝까지 기다리기. 끝나는 때가 정해지지 않아서 뺐다(개선 사항).
- **시작 화면**(사용자 결정 2026-11-23, 로그아웃은 하지 않음): `#start-screen`은 화면 전체를 덮는 [화면을 눌러 시작하세요] 버튼이고, HTML에서 숨김이 아닌 채로 시작한다(처음 열 때). 시계의 `onClear`만 `resetAll({ toStart: true })`로 시작 화면을 다시 보인다. [새 대화]와 세션 끝(404)은 `resetAll()`이라 시작 화면 없이 비운다. 시작 화면을 누르는 것도 입력이라 이용 상한 시계가 그때 시작한다. 토큰은 건드리지 않는다. 대안: 키오스크를 로그아웃시켜 로그인 화면으로 보내기. 사서가 없는 도서관에서 다음 이용자가 직원 계정을 모르므로 뺐다.

### 5. 관리자 화면 구조

```
admin/index.html   머리(기관 이름, 아이디, [로그아웃]) + 탭 넷 + 탭 판 넷
admin/main.js      requireRole("admin") -> GET /library(loan_mode) -> 탭 보이기
                   hashchange로 탭 전환, 각 탭 모듈의 show()
admin/chat.js      운영 대화
admin/approvals.js 승인 목록(종류별 설정 표 하나로 세 묶음)
admin/requests.js  희망도서
admin/overdue.js   오늘의 연체
admin/admin.css    탭, 목록 줄, 상세, 720px 아래 한 줄 쌓기
shared/dom.js      el(tag, {className, text, attrs}) 같은 작은 도우미(textContent만)
```

- 탭 hash: `#chat`(기본), `#approvals`, `#requests`, `#overdue`. 숨긴 탭의 hash로 들어오면 `#chat`으로 간다.
- `loan_mode`: `internal`일 때만 `#tab-overdue`와 승인 목록의 `#group-templates`의 `hidden`을 푼다. 기관 정보를 못 읽으면 숨긴 채 둔다. 이용자 화면의 `loadGuide`와 같은 꼴이다.
- 모바일: `@media (max-width: 720px)`에서 탭은 가로 스크롤, 목록 표는 줄 카드로 쌓고, 버튼 높이는 44px 이상으로 한다.
- 대안: 탭마다 페이지 하나. 페이지마다 역할 확인·로그아웃·머리를 되풀이해서 뺐다.

### 6. 운영 대화

- `admin/chat.js`는 `shared/sse.js`만 공유하고, 이용자 `chat.js`를 옮기지 않는다. 이용자 쪽은 카드·고른 책·찾은 책이 얽혀 있어 나누는 비용이 더 크다.
- 본문은 `{ session_id, message }`이고 첫 턴은 `session_id` 없이 보낸다.
- 답은 `white-space: pre-wrap`인 요소에 `textContent`로 넣는다. `status`는 흐린 한 줄로 보이고 답이 오면 지운다.
- `unsupported`가 참이면 "지금은 못 하는 분석이에요(기록해 둡니다)"를 붙인다.
- 보내는 동안 입력과 보내기를 잠근다. [새 대화]는 진행 중 요청을 abort하고, 세션이 있으면 대화 종료를 부른 뒤 화면을 비운다.
- 404(세션 끝)면 세션 id를 버리고 "대화가 끝나 새 대화로 시작해요"를 보이며 보낸 문장을 입력칸에 되돌린다. 409·429는 서버 문구를 대화에 보인다.
- `done` 뒤 `refreshPendingCount()`가 큐레이션·요청서(자체 대출이면 틀도) 목록을 `?status=pending_approval`로 불러 개수를 [승인 목록] 탭에 보인다. 관리자 화면을 열 때도 한 번 부른다.

### 7. 승인 목록

종류별 설정 표 하나로 세 묶음을 그린다.

| 종류 | 경로 | 줄 | 상세 | 동작 |
| --- | --- | --- | --- | --- |
| 큐레이션 | `/curations` | 제목 · 권수 · 상태 · 만든 때 | 제목, 소개, 책(서명·저자·이유) | 승인 대기: 승인·반려 / 게시: 내리기 |
| 연체 안내문 틀 | `/overdue-notice-templates` | 문장 앞 40자 · 상태 · 쓰는 중 표시 | 문장 전체(자리표시 그대로) | 승인 대기: 승인·반려 |
| 구매 요청서 | `/purchase-requests` | 제목 · 항목 수 · 상태 · 확정본 총액 | 아래 | 승인 대기: 승인·반려 |

- 보기 전환: [승인 대기](기본, `?status=pending_approval`) / [전체](거르기 없음).
- 줄을 누르면 그 줄 아래에 상세를 펼친다(한 번에 하나). 상세는 늘 `GET /{id}`로 새로 읽는다.
- 구매 요청서 상세
  - 확정 전: 항목 표(ISBN, 서명, 저자, 권수, 근거 종류, 추정 단가, 금액). 단가가 null이면 "가격 없음"으로 보인다. 위에는 추정 총액과 조회 시각을 보인다.
    - `missing_price_count > 0`이면 "가격 없는 항목이 있으면 승인할 수 없어요"를 보인다.
    - `unavailable`이면 "지금 정가를 조회할 수 없어요"를 보인다.
  - 확정본: 기록한 단가·금액·총액·`priced_at`·`price_source`("YES24 정가")와 "확정본은 고칠 수 없어요"를 보인다.
- [승인]은 `confirm()`을 한 번 거친다. 구매 요청서는 "승인하면 정가를 다시 조회해 금액을 기록하고, 같은 ISBN의 희망도서를 닫습니다"를 문구에 넣는다. 요청 중에는 버튼을 잠그고 "처리하는 중"을 보인다(YES24 조회로 몇 초 걸릴 수 있음).
- [반려]는 사유 칸(`maxlength`는 서버 상한과 같음)을 펼친다. 비어 있으면 보내지 않는다.
- 오류: `ApiError.detail`을 상세 안 오류 줄에 `textContent`로 넣는다. 503은 문구 뒤에 "잠시 뒤 다시 해 주세요"를 붙인다.
- 성공하면 상세와 그 묶음 목록, 승인 대기 수를 다시 읽는다.

### 8. 희망도서와 오늘의 연체

- 희망도서: `GET /book-requests?status=requested&limit=20&offset=n`이다. 줄에는 서명, 저자, ISBN, 회원번호, 신청일이 있다. 나머지가 있으면 [더 보기]를 둔다. [닫기]는 `confirm()` 뒤 `PATCH /book-requests/{id}`(`{status: "closed"}`)를 보내고 성공하면 그 줄을 지운다.
- 오늘의 연체: `GET /overdue-notices/today`다. 위에 오늘 날짜와 건수를 둔다. 줄에는 회원번호, 이름, 전화, 서명, 등록번호, 반납 예정일, 연체 일수, 채운 문안(`pre-wrap`)이 있다. 409면 서버 문구 + "운영 대화에서 안내문 틀을 만들어 승인해 주세요"를 보인다.
- 두 탭의 `show()`는 목록을 비우고 서버에서 다시 읽는다(탭에 들어올 때마다). 떠날 때 지우지는 않는다. 사용자 결정(2026-11-23): 숨긴 패널은 화면에 보이지 않고 DOM을 볼 수 있는 사람은 이미 로그인한 탭을 쥔 사람이라 지워도 막는 것이 거의 없다. 개인정보는 `sessionStorage` 토큰, 뒤로 가기 때 토큰 재확인, 복사·출력 버튼 없음이 지킨다.
- 복사·출력·내려받기 버튼은 없다.

### 9. 소스 검사(`tests/platform/test_web_ui.py`)

지금 방식(스크립트 글자를 읽어 검사)을 넓힌다. 요구사항마다 테스트 이름이나 docstring에 요구사항 이름을 적는다.

| 요구사항 | 검사 |
| --- | --- |
| 로그인·관리자 화면 내주기 | 두 HTML 200, 참조 파일 모두 200(지금의 `_reachable`을 두 HTML에서도 시작) |
| 기존 API만 사용 | 모든 화면 스크립트의 경로가 허용 목록 안에 있고, 메서드와 함께 `app.routes`에 있음 |
| 브라우저 저장 | 저장소 접근은 `api.js`의 두 키뿐. `chaekbang.token`·`#token=` 없음 |
| 서버 값의 안전한 표시 | HTML 해석 금지어가 세 화면 모두에 없음 |
| 회원번호의 행선지 | 본문에 `member_number`를 넣는 곳은 `borrow`·`requestBook`뿐. 이용자 화면 파일의 `member_number`도 그 둘뿐. AI 사서 대화 본문 키 그대로 |
| 로그인과 역할별 행선지 | `login.js`의 역할 → 경로 표가 `kiosk`·`admin` 둘. 입력칸 `autocomplete="off"`, 안내 문구 |
| 화면의 역할 확인 | 이용자 `main.js`는 `requireRole("kiosk")`, 관리자 `main.js`는 `requireRole("admin")`. 이용자 화면에 `/auth/logout`·로그아웃 버튼 없음 |
| 무입력·이용 상한 | `idle.js` 상수 넷의 값, 두 값이 `settings.librarian_session_idle_minutes`보다 짧음 |
| 탭과 운영 방식 | HTML에서 `#tab-overdue`·`#group-templates`가 `hidden`. `hidden`을 푸는 곳은 `loan_mode === "internal"` 한 곳 |
| 운영 대화 화면 | 운영 에이전트 대화 본문 키가 `session_id`, `message`뿐 |
| 관리자 화면의 회원 값 | `member_number`·`phone`을 읽는 관리자 파일은 `requests.js`·`overdue.js`뿐. 세 화면에 `console.` 없음 |

승인 목록의 동작은 브라우저 확인(B 목록)으로 본다. 서버의 승인 규칙은 이미 각 스펙의 pytest가 본다.

### 10. curl 확인

apply 끝에 개발 서버로 화면이 부르는 순서대로 확인한다.
1. 두 역할 로그인 → `/auth/me`
2. 관리자 목록(`?status=pending_approval`)
3. REST로 만든 큐레이션 초안의 제출·반려·다시 만들기·승인·내리기
4. 틀 승인
5. 구매 요청서(2~3항목) 상세와 승인(YES24 약 5회 이하, 미리 승인받음)
6. 희망도서 닫기, `/overdue-notices/today`
7. 로그아웃 뒤 401

LLM은 부르지 않는다. 확인용으로 만든 데이터는 끝에 지우거나 되돌린다.

## Risks / Trade-offs

- [3분 상한이 대화에 빠듯함: 답 한 번이 10~30초] → 상수 넷을 `idle.js` 한곳에 두어 바꾸기 쉽게 한다. 써 보고 바꾸려면 상수만 고친다(스펙의 시간 값 시나리오도 함께)
- [크롬이 `autocomplete="off"`를 무시하고 관리자 비밀번호 저장을 제안할 수 있음] → 로그인 화면 안내 문구와 README 운영 안내(키오스크 PC에서 "비밀번호 저장 안 함")로 줄인다. 완전히 막지는 못한다
- [관리자가 공용 PC에서 탭을 열어 둔 채 자리를 비움] → 탭을 닫으면 토큰이 사라진다. 무입력 자동 로그아웃은 사용자 결정으로 뺐다(미룰 것)
- [소스 검사는 글자 검사라 우회한 코드를 못 잡음] → 저장소·경로·HTML 해석은 한 모듈(`api.js`, `dom.js`)로 모으는 규칙과 함께 쓴다. 동작은 B 목록으로 본다
- [옛 키 `chaekbang.token`이 이미 켠 키오스크 브라우저에 남음] → 새 코드는 읽지 않는다. 개발 PC뿐이라 Migration에 지우는 방법을 적는다
- [구매 요청서 승인이 YES24 조회로 몇 초 걸림] → 버튼을 잠그고 처리 중을 보인다. 두 번 누름은 서버의 조건부 갱신(409)이 막는다

## Migration Plan

- 서버·DB 변경이 없다. 배포는 정적 파일만 바뀐다.
- 켜 둔 키오스크는 새 화면을 열면 로그인 화면으로 간다. 키오스크 계정으로 한 번 로그인한다. 개발 브라우저의 옛 키는 개발자 도구 > Application > Local Storage에서 `chaekbang.token`을 지운다(남아도 쓰이지 않음).
- 되돌리기: 이 change의 화면 파일을 되돌리면 이전 `#token=` 방식으로 돌아간다.

## 사용자 확인 항목 (브라우저)

WSL에서 브라우저 자동화가 되지 않아 사용자가 자기 Chrome에서 본다. 서버 API는 curl로 먼저 본다. 자체 대출 기관과 외부 대출 기관의 키오스크·관리자 계정이 각각 필요하다.

- B1 로그인: 키오스크 계정은 이용자 화면으로, 관리자 계정은 관리자 화면으로 간다. 틀린 비밀번호는 문구가 나오고 머문다. 입력칸 아래 비밀번호 저장 안내가 보인다.
- B2 토큰 분리: 키오스크로 로그인한 탭을 둔 채 새 탭에서 관리자로 로그인하고, 관리자 탭을 닫은 뒤 이용자 화면을 새로 고친다. 이용자 화면이 그대로 열리고, 개발자 도구의 저장소에 관리자 키가 없다.
- B3 잘못된 토큰: 개발자 도구로 키오스크 키에 관리자 토큰을 넣고 이용자 화면을 새로 고치면 로그인 화면으로 간다. 키를 지우고 `/ui/librarian/`을 열어도 로그인 화면으로 간다.
- B4 무입력(`?idle_seconds=20`): 시작 화면을 누른 뒤 입력하고 손을 떼면 5초쯤에 알림 띠와 남은 초가 나온다. [계속 쓰기]나 화면을 누르면 닫힌다. 다시 손을 떼면 20초에 화면이 비워지고 시작 화면이 보이며, 로그인 화면으로 가지 않는다.
- B5 이용 상한(`?cap_seconds=40`): 계속 입력하면 10초쯤에 끝난다는 알림이 나오고, 입력해도 닫히지 않는다. 40초에 비워지고 시작 화면이 보인다. 답을 받는 중에 40초가 되어도 비워진다.
- B6 쓰지 않는 화면: 시작 화면을 그대로 두면 알림이 뜨지 않는다. 시작 화면을 누르면 대화 화면이 나오고, 이용자 화면을 처음 열 때도 시작 화면이 먼저 나온다. [새 대화]는 시작 화면 없이 비운다.
- B7 관리자 탭: 탭 넷이 보이고, 주소 hash가 바뀌며, 새로 고쳐도 같은 탭이다. 외부 대출 기관 관리자는 [오늘의 연체] 탭과 연체 안내문 틀 묶음이 보이지 않는다.
- B8 운영 대화: "이번 달 대출이 많은 분야 알려줘"에 status 줄 뒤 답 문장이 나온다. "공룡 책 큐레이션 초안 만들어 줘" 뒤 [승인 목록] 숫자가 는다. [새 대화]로 비워진다.
- B9 승인: 큐레이션 초안을 반려(빈 사유는 막힘, 사유를 적으면 반려 사유가 보임)한 뒤, 다른 초안을 승인해 게시 상태가 된다. 이용자 화면에서 AI 사서에게 추천 큐레이션을 물으면 그 큐레이션이 나온다. 게시를 내린다.
- B10 연체 안내문 틀: 틀 초안을 승인하면 "쓰는 중"이 붙는다. [오늘의 연체]에 그 틀로 채운 문안이 나온다(연체 대출이 있을 때). 틀이 없는 기관에서는 안내가 나온다.
- B11 구매 요청서: 확정 전 상세에 추정 단가·총액·조회 시각이 나온다. 가격 없는 ISBN이 있는 요청서의 승인은 서버 문구가 나오고 승인 대기로 남는다. 정상 요청서를 승인하면 확정본의 기록 금액과 출처가 나오고 버튼이 없다. 같은 ISBN의 희망도서가 [희망도서] 탭에서 빠진다.
- B12 희망도서: 처리 전 목록에 회원번호가 보이고, [더 보기]와 [닫기]가 된다.
- B13 다시 읽기: [오늘의 연체]를 연 뒤 [운영 대화]로 옮기고 그사이 연체 대출 하나를 반납한 다음 [오늘의 연체]로 돌아오면 반납한 줄이 없다. [희망도서]도 닫은 신청이 돌아와도 없다.
- B14 로그아웃: [로그아웃] 뒤 [뒤로]를 누르면 관리자 내용이 보이지 않고 로그인 화면으로 간다.
- B15 모바일: 개발자 도구의 좁은 화면(390px)에서 관리자 화면의 탭·목록·상세 버튼을 누를 수 있고 가로로 넘치지 않는다.
