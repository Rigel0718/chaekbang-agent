## Context

- 벡터는 `book_embeddings` 한 테이블에 기관 도서 기준으로 있다(`add-book-embeddings` 결정 1). 텍스트는 `LibraryBook.shown`(공식 값 먼저, 비면 기관 값)으로 만든다. 개발 DB의 `book_embeddings`는 비어 있다.
- 공식 서지 쪽에는 이미 기여자 표(`book_contributors`, 기관 공통 테이블)가 있고, 공식 서지를 만드는 경로(채움 `_create_official`, 시드, `load_catalog`)가 모두 `sync_contributors`를 부른다.
- `books.kdc`는 YES24가 주지 않아 비어 있다. 지금 임베딩 텍스트의 KDC 주류 이름은 `shown("kdc")`로 기관 값에서 온다.
- KDC 주류 이름 함수 `kdc_class_name`은 `app/library/recommendation/kdc.py`에, 벡터 열 차원 상수 `EMBEDDING_DIM`은 `app/library/models/embedding.py`에 있다. 운영자 층은 둘 다 import할 수 없다.
- 개발 DB: Faker 기관 2개, 기관 도서 270권, 공식 서지 0건(270권 모두 `pending`). 평가 표본 87권은 테스트 DB 트랜잭션에서만 산다.
- YES24: 지금 쓰는 엔드포인트는 `itemDetail`(채움)과 `itemList`(평가 표본)이다. 카테고리 API(`/category/bestsellerSteady` 등)는 문서만 있고 호출해 본 적이 없다. 카테고리 목록 원본(`yes24-open-api-guide/category.json`, 1,361개)이 로컬에 있다. 시리즈는 응답의 목록을 `, `로 이어 `series_name` 한 문자열로만 저장한다.
- ONNX 적재 측정(87권, 두 번 평균): 배치 1은 126.5초, 4는 128.6초, 8은 145.3초, 32는 152.1초. 흔들림은 10~20%다.
- 평가 표본 87권의 분야: 어린이 13, 유아 13, 소설/시/희곡 11, 가정 살림 8, 에세이 7, 인문 7, 자기계발 5, 건강 취미 4, 만화 3, IT 3, 역사 3, 예술 1, 청소년 1. 경제 경영, 사회 정치, 자연과학, 종교는 0이다. 소개 없는 책 3권, 시리즈 있는 책 40권.

## Goals / Non-Goals

**Goals:**

- 같은 공식 서지는 기관이 몇이든 한 번만 인코딩하고, 그 벡터에 기관 값이 섞이지 않는다는 것을 테스트가 지킨다.
- 책 하나는 항상 한 층에서만 벡터를 얻는다. 조회는 두 층을 한 순위로 돌려주고 기관 분리와 추천 가능 조건이 그대로다.
- 다음 change가 마이그레이션 없이 필드별 벡터와 텍스트 버전을 더해 비교할 수 있다.
- 개발 DB에 실제 서지 약 500권과 그것을 소장한 가상 기관이 있고, 다시 만들 수 있다(파일 → DB).

**Non-Goals:**

- 추천 순위, 신호 합치기, 평가 세트, 텍스트 버전·필드별 비교(`add-recommendation-experiments`).
- 실험 장서의 대출 기록과 회원. "함께 대출된 책"은 `add-bibliographic-sources`에서 다룬다.
- 실험 장서를 지우는 명령. 서지 출처를 바꾸는 `add-bibliographic-sources`에서 만든다.
- 쓰지 않는 벡터 정리(옛 버전, 나중에 연결된 책의 기관 도서 벡터). 조회가 걸러 낸다.
- 벡터 인덱스. 500권 규모에서는 필요 없고, 다시 잰 값만 남긴다.

## Decisions

### 1. 벡터 두 층 (`add-book-embeddings` 결정 1을 뒤집는다)

- **이전 결정**: 기관 도서 기준 테이블 하나(A안). 이유는 테이블 하나, ISBN 없는 책이 같은 경로, 기관 분리가 다른 기관 데이터 테이블과 같은 방식이라는 것이었다. 공식 서지 기준(B안)은 "표시 값은 공식 값이 비면 기관 값으로 채워지므로 공식 서지의 텍스트가 기관마다 달라져 공유가 깨진다", "기관 공통 테이블에 기관 실행이 쓰게 된다"는 이유로 버렸다.
- **바뀐 사정**
  1. 공식 서지 층에 파생 값을 두는 선례가 생겼다. `book_contributors`가 기관 공통 테이블이고 운영자 실행만 쓴다. 벡터도 같은 자리에 둘 수 있다.
  2. 추천 실험은 텍스트 버전과 종류를 바꿔 가며 여러 번 적재한다. 권당 약 1.45초라 기관마다 다시 인코딩하는 비용이 실험 횟수만큼 곱해진다.
  3. 기관 값이 섞인 벡터로는 "이 텍스트 구성이 낫다"는 실험 결과가 기관의 입력 품질에 따라 달라진다. 서지 출처를 YES24에서 카카오·정보나루로 바꿔 비교하려면(`add-bibliographic-sources`) 벡터의 입력이 출처 값만이어야 한다.
  4. B안을 버린 두 이유는 규칙으로 없앨 수 있다. 공식 서지 텍스트를 **공식 값만으로** 만들면 기관마다 달라지지 않고, 적재를 운영자 층 함수로 두면 기관 실행이 공통 테이블에 쓰지 않는다.
- **정한 것**
  - 공식 서지 벡터: 새 테이블, 운영자 층, 공식 값만.
  - 기관 도서 벡터: 지금 테이블, 대상을 `book_id IS NULL`인 책으로 좁힌다.
  - 책 하나는 한 층에만 속한다. 연결 여부(`library_books.book_id`)가 층을 정한다.
- **잃는 것**: 연결된 책의 텍스트에서 기관 값이 빠진다. 실제로 빠지는 것은 KDC 주류 이름(`문학` 같은 한 낱말)이다. 공식 서지의 `kdc`가 비어 있기 때문이다. 외부 분류 원문(`국내도서-소설/시/희곡`)은 그대로 들어간다. 정보나루가 KDC를 주면(`add-bibliographic-sources`) 공식 값으로 다시 들어온다.
- 텍스트 버전은 2로 올린다. 저자를 빼서(결정 4) 조립 규칙이 바뀌었다. 저장된 벡터는 아직 없지만, archive된 `add-book-embeddings`의 "v1 = 서명·부제, 저자, 분류, 소개"가 계속 같은 뜻으로 읽히게 번호를 올린다.

### 3. 벡터 종류 칸 `kind`

- 둔다. 유니크 키는 (대상, 모델, 텍스트 버전, 종류)다.
- 값은 코드의 `TextKind`(StrEnum)로 정의하고 이번에는 `full` 하나다. DB에는 값 목록을 CHECK로 두지 않고 "비어 있지 않다"만 건다.

| 안 | 내용 |
| --- | --- |
| **A. 자유 문자열 + 코드의 StrEnum (선택)** | 다음 change가 종류(`description`, `title_category` 등)를 더할 때 마이그레이션이 없다. `model_name`, `text_version`과 같은 성격의 값이다 |
| B. `str_enum` + CHECK | 다른 상태 값과 같은 방식이지만 실험에서 종류를 더할 때마다 마이그레이션이 필요하다 |
| C. 칸을 두지 않고 텍스트 버전 번호로 나눈다 | "v2는 저자 빼기, v3은 소개만"처럼 번호에 두 뜻이 섞인다. 필드별 벡터 여러 개를 한 조회에서 함께 쓰기 어렵다 |

- 뜻의 구분: `text_version`은 조립 규칙 전체의 판(순서, 구분자, 이름표), `kind`는 그 규칙 안에서 어떤 필드를 넣었는지다.
- 적재와 조회 함수는 `kind`를 인자로 받고 기본값이 `full`이다. CLI에는 아직 옵션을 두지 않는다(값이 하나다).

### 4. 임베딩 텍스트 모듈을 세 곳으로

| 위치 | 내용 | 아는 것 |
| --- | --- | --- |
| `app/core/embedding_text.py` | `TEXT_VERSION`(2), `TextKind`, `compose(kind, *, title, subtitle, categories, description) -> str`, `content_hash` | 문자열만 |
| `app/central/embedding_text.py` | `official_embedding_text(book: Book, kind) -> str` | `Book` |
| `app/library/recommendation/embedding_text.py` | `library_embedding_text(book: LibraryBook, kind) -> str` | `LibraryBook`의 기관 값. `shown`을 쓰지 않는다 |

- 조립 규칙(순서, 빈 값 건너뛰기, 부제 붙이기, 소개를 마지막에)은 `core` 한 곳에 둔다. 두 층이 규칙을 따로 가지면 같은 책이 층에 따라 다른 텍스트가 되고, 실험에서 버전을 올릴 때 두 곳을 고쳐야 한다.
- `kdc_class_name`을 `app/core/kdc.py`로 옮긴다(문자열만 다루는 순수 함수다). 기관 쪽 import를 고친다.
- 층별 입력:

| 항목 | 공식 서지 | 기관 도서 |
| --- | --- | --- |
| 서명, 부제 | `title`, `subtitle` | `title`, 부제 없음 |
| 저자 | 넣지 않음 | 넣지 않음 |
| 분류 | `external_category`, `kdc` 주류 이름 | `kdc` 주류 이름 |
| 소개 | `description` | `description` |

- **저자를 넣지 않는다** (2026-11-15 사용자 결정. `add-book-embeddings`의 v1은 저자를 넣었다)
  - 저자 이름은 고유명사라 뜻의 이웃을 만드는 데 도움이 되지 않고, 오히려 이름이 비슷한 책끼리 가까워지거나 같은 저자의 다른 분야 책이 주제 이웃에 끼어들 수 있다.
  - 저자는 정확히 맞추는 신호가 따로 있다. 공식 서지는 기여자 표(`book_contributors`), ISBN 없는 책은 저자 키(`author_keys`)로 "같은 저자"를 찾고, 저자 이름이 든 질의는 서명·저자 찾기(오타 허용)가 맡는다. 벡터에도 넣으면 같은 신호를 두 번 센다.
  - 글·그림·옮김 이름이 모두 빠진다. 저자 원문이 한 문자열이라 역할별로 나눠 넣지 않는다.
  - 잃는 것: 그림책처럼 작가 이름이 화풍·분위기의 대리 신호인 경우. 이것은 같은 저자 신호가 맡는다.
  - 확인: `add-recommendation-experiments`에서 "저자 넣기"(v1과 같은 필드) 종류를 비교 대상으로 둔다. 질의 쪽 수치가 저자 넣기가 낫다고 나오면 그때 되돌린다.
  - 512토큰에서 잘릴 때 앞에 남는 것은 서명·분류가 된다. 서명·저자·분류를 합쳐도 중앙값 약 28토큰이라 저자를 빼도 512토큰을 넘는 책은 거의 그대로다(archive된 `add-book-embeddings` design의 참고 수치).

- **지키는 테스트**(완료 기준 "기관 값이 섞이지 않는다"): ① `official_embedding_text`는 `Book`만 받는다(운영자 층은 `LibraryBook`을 import할 수 없고 층 테스트가 막는다) ② 연결된 기관 도서의 모든 서지 필드를 다른 값으로 채운 뒤 적재해도 공식 서지 벡터의 해시가 공식 값만의 해시와 같다 ③ 기관 값을 고친 뒤 증분이 0건이다.

### 5. 공식 서지에 소개가 없고 기관에만 있는 경우

| 안 | 내용 |
| --- | --- |
| **A. 공식 값만 쓴다. 소개 없이 서명·분류로 벡터를 만든다 (선택)** | 규칙이 하나다(연결되면 공식 서지 벡터). 기관 값이 공통 벡터에 들어갈 길이 없다 |
| B. 그 책만 기관 도서 벡터를 따로 만들고 조회가 그것을 먼저 쓴다 | 책이 두 층에 걸치는 세 번째 상태가 생긴다. 증분과 조회가 "공식 소개가 생기면 되돌린다"까지 알아야 한다 |
| C. 기관 소개를 공식 서지 텍스트에 넣는다 | 공유가 깨진다(결정 1의 전제) |

- A로 정한다. 드문 경우다. 가져오기 파일에 소개 열이 있는 일이 드물고, 평가 표본에서 소개 없는 책이 3%다.
- 얼마나 되는지는 잰다. 적재 CLI가 끝에 "공식 소개 없음 N건(그중 기관 소개 있음 M건)"을 출력한다. M이 눈에 띄게 크면 `add-recommendation-experiments`에서 B를 다시 본다.

### 6. 적재

```python
# app/central/embedding.py
@dataclass
class EmbeddingRun: targets, encoded, skipped, stopped

# app/central/official_embeddings.py
async def run_official_embedding(session, embedder, *, full, batch_size,
                                 kind=TextKind.FULL, within: Select | None = None,
                                 on_progress=None) -> EmbeddingRun

# app/library/recommendation/embeddings.py
async def run_library_embedding(session, embedder, *, full, batch_size,
                                kind=TextKind.FULL, library_id: int | None = None,
                                on_progress=None) -> EmbeddingRun
def held_official_ids(library_id: int) -> Select  # 그 기관의 추천 가능한 책에 연결된 공식 서지 id
```

- **공식 서지 층의 대상은 공식 서지 전부다.**

| 안 | 내용 |
| --- | --- |
| **A. 공식 서지 전부 (선택)** | 운영자 층이 기관을 몰라도 된다. 공식 서지는 소장 도서의 ISBN으로만 만들어지므로 거의 모두 누군가 가진 책이다 |
| B. 어느 기관에서든 추천 가능한 책에 연결된 공식 서지만 | 접점(`EnrichmentTargets` 같은 것)이 하나 더 필요하다. 사본이 모두 분실인 책 몇 권을 아끼는 정도다 |

- 기관을 지정한 실행(`--library-id`)은 스크립트가 `held_official_ids(library_id)`를 `within`으로 넘긴다. 운영자 층은 그 뜻을 모르고 id 조건으로만 쓴다(`search_collection`의 `within`과 같은 모양).
- 기관 도서 층의 대상: 추천 가능 조건(`recommendable_ids`와 같은 식)에 `LibraryBook.book_id.is_(None)`을 더한다.
- 배치 흐름(id 순서로 읽기 → 텍스트와 해시 → 저장된 해시와 비교 → 커밋 → 인코딩 → `ON CONFLICT DO UPDATE` → 커밋)은 지금과 같다. 인코딩 동안 트랜잭션을 잡지 않는다. 두 층이 같은 흐름이라 뼈대는 `app/central/`에 한 번만 두고 층마다 "대상 읽기, 텍스트 만들기, 저장"만 넘긴다.
- 운영자 실행이 기관 테이블(`book_embeddings`)에 쓰는 것은 지금과 같다(파생 값만). 훅을 부르지 않는다.
- 공식 서지가 생기거나(채움) 바뀌면 해시가 달라져 증분이 잡는다. 기관 도서가 나중에 연결되면 기관 도서 층의 대상에서 빠지고, 남은 기관 도서 벡터는 지우지 않는다(조회가 쓰지 않는다).

### 7. 조회

```python
async def similar_books(session, embedder, *, library_id, query, limit=5, kind=TextKind.FULL) -> list[SimilarBook]
```

- 기준은 기관 도서다. `library_books`에서 그 기관의 추천 가능한 책을 고르고 벡터를 두 갈래로 붙인다.
  - 연결된 책: `official_book_embeddings.book_id = library_books.book_id`
  - 연결되지 않은 책(`book_id IS NULL`): `book_embeddings`의 (`library_id`, `library_book_id`)
  - 두 갈래를 `UNION ALL`로 합쳐 코사인 거리, 기관 도서 id 순으로 정렬한다. 모델 이름, 텍스트 버전, 종류는 갈래마다 건다.
- 한 기관에 같은 ISBN의 기관 도서는 하나뿐이라(`uq_library_books_library_id_isbn`) 책이 두 번 나오지 않는다.
- 기관 분리: 공식 서지 벡터는 기관에 속하지 않지만, 결과에 오르는 길은 "이 기관의 추천 가능한 기관 도서가 그 공식 서지를 가리킨다" 하나뿐이다. 다른 기관만 가진 공식 서지는 붙을 기관 도서가 없다.
- 돌려주는 것은 지금처럼 `LibraryBook`과 유사도다. REST와 tool에는 잇지 않는다.
- 속도: 5,000권(공식 4,500 + 기관 500, 무작위 정규화 벡터)에서 상위 5권 조회를 다시 잰다. 이전 기준은 한 테이블 50ms, 목표 100ms 아래다. 넘으면 수치를 보고하고 인덱스는 다음 change에서 정한다.
  - **잰 값** (2026-11-15, 테스트 DB 트랜잭션, `ANALYZE` 뒤 다섯 번씩 두 차례): 69.5 / 44.4 / 44.4 / 48.6 / 47.8ms, 67.0 / 45.2 / 44.3 / 38.9 / 42.9ms. 첫 조회 약 68ms, 그 뒤 약 45ms로 목표 안이다. 인덱스는 두지 않는다.

### 8. CLI

- `scripts/embed_books.py --full|--incremental [--layer official|library] [--library-id N] [--batch-size N]`
  - `--layer`가 없으면 공식 서지, 기관 도서 순서로 둘 다. 앞 층이 멈추면 뒤 층은 시작하지 않는다.
  - 진행 출력에 층 이름을 붙인다: `[공식 서지 64/450] 인코딩 60, 건너뜀 4`.
  - 끝: `공식 서지 벡터 450건: 인코딩 …, 건너뜀 … / 기관 도서 벡터 45권: … (모델 …, 텍스트 버전 2, 종류 full)`과 결정 5의 소개 없음 건수.
  - 종료 코드는 그대로다(0, 1, 2).

### 9. 적재 배치 기본값: 32 → 4

| 배치 | 87권 적재 | 비고 |
| --- | --- | --- |
| 1 | 126.5초 | 호출 87번, 커밋 87번 |
| **4 (선택)** | 128.6초 | 1과 흔들림 안에서 같다. 호출과 커밋이 4분의 1 |
| 8 | 145.3초 | |
| 32 | 152.1초 | 지금 기본값. 4보다 약 18% 느리다 |

- 4로 정한다. 서버가 한 배치를 가장 긴 책 길이로 채워 계산해 배치가 클수록 느리다. 1과 4가 같다면 왕복과 커밋이 적은 4가 낫고, 중간에 멈췄을 때 잃는 것도 4권뿐이다.
- 500권에서 약 2분을 줄인다. 실험에서 버전마다 다시 적재하므로 그만큼 곱해진다.
- **개발 DB 적재 결과** (2026-11-15, 배치 4, CPU ONNX): `--full`로 공식 서지 벡터 472건과 기관 도서 벡터 316권(실험 장서의 ISBN 없는 책 53권 + 시드 기관의 Faker 책 263권. 개발 DB의 시드 책은 공식 서지에 연결돼 있지 않다)을 693초에 만들었다(권당 약 0.88초). 바로 뒤 `--incremental`은 두 층 모두 0건. 공식 소개 없음 10건, 그중 기관 소개 있음 0건(결정 5의 B안을 다시 볼 이유가 없다).
- **조회 확인**: 가상 기관에서 질의 6개, 상위 10권. 3개 질의에서 두 층의 책이 한 순위에 섞였다. 결과에 다른 기관의 책과 분실·제적 사본만 남은 책(52권)은 없었다.
- `EMBEDDING_BATCH_SIZE` 기본값과 `.env.example`, 스펙의 기본값을 함께 바꾼다. 타임아웃(600초)은 그대로 둔다. GPU 장비에서는 큰 배치가 빠를 수 있어 설정과 `--batch-size`는 남긴다.

### 10. 공식 서지를 만드는 함수 하나와 시리즈 키

- `app/central/enrichment.py`의 `_create_official`을 `app/central/official_books.py`의 `create_official(session, isbn, item: Yes24Item) -> Book`으로 옮긴다. 채움과 실험 장서 적재가 함께 부른다. 하는 일은 지금과 같다: `ON CONFLICT (isbn) DO NOTHING`으로 넣고, 다시 읽고, `sync_contributors`를 부른다. 이미 있으면 고치지 않는다.
- **시리즈 키를 여기서 저장한다**(`add-book-contributors` Open Questions 2).
  - `Yes24Item`에 `series_names: tuple[str, ...]`(응답 목록 그대로, 빈 값 제외)를 더한다. `series_name`(이어 붙인 표시용)은 그대로다.
  - `books.series_keys`: `text[]`, NOT NULL, 서버 기본값 `'{}'`. 값은 `series_names`마다 `match_key`, 빈 키와 중복 제외, 순서 유지.
  - 저자 키(`author_keys`)와 달리 기본값을 둔다. 저자 키는 같은 행의 `author`에서 언제든 다시 계산되지만, 시리즈 목록은 응답에만 있어 "빠뜨리면 거부"로 지킬 수 있는 불변식이 없다. 만드는 곳을 `create_official` 하나로 모으는 것으로 지킨다.
  - 시드(Faker, 시리즈 없음)와 평가 표본 적재(`load_catalog`, 표본 파일에 이어 붙인 문자열만 있음)는 빈 목록으로 둔다. 표본은 다시 받지 않는다.
  - 인덱스는 두지 않는다. 같은 시리즈 조회는 `add-recommendation-experiments`가 만들고, 느리면 GIN을 더한다.
- 기관 도서에는 시리즈 칸이 없다(가져오기 파일에 시리즈 열이 없다). 연결되지 않은 책은 "같은 시리즈" 신호에 못 들어간다.

### 11. 받는 방식: 카테고리 스테디셀러

| 안 | 내용 |
| --- | --- |
| **A. 카테고리 스테디셀러 `bestsellerSteady` (선택)** | 분야별 권수를 카테고리 id로 정확히 맞춘다. 오래 꾸준히 읽힌 책이라 도서관 장서와 닮았다. 카테고리 id와 순서로 무엇을 받았는지 기록이 분명하다 |
| B. 카테고리 베스트셀러 `bestseller` | 지금 잘 팔리는 책에 치우친다(신간, 굿즈 세트). 작은도서관 장서는 몇 해에 걸쳐 쌓인 책이다 |
| C. 상품 검색 `itemList`(검색어) | 평가 표본이 쓴 방식이다. 검색어가 서명에 든 책만 나와 분야 안에서 치우치고(`공룡` → 서명에 공룡), 토이북·잡지가 섞였다(표본 87권 중 바코드·ISSN 상품이 있었다). 분야별 권수를 맞추기 어렵다 |

- `app/central/external/yes24/category.py`에 `steady_sellers(client, category_id, *, page, page_size) -> list[dict]`를 둔다. 원본 상품(dict)을 돌려준다. 파일에 원본을 남겨야 해서다. 엔드포인트와 새 응답 키(성인 표시, 저장하지 않는 변동 값 키 목록)는 `definitions.py`에 둔다.
- **호출 전에 확인할 것**(문서와 실제 응답이 다른 곳이 있다. 승인 뒤 1~3회 호출): ① `detail=Y` 응답에 소개(`contentDetail`), 시리즈 목록, 분류 원문이 있는가 ② 12자리 하위 카테고리 id(`001001046014` 시/희곡)를 받는가 ③ 한 카테고리에서 몇 권까지 주는가(`totalCount`).
  - ①이 아니면: 목록으로 ISBN만 정하고 `itemDetail`을 ISBN마다 부른다(최대 약 550회 추가).
  - ②가 아니면: 시와 청소년 문학만 상품 검색(`시집`, `청소년 소설`)으로 받고 기록에 방식을 적는다.
  - ③이 목표보다 적으면: 같은 카테고리의 월별 베스트셀러로 채우고 기록에 적는다.
  - 셋 중 하나라도 어긋나면 받기 전에 design과 스펙을 고치고 알린다.
- 호출 수: 분야 19개 × 1~2쪽(`pageSize` 100) ≈ 25회. 하루 한도 2만 회, 초당 5회 제한(`RateLimiter`)은 그대로 쓴다.
- **확인 결과** (2026-11-15, 호출 2회: `시/희곡` 12자리 id와 `유아` 9자리 id, `pageSize` 5)
  - ① `detail=Y` 응답에 `contentDetail`(소개), `series`(목록), `goodsSortNm`(분류 원문), `adultYn`이 있다. 상품 키는 38개로 문서와 같다. → 목록 응답만으로 받는다. 상세 조회는 부르지 않았다.
  - ② 12자리 하위 카테고리 id를 받는다. 결과의 관리 분류(`goodsSortNm`)는 책마다 하나라 진열 카테고리와 다를 수 있다(`시/희곡` 5권 중 2권이 `국내도서-에세이`, `국내도서-인문`). → 대안으로 바꾸지 않는다.
  - ③ `totalCount`는 두 곳 다 1000(상한으로 보인다)이다. 모든 분야의 목표보다 많다.
- **받은 결과** (2026-11-15, 호출 19회, 분야마다 1쪽): 525/525권. 거른 것은 분야 사이 중복 42건뿐이다(ISBN 아님, 서명·저자 없음, 잡지·전집, 성인 0건). 소개 없는 책 11권(2%). 평가 표본 87권과 겹친 ISBN 20권.
  - 분야별 관리 분류가 진열 분야와 같은 비율: 유아 75/75, 청소년 문학 30/30, 어린이 94/95, 자기계발 20/20, 만화 20/20, 가정 살림 15/15, 소설 39/40, 경제 경영 24/25, 자연과학 23/25, 시/희곡 13/15, 에세이 26/30, 인문 22/25, 사회 정치 14/20, 역사 17/25, 종교 9/10, 예술 14/15, 건강 취미 12/15, 여행 0/10(에세이 6, 건강 취미 3, 청소년 1).
  - 어린이 구분은 관리 분류(`국내도서-유아`, `국내도서-어린이`)를 근거로 하므로, 어린이 분야의 책 1권(`국내도서-청소년`)과 다른 분야에 섞인 `국내도서-청소년` 책은 일반 도서다. 여행 분야는 관리 분류가 `여행`인 책이 없다. 남겨 둔 분야라 이번 실험에는 쓰지 않고, `add-bibliographic-sources`에서 분야를 볼 때 관리 분류 기준으로 다시 묶는다.

- 표본에 없던 분야(경제 경영, 사회 정치, 자연과학, 종교, 시, 청소년 문학)와 적던 분야(역사, IT, 만화, 예술)를 넣었다.
- 받는 순서는 하위 카테고리(시/희곡, 청소년 문학)를 상위보다 먼저 한다. 중복은 먼저 받은 분야에 남으므로 시집이 소설 몫에 먹히지 않는다.

### 13. 거르기와 평가 표본과의 겹침

- 빼는 것: ISBN이 978·979로 시작하는 올바른 ISBN-13이 아닌 상품(`real_isbn`과 같은 규칙), 서명·저자가 없는 상품, 분류 원문이 잡지·전집인 상품, 성인 표시 상품. 뺀 건수를 이유별로 기록한다.
- **소개 없는 책은 빼지 않는다.** 실제 장서에도 있고(표본 3%), 결정 5의 경우를 재려면 있어야 한다. 건수를 기록한다.
- **평가 표본 87권과 ISBN이 겹쳐도 그대로 넣는다.** 표본은 테스트 DB 트랜잭션에서만, 실험 장서는 개발 DB에서만 살아 한 DB에서 만나지 않는다. 겹치는 책을 빼면 분야의 윗자리 책이 빠져 구성이 틀어진다. 겹친 건수만 받기 출력에 적는다.

### 14. 원본 파일

- 위치: `evals/collection/data/yes24_collection.json`. `.gitignore`에 `evals/collection/data/`를 더한다(평가 표본과 같은 이유).
- 형식:

```json
{
  "fetched_on": "2026-11-…",
  "source": "yes24",
  "method": "category/bestsellerSteady",
  "fields": [{"key": "toddler", "name": "유아", "category_id": "001001027", "target": 75,
              "fetched": 75, "skipped": {"not_isbn": 3, "adult": 0}, "holdout": false}],
  "books": [{"field": "toddler", "rank": 1, "item": { …응답 상품 원본… }}]
}
```

- `item`은 응답 상품 그대로이되 저장하지 않는 값(판매가, 판매 상태, 포인트, 판매지수, 평점)의 키를 뺀다. 키 목록은 `definitions.py`에 둔다. 표지는 URL만 있다.
- 적재는 `item`을 `parse_item`으로 읽는다. 채움과 같은 해석 경로를 타야 같은 공식 서지가 나온다.
- 코드: `evals/collection/plan.py`(결정 12의 표), `evals/collection/fetch.py`(`uv run python -m evals.collection.fetch`, `--dry-run`은 분야별 목표와 예상 호출 수만 출력). 받기는 서비스 경로가 아니라 `evals/` 아래에 둔다(`fetch_sample.py`와 같은 자리).
- 파일이 있으면 다시 받지 않는다. 중간에 멈추면 파일을 쓰지 않는다(약 25회라 처음부터 다시 받는다).

### 15. 넣는 경로: 별도 스크립트

| 안 | 내용 |
| --- | --- |
| **A. `scripts/seed_experiment.py` + `app/seed/experiment.py` (선택)** | 시드는 그대로다. 파일이 없는 사람도 `scripts/seed.py`가 돈다 |
| B. `scripts/seed.py --experiment` | 시드 스펙(공식 서지 45건 등 건수 고정)과 `test_seed.py`가 저장소에 없는 파일에 기대게 된다. 전제 조건이 다르다 |

- 층: 공식 서지를 만드는 것은 운영자 층(`create_official`)이고, 가상 기관의 기관 도서·사본·어린이 구분은 조립 층(`app/seed/`)이 만든다. `app/seed/`는 어느 층이든 import할 수 있다. 스크립트는 `scripts/seed.py`처럼 연결·마이그레이션 확인 뒤 한 트랜잭션으로 넣는다.
- 멱등: 가상 기관은 이름으로, 계정은 시드와 같은 방식으로, 공식 서지는 ISBN 충돌 무시로, 기관 도서는 (기관, ISBN) 또는 ISBN 없는 책은 (기관, 서명, 저자)로, 사본은 (기관, 등록번호)로 찾고 없을 때만 만든다. 이미 있는 행은 고치지 않는다.
- 기관 도서는 ORM으로 만든다. 저자 키를 모델이 정한다.
- 어린이 기능은 `app/features/children`의 함수를 직접 부른다(`load_catalog`와 같다). 서버를 거치지 않는 진입점이라 훅 등록에 기대지 않는다.

### 16. 장서처럼 만들기

- 가상 기관: 이름 `실험용 가상 작은도서관`, `small_library`, 운영 방식 `internal`, 대출 기간 14일. 관리자·키오스크 계정 하나씩(비밀번호는 시드 비밀번호 설정). 로그인해 찾기와 대화를 직접 써 볼 수 있다.
- 책의 상태는 ISBN 순서 번호 `i`로 정한다(난수 없음. 평가 표본 적재의 규칙과 같은 방식).

| 조건 | 구성 | 500권일 때 |
| --- | --- | --- |
| `i % 10 == 3` | ISBN 없는 기관 도서. 서명·저자·출판사·소개를 기관 값으로 넣고 공식 서지를 만들지 않는다. 사본 1권 대출 가능 | 약 50 |
| `i % 20 == 7` | 분실 사본만 1권 | 약 25 |
| `i % 20 == 17` | 제적 사본만 1권 | 약 25 |
| `i % 10 == 8` | 사본 1권, 대출 중 | 약 50 |
| `i % 10 == 0` | 사본 2권(대출 가능 1, 대출 중 1) | 약 50 |
| 그 밖 | 사본 1권 대출 가능 | 약 300 |

- **일부를 ISBN 없는 책으로 넣는다.** 기관 도서 벡터, 저자 키, "연결된 책과 연결되지 않은 책이 한 순위에서 만난다"가 실제 값으로 쓰여야 실험이 두 층을 다 본다. 이 책들의 소개는 `library_books`에 들어간다(개발 DB에만).
- 입수 구분: ISBN과 정가가 있으면 매입(구입가 = 정가의 90%, 정수 나눗셈), 아니면 기증.
- 등록번호: ISBN 순서로 `EX00001`부터.
- 서가 위치: 분야에서 정한다(`유아 자료실`, `어린이 자료실`, `청소년 서가`, 그 밖은 `일반 자료실`).
- 어린이 구분: 연결된 책은 `apply_category`(외부 분류 근거), ISBN 없는 책은 `apply_file_row`(서가 위치 근거). 등록·가져오기와 같은 경로다.
- **청구기호와 분류기호(KDC)는 비워 둔다.** YES24는 KDC를 주지 않는다. 분야에서 KDC를 지어내면 "같은 KDC 세목" 신호가 외부 분류를 한 번 더 센 것이 되어 실험 결과를 속인다. 실제 KDC는 정보나루 연동(`add-bibliographic-sources`)에서 들어온다.
- 회원, 대출, 도서관 안내는 만들지 않는다. 대출 중 사본에 대출 행이 없는 것은 평가 표본 적재와 같다.

## Risks / Trade-offs

- **[YES24 이용 조건]** 카테고리 목록에서 약 500권을 받아 개발 DB에 두는 것은 지금까지 문서에 "하지 않는다"고 적어 둔 일이다. 이용 조건이 막는 것은 "전체 도서 정보의 축적과 재배포"이고 500권은 전체가 아니지만, 소장 도서가 아닌 책을 받는다는 점에서 평가 표본과 같은 예외다 → 한 번만 받는다(파일이 있으면 받기가 멈춘다). 파일과 개발 DB에만 두고 저장소·배포 환경에 넣지 않는다. 변동 값은 파일에도 넣지 않는다. 서지 출처를 바꾸는 `add-bibliographic-sources`에서 지운다. `docs/design.md`의 YES24 확인 항목에 더한다.
- **[카테고리 API가 문서와 다를 수 있다]** → 받기 전에 1~3회 호출로 확인하고(결정 11), 어긋나면 대안으로 바꾸고 design·스펙을 먼저 고친다. 최악의 경우 호출이 약 575회로 늘지만 한도 안이다.
- **[연결된 책의 텍스트에서 KDC 주류 이름이 빠진다]** → 결정 1. 외부 분류 원문이 남고, 저장된 벡터가 없어 지금 바뀌는 결과가 없다.
- **[공식 소개가 없는 책의 벡터가 빈약하다]** → 결정 5. 건수를 출력해 다음 change에서 판단한다.
- **[남는 벡터]** 나중에 연결된 책의 기관 도서 벡터, 옛 버전·종류의 벡터가 쌓인다 → 조회가 걸러 내 결과에 영향이 없다. 정리 명령은 실험이 끝난 뒤 정한다.
- **[시리즈 키는 다시 계산할 수 없다]** 응답의 목록을 DB에 따로 두지 않아, `match_key` 규칙을 바꾸면 실험 장서는 파일에서 다시 넣어야 하고 채움으로 만든 공식 서지는 옛 키로 남는다 → 규칙을 바꿀 때 `rebuild_contributors.py --check`가 "시리즈명이 있는데 키가 빈 공식 서지" 건수를 함께 보고하게 한다. 지금 채움으로 만든 공식 서지는 0건이다.
- **[실험 장서에 KDC가 없다]** "같은 KDC 세목" 신호를 `add-recommendation-experiments`에서 실제 값으로 볼 수 없다 → Open Questions 1.
- **[스테디셀러 치우침]** 분야마다 윗자리 책이라 유명한 책에 몰린다. 작은도서관의 기증 도서나 오래된 책은 없다 → 실험 결과를 읽을 때 적는다. 카카오·정보나루 일반화에서 다른 구성으로 다시 본다.
- **[개발 DB가 커진다]** 가상 기관과 약 1,000행, 벡터 약 500건(약 2MB) → 적용 전 백업한다. 시드 기관은 건드리지 않는다.
- **[1주 분량]** 벡터 두 층 2일, 받기와 적재 2일, 실행·역할 표·문서 1일로 본다. 나누지 않는다. 카테고리 API 확인에서 대안으로 넘어가면 반나절쯤 늘어난다.

## Migration Plan

1. 기준 수치: `uv run pytest` 통과 수, `uv run python -m evals.catalog_search` 결과를 남긴다.
2. 개발 DB 백업(`pg_dump`)을 만들고 경로를 알린다.
3. `uv run alembic upgrade head && uv run alembic downgrade -1 && uv run alembic upgrade head && uv run alembic check`
4. `uv run python scripts/rebuild_contributors.py --check`(차이 0. 시리즈 키 열이 생겨도 기존 값은 그대로다)
5. 외부 호출 승인 → 카테고리 API 확인(1~3회) → `uv run python -m evals.collection.fetch --dry-run` → 승인 → 받기.
6. 백업을 한 번 더 만든 뒤 `uv run python scripts/seed_experiment.py`, 다시 한 번 돌려 건수가 같은지 확인한다.
7. 역할 표를 넓혔으면 `uv run python scripts/rebuild_contributors.py && uv run python scripts/rebuild_contributors.py --check`
8. `docker compose --profile embedding up -d embedder` → `uv run python scripts/embed_books.py --full`(약 12분, 백그라운드) → `--incremental`이 0건인지 확인 → `scripts/embedding_search.py "질의" --library-id <가상 기관>` → 임베딩 서버를 내린다.
9. 되돌리기: `uv run alembic downgrade -1`(새 테이블, `kind` 열, `series_keys` 열 제거. `kind`가 `full`이 아닌 행이 있으면 유니크 키를 되돌릴 수 없어 먼저 지운다). 실험 장서는 2번 백업으로 되돌린다.

## Open Questions

1. **실험 장서의 KDC.** 비워 둔다(결정 16). `add-recommendation-experiments`에서 "같은 KDC 세목"을 외부 분류 원문으로 대신 볼지, 정보나루 연동 뒤로 미룰지는 그 change에서 정한다. 이번 구현은 어느 쪽이든 같다.
2. **공식 소개가 없고 기관 소개만 있는 책**(결정 5)을 보완할지. 적재가 출력하는 건수를 보고 `add-recommendation-experiments`에서 정한다.
3. **실험 장서를 지우는 방법.** 서지 출처를 바꿀 때(`add-bibliographic-sources`) 같은 ISBN을 새 출처로 다시 채울지, 가상 기관째 지우고 다시 만들지 그때 정한다.
