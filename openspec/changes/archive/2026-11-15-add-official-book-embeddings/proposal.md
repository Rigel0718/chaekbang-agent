## Why

추천 실험(`add-recommendation-experiments`)은 벡터 이웃, 같은 저자, 같은 시리즈를 한 장서 위에서 비교해야 하는데, 지금은 그 바탕이 둘 다 없다. 벡터는 기관 도서마다 따로 만들어 같은 책을 기관 수만큼 인코딩하고 텍스트에 기관 값이 섞이며, 개발 DB에는 Faker로 만든 책 270권뿐이라 실제 소개글과 분야가 있는 장서가 없다(평가 표본 87권은 테스트 트랜잭션 안에서만 산다).

`add-book-contributors`가 공식 서지에 기여자를 붙였으므로, 이번에는 같은 층에 벡터를 두고 실험 장서를 넣는다. 2026-11-12에 정한 "저장 구조와 정규화"의 뒤쪽 절반이고 범위는 줄이지 않았다.

## What Changes

- **벡터 두 층** (`add-book-embeddings` design 결정 1을 뒤집는다. design 결정 1에 "이전 결정 → 바뀐 사정 → 정한 것"으로 남긴다)
  - **공식 서지 벡터**(새 테이블 `official_book_embeddings`, 운영자 층, 기관 공통 테이블): 공식 서지마다 벡터를 하나 둔다. 텍스트는 공식 값만으로 만든다. 기관 값으로 채우지 않는다.
  - **기관 도서 벡터**(지금 테이블 `book_embeddings`): 대상을 공식 서지에 연결되지 않은 책(ISBN 없음, 못 찾음)으로 좁힌다. **BREAKING**(내부 동작): 연결된 책의 텍스트는 이제 기관 값으로 빈칸을 채우지 않는다. 저장된 벡터가 아직 없어 옮길 데이터는 없다.
  - **조회**: 한 기관의 추천 가능한 책을 공식 서지 id로 이어 두 층의 벡터를 한 순위로 비교한다. 기관 분리와 추천 가능 조건은 그대로다.
  - **벡터 종류 칸**(`kind`): 두 테이블 모두에 "어떤 텍스트의 벡터인지"를 두고 유니크 키에 넣는다. 이번에는 `full` 하나만 만든다. 필드별 벡터 비교는 다음 change가 마이그레이션 없이 더한다.
  - **임베딩 텍스트에서 저자를 뺀다**: 텍스트는 서명·분류·소개이고 텍스트 버전이 2가 된다. 저자는 고유명사라 기여자·저자 키와 서명·저자 찾기가 맡는다. "저자 넣기"는 `add-recommendation-experiments`의 비교 대상으로 남긴다.
  - **임베딩 텍스트 모듈 나눔**: 조립 규칙과 해시는 `app/core/`, 공식 서지 텍스트는 `app/central/`, 기관 도서 텍스트는 `app/library/`. 운영자 층은 기관 모델을 모른다.
  - 적재 CLI `scripts/embed_books.py`가 두 층을 차례로 적재하고 층별 건수를 출력한다(`--layer`).
- **적재 배치 기본값**: 32 → 4. ONNX에서 배치가 클수록 느리고(87권 152초 → 129초), 1과 4는 흔들림 안에서 같다.
- **실험 장서**: YES24 약 500권
  - 카테고리 스테디셀러를 분야별 권수대로 한 번 받아 원본을 파일로 남긴다(저장소에 넣지 않는다). 받은 날짜, 카테고리, 분야별 권수를 함께 적는다. 어린이·유아 비중을 약 40%로 두고, 평가 표본에 없거나 적은 분야를 넣는다.
  - 파일을 개발 DB에 넣는 운영자 스크립트: 공식 서지(기여자, 시리즈 키 포함)를 만들고, 가상 기관 하나가 기관 도서·사본으로 소장한다. 약 10%는 ISBN 없는 기관 도서로 넣어 기관 도서 벡터와 저자 키 경로가 쓰이게 한다. 다시 돌려도 같은 결과다. Faker 기관과 평가 표본 87권은 그대로 둔다.
  - 적재 뒤 텍스트 버전 2(`full`, 저자 없음)의 임베딩을 한 번 만든다(약 12분).
- **시리즈 키** `books.series_keys`(이름 맞춤 키 배열): 응답의 시리즈 목록을 이어 붙이기 전에 저장한다(`add-book-contributors` Open Questions 2).
- **역할 표 넓히기**: 500권의 저자 표기에서 처음 보는 역할 표기를 `app/core/contributors.py`에 더하고 `rebuild_contributors.py`로 맞춘다.
- **YES24 예외 문구**: CLAUDE.md, `evals/librarian/`의 주석, `app/central/README.md`, `docs/design.md`의 "평가 표본만 예외", "카테고리를 돌며 쌓지 않는다"를 "평가 표본과 실험 장서만 예외(한 번 받고, 개발 DB에만, 저장소에 넣지 않고, 서지 출처를 바꿀 때 지운다)"로 고친다.

범위 밖: 추천 실험 틀, 평가 세트, 요청 세 종류의 전략 비교, 임베딩 텍스트 버전·필드별 비교(`add-recommendation-experiments`). 카카오·정보나루 연동(`add-bibliographic-sources`). 비슷한 책의 REST·tool·화면(`add-related-books`). 벡터 인덱스, 서버 실행 중 자동 적재, 쓰지 않는 벡터 정리.

## Capabilities

### New Capabilities

- `platform/experiment-collection`: 실험 장서. 외부 서지를 분야 구성대로 한 번 받아 기록과 함께 파일로 남기고, 개발 DB에 공식 서지와 가상 기관의 장서로 반복 실행해도 같게 넣는다.

### Modified Capabilities

- `catalog/book-embeddings`: 임베딩 텍스트(공식 값만 / 기관 값만), 벡터 저장 키(종류 추가), 적재 대상(두 층), 배치 기본값, CLI 출력(층별), 유사도 조회(두 층을 한 순위로). 공식 서지 벡터에 기관 값이 섞이지 않는다는 요구사항을 더한다.
- `platform/database-schema`: 테이블 22개(`official_book_embeddings` 추가, 기관 공통), 두 임베딩 테이블의 종류 칸과 유니크 키, `books.series_keys`.
- `catalog/books`: 공식 서지를 만드는 경로에 실험 장서 적재를 더하고, 시리즈 키 요구사항을 더한다.

## Impact

- **DB**: 마이그레이션 하나(새 테이블, `book_embeddings.kind`와 유니크 키 교체, `books.series_keys`). 개발 DB에 공식 서지 약 450건, 기여자, 가상 기관 1개와 기관 도서 약 500건, 벡터 약 450건이 생긴다. 적용 전 백업한다.
- **코드**: `app/core/`(임베딩 텍스트 조립, KDC 주류 이름 이동), `app/central/`(공식 서지 벡터 모델·텍스트·적재, 공식 서지 만들기 함수, YES24 카테고리 API와 시리즈 목록), `app/library/recommendation/`(기관 도서 텍스트·적재 대상·두 층 조회), `app/seed/`(실험 장서 넣기), `scripts/`(`embed_books.py`, `embedding_search.py`, 새 스크립트 둘), `app/core/config.py`와 `.env.example`(배치 기본값).
- **외부 호출**(실행 전 호출 수를 알리고 승인받는다): YES24 응답 확인 1~3회, 받기 약 25회(응답에 소개가 없으면 상세 조회 최대 약 550회 추가). 하루 한도 2만 회 안이다. 새 의존성과 이미지는 없다.
- **기존 테스트·평가**: 임베딩 테스트(`tests/library/test_book_embeddings.py`, `test_embedding_text.py`, `test_embedding_scripts.py`, `tests/embedding_live/`)가 두 층 기준으로 바뀐다. AI 사서 평가와 서명·저자 찾기 평가는 임베딩을 쓰지 않아 수치가 그대로여야 한다.
- **YES24 이용 조건**: 카테고리 목록에서 약 500권을 받는 것은 지금까지 스스로 막아 둔 일이다. 개발용으로 한 번만 받고 재배포하지 않으며 서비스 전에 출처를 바꾼다는 전제로 진행한다(design Risks).
