# Proposal

## Why

자체 대출 기관의 관리자는 사본 상태 바꾸기(분실·훼손·제적), 새 책 등록, 회원 등록·번호 고치기, 임시 휴관일 넣기를 지금 Swagger로만 할 수 있다. 담당자는 Swagger를 쓰지 못하므로 MVP 출시와 데모 전에 관리자 화면에 이 길이 있어야 한다. 장서 가져오기 탭은 외부 대출 기관에만 있어서, 자체 대출 기관은 화면에서 책을 늘릴 방법이 없다.

또 회원 탭을 만들면 회원 이름이 찾기 주소(`GET /members?q=`)에 실리는데, 지금 서버 접속 기록은 주소를 질의 문자열까지 남긴다. 이용자 검색어(`/catalog/search?q=`)도 같다. 회원 값과 질의를 기록에 남기지 않는다는 원칙에 맞추려면 이 change에서 함께 막아야 한다.

## What Changes

- **사본 찾기 인자(새로 만든다)**: `GET /holdings?q=`. 등록번호와 같은 사본, 또는 서명·저자(표시 값: 공식 값 먼저, 기관 값)에 그 글자가 든 사본을 찾는다. `q`가 있으면 `status`를 주지 않아도 제적 사본까지 모든 상태를 돌려준다. 오타 허용은 없다. 기관 범위는 코드가 강제한다.
- **접속 기록 필터(새로 만든다)**: 서버 접속 기록(`uvicorn.access`)에서 요청 주소의 `?` 뒤를 지운다.
- **관리자 화면 [장서] 탭(새로 만든다, 자체 대출 기관만)**: 서명·저자·등록번호로 사본을 찾아 표로 보인다. 상태를 이용 가능·분실·훼손·제적 중에서 고르고(제적만 한 번 더 묻기), 대출 중인 줄에는 [반납]을 둔다. [책 등록]은 ISBN으로 이미 있는 책인지 확인한 뒤 기관 도서와 사본을 기존 REST로 차례로 등록하고, 이미 있으면 사본만 더한다.
- **관리자 화면 [회원] 탭(새로 만든다, 두 방식 모두)**: 이름·회원번호로 찾기, 등록, 이름·번호 고치기, 삭제(한 번 더 묻기).
- **관리자 화면 [휴관일] 탭(새로 만든다, 두 방식 모두)**: 임시 휴관일 더하기와 지우기.
- **피드백 반영(2026-11-26 확인 뒤)**: [장서]는 들어오면 최근에 등록한 사본부터 보이고 찾은 뒤 [전체 보기]로 돌아간다(`GET /holdings`의 기본 순서를 최근 등록순으로). 회원의 휴대폰 번호를 새 등록·고치기에서 필수로 한다(서버도, 번호 없는 기존 회원은 그대로). 화면의 휴대폰 번호는 하이픈을 넣어 보이고, 치는 칸(관리자 회원, 이용자 회원 로그인)은 치는 대로 하이픈을 넣는다. 화면 문구 전체 다듬기는 따로 change로 한다.
- 관리자 화면의 탭은 다섯에서 여덟로 늘고, 회원 값을 보이는 탭에 [회원]이 더해진다.
- 스키마 변경 없음, LLM·외부 API 호출 없음. 기존 REST에서 바뀌는 것은 `GET /holdings`의 `q` 인자와 기본 순서(등록번호 순 → 최근 등록순), 회원 등록·고치기의 번호 필수뿐이다. **BREAKING**: 번호 없이 `POST /members`를 부르거나 `PATCH /members/{id}`로 번호를 지우던 클라이언트는 422를 받는다.

**하지 않는 것**(roadmap 미룬 일): ISBN으로 서명·저자 자동 채우기, 등록번호·회원번호 자동 매기기, 확정된 구매 요청서에서 바로 등록, 책 정보 고치기, 분실로 반납 한 번에 하기, 빈 찾기의 분실·훼손 목록, 운영 시간·자유 항목 화면 고치기, 직원 계정 화면, 어린이 구분 손으로 고치기, Playwright, 운영 에이전트 프롬프트 수정.

## Capabilities

### New Capabilities
- `platform/request-logging`: 서버 접속 기록에 남기는 값. 요청 주소의 질의 문자열(회원 이름, 검색어)을 기록하지 않는다.

### Modified Capabilities
- `catalog/holdings`: 사본 조회에 찾기 인자 `q`(등록번호 같음, 서명·저자 포함, 상태 무관)를 더하고, `q`가 없을 때의 순서를 최근 등록순으로 정한다.
- `circulation/members`: 새 회원과 번호 고치기에서 전화번호를 필수로 한다(번호 없는 기존 회원은 남긴다).
- `platform/web-ui`: 관리자 화면의 탭(여덟, 운영 방식별 표시), 기존 API 목록, 회원 값을 보이는 탭을 고치고 [장서]·[책 등록]·[회원]·[휴관일] 화면과 휴대폰 번호 하이픈 요구사항을 더한다.

## Impact

- 서버: `app/library/api/holdings.py`, `app/library/services/holdings.py`(찾기 조건), `app/main.py` 또는 `app/core/`의 기록 필터.
- 화면: `app/web/public/admin/`의 `index.html`, `main.js`, `admin.css`, 새 스크립트(장서·회원·휴관일).
- 테스트: `tests/catalog/test_holdings_api.py`, `tests/platform/test_web_ui.py`, 기록 필터 테스트(새로 만든다).
- 문서: `app/web/README.md`, `docs/roadmap.md`.
- 개발 DB 스키마와 데이터는 바꾸지 않는다.
