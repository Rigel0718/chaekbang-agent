# Design

## Context

- 관리자 화면(`app/web/public/admin/`)은 빌드 없는 정적 파일이다. 탭 다섯, 탭마다 스크립트 하나(`chat.js`, `approvals.js`, `requests.js`, `overdue.js`, `imports.js`)이고 `main.js`가 탭과 운영 방식을 정한다. 화면 규칙은 주로 소스 검사 테스트(`tests/platform/test_web_ui.py`)와 사용자 브라우저 확인(B1…)으로 지킨다.
- 이 change가 쓰는 REST는 모두 있다: `/holdings`, `/library-books`, `/members`, `/library/closures`, `/loans/return`(직원 토큰만으로 부를 수 있고 회원 세션이 필요 없다). 서버는 상태 규칙(`on_loan` 409), 입수 구분 규칙(422), 등록번호·ISBN·회원번호·전화번호 중복(409), 기관 분리(404)를 이미 지킨다.
- `GET /holdings`는 기관 도서 id와 상태로만 거른다. `GET /catalog/search`는 추천 가능한(이용 가능·대출 중) 사본이 있는 책만 찾아서, 분실·제적만 남은 책은 찾지 못한다.
- 앱에는 접속 기록 설정이 없다. `uv run uvicorn app.main:app`의 기본 접속 기록(`uvicorn.access`)은 요청 주소를 질의 문자열까지 남긴다.

## Goals / Non-Goals

**Goals:**
- 자체 대출 기관의 관리자가 Swagger 없이 장서와 회원을 다루고 휴관일을 넣는다.
- 서버 변경은 찾기 인자 하나와 기록 필터 하나로 끝낸다. 스키마와 기존 응답은 바꾸지 않는다.

**Non-Goals:**
- 외부 대출 기관의 사본 고치기: 다음 파일 가져오기가 상태를 덮으므로 [장서] 탭을 두지 않는다(서버 API는 그대로 열려 있다).
- 책 정보(서명·저자·KDC) 고치기, 운영 시간·자유 항목 고치기, 직원 계정: 미룬 일.
- 브라우저 자동화 테스트.

## Decisions

### 1. 사본 찾기는 `GET /holdings?q=` 하나로 한다
- 조건: `Holding.accession_number == q` 또는 기관 도서의 서명·저자(기관 값 `library_books.title`·`author`, 연결된 공식 서지 `books.title`·`author`)에 `q`가 든 것. 대소문자 무시 부분 일치(`ilike`, `autoescape=True`라 `%`·`_`는 글자 그대로). 공식 서지는 바깥 조인이다.
- 표시 값(`shown`)은 "공식 값이 먼저, 비면 기관 값"이지만, 찾기는 두 값 중 하나라도 맞으면 된다. 관리자가 책 등에 붙은 기관 값으로 쳐도, 화면에 보이는 공식 값으로 쳐도 찾게 하기 위해서다.
- `q`가 있고 `status`가 없으면 제적 사본을 빼지 않는다. 찾는 목적이 분실·제적 사본을 되돌리는 것이기도 해서다. `q`가 없을 때의 동작(제적 제외)은 그대로다.
- 정렬: `q`가 있으면 등록번호 일치 먼저, 그다음 표시 서명(`coalesce(books.title, library_books.title)`)의 `korean_order`, 등록번호, id 순이다. `q`가 없으면 지금처럼 등록번호 순이다.
- `q`는 `strip` 뒤 1~100자(`/catalog`의 상한과 같다). 라우터는 인자만 넘기고 조건은 `services/holdings.py`의 `list_holdings`에 둔다.
- 다른 안: `GET /library-books`에 서명 찾기를 더해 "책 → 사본" 두 단계로 보이기. 화면이 두 단계가 되고 등록번호 찾기는 따로 필요해서 고르지 않았다. `/catalog/search`에 관리자용 인자를 더하는 안은 추천 경로의 조건을 흔들어서 고르지 않았다.

### 2. 책 등록은 화면이 두 REST를 차례로 부른다
- 흐름: ISBN이 있으면 `GET /library-books?isbn=`(제적만 남은 책도 찾도록 `held` 없이) → 있으면 그 id, 없으면 `POST /library-books` → `POST /holdings`.
- 화면은 등록 칸의 상태로 "확인한 기관 도서 id"를 들고 있는다. 기관 도서를 만든 뒤 사본 등록이 실패하면 그 id를 그대로 두어, 다시 [등록]을 누르면 사본만 보낸다. 칸을 닫으면 지운다.
- `POST /library-books`가 409(같은 ISBN이 그사이 생김)면 ISBN으로 다시 확인해 그 id로 이어 간다.
- 다른 안: 기관 도서와 사본을 한 트랜잭션으로 만드는 새 API. 원자적이지만 화면 전용에 가까운 API가 생기고, 중간 실패가 남기는 것은 사본 없는 기관 도서 하나(추천·검색에 안 나옴)라서 고르지 않았다.
- 새 기관 도서는 공식 서지가 있으면 연결되고(`link_official`, 어린이 구분 훅도 기존대로), 없으면 채움 대기다. 소개·표지·벡터는 운영자 스크립트가 채운다.

### 3. 접속 기록 필터는 `uvicorn.access` 로거에 붙인다
- `logging.Filter` 하나(새로 만든다)가 기록의 인자에서 요청 주소를 `?` 앞까지로 바꾼다. uvicorn 접속 기록의 인자는 `(client_addr, method, full_path, http_version, status_code)`이고, 필터는 인자 모양이 다르면 손대지 않고 통과시킨다.
- 붙이는 곳은 앱 모듈을 불러올 때(`app/main.py`)이고, 같은 필터가 이미 있으면 다시 붙이지 않는다. uvicorn은 앱을 불러오기 전에 기록 설정을 마치므로 불러올 때 붙인 필터가 남는다. 필터 코드는 `app/core/`에 둔다(어느 층도 모르는 공통 도구).
- 다른 안: 실행 명령에 `--no-access-log`. 접속 기록 자체(경로·응답 코드)는 운영에 필요하고, 실행 명령을 잊으면 새는 방식이라 고르지 않았다. 배포 change의 실행 명령도 이 필터에 기댄다.

### 4. 화면은 탭마다 스크립트 하나를 새로 만든다
- `collection.js`(찾기·상태·반납·책 등록), `members.js`, `closures.js`를 새로 만들고 기존 탭처럼 `main.js`가 `create…`로 조립한다. 요청은 `shared/api.js`의 요청 함수를 쓴다.
- hash는 `#collection`, `#members`, `#closures`다. [장서]와 [장서 가져오기]는 운영 방식이 달라 한 화면에 같이 보이지 않는다.
- 상태 이름은 분석 표와 같은 한국어(이용 가능·대출 중·분실·훼손·제적)를 쓴다. 테스트가 서버 `HoldingStatus` 값과 화면 표의 키를 맞춘다.
- 확인 문구(`confirm`)는 제적, 반납, 회원 삭제, 휴관일 삭제에만 둔다. 성공 문구는 두지 않는다.
- 휴관일 날짜는 화면이 기관 시간대가 아닌 브라우저 날짜로 오늘을 정한다. 키오스크·관리자 PC가 기관에 있으므로 같다고 본다.

### 5. 회원 탭은 회원 값을 보이는 탭에 더한다
- 회원 값 소스 검사(`member_number`, `phone`을 읽는 곳 허용 목록)에 `members.js`를 더한다. 회원 목록은 화면 메모리에만 두고, 탭에 들어올 때 다시 읽는다.
- 찾기 글자는 주소(`?q=`)에 실리지만 결정 3의 필터로 접속 기록에 남지 않는다. 전화번호는 서버가 찾기에 쓰지 않는다(기존 규칙).

## Risks / Trade-offs

- [두 번 부르는 등록의 중간 실패로 사본 없는 기관 도서가 남음] → 추천·검색에는 나오지 않고, 같은 ISBN으로 다시 등록하면 그 책에 사본이 붙는다. ISBN 없는 기증 도서는 다시 누르면 화면이 가진 id로 이어 가지만, 칸을 닫고 새로 등록하면 같은 서명의 기관 도서가 하나 더 생긴다(받아들임, 책 정보 고치기·지우기 화면과 함께 미룸).
- [`ilike` 부분 일치가 장서가 커지면 느려짐] → 작은도서관 규모(수천 권)에서는 문제없다고 본다. 테스트 DB 장서로 응답 시간을 잴 일은 만들지 않고, 느려지면 trigram 인덱스를 따로 연다.
- [uvicorn이 아닌 다른 실행기·로거가 주소를 남김] → 이 change는 `uvicorn.access`만 다룬다. 앱 자체 로거는 주소를 남기지 않는다. 배포 change에서 실행 방식을 정할 때 다시 본다.
- [외부 대출 기관도 `PATCH /holdings`로 상태를 바꿀 수 있음] → 화면만 숨기고 서버는 막지 않는다(지금과 같음).
- [휴관일의 브라우저 날짜] → PC 시계가 틀리면 목록 시작일이 하루 어긋날 수 있다. 등록·판정은 서버가 하므로 보기만 어긋난다.

## Migration Plan

스키마 변경이 없다. 배포는 코드 교체뿐이고 되돌리기도 코드만 되돌린다. 개발 DB는 바꾸지 않는다.

## 확인 결과와 미룬 일

- 테스트: `uv run pytest` 2224 통과(7 건너뜀), `ruff` 통과. 사본 찾기 11개, 접속 기록 4개, 화면 소스 검사 11개를 더했다. 기존 검사 하나(`test_admin_approval_actions_guarded`)는 `api.js`의 `PATCH` 수를 세던 것을 "`PATCH`는 희망도서 닫기·사본 상태·회원 고치기뿐"으로 바꿨다(승인 목록에 고치기가 없다는 뜻은 같다).
- 접속 기록: uvicorn을 실제로 띄워 `/members?q=김하늘`을 보내 기록에 `"GET /members HTTP/1.1" 401`만 남는 것을 봤다(퍼센트 인코딩한 질의도 지워진다).
- 브라우저 확인 B1~B16(2026-11-26, 사용자, 확인용 DB `chaekbang_check`: 개발 DB를 복사, alembic `949a92d2205d`): **모두 통과**. 확인 값과 단계는 `check-samples/add-admin-collection-ui.md`(git 제외)에 있다. 개발 DB 상태(읽기 전용 확인): 햇살 기관 도서 35·사본 54(이용 가능 41·훼손 5·분실 1·대출 중 7)·회원 10, 푸른숲 기관 도서 235·사본 254·회원 10.
- 구현 중 스펙을 고친 곳: web-ui "휴관일 화면 / 휴관일 더하기" 시나리오. 시드 기관은 도서관 안내를 등록하지 않아 이용자 화면 위 띠에 휴관이 나오지 않으므로, 오늘 날짜를 더하고 `GET /library/guide`의 `today`로 확인하는 것으로 바꿨다(B15).
- 미룬 일(proposal "하지 않는 것"과 같다): ISBN으로 서명·저자 자동 채우기, 등록번호·회원번호 자동 매기기, 확정된 구매 요청서에서 바로 등록, 책 정보 고치기, 분실로 반납 한 번에 하기, 빈 찾기의 분실·훼손 목록, 운영 시간·자유 항목 화면 고치기(배포 change의 기관 만들기 스크립트로), 직원 계정 화면, 어린이 구분 손으로 고치기, Playwright. 받아들인 위험: ISBN 없는 기증 도서는 칸을 닫고 새로 등록하면 같은 서명의 기관 도서가 하나 더 생긴다.

### 확인 뒤 피드백(2026-11-26)

B1~B16 통과 뒤 사용자 피드백으로 더한 것이다(tasks 4).

- [장서]는 들어오면 최근에 등록한 사본부터 보이고, 찾는 동안에만 [전체 보기]가 있다. `q` 없는 `GET /holdings`의 순서를 등록번호 순에서 최근 등록순으로 바꿨다(같은 시각에 들어온 가져오기 사본은 id 내림차순). 탭에 다녀오면 지난 찾기가 남는다(처음 목록으로 바꾸는 안을 냈으나 지금 동작 유지).
- 회원의 휴대폰 번호는 새 등록과 고치기에서 필수다(`RequiredPhone`, `MemberUpdate`의 `phone` null 422). DB 칸은 그대로라 번호 없는 기존 회원이 남고 마이그레이션은 없다. 번호가 기관 안에서 유일하므로 가족은 번호의 회원 한 명이 빌린다.
- 하이픈 규칙은 `shared/phone.js` 한 곳이다. 서버는 원래 하이픈을 지워 저장해 바뀌지 않았다. 치는 중에는 `010`을 3-4-4로 보이므로 10자리 `010` 번호는 입력칸에서 `010-1234-567`처럼 보인다(목록은 `010-123-4567`).
- 확인 R1~R9(2026-11-26, 사용자, 확인용 DB `chaekbang_check`): **모두 통과**.
- 테스트: `uv run pytest` 2231 통과(7 건너뜀), `ruff` 통과. 하이픈 "보이는 꼴" 테스트는 node가 없으면 건너뛴다.
