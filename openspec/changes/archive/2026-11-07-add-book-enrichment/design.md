# Design

## Context

**지금 코드에 있는 것**
- `books`는 공식 서지이고 기관 API로 쓸 수 없다. 지금은 시드 외에 쓰는 코드가 없다.
- `library_books`가 기관 값과 어린이 구분을 가지고, `link_official`이 등록·ISBN 수정에서 공식 서지를 연결한다. 가져오기는 `_new_book`에서 스냅숏의 공식 서지를 직접 연결한다.
- 표시 값은 `LibraryBook.shown`이 공식 값을 먼저 쓴다. 연결된 도서는 ISBN과 대상 구분만 고칠 수 있다.
- `holding_imports._fill_book`은 근거가 `default`일 때만 파일 근거를 적용한다.
- `httpx`는 이미 의존성에 있다. `app/external/`은 없고, `.env.example`에 `YES24_API_KEY`가 있지만 `Settings`에는 없다.
- `scripts/seed.py`는 얇은 진입점이고, 전제 조건 확인과 안내 메시지는 `app/seed/runner.py`에 있다.

**외부 API에서 확인한 것** (`yes24-open-api-guide/`, 2026-11-07 실제 호출)
- 한도는 키 기준 하루 20,000회, 초당 10회다. 초과하면 HTTP 429이고, 일일 한도는 자정에 초기화된다.
- 상품 응답에 `categoryId`는 없다. 분류 값은 `goodsSortNm`이다.
- 문서와 다른 실제 값: `publishDate`는 `19960401`, `goodsType`은 `도서`, `goodsSortNm`은 `국내도서-유아`, 빈 값은 `""`로 온다.
- `cover`는 표지가 없는 상품에도 대체 이미지 URL을 돌려준다.

**표본** (카테고리별 베스트셀러 상위 100건씩, 6개 카테고리 600건)

인기 도서에 치우친 표본이다. 값의 형태를 본 것이지 분류 정확도가 아니다.

| 조회한 카테고리 | 규칙으로 `children`이 되는 건수 |
| --- | --- |
| 유아 | 100 |
| 어린이 | 98 (나머지 2건은 `국내도서-청소년`) |
| 초등참고서 | 93 (나머지 7건은 `국내도서-중고등학습서-중학교`) |
| 청소년 | 1 |
| 소설/시/희곡, 전집 | 각 0 |

전집 100건 중 99건은 ISBN이 없고 98건은 소개가 없었다. `초등참고서` 카테고리의 값은 `국내도서-초등학습서`였고 `국내도서-중고등학습서-중학교`처럼 3단인 값도 있어서, `goodsSortNm`은 카테고리 이름과 항상 같지 않다.

**YES24 FAQ의 이용 조건**
- 서비스 제공에 필요한 범위의 캐싱은 허용한다.
- 전체 도서 정보를 수집해 자체 DB로 축적하거나 제3자에게 재배포하는 것은 허용하지 않는다.
- 가격·재고 같은 변동 정보는 갱신 주기를 짧게 유지해야 한다.

## Goals / Non-Goals

**Goals:**
- 새 엔드포인트나 필드를 정의 파일에 추가하는 것으로 끝나게 한다.
- 파싱과 분류 판단을 DB 없는 순수 함수로 두어 표 형태로 테스트한다.
- 실행 로직은 service에 두어 스크립트가 얇고, 나중에 스케줄러가 같은 함수를 부르게 한다.
- 테스트는 실제 네트워크를 쓰지 않는다.

**Non-Goals:**
- 기관 관리자가 실행하는 API, 스케줄러, 백그라운드 작업 큐.
- 기관별로 어린이 구분을 끄는 설정. 어린이 구분은 기관 층에 있어서 군부대·대학 같은 기관 유형을 추가할 때 기관 설정으로 넣을 수 있다. 지금은 쓰지 않는 기관이 있어도 값이 `general`로 남을 뿐이다.
- 호출 재시도. 다음 실행이 이어서 처리하므로 한 실행 안에서는 다시 시도하지 않는다.
- 이미 만든 공식 서지의 갱신.
- 저자 구조화와 저자 검색. `books.author`에 원문을 두고, 표본으로 표기를 확인한 뒤 다음 change에서 검토한다.

## Decisions

### 1. 실행 주체는 운영자 스크립트

`books`는 운영자 층이고 기관 API로 쓰지 않는다는 규칙을 지키기 위해, 채움은 `scripts/enrich_books.py`로 실행한다.
- 키 하나의 호출 한도를 한곳에서 조절하고, 여러 기관이 가진 ISBN을 한 번만 조회한다.
- 프로세스가 하나라서 호출 속도 조율이 단순하고, HTTP 요청 시간에 묶이지 않는다.
- 기관에는 읽기 전용 `GET /book-enrichment`만 연다.
- **대안: 기관 관리자 API** → 담당자가 바로 채울 수 있지만 쓰기 제한에 예외가 생기고, 같은 ISBN을 기관마다 조회하며, 한 기관이 일일 한도를 다 쓸 수 있다.
- 파일을 올린 뒤 운영자가 돌리기 전까지 소개가 비어 있다. 나중에 스케줄러가 같은 service를 부르게 해서 줄인다.

### 2. 모듈 구성

```
app/external/yes24/
├── definitions.py  # Base URL, 엔드포인트, 응답 필드 이름, 오류 구분
├── client.py       # 인증 헤더, 호출 속도 제한, 응답 봉투 해석, 오류 → 예외
├── parsing.py      # 응답 상품 → Yes24Item (빈 문자열, 날짜, 정가, 줄바꿈)
└── goods.py        # GOODS API 역할 함수: get_item_by_isbn
app/services/book_enrichment.py  # 운영자 층: 실행, 현황
app/services/audience.py         # 기관 층: 분류 원문이 어린이 근거인지 판단
app/api/book_enrichment.py       # GET /book-enrichment
scripts/enrich_books.py          # 인자 해석, 전제 조건 확인, 결과 출력
```

`app/external/yes24/`와 `book_enrichment.py`에는 어린이 개념을 두지 않는다. `category.py`는 Category API를 쓰는 change에서 추가한다. 쓰지 않는 코드를 미리 만들지 않는다. 역할 함수에는 하는 일을 한국어로 적는다.

### 3. 정의 파일 한곳에 모으기

`definitions.py`에 엔드포인트(이름, 경로)와 `Yes24Item` 필드별 응답 키를 표로 둔다. `parsing.py`는 이 표를 읽어 값을 꺼내고, 응답 키 문자열을 다른 파일에 쓰지 않는다. 새 필드는 표에 한 줄 추가하고 필요하면 변환 함수를 지정한다.
- **대안: 응답 전체를 Pydantic 모델로 정의** → 문서와 실제 값이 달라서 한 필드만 어긋나도 응답 전체가 실패한다. 필드별로 관대하게 읽어야 "그 필드만 비우고 계속"을 지킬 수 있다.

### 4. `itemDetail` 하나, `detail=Y`

한 번의 호출로 서지정보, 분류, 시리즈를 모두 받는다. `searchType=ISBN13`은 생략해도 되지만 항상 명시한다.
- **대안: `itemList`로 ISBN 검색** → 결과가 없으면 검색어가 자동 교정돼서 다른 책이 나올 수 있다.

### 5. 운영자 층과 기관 층 분리

| 층 | 하는 일 | 어린이 구분 |
| --- | --- | --- |
| 운영자 (`books`, `app/external/yes24/`, `book_enrichment.py`) | YES24 값을 공식 서지로 보관하고 기관 도서를 연결. 분류 원문은 사실로만 둔다 | 모르고 바꾸지 않음 |
| 기관 (`library_books`, `audience.py`, `importing/classify.py`) | 기관의 요청에서 공식 서지와 파일을 보고 그 기관의 어린이 구분을 정함 | 판단하고 저장 |

어린이 구분은 MVP 대상인 작은도서관에 필요한 기관의 기능이다. 군부대, 대학, 어르신 도서관처럼 필요 없는 기관도 있으므로 공식 서지나 외부 연동의 일부가 되면 안 된다. 코드 위치뿐 아니라 실행도 나눈다. 운영자 실행은 공식 서지 참조와 처리 상태만 쓰고 어린이 구분에는 닿지 않는다. 어린이 구분이 바뀌는 곳은 등록, 가져오기, ISBN 수정, 기관 관리자의 갱신뿐이다.

**어린이 도서의 정의**: 영유아·초등학생 대상 도서. 부가기호표의 6·7, YES24의 유아·어린이·초등학습서가 이 경계와 맞는다. 청소년은 제외한다.

**분류 원문 규칙**: `app/services/audience.py`의 `CHILDREN_CATEGORIES = {"국내도서-유아", "국내도서-어린이", "국내도서-초등학습서"}`와 완전히 일치할 때만 근거로 본다.
- `-`로 나누거나 "어린이"가 포함됐는지 보지 않는다. 표본에서 값이 카테고리 이름과 다르고 단계 수도 달랐기 때문이다.
- 초등학습서는 근거다. 값이 대상을 직접 말하고, `general`로 두면 소장 중인 초등 문제집을 어린이 요청에서 찾지 못한다. 같은 카테고리에 섞인 `국내도서-중고등학습서-중학교`는 값이 달라서 자동으로 빠진다.
- `audience`는 어린이 도서인지만 나눈다. 학습서를 추천 후보로 쓸지는 추천의 문제이므로 분류 원문으로 따로 다룬다.
- 전집, 청소년은 근거가 아니다. 전집은 `초등 저학년` 같은 하위 분류가 있어도 값이 하나로 묶여 어른 전집과 구분되지 않는다. 애매하면 `general`로 두는 원칙을 따른다.
- 외국도서 분류는 실제 값을 보지 못해서 넣지 않는다.
- 분류 원문을 보관해서, 규칙을 바꿔도 외부 호출 없이 다시 판단할 수 있다.
- **대안: `category.json`으로 카테고리 ID 판단** → 상품 응답에 카테고리 ID가 없어서 연결할 수 없다.

**파일 근거 정리** (`app/importing/classify.py`)
- 부가기호 첫 자리 6을 넣는다. 국립중앙도서관 부가기호표에서 6은 초등학생용 학습참고서이고, 7은 초등학습참고서가 아닌 영유아·초등학생 도서다. 빼면 같은 초등 문제집이 근거마다 다르게 분류된다. 4(청소년)와 5(중·고교용)는 근거가 아니다.
- 별치기호 `어`, `c`를 뺀다. 어린이 표시라는 출처를 찾지 못했고, 틀리면 어른 책이 어린이 도서가 된다. 실제 파일에서 쓰임이 확인되면 다시 넣는다.

### 6. 어린이 구분은 기관 도서에 저장

공식 서지에는 분류 원문(`external_category`)만 두고, 기관의 요청에서 코드가 판단해 기관 도서의 `audience`에 저장한다. 판단 결과를 공식 서지에 따로 저장하지 않아서, 같은 정보를 두 곳에 두지 않고 규칙을 바꿔도 공식 서지를 다시 계산할 필요가 없다.
- 어린이 필터와 자연어 SQL이 `library_books.audience` 하나만 보면 된다.
- **대안: 조회할 때마다 기관 값과 공식 값을 비교** → 저장은 한 번 줄지만 어린이 필터를 쓰는 모든 쿼리가 복잡해지고, 필터 하나만 빠져도 어린이 요청에 일반 도서가 나갈 수 있다.
- 파일 근거는 `external_category`를 덮어쓰고, 관리자 지정은 어떤 근거도 바꾸지 못한다.

### 7. 연결 처리를 한곳에

`app/services/library_books.py`에 함수를 둘로 나눈다.
- `connect_official(library_book, book)`: 공식 서지 참조와 처리 상태만 쓴다. 운영자 실행은 이 함수만 부른다.
- `apply_audience(library_book)`: 연결된 공식 서지의 분류 원문으로 어린이 근거를 맞춘다.
- `apply_official(library_book, book)`: 두 함수를 잇는다. 등록, ISBN 수정, 가져오기의 `_new_book`처럼 기관의 요청에서 쓴다.
- `refresh_audience(session, library_id)`: 기관 관리자의 갱신. 근거가 `default`나 `external_category`인 자기 기관 도서에 `apply_audience`를 쓴다.

아래 표는 `apply_official`의 동작이다.

새로 만든 `LibraryBook`은 저장 전까지 `audience_source`가 `None`이다. 기본값이 DB에 있기 때문이다. `apply_audience`는 `None`을 `default`로 다뤄야 한다. 그렇지 않으면 등록과 가져오기에서 외부 근거가 조용히 빠진다.

| 상황 | book_id | 처리 상태 | 어린이 구분 |
| --- | --- | --- | --- |
| 공식 서지 있음, 분류가 어린이 근거, 근거 `default` | 연결 | `enriched` | `children`, `external_category` |
| 공식 서지 있음, 분류가 근거 아님, 근거 `external_category` | 연결 | `enriched` | `general`, `default` |
| 공식 서지 있음, 근거 `manual`·`import_label` | 연결 | `enriched` | 그대로 |
| 공식 서지 없음 | 비움 | `pending` | 근거가 `external_category`면 `general`, `default` |

가져오기는 `_new_book`이 연결한 뒤 `_fill_book`이 파일 근거를 적용하므로, 파일 근거가 외부 근거 위에 놓인다.

### 8. 데이터 모델

`books`에 추가하는 열:

| 열 | 타입 | 내용 |
| --- | --- | --- |
| subtitle | String(500)? | 부제 |
| table_of_contents | Text? | 목차 |
| series_name | String(500)? | 시리즈명, 여러 개면 쉼표로 연결 |
| external_source | enum? | 출처 (`yes24`) |
| external_url | String(1000)? | 상품 링크 |
| external_category | String(100)? | 분류 원문 (`goodsSortNm`). 어린이 판단은 저장하지 않는다 |

`library_books`에 추가하는 열:

| 열 | 타입 | 내용 |
| --- | --- | --- |
| enrichment_status | enum, 기본 `pending` | `pending`, `enriched`, `not_found`, `mismatch` |
| enrichment_checked_at | DateTime(tz)? | 마지막 처리 시각 |

- 처리 상태를 `library_books`에 두는 이유는 `books` 행이 조회에 성공해야 생기기 때문이다. `not_found`를 둘 곳이 없다.
- `AudienceSource`에 `external_category`를 추가한다.
- ISBN 없음은 상태로 저장하지 않고 `isbn IS NULL`로 센다. 상태로 저장하면 나중에 ISBN을 채울 때 되돌리는 경로가 하나 더 생긴다.
- 소개는 `bookIntroduction`을 쓰고, 없으면 `bookSummary`를 쓴다. 줄거리 열을 따로 두지 않는다.
- 새 공식 서지 필드는 `LibraryBookRead`에 읽기 전용으로 추가한다. 등록·수정 스키마에는 넣지 않는다. 연결이 없으면 비어 있다.
- `books.author`가 YES24 원문이 되고 파일 값은 `library_books.author`에 남으므로 저자 원문 열을 따로 두지 않는다.
- **대안: 별도 `book_enrichments` 테이블** → 처리 상태는 기관 도서와 1:1이고 조회할 때마다 조인이 늘어난다.

### 9. 실행 흐름

1. 대상 ISBN을 고른다. 제적 아닌 사본이 있고 처리 상태가 `pending`인 기관 도서의 ISBN을 중복 없이 정렬한다. `--retry-failed`면 그 뒤에 `not_found`, `mismatch`를 붙인다. `--limit`개까지만 쓴다.
2. 트랜잭션을 끝낸 뒤 ISBN마다 처리한다. 외부 호출 동안 DB 트랜잭션이나 행 잠금을 잡지 않는다.
3. `books`에 이미 있으면 호출 없이 연결한다. 없으면 호출한다.
4. 찾으면 `books` 행을 만들고(`ON CONFLICT (isbn) DO NOTHING` 뒤 다시 읽음) 같은 ISBN의 기관 도서를 모두 `connect_official`로 연결한다. `FOR UPDATE`로 읽어 그 사이의 수정과 겹치지 않게 한다.
5. ISBN마다 커밋한다. 중단돼도 처리한 결과가 남는다.

서지 값은 공식 서지에만 쓰고 기관 값은 건드리지 않는다.

### 10. 호출 속도와 오류 구분

제한기가 호출 사이를 최소 0.2초로 벌린다. 공식 한도의 절반이다.

| 외부 결과 | 처리 |
| --- | --- |
| 200 + 상품 있음, ISBN 일치, 서명·저자 저장 가능 | `enriched` |
| 200 + 상품 있음, ISBN 불일치 | `mismatch` |
| 200 + 서명·저자가 없거나 길이 초과 | `not_found` |
| 200 + 빈 목록, 404, `PARAM_004` | `not_found`, 다음 ISBN으로 |
| 429 | 중단 `rate_limited` |
| 401 | 중단 `auth_failed` |
| 그 밖의 4xx·5xx, 시간 초과, 네트워크 오류, 해석 불가 응답 | 중단 `upstream_unavailable` |

- 429는 문서에 오류 코드가 없어서 본문이 아니라 HTTP 상태로 판단한다.
- 서명·저자는 필수라 "그 필드만 비움"을 적용할 수 없다. 기관 값으로 채우면 쓰기 제한을 어기므로 공식 서지를 만들지 않는다.

### 11. 스크립트

- 인자는 `--limit`(기본 100)과 `--retry-failed`다. 100개면 약 20초다.
- 시드처럼 DB 연결과 마이그레이션 상태를 먼저 확인한다. `app/seed/runner.py`의 확인 함수를 쓴다.
- 종료 코드는 완료 0, 전제 조건·잘못된 인자·키 미설정 1, 외부 장애로 중단 2다.
- 시작 전에 키를 확인한다. 키가 없으면 어떤 상태도 바꾸지 않는다.

### 12. 키 보호

- `Settings.yes24_api_key`는 `SecretStr | None`이다. 설정 객체를 출력해도 값이 나오지 않는다.
- 키는 `X-Api-Key` 헤더로만 보낸다. 예외 메시지에는 HTTP 상태와 오류 코드만 담고 요청 객체나 헤더를 넣지 않는다.

### 13. 테스트

- service는 클라이언트를 인자로 받는다. 테스트는 `httpx.MockTransport`를 쓰는 클라이언트를 넘겨 호출 건수와 요청 내용을 기록하고 "호출하지 않음"까지 확인한다.
- 픽스처는 실제 응답 구조를 줄여서 쓴다. 키는 들어가지 않는다.
- 속도 제한은 시계를 주입해 실제로 기다리지 않고 확인한다.

## Risks / Trade-offs

- [분류 규칙의 표본이 인기 도서에 치우침] → 분류 원문을 보관해 호출 없이 다시 판단할 수 있고, 관리자 지정이 항상 우선한다.
- [운영자가 공식 서지를 채운 뒤 기관이 갱신하기 전까지 어린이 구분에 반영되지 않음] → 그동안 어린이 요청에서 빠질 뿐 일반 도서가 섞이지는 않는다. 관리자 화면의 버튼이나 기관 설정의 자동 실행으로 줄일 수 있다.
- [어린이 도서가 `general`로 남음. 전집이 대표적] → 어린이 요청에 일반 도서가 나가는 것보다 낫다고 본다. 비율은 `add-recommendation-evals`에서 본다.
- [어린이 추천 후보에 문제집이 섞일 수 있음] → `add-recommendation-evals`에서 확인하고, 문제가 되면 `external_category` 값으로 추천 후보에서 낮춘다.
- [`초등참고서` 아래 `예비중` 도서가 `국내도서-초등학습서` 값으로 올 수 있음] → 어른 책은 아니므로 허용한다.
- [외부 분류가 나중에 바뀌어도 반영되지 않음] → 이미 만든 공식 서지는 고치지 않는다. 갱신은 필요해질 때 만든다.
- [표지가 없는 상품도 대체 이미지 URL이 채워짐] → 표지 유무를 판단에 쓰지 않는다.
- [정가가 오래된 값이 될 수 있음] → 판매가와 판매 상태는 저장하지 않고, 처리 시각을 남긴다. 구매 요청서의 금액은 해당 change에서 작성 시점의 값을 다시 조회한다.
- [공식 서지를 기관들이 함께 보는 것이 재배포인지 FAQ에 명시되지 않음] → 같은 서비스 안의 제공으로 보고, YES24에서 받은 값을 내보내는 외부 API나 파일 기능을 만들지 않는다. 여러 기관에 실제로 서비스하기 전에 YES24에 확인한다.
- [어느 기관도 소장하지 않게 된 공식 서지가 남음] → 제적은 복구될 수 있고 지금 규모에서는 작다. FAQ의 "필요한 범위"를 지키기 위해 기관이 늘기 전에 정리 기준을 정한다.
- [`not_found`인 ISBN은 등록 뒤에도 자동으로 다시 조회되지 않음] → 운영자가 `--retry-failed`로 다시 조회한다.
- [스크립트를 두 개 동시에 돌리면 속도 제한이 나뉨] → 운영자가 하나만 돌린다. 넘치면 429로 멈추고 다음 실행이 이어서 처리한다.

## Migration Plan

1. 리비전을 손으로 작성한다. 열 추가와 `library_books.audience_source` CHECK 교체다.
2. upgrade는 `book_id`가 있는 기관 도서를 `enriched`로 바꾸고, 나머지는 기본값 `pending`으로 둔다.
3. downgrade는 `external_category` 근거인 기관 도서를 `general`, `default`로 되돌린 뒤 CHECK를 복구하고 열을 지운다.
4. 작업 전에 개발 DB를 백업하고, 명령은 `&&`로 이어 앞 단계가 실패하면 멈춘다.
