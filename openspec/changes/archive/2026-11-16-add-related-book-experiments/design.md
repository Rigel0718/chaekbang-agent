### 2. 코드 자리

- 새 `app/library/recommendation/related.py`
  - 신호: `series_ranking`, `kdc_ranking`, `category_ranking`, `neighbor_ranking`(아래 3), `author_ranking`(`same_author_books`를 id 순위로)
  - `editions_of(session, library_id, ids) -> set[int]`(결정 4)
  - `find_similar(session, embedder_name, *, library_id, library_book_id, within=None, settings: SimilarSettings) -> list[Ranked]`
  - `find_from_history(session, embedder_name, *, library_id, library_book_ids, within=None, settings: HistorySettings) -> list[Ranked]`
  - `popular_ranking(session, library_id, *, within=None, days=180, depth)`
- `embeddings.py`: `neighbors_of(session, model_name, *, library_id, library_book_ids, limit, kind/weights, within)`. 기준 책 벡터를 `book_vectors`로 읽어 평균한 뒤, 지금 `similar_books`의 두 갈래 조회를 벡터로 돈다. `similar_books`는 질의를 인코딩한 뒤 같은 내부 함수를 부르도록 나눈다(동작 그대로, 기존 테스트로 확인).
- 어린이 조건은 실험 틀이 `children_book_ids`를 `within`으로 넘긴다(공통 코드는 뜻을 모른다).
- 기관 범위: 기준 책은 `get_owned`로 그 기관의 것인지 먼저 본다(다른 기관이면 NotFoundError). 최근 기록은 그 기관의 책만 남기고 나머지는 근거로 쓰지 않는다(오류로 멈추지 않는다: 기록은 대화에서 쌓인 목록이라 일부가 제적될 수 있다).

### 3. 신호

| 신호 | 순위 | 깊이 | 실험 장서 |
| --- | --- | --- | --- |
| `series` 같은 시리즈 | 시리즈 키 겹침, 서명 정렬 순서 | 전부(최대 30) | 2/20 |
| `author` 같은 저자 | 겹치는 지은이 수, 서명 정렬 순서(기존) | 20(기존 상한) | 9/20 |
| `kdc` 같은 KDC 세목 | 소수점 첫째 자리까지 같음, 서명 정렬 순서 | 30 | 0 |
| `category` 같은 외부 분류 | 같은 원문 안에서 벡터 이웃 순서 | 30 | 진단용 |
| `vector` 벡터 이웃 | 기준 책 저장 벡터와의 코사인 | 30 | 20/20 |

- 벡터 이웃은 기준 책의 **저장된** 벡터를 쓴다. 기준 책 텍스트를 다시 인코딩하면 같은 벡터가 나오는데 서버만 더 필요하다. 그래서 이번 실행에는 임베딩 서버가 필요 없다.
- KDC 세목: `kdc_key`는 `813.7`, `813.72`처럼 소수점 아래를 둔다. "세목"을 소수점 첫째 자리까지로 본다(`813.72`와 `813.7`은 같고 `813.6`과 다르다). 표시 값은 공식 서지 KDC가 먼저, 없으면 기관 도서 KDC다. 실험 장서에서는 0건이다(이전 결정 14).
- 같은 외부 분류(결정 이전 14에서 남긴 것): 상위 분야 18가지라 "같은 세목" 대신으로 쓰지 않는다. 같은 분류 안에서 순서를 정할 다른 값이 없어 벡터 이웃 순서를 쓴다. 결국 "벡터 이웃을 같은 외부 분류로 좁힌 것"이라 진단 변형 하나(`sim-vec-cat`)로만 잰다. 분야를 넘는 이웃이 득인지 손해인지 본다.
  - **추천: 한 변형만 잰다.** 안 재면 "어린이·유아 사이를 넘나드는 이웃"이 좋은지 알 수 없고, 신호로 RRF에 넣으면 벡터와 같은 순서를 두 번 센다.

### 4. 기준 책과 다른 판본 빼기

- 같은 판본 규칙: `match_key(strip_edition(표시 서명))`이 같고 지은이 키(`writer_keys_sql`)가 하나 이상 겹친다. 둘 다 이미 있는 정규화다(찾기의 판본 표기 지우기, 같은 저자).
- 신호마다 순위를 만든 뒤, 합치기 전에 기준 책과 그 판본을 뺀다. 실행 전 라벨 후보도 같은 함수로 뺀다(스펙 "기준 책의 다른 판본").
- 실험 장서에서는 3묶음(6권)이고 그중 `에듀퐁퐁 (봄·여름)`/`(가을·겨울)`은 다른 권인데 같은 판본으로 잡힌다. 괄호를 지우는 규칙의 한계다. 놀이책 1묶음이라 받아들이고 결과에 적는다. ISBN이 다르면 다른 판본이라는 보완(부제 비교 등)은 실제 장서에서 다시 본다.
- 안: (a) 같은 공식 서지만 뺀다 — ISBN이 다르면 같은 책이 그대로 추천된다(`총 균 쇠` 두 판). (b) 서명만 같으면 뺀다 — 동명의 다른 책이 빠진다. **(c) 서명 + 지은이 (선택)**.

### 5. 비슷한 책 합치기

```python
@dataclass(frozen=True)
class SimilarSettings:
    signals: Mapping[str, float] = {"series": 1, "author": 1, "kdc": 1, "vector": 1}  # 가중치
    fusion: Literal["rrf", "priority"] = "rrf"
    order: Sequence[str] = ("series", "author", "kdc", "vector")  # priority일 때
    weights: Mapping[TextKind, float] = {FULL: 1.0}  # 벡터 이웃의 텍스트 종류
    category_scope: bool = False  # 벡터 이웃을 같은 외부 분류 안으로
    depth: int = 30
    rrf_k: int = 60
    series_cap: int | None = None
    mmr_lambda: float | None = None
    limit: int = 5
```

- **RRF**(topic과 같은 `fuse_rrf`, k 60): 규칙 신호는 짧다(1~6권). k 60이면 규칙 신호의 1위(1/61)와 벡터 1위가 같은 무게라, 같은 저자이면서 벡터도 가까운 책이 위로 온다.
- **규칙 먼저(`priority`)**: 같은 시리즈 → 같은 저자 → KDC → 벡터 순서로 앞 신호의 책을 먼저 둔다(한 번 나온 책은 다시 넣지 않는다). 도서관 사서가 흔히 하는 "같은 시리즈 다음, 같은 작가"를 그대로 옮긴 것이다. 같은 저자 6권(나태주)이면 5권이 모두 같은 저자가 된다.
- 근거: `Ranked.ranks`에 신호별 순위를 그대로 둔다(topic과 같은 모양). `priority`도 신호별 순위를 근거로 둔다. 카드 문구("같은 작가의 책")는 `add-related-books`에서 정한다. **추천: 근거는 모든 결과에 둔다.** 비용이 없고, 카드에서 "왜 이 책인지"를 데이터로 보여 줄 수 있다(설계 원칙 6).
- 시리즈 묶기·MMR은 topic의 함수를 그대로 쓴다. 비슷한 책에서는 같은 시리즈가 나오는 것이 의도일 수 있어(다음 권) 묶기 상한 1·2를 둘 다 잰다.
- 겹침 지표(같은 지은이·시리즈 쌍)는 비슷한 책에서 "나쁨"이 아니다. 요약에 적되 채택 근거로 쓰지 않는다. 시리즈 묶기·MMR은 nDCG가 같거나 오를 때만 켠다.

### 6. 비슷한 책 변형 (단계별, 앞 단계 승자 위에)

| 단계 | 변형 | 내용 |
| --- | --- | --- |
| 0 기준 | `sim-vec` | 벡터 이웃만, `full` |
| 1 텍스트 종류 | `sim-vec-author`, `sim-vec-desc`, `sim-vec-fields` | `with_author`, `description`, 필드별 1:1:1 |
| 1' 분야 좁히기(진단) | `sim-vec-cat` | 1의 승자를 같은 외부 분류 안으로 |
| 2 규칙만(진단) | `sim-rules` | 같은 시리즈 → 같은 저자 → KDC(벡터 없음). 비는 기준 책이 많아 채택 대상이 아니다. 관련 책 있음 묶음에서만 읽는다 |
| 3 합치기 | `sim-rrf`, `sim-rrf-rule2`, `sim-priority`, `sim-author-rrf` | 규칙 + 벡터. RRF 1:1, RRF 규칙 가중치 2, 규칙 먼저, 규칙 + 벡터(`with_author`) |
| 4 묶기·다양화 | `+series1`, `+series2`, `+mmr0.7` | |
| 확인 | `sim-best`, `sim-best-kdc0` | 채택 설정, 그리고 KDC 신호를 뺀 것(실험 장서에서 같아야 한다. 같음을 보고) |

- 기준 변형은 `sim-vec`이다. 지금 제품에 비슷한 책이 없어 가장 단순한 것을 기준으로 둔다.
- 텍스트 종류: `with_author`는 책→책에서 같은 저자 책을 끌어올릴 수 있어 주제로 찾기와 다르게 나올 수 있다. 1에서 `with_author`가 이기면 3에서 "규칙 신호 + `full`"과 "`with_author` 하나"를 다시 비교한다(같은 저자를 두 번 세는지). `title`·`category` 단독은 재지 않는다(이전 결정 3: 분류 벡터는 18가지 값뿐).
- 채택 규칙은 이전 결정 11 그대로(조정 세트에서 평균 차이 > 0, 이김 > 짐, 구간 하한 > 0. 아니면 단순한 쪽).

### 7. 최근 기록 합치기

```python
@dataclass(frozen=True)
class HistorySettings:
    method: Literal["mean", "per-book"] = "per-book"
    similar: SimilarSettings = SimilarSettings()  # per-book일 때 책마다 쓰는 설정(비슷한 책의 승자)
    weights: Mapping[TextKind, float] = {FULL: 1.0}  # mean일 때
    popular_fill: bool = True  # 결과가 모자라면 우리 도서관 인기로 채운다
    ...
```

- **벡터 평균(`mean`)**: 기록 책 벡터의 평균 하나로 이웃을 찾는다. 같은 분야 기록에 좋고, 섞인 기록(이유식 + 소설)에서는 어느 쪽도 아닌 가운데로 간다.
- **책별 RRF(`per-book`)**: 기록 책마다 비슷한 책 순위(6의 승자)를 만들고, 책마다 한 신호로 RRF(1:1, k 60)로 합친다. 겹치는 저자·시리즈는 각 책의 비슷한 책 순위 안에 이미 들어 있다. 여러 책의 이웃에 함께 오르는 책이 위로 온다. 섞인 기록에서 책마다 몫이 남는다.
- 처음 계획의 "분야"(KDC 세목)는 실험 장서에 값이 없다. 외부 분류로 대신하지 않는다(결정 3과 같은 이유). 비슷한 책 순위의 `kdc` 신호로 들어가 실제 KDC가 생기면 그대로 쓰인다.
- **추천: 둘 다 재고 `per-book`을 먼저 기대한다.** 근거: 섞인 기록 3개가 평균을 흐린다. 같은 분야 묶음에서는 비김이 예상된다. 결과로 정한다.
- 기록 책과 그 판본은 결과에서 뺀다. 어린이 조건은 기록 책이 모두 어린이 도서일 때 건다(이번 세트의 어린이 기록 3개).

| 단계 | 변형 | 내용 |
| --- | --- | --- |
| 0 기준 | `hist-mean` | 벡터 평균, 비슷한 책 단계 1의 승자 종류 |
| 1 | `hist-per-book` | 책별 비슷한 책 순위(6의 승자) RRF |
| 1' | `hist-per-book-vec` | 책별 벡터 이웃만 RRF(규칙 신호의 몫을 본다) |
| 1'' | `hist-per-book-k1` | 진단: 책별 RRF의 k를 1로. 2026-11-16 결과를 본 뒤 더했다(책별 RRF가 크게 진 원인 확인) |
| 2 | `+series1`, `+mmr0.7` | |

### 8. 우리 도서관 인기

- 그 기관의 대출 행(`loans`) 중 `loaned_on`이 기관 시간대 오늘(`app/core/clock`)에서 180일 안인 것을 기관 도서별로 센다. 추천 가능·`within`을 먼저 건다. 같으면 서명 정렬 순서, id.
- 180일: 작은도서관의 한 학기·두 계절. 실험으로 정할 수 없어(대출 행 0) 상수로 두고 `add-bibliographic-sources`에서 정보나루 인기와 함께 다시 본다.
- 최근 기록 결과가 `limit`보다 적을 때만 뒤를 채운다(`popular_fill`). 기록이 1권 이상이면 비슷한 책 순위가 거의 늘 5권을 넘으니 실험 장서에서는 쓰이지 않는다. 0건으로 보고한다.
- 가져오기 기관(`loan_mode = imported`)은 대출 행이 없을 수 있다. 그때 빈 결과다. 가져온 대출 상태로 인기를 셀지는 정보나루 연동 때 정한다.
- 정보나루 인기 자리는 만들지 않는다(인터페이스 없이, 그 change가 체인 뒤에 더한다).

### 9. 실험 틀

- `uv run python -m evals.recommendation similar|history [--variants …] [--split …] [--reference …]`. `topic`과 같은 지문·요약·`results.json`·위반 검사·짝 비교를 쓴다. 지금 `run_topic`의 항목 루프와 요약 쓰기를 세트 공통으로 나눈다(항목 = 질의·기준 책·기록, `children`·묶음은 세트가 정한다).
- 변형 표는 세트마다 따로(`TOPIC_VARIANTS`, `SIMILAR_VARIANTS`, `HISTORY_VARIANTS`). 다른 세트의 이름은 오류다.
- 어린이 항목: 기준 책이 어린이 도서이면, 기록은 책이 모두 어린이 도서이면 `within = children_book_ids`. 위반 검사도 같은 기준이다.
- 묶음: 비슷한 책은 어린이·일반, 관련 책 있음·없음(`pick`의 `related`와 같은 정의), 최근 기록은 같은 분야·섞인 분야·어린이(기록 책들의 분야로 계산).
- 신호 건수: 요약에 신호별 "결과가 비지 않은 항목 수 / 평균 권수"(스펙 "신호 건수 보고"). KDC·인기는 0건으로 나온다.
- 질의 인코딩이 없으므로 질의 벡터 캐시를 쓰지 않는다. 인코더는 이름만 쓴다(조회 함수가 모델 이름을 받는다).
- `draft dump|apply similar|history`, `review similar|history`: 후보는 `label.py`의 `related_candidates`(판본 빼기, 어린이 조건을 더함). 검수 화면 위쪽에 기준 책(들)의 카드(소개 전문)를 둔다. `--sample`은 고정 표본(결정 10)만 보여 주고, 요약에 표본 일치율을 적는다.

**읽기**

- **채택 규칙을 넘은 변형이 없다.** 기준(`sim-vec`: 벡터 이웃만, `full`)보다 평균이 오르고 구간 하한이 0을 넘는 변형이 조정 세트에 하나도 없다.
- **책→책 텍스트 종류는 `full` 그대로**(이전 Open Question 2의 답). `with_author`는 차이 없음(+0.008, 4·1·9)이고 어린이 묶음에서는 낮다(-0.066). `description`은 조정에서 같고 확인에서 크게 낮다(-0.205). 필드별은 조정에서 낮고 확인에서 높아 방향이 엇갈린다. 종류를 신호별로 따로 둘 근거가 없다. 스펙의 기본 종류는 바꾸지 않는다.

## Risks / Trade-offs

- **[규칙 신호가 드물다]** 같은 시리즈 2권, 같은 저자 9권뿐이라 합치기의 차이가 대부분 "비김"이다 → 관련 책 있음 묶음(10권)을 따로 읽고, 차이 없음이면 단순한 쪽을 둔다. 실제 작은도서관(시리즈물이 많음)에서는 다를 수 있어 `add-bibliographic-sources`에서 다시 본다.
- **[라벨 후보가 분야로 좁혀짐]** 어린이 기준 책의 후보는 그 분야(어린이 또는 유아)만이라, 분야를 넘는 이웃은 보충 단계에서만 라벨이 붙는다 → 보충은 변형이 낸 책만 보므로 보고한 변형에 조금 유리하다(이전과 같은 풀링 치우침). 단계별 수를 적는다.
- **[정답이 Claude 판단에 기댐]** 라벨은 거의 모두 Claude가 달고 사람은 표본 45건만 본다. 판단자가 비교 대상(규칙 신호, 임베딩 모델)과 달라 특정 변형 쪽으로 기우는 정도는 작지만, Claude가 "같은 저자·같은 시리즈면 납득"으로 기울면 규칙 신호에 유리하다 → 기준에 "같은 시리즈 다음 권도 판단한다(자동 2가 아니다)"를 두고, 표본에 규칙 신호 책을 섞어(등급별 고른 표본) 사람이 본다. 결과에 "라벨 Claude, 표본 검수 사용자, 일치율"을 밝히고 수치는 방식끼리의 상대 비교에만 쓴다.
