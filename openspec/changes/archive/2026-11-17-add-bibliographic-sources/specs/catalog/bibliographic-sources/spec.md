## Purpose

외부 서지 출처 셋(도서관 정보나루, 카카오 책 검색, YES24)의 응답을 출처마다 정해진 규칙으로 읽고, 필드마다 정한 기준 출처 순서로 합쳐 공식 서지 하나의 값을 만든다. 어느 필드가 어느 출처에서 왔는지 남긴다.

## ADDED Requirements

### Requirement: 필드별 기준 출처
시스템은 한 ISBN의 정보나루, 카카오, YES24 결과를 필드마다 정한 순서로 MUST 합친다. 앞 출처에 값이 없으면 다음 출처를 본다.
- 서명·부제·저자: YES24 → 정보나루 → 카카오. 셋은 한 출처에서만 가져온다. 서명이나 저자가 없는 출처는 건너뛴다.
- 출판사: 정보나루 → YES24 → 카카오
- 소개: YES24 → 정보나루 → 카카오
- 목차, 시리즈, 분류 원문: YES24
- KDC, KDC 분류명, 부가기호, 권: 정보나루
- 출간일: 카카오 → YES24 → 정보나루(날짜까지 있을 때만)
- 정가: 카카오 → YES24
- 표지 URL과 상품 링크: YES24 → 카카오. 둘은 한 출처에서 가져오고, 정보나루 표지는 쓰지 않는다.

세 출처 모두 서명·저자를 줄 수 없으면 공식 서지 값을 만들지 않는다.

#### Scenario: 세 출처가 모두 있음
- **WHEN** 정보나루 결과에 서명·저자·KDC `813.8`·부가기호 `77810`이 있고, 카카오 결과에 정가 14000이 있고, YES24 결과에 소개·시리즈 둘·표지 URL·분류 원문 `국내도서-유아`가 있으면
- **THEN** KDC·부가기호는 정보나루 값, 정가는 카카오 값, 서명·저자·소개·시리즈·표지 URL·상품 링크·분류 원문은 YES24 값이다

#### Scenario: 정보나루에 없는 책
- **WHEN** 정보나루 결과가 없고 YES24와 카카오 결과에 서명·저자가 있으면
- **THEN** 서명·부제·저자는 YES24 값이고 KDC와 부가기호는 비어 있다

#### Scenario: YES24에 없는 책
- **WHEN** YES24 결과가 없고 정보나루와 카카오 결과에 서명·저자가 있으면
- **THEN** 서명·부제·저자는 정보나루 값이다

#### Scenario: 정보나루와 YES24에 없는 책
- **WHEN** 카카오 결과에만 서명·저자가 있으면
- **THEN** 서명·저자·출판사·소개는 카카오 값이고 부제, KDC, 부가기호, 시리즈는 비어 있다

#### Scenario: 서명과 저자를 섞지 않음
- **WHEN** YES24 결과에 서명은 있고 저자가 비어 있으며 정보나루 결과에 서명과 저자가 모두 있으면
- **THEN** 서명과 저자가 모두 정보나루 값이다

#### Scenario: 소개 순서
- **WHEN** YES24 결과에 소개가 없고 정보나루와 카카오 결과에 소개가 있으면
- **THEN** 소개는 정보나루 값이다

#### Scenario: 해만 있는 출간일
- **WHEN** 카카오와 YES24 결과에 출간일이 없고 정보나루 출간일이 `2017`이면
- **THEN** 출간일은 비어 있다

#### Scenario: 표지와 링크는 한 출처
- **WHEN** YES24 결과에 표지 URL과 상품 링크가 모두 없고 카카오 결과에 둘이 있으면
- **THEN** 표지 URL과 상품 링크가 모두 카카오 값이다

#### Scenario: 세 출처 모두 서명·저자 없음
- **WHEN** 세 출처 결과 모두 저자가 비어 있으면
- **THEN** 공식 서지 값이 만들어지지 않는다

### Requirement: 필드별 출처 기록
시스템은 합친 값의 출처를 MUST 남긴다. 서명·저자의 출처는 공식 서지의 출처(`external_source`)로, 나머지 필드는 값이 있는 필드마다 출처 이름으로 남긴다. 출처 이름은 `data4library`, `kakao`, `yes24`다.

#### Scenario: 출처 기록
- **WHEN** 서명·저자·소개·표지 URL이 YES24에서, 정가가 카카오에서, KDC가 정보나루에서 온 공식 서지를 만들면
- **THEN** 공식 서지의 출처는 `yes24`이고 필드별 출처에 정가 `kakao`, 소개 `yes24`, 표지 URL `yes24`, KDC `data4library`가 있다

#### Scenario: 빈 필드
- **WHEN** 정가가 어느 출처에도 없으면
- **THEN** 필드별 출처에 정가가 없다

### Requirement: 정보나루 서명 정리
시스템은 정보나루 서명을 공식 서지의 서명으로 쓸 때 MUST 다음 규칙으로 정리한다(YES24 서명이 없는 책).
- 첫 ` :`(공백 뒤 쌍점), ` =`, ` /`, ` - ` 앞을 서명으로 둔다. ` :`나 ` - ` 뒤는 부제이고, 부제 안의 ` =`·` /` 뒤(대등 서명)는 버린다. ` =`·` /` 뒤만 있으면 부제는 비어 있다. 앞에 공백이 없는 `:`에서는 나누지 않는다.
- 서명 앞의 괄호 관제는 괄호만 푼다(`(어린이) 훈민정음` → `어린이 훈민정음`).
- 권(`vol`)이 숫자뿐이면 서명 뒤에 한 칸 띄어 붙인다. 숫자가 아닌 권 표기(`양장`, `무선`)는 붙이지 않는다.

YES24와 카카오 서명은 나누지 않고, 부제는 서명과 같은 출처의 값이다(YES24 부제, 카카오는 없음).

#### Scenario: 부제가 붙은 서명
- **WHEN** 정보나루 서명이 `아몬드 :손원평 장편소설`이면
- **THEN** 서명은 `아몬드`, 부제는 `손원평 장편소설`이다

#### Scenario: 부제 안의 쉼표
- **WHEN** 정보나루 서명이 `사피엔스 :유인원에서 사이보그까지, 인간 역사의 대담하고 위대한 질문`이면
- **THEN** 서명은 `사피엔스`이고 부제는 쌍점 뒤 전체다

#### Scenario: 대등 서명
- **WHEN** 정보나루 서명이 `노르웨이의 숲 =Norwegian wood`이거나 `해독 혁명 =질병 없는 몸을 위한 5단계 독소 해방 /Detox revolution`이면
- **THEN** 서명은 `노르웨이의 숲`, `해독 혁명`이고 부제는 비어 있다

#### Scenario: 하이픈 부제
- **WHEN** 정보나루 서명이 `언제나 기억해 - 소년과 두더지와 여우와 말, 그리고 폭풍우`이면
- **THEN** 서명은 `언제나 기억해`, 부제는 `소년과 두더지와 여우와 말, 그리고 폭풍우`다

#### Scenario: 괄호 관제
- **WHEN** 정보나루 서명이 `(한밤중) 달빛 식당`이면
- **THEN** 서명은 `한밤중 달빛 식당`이다

#### Scenario: 권 붙이기
- **WHEN** 정보나루 서명이 `고양이 해결사 깜냥`이고 권이 `8`이면
- **THEN** 서명은 `고양이 해결사 깜냥 8`이다

#### Scenario: 숫자가 아닌 권
- **WHEN** 정보나루 서명이 `총, 균, 쇠`이고 권이 `양장`이면
- **THEN** 서명은 `총, 균, 쇠`다

#### Scenario: 나누지 않는 쌍점
- **WHEN** 정보나루 서명이 `시선으로부터,`이거나 `C++:기초`이면
- **THEN** 서명은 원문 그대로이고 부제는 비어 있다

### Requirement: 정보나루 응답 해석
시스템은 정보나루 도서 상세 응답을 MUST 관대하게 읽는다.
- 문자열 값의 앞뒤 공백을 지우고, 빈 값은 값 없음으로 본다.
- 소개의 HTML 이스케이프(`&lt;`, `&gt;`, `&amp;`)를 원래 문자로 되돌린다.
- 부가기호는 5자리 숫자일 때만 둔다.
- KDC는 분류기호 저장 규칙(앞의 `KDC` 등 표기를 뗀 값)으로, KDC 분류명은 원문 그대로 둔다.
- 표지 URL은 쓰지 않는다.

#### Scenario: 앞뒤 공백
- **WHEN** 응답의 출판사가 ` 창비 `이면
- **THEN** 출판사는 `창비`다

#### Scenario: 이스케이프된 소개
- **WHEN** 응답의 소개에 `&lt;아몬드&gt;`가 있으면
- **THEN** 소개에는 `<아몬드>`로 들어간다

#### Scenario: 잘못된 부가기호
- **WHEN** 응답의 부가기호가 `7485`이거나 비어 있으면
- **THEN** 부가기호는 비어 있다

#### Scenario: 정보나루 표지 미사용
- **WHEN** 정보나루 응답에만 표지 URL이 있고 카카오와 YES24 결과가 없으면
- **THEN** 공식 서지의 표지 URL은 비어 있다

### Requirement: 카카오 응답 해석
시스템은 카카오 책 검색 응답에서 요청한 ISBN과 같은 문서만 MUST 쓴다. ISBN 칸은 공백으로 나눈 값 중 13자리 값으로 비교한다. 출간일은 ISO 8601 값의 날짜를 쓰고, 정가는 1 이상일 때만 둔다. 판매가와 판매 상태는 읽지 않는다.

#### Scenario: ISBN10과 ISBN13
- **WHEN** 문서의 ISBN 칸이 `8996991341 9788996991342`이고 요청 ISBN이 `9788996991342`이면
- **THEN** 그 문서를 쓴다

#### Scenario: 다른 ISBN 문서만 있음
- **WHEN** 세 출처 응답의 ISBN13이 모두 요청과 다르면
- **THEN** 공식 서지 값은 없고 ISBN 불일치로 기록된다

#### Scenario: ISO 출간일
- **WHEN** 문서의 출간일이 `2014-11-17T00:00:00.000+09:00`이면
- **THEN** 출간일은 2014-11-17이다

#### Scenario: 정가 0
- **WHEN** 문서의 정가가 0이면
- **THEN** 정가는 비어 있다
