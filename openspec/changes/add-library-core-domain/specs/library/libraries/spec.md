# Spec Delta

## Purpose

여러 작은도서관이 한 서비스를 함께 쓰도록 기관 정보와 운영 방식을 보관하고, 로그인한 기관의 데이터만 보이고 바뀌도록 기관 분리를 강제한다.

## ADDED Requirements

### Requirement: 기관 정보와 운영 방식
시스템은 기관마다 이름, 유형, 운영 방식, 기본 대출 기간을 SHALL 보관한다.
- 유형: `small_library` 또는 `bookstore`
- 운영 방식(`loan_mode`): `imported`(기존 대출 프로그램에서 가져오기) 또는 `internal`(자체 대출)
- 기본 대출 기간: 1 이상의 일수

로그인한 직원은 자기 기관 정보를 조회할 수 있고, 관리자는 이름·운영 방식·기본 대출 기간을 수정할 수 있다.

#### Scenario: 자기 기관 조회
- **WHEN** 로그인한 직원이 `GET /library`를 호출하면
- **THEN** 자기 기관의 이름, 유형, 운영 방식, 기본 대출 기간을 돌려준다

#### Scenario: 기본 대출 기간 수정
- **WHEN** 관리자가 `PATCH /library`로 기본 대출 기간을 21로 바꾸면
- **THEN** 바뀐 값을 돌려주고 이후 대출의 반납 예정일 계산에 쓰인다

#### Scenario: 잘못된 대출 기간
- **WHEN** 관리자가 기본 대출 기간을 0으로 바꾸려 하면
- **THEN** 422를 돌려주고 값은 바뀌지 않는다

#### Scenario: 허용되지 않은 운영 방식
- **WHEN** 관리자가 운영 방식을 `hybrid`로 바꾸려 하면
- **THEN** 422를 돌려준다

### Requirement: 기관 데이터 분리
시스템은 모든 기관 데이터(사본, 회원, 대출, 직원 계정)의 조회와 쓰기를 로그인한 계정의 기관 범위로 MUST 제한한다.
- 기관은 요청 값이 아니라 인증 토큰으로 정한다.
- 다른 기관의 데이터를 가리키는 요청은 그 데이터가 없는 것처럼 404로 응답한다.
- 목록 조회에는 다른 기관의 데이터가 들어가지 않는다.

#### Scenario: 다른 기관의 사본 조회
- **WHEN** A 기관 직원이 B 기관 사본의 id로 `GET /holdings/{id}`를 호출하면
- **THEN** 404를 돌려준다

#### Scenario: 목록에 다른 기관 데이터 없음
- **WHEN** A, B 두 기관에 회원이 있을 때 A 기관 관리자가 `GET /members`를 호출하면
- **THEN** A 기관 회원만 돌려준다

#### Scenario: 요청 본문의 library_id 무시
- **WHEN** A 기관 관리자가 본문에 B 기관의 `library_id`를 넣어 `POST /members`를 호출하면
- **THEN** 회원은 A 기관에 만들어진다

#### Scenario: 다른 기관 데이터 수정
- **WHEN** A 기관 관리자가 B 기관 회원의 id로 `PATCH /members/{id}`를 호출하면
- **THEN** 404를 돌려주고 B 기관 회원은 바뀌지 않는다
