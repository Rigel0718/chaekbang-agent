## Context

왜 하는지는 proposal.md의 Why에 있다. 요구사항은 `specs/platform/web-ui/spec.md`에 있다.

화면이 쓸 백엔드는 이미 다 있다(2026-11-20 확인).

| 화면에서 | API | 주는 값 |
| --- | --- | --- |
| 자동완성 | `GET /catalog/suggest?q=` | 최대 8개. 기관 도서 id, 서명, 저자. 조합 중인 자모도 맞는다 |
| 검색 카드 줄 | `GET /catalog/search?q=` | `BookSummary` 목록 |
| 비슷한 책 | `GET /catalog/books/{id}/similar` | `RelatedBook` 최대 5권(`basis_text` 더함). LLM 없음, 실행·대화·노출 기록 없음 |
| 대화 | `POST /librarian/messages` (SSE) | `session` → `found`(있으면) → `status`(여러 번) → `answer` → `done`. 고른 책만 보내면 `session`·`found`·`done`만 나간다 |
| 새 대화 | `DELETE /librarian/sessions/{id}` | 204 |
| 반납일 머리 | `GET /library/guide` | `registered`, `today`(`status`, `due_if_borrowed`), `due_is_estimate`(외부 대출 기관) |

- `answer`의 값: `message`, `recommendations`(`BookCard` = `BookSummary` + `reason`), `suggest_book_request`, `loan_mode`.
- 화면이 받는 오류:
  - 401: 토큰 없음 또는 만료
  - 404: 끝난 세션
  - 409: 답하는 중에 또 보냄, 또는 대화의 턴 한도 20
  - 429: 기관의 일일 상한
  - 422: 입력 형식
- 대화 세션은 입력 없이 5분이 지나면 서버가 지운다(`librarian_session_idle_minutes`, 1분마다 지우는 작업). 고른 책 턴도 이용자 메시지 한 줄이라 턴 한도에 들어간다.
- 대화 요청은 POST에 토큰 헤더를 붙여야 해서, 브라우저의 `EventSource`로는 받을 수 없다.

## Goals / Non-Goals

**Goals:**
- 기존 API만으로 이용자 화면을 그린다. 화면 코드는 나중에 React로 옮길 때 그대로 쓰거나 한 단위로 바꿀 수 있게 작은 모듈로 나눈다(API 부르기, SSE 읽기, 카드 그리기).
- 공용 PC에 앞사람의 대화와 담은 책이 남지 않는다.

**Non-Goals:**
- 로그인 화면, 토큰 갱신, 역할별 화면 나누기는 하지 않는다(`add-web-ui`).
- 화면을 위해 API 응답을 바꾸거나 경로를 더하지 않는다.
- 브라우저 자동화 테스트는 하지 않는다.
- 접근성·디자인 다듬기는 기본만 한다: 키보드로 고르기, 읽기 쉬운 글자 크기, 좁은 화면에서 사이드 접기.

## Decisions

### 1. 정적 파일, 빌드 없음, `/ui/`에 마운트

- `app/web/`에는 `README.md`, `CLAUDE.md`와 내주는 파일 폴더 `public/`이 있다. `app/main.py`가 `public/`만 `/ui`에 마운트한다(`StaticFiles(..., html=True)`). README·CLAUDE.md가 내주는 폴더 밖에 있어서 `/ui/README.md`는 404다.
- `/librarian`에 마운트하지 않는 이유: API가 `/librarian/...`를 쓰므로 경로가 겹친다. `/`에 마운트하지 않는 이유: `/docs`, API와 섞인다.
- **다른 안**
  - Jinja 템플릿: 서버에 화면용 Python 코드가 생기고, React로 옮길 때 버린다.
  - React와 빌드: 화면이 얇아서 지금은 과하다. Node가 스택에 들어온다.
- 의존 방향 테스트는 Python import만 보므로 `app/web/`은 그 검사에 걸리지 않는다. 마운트는 조립 파일인 `app/main.py`에 둔다.

```
app/web/
  README.md, CLAUDE.md        (내주지 않음)
  public/                     -> /ui/
    shared/                   관리자 화면도 쓸 모듈
      api.js                  fetch + 토큰 헤더, 경로 함수, 오류 구분
      sse.js                  fetch 스트림 -> {name, data} 사건
      card.js                 BookSummary 계열 -> 카드 요소, 안전한 주소 함수
      base.css
    librarian/
      index.html
      librarian.css
      suggest.js              자동완성
      chat.js                 턴 흐름
      basket.js               담기
      idle.js                 비우기 타이머
      main.js                 조립, 반납일 머리, 토큰 넣기
```

### 2. 입력창 하나 (탐색 결정 2)

`docs/design.md`의 이용자 화면을 그대로 따른다. 검색과 대화를 탭이나 입력창 둘로 나누지 않는다. 이용자가 "검색할지, 물어볼지"를 먼저 고르지 않아도 되고, 서명이 든 질문도 결국 찾은 책 카드가 나오기 때문이다.

| 이용자 동작 | 부르는 API | 화면 | LLM |
| --- | --- | --- | --- |
| 입력 중 | suggest (입력이 200ms 멈추면) | 입력창 위 후보 목록과 마지막 줄 "'…'로 책 모두 찾기" | 없음 |
| 후보를 클릭하거나 화살표로 골라 Enter | messages + `selected_library_book_id` | 대화에 그 책 카드, 아래에 비슷한 책 자동 펼침 | 없음 |
| "모두 찾기" | search | 대화 흐름에 검색 결과 카드 줄 블록(서버 세션에는 남지 않음) | 없음 |
| 그냥 Enter | messages + `message` | 찾은 책 카드 → 진행 문구 → 답 말풍선 → 추천 카드 | 있음 |

**자동완성 입력 처리**
- 입력이 200ms 멈추면 부른다. 새로 부를 때 끝나지 않은 앞 요청은 `AbortController`로 취소한다. 늦게 온 앞 결과가 지금 입력의 목록을 덮지 않게 하기 위해서다.
- 조합 중(`isComposing`)인 Enter는 무시한다. 한글 IME에서 Enter가 두 번 들어와 두 번 보내지는 것을 막는다. 후보 부르기는 조합 중에도 한다. 서버가 조합 중인 자모를 맞추기 때문이다.
- Enter는 화살표로 후보를 고른 상태가 아니면 항상 사서에게 보낸다. Esc나 입력창 밖을 누르면 후보 목록을 닫는다.
- 문장이 길어지면 앞부분이 맞는 책이 없어 후보가 저절로 사라진다. 길이로 따로 끊지 않는다.

### 3. 카드 누르기 (탐색 결정 3)

- **카드 본문을 누르면** 비슷한 책 줄을 그 아래에 펼치고, 다시 누르면 접는다. 기록도 턴도 쓰지 않는다. 한 번 받은 결과는 그 카드가 화면에 있는 동안 다시 부르지 않는다.
- **[이 책 물어보기]**는 고른 책 턴(1턴)이다. 그 책이 대화 세션의 책이 되어 다음 질문의 문맥이 된다. 검색 결과 카드 줄은 서버 세션에 남지 않으므로 이 버튼으로 문맥에 넣는다.
- **자동 펼침**은 `found`가 한 권일 때만 한다. 추천 카드 여러 권이 모두 펼쳐지면 카드가 너무 많아진다.
- 결과가 빈 비슷한 책은 "비슷한 책을 찾지 못했어요"라는 한 줄로 보인다.
- **다른 안**: 카드를 누르면 고른 책 턴을 보내는 방법. 동작이 하나라 단순하지만, 턴을 쓰고 같은 카드가 대화에 다시 나온다.

### 4. 카드 하나

`card.js`는 책 값 하나와 종류(`summary`·`recommend`·`similar`)를 받아 같은 모양을 그린다.

- 표지는 `cover_url`을 원본 주소 그대로 쓴다. 없거나 불러오지 못하면 서명 첫 글자를 넣은 자리 표시를 둔다. 표지 아래에 "표지: {cover_source}"를 두고, `product_url`이 있으면 그 문구를 링크로 건다.
- 대출 상태
  - `available_count > 0`이면 "대출 가능 N권"이다. 0이고 `on_loan_count > 0`이면 "모두 대출 중"이다.
  - `status_synced_at`이 있으면(외부 대출 기관) "대출 상태 {날짜 시각} 기준"을 덧붙인다.
- 서가 위치와 청구기호를 함께 보인다. 둘 다 없으면 줄을 생략한다.
- 종류에 따른 한 줄: `recommend`는 `reason`, `similar`는 `basis_text`를 ` · `로 잇는다.
- 버튼: [이 책 물어보기], [담기]/[담김].
- 책 값은 `book.필드` 형태로만 읽는다. 카드 필드 계약 테스트가 이 형태를 모아 스키마와 맞춰 본다.
- 주소는 `safeUrl()` 하나를 거친다. `http:`·`https:`가 아니면 쓰지 않는다.

### 5. SSE 읽기

`sse.js`는 `fetch` 응답 본문을 `TextDecoderStream`으로 읽는다. 빈 줄로 사건을 나누고 `event:`·`data:` 줄을 풀어 `{name, data}`를 차례로 내준다. 청크가 사건 중간에서 끊길 수 있으므로 남은 조각은 버퍼에 이어 붙인다. `chat.js`의 처리는 이렇다.

- `session`: 세션 id를 메모리에 둔다.
- `found`: 이용자 말풍선 바로 아래에 카드 줄. 한 권이면 비슷한 책 자동 펼침.
- `status`: 답 자리에 진행 문구를 바꿔 가며 보인다.
- `answer`: 진행 문구를 지우고 답 말풍선과 추천 카드를 그린다. `suggest_book_request`가 참이면 "희망도서 신청은 곧 열려요" 안내 한 줄을 붙인다.
- `done`: 입력창을 다시 연다. 보내는 동안에는 입력창을 잠가서 409(답하는 중)를 화면에서 먼저 막는다.

### 6. 담기 (탐색 결정 4)

- 담은 책은 `basket.js`의 메모리 목록(기관 도서 id 순서를 지키는 Map)에만 둔다. 같은 책은 한 번만 담긴다.
- 사이드 한 줄: 서명, 서가 위치·청구기호, 대출 가능 여부, [x].
- 좁은 화면(약 900px 아래)에서는 사이드를 접고, 위쪽에 [담은 책 N] 버튼을 둔다.
- 저장소에 두지 않는 이유는 공용 PC이기 때문이다. 새로 고치면 사라지는 것이 의도한 동작이다.

### 7. 비우기

| 언제 | 하는 일 |
| --- | --- |
| [새 대화] | 세션이 있으면 `DELETE`를 보내고(실패해도 진행), 대화·검색 결과·후보·담은 책·세션 id를 비운다 |
| 입력·클릭·스크롤 없이 4분 30초 | 같은 비우기 |
| 요청이 세션 404를 받음 | 같은 비우기를 하고 "대화가 끝나서 새로 시작해요"를 한 줄 보인다 |

- 4분 30초는 `idle.js`의 상수다. 서버의 5분(`librarian_session_idle_minutes`)보다 앞서도록 둔다. 서버 값을 바꾸면 이 상수도 바꾼다(README에 적는다). API로 내주지 않는 것은 화면 전용 응답 변경을 피하려는 것이다.
- 답을 받는 동안에는 타이머를 멈춘다.
- 비우기 30초 전 알림은 `add-web-ui`에서 한다.

### 8. 반납일 머리와 문구

- `GET /library/guide`를 화면을 열 때와 비울 때 부른다.
  - `registered`가 false면 머리를 숨긴다.
  - `today.status`가 휴관이면 "오늘은 쉬는 날이에요"와 `closed_reason`을 보인다.
  - 그렇지 않으면 "오늘 빌리면 {M월 D일(요일)}까지 반납"을 크게 보인다. 날짜는 `today.due_if_borrowed`를 그대로 쓰고, 화면은 날짜를 세지 않는다.
  - `due_is_estimate`가 참(외부 대출 기관)이면 "(예상)"을 붙인다.
- 입력창 아래에 개인정보 주의 문구를 둔다: "이름, 전화번호 같은 개인정보는 적지 마세요."
- 화면 문구는 HTML에 직접 쓴다. 다국어는 하지 않는다.

### 9. 개발용 토큰

- `main.js`가 시작할 때 주소의 `#token=`을 읽는다. 값이 있으면 `localStorage`의 토큰 키 하나에 넣고 `history.replaceState`로 주소에서 지운다. `#` 뒤의 값은 서버에 보내지지 않아 접근 로그에 남지 않는다.
- 401을 받으면 토큰을 지우고 "토큰이 없거나 만료됐어요" 안내를 보인다. 개발자 안내도 덧붙인다: Swagger에서 키오스크 계정으로 로그인한 뒤 `/ui/librarian/#token=…`으로 연다.
- 로그인 화면이 생기면(`add-web-ui`) 이 자리를 대신한다. 저장 키는 그대로 쓴다.

### 10. 오류 표시

| 상태 | 화면 |
| --- | --- |
| 401 | 토큰 안내(결정 9) |
| 404 (대화) | 비우기(결정 7) |
| 409, 429 | 서버의 `detail` 문구를 그대로 답 자리에 보인다 |
| 422, 네트워크 오류, 5xx | "잠시 뒤에 다시 시도해 주세요" |
| 스트림이 `done` 없이 끊김 | 같은 문구를 보이고 입력창을 연다 |

### 11. 시험 (탐색 결정 6)

- **pytest** (`tests/platform/test_web_ui.py`): 스펙 시나리오마다 하나 이상이다. 서빙과 경로는 기존 `client` 픽스처로 부른다.
  - 화면이 부르는 경로는 JS 파일의 `/`로 시작하는 문자열을 모아 허용 목록과 맞춘다.
  - 저장소, HTML 해석, 주소 함수는 JS 소스를 검사한다.
  - 카드 필드 계약은 `card.js`의 `book.(\w+)`을 모아 `BookSummary`·`BookCard`·`RelatedBook`의 `model_fields` 합집합과 맞춘다.
- **브라우저 확인**: 아래 표의 항목을 tasks 끝에서 돌리고 결과(스크린숏 경로, 잘 안 된 것)를 이 문서의 "결과"에 적는다.
  - 데이터는 개발 DB의 `실험용 가상 작은도서관`과 임베딩 서버다.
  - 실제 LLM을 부르는 항목은 돌리기 전에 호출 수를 알리고 승인을 받는다.
- **Playwright를 넣지 않는 이유**
  - 이 화면은 `add-web-ui`에서 크게 바뀌거나 React로 옮겨질 수 있다.
  - 기존 API를 그리기만 해서 잘못되면 열어 보는 순간 보인다.
  - 하루 비용(브라우저 내려받기, 마커, 가짜 응답 도우미)이 1주 change에 크다.
  - 대출·승인처럼 여러 단계 흐름이 생기면 다시 본다.
- **evals**: AI 사서의 프롬프트, tool, 답 구조가 바뀌지 않으므로 없다.

**브라우저 확인 항목**

| # | 확인 | 판정 |
| --- | --- | --- |
| B1 | 자동완성 | `데미`를 빠르게 치면 suggest 요청이 마지막 입력에 대해 한 번 나가고(네트워크 탭), 후보가 뜬다. 화살표와 Enter로 고르면 그 책 카드 하나가 나오고 status·answer 사건이 없다 |
| B2 | 검색 카드 줄 | "모두 찾기"를 누르면 search 결과 수만큼 카드가 한 줄 블록으로 나온다 |
| B3 | 대화 순서 | 서명이 든 질문에서 찾은 책 카드 → 진행 문구 → 답 → 추천 카드 순서로 화면에 놓인다 |
| B4 | Enter는 사서에게 | 후보가 떠 있어도 고르지 않은 Enter는 `message` 요청이다 |
| B5 | IME | 한글 조합 중 Enter로 한 번만 보내진다 |
| B6 | 카드 표시 | 표지 없음 자리 표시, 표지 출처 문구, 모두 대출 중, 서가 위치·청구기호. 외부 대출 기관 토큰으로 갱신 시각과 "(예상)" |
| B7 | 펼치기 | 카드를 누르면 similar 한 번과 근거 문구가 있는 카드 줄이 나오고, 다시 누르면 접힌다. 찾은 책이 한 권이면 저절로 펼쳐진다 |
| B8 | 이 책 물어보기 | 버튼 뒤 "이거랑 비슷한데 더 얇은 책"에 그 책을 문맥으로 답한다 |
| B9 | 담기 | 담으면 사이드에 한 줄이 생기고 버튼이 [담김]이다. [x]로 빠진다. 좁은 화면에서는 접힌다 |
| B10 | 비우기 | 새 대화(DELETE 요청), 4분 30초(시간을 줄인 개발 설정으로 확인), 세션 404 세 경우 모두 대화와 담은 책이 빈다 |
| B11 | 오류 | 401 토큰 안내, 409(보내는 중에 다시 보내기)를 서버 문구로 |
| B12 | 반납일 머리와 주의 문구 | 등록된 기관은 날짜, 휴관일은 휴관 문구. 주의 문구가 입력창 아래에 있다 |
| B13 | 저장 | 새로 고친 뒤 대화와 담은 책이 없다. 개발자 도구의 저장소에 토큰 키 하나만 있다 |

## Risks / Trade-offs

- **[화면 동작에 회귀 테스트가 없음]** → pytest는 계약(경로, 저장, 필드)만 막는다. 동작은 브라우저 확인 항목을 change마다 다시 돌린다. 여러 단계 흐름이 생기면 Playwright를 다시 본다.
- **[4분 30초 상수와 서버 5분이 어긋날 수 있음]** → README와 `idle.js`에 서버 설정 이름을 적는다. 어긋나도 결과는 세션 404 → 비우기라 안전한 쪽으로 끝난다.
- **[토큰이 `localStorage`에 있음]** → 같은 출처의 스크립트만 읽는다. HTML 해석을 금지하고(스펙) 외부 스크립트를 불러오지 않는다. 키오스크 토큰은 이용자 권한이라 관리자 API는 403이다.
- **[검색 카드 줄은 서버 세션에 없음]** → "이거랑 비슷한 책"을 사서가 모를 수 있다. [이 책 물어보기]와 카드 펼치기로 대신한다. 쓰다가 불편하면 다음 change에서 다시 본다.
- **[표지 원본 주소가 깨짐]** → 불러오기 실패(`error` 사건)면 자리 표시로 바꾼다.
- **[`TextDecoderStream` 미지원 브라우저]** → 도서관 PC는 최신 크롬·엣지를 가정한다. README에 적는다.

## Migration Plan

DB와 API 변경이 없다. 배포는 서버 재시작 한 번이다. 되돌리려면 `app/main.py`의 마운트 한 줄을 지운다.
