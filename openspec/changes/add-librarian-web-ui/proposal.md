## Why

AI 사서의 검색, 대화, 추천 카드, 비슷한 책까지 API는 다 있지만 아직 화면이 없어서, 지금까지 만든 결과를 이용자 눈으로 확인하지 못했다. 승인 흐름(`add-approval-flow`)으로 넘어가기 전에 얇은 이용자 화면을 먼저 붙인다. 이 화면으로 확인할 것은 네 가지다. ① 검색이 되는지 ② AI 사서가 답하는지 ③ 찾은 책 카드가 답보다 먼저 나오는지 ④ 검색하면 카드 줄이 나오는지. 백엔드를 실제로 붙여 봐야 SSE와 카드 문제가 보인다.

## What Changes

- **이용자 화면 하나** (`/ui/librarian/`): FastAPI가 정적 파일(빌드 없는 HTML·CSS·ES 모듈 JS)로 내준다. 화면 전용 API는 만들지 않고 기존 API만 쓴다.
  - `GET /catalog/suggest`, `GET /catalog/search`, `GET /catalog/books/{id}/similar`
  - `POST /librarian/messages`(SSE), `DELETE /librarian/sessions/{id}`
  - `GET /library/guide`
- **입력창 하나**: 검색과 대화를 한 입력창에서 한다(`docs/design.md`의 이용자 화면 그대로).
  - 입력하는 동안 자동완성 후보가 뜬다. 후보를 고르면 LLM 없이 고른 책 턴이 된다.
  - 후보 목록의 "모두 찾기"를 누르면 검색 결과가 카드 줄로 나온다.
  - Enter는 항상 AI 사서에게 보낸다.
  - 대화는 찾은 책 카드 → 진행 문구 → 답 → 추천 카드 순서로 그린다.
- **책 카드 하나를 모든 곳에 쓴다**: 검색 결과, 찾은 책, 추천 책, 비슷한 책이 같은 카드를 쓴다.
  - 카드에는 표지(원본 URL과 출처, 없으면 자리 표시), 서명·저자·출판사, 대출 가능 여부, 서가 위치·청구기호가 있다. 외부 대출 기관이면 대출 상태의 갱신 시각도 보인다.
  - 카드 종류에 따라 한 줄이 더 붙는다. 추천 카드는 이유, 비슷한 책 카드는 근거 문구다.
  - 카드를 누르면 비슷한 책이 그 아래에 펼쳐진다(LLM 없음, 기록 없음, 대화 턴을 쓰지 않음). 찾은 책이 한 권이면 저절로 펼쳐진다.
  - [이 책 물어보기]를 누르면 고른 책 턴을 보내서 그 책이 대화 문맥에 들어간다.
- **담기**: 카드를 오른쪽 사이드에 담는다(서명, 서가 위치·청구기호, 대출 가능 여부). 담은 책은 화면 메모리에만 둔다.
- **공용 PC 비우기**: 아래 세 경우에 대화, 검색 결과, 담은 책을 비우고 처음 화면으로 돌아간다.
  - [새 대화]를 누를 때(세션 종료 요청)
  - 입력 없이 4분 30초가 지날 때(서버의 무입력 세션 삭제 5분보다 앞)
  - 서버가 세션을 찾지 못할 때
- **화면 위쪽**: 오늘 빌리면 반납 예정일을 크게 보인다. 오늘이 휴관이면 휴관을 보인다. 안내를 등록하지 않은 기관에서는 숨긴다.
- **개인정보 입력 주의 문구**: 입력창 근처에 둔다.
- **개발용 토큰**: 로그인 화면은 이번에 만들지 않는다. `#token=`으로 넣은 토큰을 브라우저에 두고 401이면 안내한다. 브라우저에는 토큰 말고 아무것도 저장하지 않는다.
- **시험**: 서빙, 경로, 소스 규칙(저장, 안전한 표시, 카드 필드 계약)은 pytest로 확인한다. 화면 동작은 브라우저 확인 항목으로 확인하고 결과를 design에 남긴다. Playwright는 넣지 않는다. AI 사서의 동작은 바뀌지 않아 evals는 없다.
- **roadmap**: 이 change를 21번에 끼우고, 기존 `add-web-ui`의 내용을 나눈다. 대출 화면은 `add-librarian-actions`로, 로그인·관리자 화면은 `add-web-ui`로 간다.
- **범위 밖**:
  - 로그인 화면, 비우기 30초 전 알림, 관리자 화면(분석 대화, 승인, 장서 가져오기) → `add-web-ui`
  - 대출·반납·희망도서 버튼과 회원번호 입력 → `add-librarian-actions`
  - 오늘의 한마디, 회원이 읽은 목록(2단계 개인화), 담은 책 출력·보내기, 브라우저 자동화 테스트

## Capabilities

### New Capabilities

- `platform/web-ui`: 화면 파일을 내주는 방식과 화면 코드의 계약. 경로, 기존 API만 쓰기, 브라우저 저장 규칙, 서버 값의 안전한 표시, 카드가 읽는 필드와 응답 스키마의 일치. 이후 관리자 화면도 같은 규칙을 따른다.

### Modified Capabilities

(없음. 기존 API와 AI 사서 동작은 바뀌지 않는다.)

## Impact

- 코드
  - 새 `app/web/`: `README.md`, `CLAUDE.md`, `librarian/index.html`, `static/css/`, `static/js/`(api, sse, card, suggest, chat, basket, idle, main 모듈)
  - `app/main.py`: `/ui` 정적 파일 마운트 한 줄
- 테스트: 새 `tests/platform/test_web_ui.py`(서빙, 경로, 라우트 목록, 소스 검사, 카드 필드 계약)
- DB, 마이그레이션, 의존성, 외부 호출: 없음. `StaticFiles`는 이미 있는 Starlette 기능이다.
- API: 바뀌지 않는다. 새 경로는 정적 파일 `/ui/...`뿐이다.
- LLM: 실제 화면 확인에서만 부른다. 돌리기 전에 승인을 받는다.
- 문서
  - `docs/roadmap.md`: 21번 끼우기, 22~25번 다시 매기기, 23·24번 내용 나누기, 미룬 일
  - `docs/design.md`: 이용자 화면 절에 화면 위치와 비우기 규칙
  - `CLAUDE.md`: 현재 단계, 화면 주소
