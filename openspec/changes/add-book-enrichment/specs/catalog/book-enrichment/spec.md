# Spec Delta

## Purpose

기관이 소장한 도서의 서지정보와 어린이 분류 근거를 외부 도서 API로 채워, 추천과 안내가 지어낸 정보 없이 데이터를 근거로 동작하게 한다.

## ADDED Requirements

### Requirement: 실행 권한과 대상
시스템은 관리자의 `POST /book-enrichment/runs` 요청으로 서지정보 채움을 SHALL 실행한다. 대상은 로그인한 기관에 제적이 아닌 사본이 있고 ISBN이 있는 도서로 MUST 제한한다. 소장하지 않은 도서는 외부 API로 조회하지 않는다.

#### Scenario: 소장 도서 처리
- **WHEN** 관리자가 실행하면
- **THEN** 로그인한 기관이 소장한 처리 대기 도서만 외부 API로 조회한다

#### Scenario: 키오스크 계정 거부
- **WHEN** 키오스크 계정이 `POST /book-enrichment/runs`를 호출하면
- **THEN** 403을 돌려주고 외부 API를 호출하지 않는다

#### Scenario: 다른 기관 소장 도서 제외
- **WHEN** B 기관만 소장한 처리 대기 도서가 있고 A 기관 관리자가 실행하면
- **THEN** 그 도서는 조회하지 않고 처리 대기로 남는다

#### Scenario: 제적 사본만 있는 도서 제외
- **WHEN** 로그인한 기관에 제적 사본만 있는 도서가 있으면
- **THEN** 그 도서는 조회하지 않는다

#### Scenario: ISBN 없는 도서 제외
- **WHEN** 로그인한 기관이 소장한 도서에 ISBN이 없으면
- **THEN** 그 도서는 조회하지 않고 처리 대기로 남는다

### Requirement: 나눠서 처리
시스템은 한 번의 실행에서 `limit`(기본 50, 최대 100)건까지만 SHALL 처리하고, 처리 결과를 도서마다 바로 저장한다. 응답에는 처리 건수, 결과별 건수, 남은 처리 대기 건수, 중단 사유를 담는다. 처리된 도서는 다음 실행에서 다시 조회하지 않는다.

#### Scenario: limit만큼 처리
- **WHEN** 처리 대기 도서가 3권이고 `limit` 2로 실행하면
- **THEN** 2권을 처리하고 남은 처리 대기 건수 1을 돌려준다

#### Scenario: 이어서 처리
- **WHEN** 위 실행 뒤 다시 실행하면
- **THEN** 남은 1권만 조회한다

#### Scenario: limit 상한 초과
- **WHEN** `limit` 101로 실행하면
- **THEN** 422를 돌려주고 외부 API를 호출하지 않는다

### Requirement: 가져오기와 분리
장서 가져오기의 미리 보기와 적용은 외부 도서 API를 MUST NOT 호출한다. 새로 만든 도서는 처리 대기 상태로 저장한다.

#### Scenario: 가져오기로 만든 도서
- **WHEN** 파일을 적용해 새 도서가 만들어지면
- **THEN** 외부 API 호출 없이 그 도서는 처리 대기 상태가 된다

### Requirement: 빈 필드만 채우기
시스템은 출판사, 출간일, 정가, 소개, 표지 URL이 비어 있을 때만 외부 값으로 SHALL 채운다. 이미 값이 있는 필드와 서명, 저자, ISBN, 대상 구분 값은 외부 값으로 덮어쓰지 않는다. 대상 구분은 외부 분류 판단 규칙으로만 바뀐다.

#### Scenario: 빈 필드 채우기
- **WHEN** 소개와 표지 URL이 빈 도서가 조회되면
- **THEN** 소개와 표지 URL이 외부 값으로 채워지고 처리 상태는 `enriched`가 된다

#### Scenario: 기존 값 유지
- **WHEN** 출판사가 `담당자 입력 출판사`인 도서의 외부 응답 출판사가 다르면
- **THEN** 출판사는 `담당자 입력 출판사`로 남는다

#### Scenario: 서명과 저자 유지
- **WHEN** 외부 응답의 서명과 저자가 도서와 다르면
- **THEN** 도서의 서명과 저자는 바뀌지 않는다

#### Scenario: 소개가 없고 줄거리만 있음
- **WHEN** 외부 응답에 책 소개가 없고 줄거리만 있으면
- **THEN** 소개가 줄거리로 채워진다

### Requirement: 추가 서지정보 보관
시스템은 부제, 쪽수, 목차, 시리즈명, 상품 링크, 외부 분류 값을 외부 응답에서 SHALL 보관하고 도서 조회 응답에 포함한다. 시리즈가 여러 개이면 이름을 쉼표로 이어서 보관한다.

#### Scenario: 추가 정보 저장
- **WHEN** 부제, 쪽수, 목차, 시리즈명이 있는 응답을 처리하면
- **THEN** `GET /books/{id}`가 그 값을 돌려준다

#### Scenario: 시리즈 여러 개
- **WHEN** 응답의 시리즈가 `민들레그림책`과 `우리그림책` 두 개이면
- **THEN** 시리즈명은 `민들레그림책, 우리그림책`이 된다

### Requirement: 응답 값 정규화
시스템은 외부 응답의 빈 문자열을 값 없음으로 MUST 다룬다. 출간일은 `YYYYMMDD`와 `YYYY-MM-DD`를 읽고, 정가는 원 단위 정수로 바꾸고, 소개와 목차의 줄바꿈은 `\n`으로 통일한다. 읽을 수 없거나 저장 길이를 넘는 값은 그 필드만 비워 두고 처리를 계속한다.

#### Scenario: 빈 문자열
- **WHEN** 응답의 부제가 빈 문자열이면
- **THEN** 부제는 비어 있는 값으로 저장된다

#### Scenario: 8자리 출간일
- **WHEN** 응답의 출간일이 `19960401`이면
- **THEN** 출간일은 1996-04-01로 저장된다

#### Scenario: 하이픈 출간일
- **WHEN** 응답의 출간일이 `2013-12-24`이면
- **THEN** 출간일은 2013-12-24로 저장된다

#### Scenario: 읽을 수 없는 출간일
- **WHEN** 응답의 출간일이 `미정`이면
- **THEN** 출간일만 비워 두고 다른 필드는 채운다

#### Scenario: 소수 표기 정가
- **WHEN** 응답의 정가가 `14000.0`이면
- **THEN** 정가는 정수 14000으로 저장된다

#### Scenario: 줄바꿈 정리
- **WHEN** 응답의 소개에 `\r\n`이 있으면
- **THEN** 저장된 소개의 줄바꿈은 `\n`이다

### Requirement: 저장하지 않는 값
시스템은 판매가, 판매 상태, 포인트, 판매지수, 평점을 MUST NOT 저장한다. 표지는 원본 URL만 저장하고 이미지 파일을 내려받지 않는다.

#### Scenario: 변동 정보 미저장
- **WHEN** 판매가와 판매 상태가 있는 응답을 처리하면
- **THEN** 그 값은 도서 조회 응답과 데이터베이스 어디에도 없다

#### Scenario: 표지 파일 미저장
- **WHEN** 표지 URL이 있는 응답을 처리하면
- **THEN** 원본 URL만 저장되고 이미지 요청은 일어나지 않는다

### Requirement: ISBN 일치 확인
시스템은 응답 상품의 ISBN13이 요청한 도서의 ISBN과 같을 때만 값을 MUST 채운다. 같은 상품이 없으면 도서를 바꾸지 않고 처리 상태를 `mismatch`로 저장한다.

#### Scenario: 다른 책 응답
- **WHEN** 요청한 ISBN과 다른 ISBN13의 상품만 응답에 있으면
- **THEN** 도서의 서지 필드는 바뀌지 않고 처리 상태는 `mismatch`가 된다

### Requirement: 찾지 못한 도서
시스템은 외부 API가 상품을 찾지 못하면 처리 상태를 `not_found`로 SHALL 저장하고 실행을 계속한다. `not_found`와 `mismatch` 도서는 기본 실행에서 다시 조회하지 않고, `retry_failed=true`로 실행할 때 처리 대기 도서 뒤에 다시 조회한다.

#### Scenario: 상품 없음
- **WHEN** 외부 API가 404를 돌려주면
- **THEN** 그 도서는 `not_found`가 되고 다음 도서를 처리한다

#### Scenario: 결과가 빈 성공 응답
- **WHEN** 외부 API가 성공 응답에 빈 상품 목록을 돌려주면
- **THEN** 그 도서는 `not_found`가 된다

#### Scenario: 기본 실행에서 제외
- **WHEN** `not_found` 도서만 있는 기관에서 기본 실행을 하면
- **THEN** 외부 API를 호출하지 않는다

#### Scenario: 다시 시도
- **WHEN** `retry_failed=true`로 실행하고 이번에는 상품을 찾으면
- **THEN** 그 도서는 `enriched`가 된다

### Requirement: ISBN 변경 시 다시 대기
시스템은 도서의 ISBN이 다른 값으로 바뀌면 처리 상태를 처리 대기로 MUST 되돌린다. 이미 채운 값은 지우지 않는다.

#### Scenario: ISBN 수정
- **WHEN** `not_found` 도서의 ISBN을 `PATCH /books/{id}`로 고치면
- **THEN** 처리 상태가 처리 대기가 된다

### Requirement: 호출 속도 제한
시스템은 외부 API를 초당 5회 이하로 SHALL 호출한다. 외부 API의 초당 한도는 키 하나를 기준으로 하므로, 같은 서버 프로세스의 동시 실행도 이 제한을 함께 쓴다.

#### Scenario: 연속 호출 간격
- **WHEN** 한 실행에서 도서 3권을 연달아 처리하면
- **THEN** 호출 사이의 간격은 0.2초 이상이다

#### Scenario: 동시 실행
- **WHEN** 두 기관이 동시에 실행하면
- **THEN** 두 실행을 합친 호출 간격도 0.2초 이상이다

### Requirement: 외부 장애 시 중단
시스템은 호출 한도 초과, 인증 실패, 외부 장애, 네트워크 오류가 나면 그 실행을 MUST 멈추고 200과 중단 사유를 돌려준다. 그 도서와 남은 도서는 처리 대기로 두고, 이미 처리한 도서의 결과는 유지한다.

#### Scenario: 호출 한도 초과
- **WHEN** 두 번째 도서에서 외부 API가 429를 돌려주면
- **THEN** 첫 번째 도서의 결과는 저장되고, 나머지는 처리 대기로 남고, 중단 사유는 `rate_limited`이다

#### Scenario: 외부 서비스 장애
- **WHEN** 외부 API가 503을 돌려주면
- **THEN** 실행을 멈추고 중단 사유는 `upstream_unavailable`이다

#### Scenario: 네트워크 오류
- **WHEN** 외부 API 호출이 시간 초과되면
- **THEN** 실행을 멈추고 중단 사유는 `upstream_unavailable`이다

#### Scenario: 인증 실패
- **WHEN** 외부 API가 401을 돌려주면
- **THEN** 실행을 멈추고 중단 사유는 `auth_failed`이며 관리자의 로그인은 유지된다

### Requirement: API 키 보호
시스템은 API 키를 환경 설정에서만 MUST 읽고 요청 헤더로만 보낸다. 키 값은 응답, 로그, 오류 메시지에 남기지 않는다. 키가 설정되지 않았으면 실행 요청에 503을 돌려준다.

#### Scenario: 키 미설정
- **WHEN** API 키가 비어 있는 서버에서 실행하면
- **THEN** 503을 돌려주고 도서의 처리 상태는 바뀌지 않는다

#### Scenario: 키 헤더 전송
- **WHEN** 외부 API를 호출하면
- **THEN** 키는 `X-Api-Key` 헤더로만 전송되고 URL에는 없다

#### Scenario: 오류에 키 없음
- **WHEN** 외부 호출이 실패해 실행 응답을 돌려주면
- **THEN** 응답과 로그에 키 값이 없다

### Requirement: 외부 분류 판단
시스템은 외부 분류 값이 정확히 `국내도서-유아`, `국내도서-어린이`, `국내도서-초등학습서` 중 하나이고 성인물이 아닌 도서만 어린이 근거로 MUST 인식한다. 근거가 있고 도서의 근거가 `default`이면 대상 구분을 `children`, 근거를 `external_category`로 정한다. 근거가 없으면 대상 구분을 바꾸지 않는다.

#### Scenario: 유아 분류
- **WHEN** 근거가 `default`인 도서의 외부 분류가 `국내도서-유아`이면
- **THEN** 대상 구분은 `children`, 근거는 `external_category`가 된다

#### Scenario: 어린이 분류
- **WHEN** 근거가 `default`인 도서의 외부 분류가 `국내도서-어린이`이면
- **THEN** 대상 구분은 `children`, 근거는 `external_category`가 된다

#### Scenario: 초등학습서 분류
- **WHEN** 근거가 `default`인 도서의 외부 분류가 `국내도서-초등학습서`이면
- **THEN** 대상 구분은 `children`, 근거는 `external_category`가 된다

#### Scenario: 어린이 근거가 아닌 분류
- **WHEN** 외부 분류가 `국내도서-청소년`, `국내도서-전집`, `국내도서-중고등학습서-중학교`, `국내도서-소설/시/희곡`이거나 비어 있으면
- **THEN** 대상 구분과 근거는 바뀌지 않는다

#### Scenario: 성인물 제외
- **WHEN** 외부 분류가 `국내도서-어린이`이고 성인물 여부가 `Y`이면
- **THEN** 대상 구분과 근거는 바뀌지 않는다

#### Scenario: 높은 근거 유지
- **WHEN** 근거가 `manual`이고 대상 구분이 `general`인 도서의 외부 분류가 `국내도서-유아`이면
- **THEN** 대상 구분은 `general`, 근거는 `manual`로 남는다

#### Scenario: 분류 값 보관
- **WHEN** 외부 분류가 `국내도서-청소년`인 응답을 처리하면
- **THEN** 대상 구분은 바뀌지 않고 외부 분류 값은 조회 응답에 나온다

### Requirement: 처리 현황 조회
시스템은 관리자의 `GET /book-enrichment` 요청에 로그인한 기관의 소장 도서를 처리 상태별로 센 건수와 ISBN 없는 도서 건수를 SHALL 돌려준다. 다른 기관만 소장한 도서는 세지 않는다.

#### Scenario: 상태별 건수
- **WHEN** 소장 도서가 처리 대기 2권, `enriched` 1권, ISBN 없음 1권이면
- **THEN** 처리 대기 2, `enriched` 1, ISBN 없음 1을 돌려준다

#### Scenario: 기관 분리
- **WHEN** B 기관만 소장한 도서가 있고 A 기관 관리자가 조회하면
- **THEN** 그 도서는 건수에 들어가지 않는다

#### Scenario: 키오스크 계정 거부
- **WHEN** 키오스크 계정이 `GET /book-enrichment`를 호출하면
- **THEN** 403을 돌려준다

### Requirement: 출처 표시
시스템은 외부 API에서 찾은 도서의 조회 응답에 출처 이름과 상품 링크를 MUST 함께 돌려준다. 외부 API에서 찾지 못한 도서는 출처를 비워 둔다.

#### Scenario: 출처와 링크
- **WHEN** 외부 API로 채운 도서를 `GET /books/{id}`로 조회하면
- **THEN** 출처 `yes24`와 상품 링크가 함께 나온다

#### Scenario: 채우지 않은 도서
- **WHEN** 처리 대기 도서를 조회하면
- **THEN** 출처와 상품 링크는 비어 있다
