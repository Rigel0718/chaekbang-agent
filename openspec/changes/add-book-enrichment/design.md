# Design

## Context

**지금 코드에 있는 것**
- `books`는 기관 공통이다. `cover_url`, `description`은 있지만 비어 있고, 근거는 `default`, `manual`, `import_label`뿐이다.
- `holding_imports._fill_book`은 근거가 `default`일 때만 파일 근거를 적용한다.
- `httpx`는 이미 의존성에 있다. `app/external/`은 없고, `.env.example`에 `YES24_API_KEY`가 있지만 `Settings`에는 없다.
- service는 HTTP를 모르고, REST 오류는 `main.py`의 핸들러가 상태 코드로 바꾼다.

**외부 API에서 확인한 것** (`yes24-open-api-guide/`, 2026-11-07 실제 호출)
- 한도는 키 기준 하루 20,000회, 초당 10회다. 초과하면 HTTP 429이고, 일일 한도는 자정에 초기화된다.
- 상품 응답에 `categoryId`는 없다. 분류 값은 `goodsSortNm`이다.
- 문서와 다른 실제 값: `publishDate`는 `19960401`, `goodsType`은 `도서`, `goodsSortNm`은 `국내도서-유아`, 빈 값은 `""`로 온다.
- `cover`는 표지가 없는 상품에도 대체 이미지 URL을 돌려준다.

**표본** (카테고리별 베스트셀러 상위 100건씩, 6개 카테고리 600건)

인기 도서에 치우친 표본이다. 값의 형태를 본 것이지 분류 정확도가 아니다.

| 조회한 카테고리 | 규칙으로 `children`이 되는 건수 |
| --- | --- |
| 유아 | 100 |
| 어린이 | 98 (나머지 2건은 `국내도서-청소년`) |
| 청소년 | 1 |
| 소설/시/희곡, 전집, 초등참고서 | 각 0 |

전집 100건 중 99건은 ISBN이 없고 98건은 소개가 없었다. `초등참고서` 카테고리의 값은 `국내도서-초등학습서`였고 `국내도서-중고등학습서-중학교`처럼 3단인 값도 있어서, `goodsSortNm`은 카테고리 이름과 항상 같지 않다.

**YES24 FAQ의 이용 조건**
- 서비스 제공에 필요한 범위의 캐싱은 허용한다.
- 전체 도서 정보를 수집해 자체 DB로 축적하거나 제3자에게 재배포하는 것은 허용하지 않는다.
- 가격·재고 같은 변동 정보는 갱신 주기를 짧게 유지해야 한다.

## Goals / Non-Goals

**Goals:**
- 새 엔드포인트나 필드를 정의 파일에 추가하는 것으로 끝나게 한다.
- 파싱과 분류 판단을 DB 없는 순수 함수로 두어 표 형태로 테스트한다.
- service 함수는 HTTP 프레임워크를 모르게 두어, 이후 에이전트 tool이 그대로 쓰게 한다.
- 테스트는 실제 네트워크를 쓰지 않는다.

**Non-Goals:**
- 여러 서버 프로세스 사이의 호출 속도 조율. MVP는 프로세스 하나로 띄우고, 넘치면 429 중단으로 처리한다.
- 호출 재시도. 다음 실행이 이어서 처리하므로 한 실행 안에서는 다시 시도하지 않는다.
- 이미 `enriched`인 도서의 갱신.

## Decisions

### 1. 모듈 구성

```
app/external/yes24/
├── definitions.py  # Base URL, 엔드포인트, 응답 필드 이름, 오류 구분, 어린이 분류 값
├── client.py       # 인증 헤더, 호출 속도 제한, 응답 봉투 해석, 오류 → 예외
├── parsing.py      # 응답 상품 → Yes24Item (빈 문자열, 날짜, 정가, 줄바꿈)
├── classify.py     # 외부 분류 값 → 어린이 근거 여부
└── goods.py        # GOODS API 역할 함수: get_item_by_isbn
app/services/book_enrichment.py  # 실행, 현황
app/api/book_enrichment.py
```

`category.py`는 Category API를 쓰는 change에서 추가한다. 쓰지 않는 코드를 미리 만들지 않는다. 역할 함수에는 하는 일을 한국어로 적는다.

### 2. 정의 파일 한곳에 모으기

`definitions.py`에 엔드포인트(이름, 경로)와 `Yes24Item` 필드별 응답 키를 표로 둔다. `parsing.py`는 이 표를 읽어 값을 꺼내고, 응답 키 문자열을 다른 파일에 쓰지 않는다. 새 필드는 표에 한 줄 추가하고 필요하면 변환 함수를 지정한다.
- **대안: 응답 전체를 Pydantic 모델로 정의** → 문서와 실제 값이 달라서 한 필드만 어긋나도 응답 전체가 실패한다. 필드별로 관대하게 읽어야 "그 필드만 비우고 계속"을 지킬 수 있다.

### 3. `itemDetail` 하나, `detail=Y`

한 번의 호출로 서지정보, 분류, 쪽수, 시리즈를 모두 받는다. `searchType=ISBN13`은 생략해도 되지만 항상 명시한다.
- **대안: `itemList`로 ISBN 검색** → 결과가 없으면 검색어가 자동 교정돼서 다른 책이 나올 수 있다.

### 4. 어린이 판단은 정확히 일치하는 값으로

`CHILDREN_CATEGORIES = {"국내도서-유아", "국내도서-어린이"}`와 완전히 일치하고 `adultYn != "Y"`일 때만 근거로 본다.
- `-`로 나누거나 "어린이"가 포함됐는지 보지 않는다. 표본에서 값이 카테고리 이름과 다르고 단계 수도 달랐기 때문이다.
- 초등학습서는 근거가 아니다. 읽을거리 추천 대상이 아니고 분류 값이 대상 연령을 말하지 않는다.
- 전집, 청소년은 근거가 아니다. 애매하면 `general`로 두는 원칙을 따른다.
- 분류 원문을 `external_category`에 보관한다. 규칙을 바꿔도 외부 호출 없이 다시 계산할 수 있다.
- **대안: `category.json`으로 카테고리 ID 판단** → 상품 응답에 카테고리 ID가 없어서 연결할 수 없다.

### 5. 데이터 모델

`books`에 추가하는 열 (모두 기관 공통, 기존 행은 비어 있거나 기본값):

| 열 | 타입 | 내용 |
| --- | --- | --- |
| subtitle | String(500)? | 부제 |
| page_count | Integer? | 쪽수 |
| table_of_contents | Text? | 목차 |
| series_name | String(500)? | 시리즈명, 여러 개면 쉼표로 연결 |
| external_source | enum? | 출처 (`yes24`) |
| external_url | String(1000)? | 상품 링크 |
| external_category | String(100)? | 외부 분류 원문 (`goodsSortNm`) |
| enrichment_status | enum, 기본 `pending` | `pending`, `enriched`, `not_found`, `mismatch` |
| enrichment_checked_at | DateTime(tz)? | 마지막 처리 시각 |

- `AudienceSource`에 `external_category`를 추가한다.
- ISBN 없음은 상태로 저장하지 않고 `isbn IS NULL`로 센다. 상태로 저장하면 나중에 ISBN을 채울 때 되돌리는 경로가 하나 더 생긴다.
- 소개는 `bookIntroduction`을 쓰고, 없으면 `bookSummary`를 쓴다. 줄거리 열을 따로 두지 않는다.
- 도서 수정·등록 스키마에는 새 열을 넣지 않는다. 외부 값이고 관리자가 입력할 값이 아니다.
- **대안: 별도 `book_enrichments` 테이블** → 도서와 1:1이고 조회할 때마다 조인이 늘어난다. 나중에 정보나루가 붙어 출처별 기록이 필요해지면 그때 나눈다.

### 6. 실행 흐름

1. 대상 도서 id를 조회한다. 기관의 제적 아닌 사본이 있고 ISBN이 있으며 상태가 `pending`인 도서를 id 순으로 고른다. `retry_failed`면 그 뒤에 `not_found`, `mismatch`를 붙인다.
2. 트랜잭션을 끝낸 뒤 도서마다 외부 API를 호출한다. 외부 호출 동안 DB 트랜잭션이나 행 잠금을 잡지 않는다.
3. 응답을 받으면 도서를 `FOR UPDATE`로 다시 읽고, 이미 다른 실행이 끝낸 도서면 건너뛴다. 빈 필드 판단은 이 시점의 값으로 해서 그 사이의 관리자 수정을 덮어쓰지 않는다.
4. 도서마다 커밋한다. 중단돼도 처리한 결과가 남는다.

- 응답은 요청 안에서 끝낸다. `limit` 100이면 약 20초다. 작은도서관 장서가 수천 권이어도 몇 번 나눠 실행하면 된다.
- **대안: 백그라운드 작업 큐** → 지금 규모에 비해 무겁고, 상태가 도서마다 저장돼 있어 나중에 스케줄러가 같은 service를 부르도록 바꾸기 쉽다.
- 처리 대상은 기관 범위지만 결과는 기관 공통 도서에 쓴다. 한 기관이 채운 값은 같은 책을 가진 다른 기관에도 보인다.

### 7. 호출 속도와 오류 구분

프로세스 공유 제한기가 호출 사이를 최소 0.2초로 벌린다. 공식 한도의 절반이다.

| 외부 결과 | 처리 |
| --- | --- |
| 200 + 상품 있음, ISBN 일치 | `enriched` |
| 200 + 상품 있음, ISBN 불일치 | `mismatch` |
| 200 + 빈 목록, 404, `PARAM_004` | `not_found`, 다음 도서로 |
| 429 | 중단 `rate_limited` |
| 401 | 중단 `auth_failed` |
| 그 밖의 4xx·5xx, 시간 초과, 네트워크 오류, 해석 불가 응답 | 중단 `upstream_unavailable` |

- 429는 문서에 오류 코드가 없어서 본문이 아니라 HTTP 상태로 판단한다.
- 외부 401을 우리 API의 401로 돌려주지 않는다. 관리자 로그인이 풀린 것처럼 보이기 때문이다.
- 중단은 실패가 아니라 결과이므로 200으로 돌려준다. 키 미설정은 아무것도 시작하지 못하므로 503이다. 새 `ServiceUnavailableError`와 핸들러를 추가한다.

### 8. 키 보호

- `Settings.yes24_api_key`는 `SecretStr | None`이다. 설정 객체를 출력해도 값이 나오지 않는다.
- 키는 `X-Api-Key` 헤더로만 보낸다. 예외 메시지에는 HTTP 상태와 오류 코드만 담고 요청 객체나 헤더를 넣지 않는다.

### 9. 테스트

- `get_yes24_client` 의존성을 만들고 테스트에서 `httpx.MockTransport`를 쓰는 클라이언트로 바꾼다. 호출 건수와 요청 내용을 기록해 "호출하지 않음"까지 확인한다.
- 픽스처는 실제 응답 구조를 줄여서 쓴다. 키는 들어가지 않는다.
- 속도 제한은 시계를 주입해 실제로 기다리지 않고 확인한다.

## Risks / Trade-offs

- [분류 규칙의 표본이 인기 도서에 치우침] → 분류 원문을 보관해 규칙을 호출 없이 다시 적용할 수 있게 하고, 관리자 지정이 항상 우선한다.
- [어린이 도서가 `general`로 남음. 전집과 초등학습서가 대표적] → 어린이 요청에 일반 도서가 나가는 것보다 낫다고 본다. 비율은 `add-recommendation-evals`에서 본다.
- [표지가 없는 상품도 대체 이미지 URL이 채워짐] → 표지 유무를 판단에 쓰지 않는다.
- [정가가 오래된 값이 될 수 있음] → 판매가와 판매 상태는 저장하지 않고, 정가는 빈 값을 채우는 데만 쓰며 처리 시각을 남긴다. 구매 요청서의 금액은 해당 change에서 작성 시점의 값을 다시 조회한다.
- [기관 공통 도서를 여러 기관이 함께 보는 것이 재배포인지 FAQ에 명시되지 않음] → 같은 서비스 안의 제공으로 보고, YES24에서 받은 값을 내보내는 외부 API나 파일 기능을 만들지 않는다. 여러 기관에 실제로 서비스하기 전에 YES24에 확인한다.
- [관리자가 직접 넣은 표지에도 도서 단위 출처가 붙을 수 있음] → 지금은 도서 단위로 표기한다. 필드별 출처가 필요해지면 그때 나눈다.
- [프로세스가 여러 개면 속도 제한이 나뉨] → 429가 오면 실행을 멈추고 다음 실행이 이어서 처리한다.

## Migration Plan

1. 리비전을 손으로 작성한다. 열 추가와 `audience_source` CHECK 교체다. 기존 도서는 `pending`이 된다.
2. downgrade는 `external_category` 근거인 도서를 `general`, `default`로 되돌린 뒤 CHECK를 복구하고 열을 지운다. 채운 소개·표지 값은 기존 열이라 남는다.
3. 명령은 `set -eo pipefail`로 실행해 앞 단계가 실패하면 멈춘다.
