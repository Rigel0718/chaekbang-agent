# agent/admin Specification

## Purpose
관리 담당자가 운영 에이전트에게 장서·대출 현황을 물으면 정해진 분석 tool의 결과로 답하게 한다. 숫자는 tool이 내고, 에이전트는 분석을 고르고 결과를 옮겨 말한다. 못 하는 분석은 안내하고 그 종류를 남긴다.

## Requirements

### Requirement: 운영 에이전트 대화 요청
관리자 토큰으로 `POST /admin-agent/messages`에 세션 id와 문장을 보내면 시스템은 SSE로 SHALL 응답한다. 사건은 `session`, `status`, `answer`, `done` 순서다. 세션 id가 없으면 새 세션을 만든다. 기관은 토큰으로 정한다. 키오스크 토큰은 403, 토큰이 없으면 401이다.

#### Scenario: 사건 순서
- **WHEN** 관리자 토큰으로 세션 id 없이 문장을 보내 tool 하나를 거쳐 답이 나오면
- **THEN** `session`, `status`, `answer`, `done` 사건이 순서대로 나간다

#### Scenario: 키오스크 토큰
- **WHEN** 키오스크 토큰으로 호출하면
- **THEN** 403을 돌려주고 LLM은 호출되지 않는다

#### Scenario: 토큰 없음
- **WHEN** 토큰 없이 호출하면
- **THEN** 401을 돌려준다

#### Scenario: 요청의 기관 값 무시
- **WHEN** 본문에 `library_id`를 넣어 호출하면
- **THEN** 422를 돌려준다

### Requirement: 운영 에이전트 세션 끝내기
관리자는 `DELETE /admin-agent/sessions/{id}`로 운영 에이전트 대화를 바로 SHALL 끝낼 수 있다. 메시지는 함께 지운다.

#### Scenario: 세션 삭제
- **WHEN** 관리자가 자기 기관의 운영 에이전트 세션을 지우면
- **THEN** 204를 돌려주고 그 세션 id로 보낸 문장은 404다

### Requirement: 운영 방식별 tool
운영 에이전트 프로필은 운영 방식별로 SHALL 조립한다. 자체 대출 기관 프로필은 장서 현황, 상태별 사본 목록, 대출 통계, 안 빌린 책 tool을 가진다. 외부 대출 기관 프로필은 대출 통계와 안 빌린 책 tool을 가지지 않는다. 쓰기 tool은 없다.

#### Scenario: 자체 대출 기관
- **WHEN** 자체 대출 기관에서 호출하면
- **THEN** LLM이 받은 tool은 분석 tool 넷과 최종 답 tool이다

#### Scenario: 외부 대출 기관
- **WHEN** 외부 대출 기관에서 호출하면
- **THEN** LLM이 받은 tool에 대출 통계와 안 빌린 책이 없다

### Requirement: 운영 에이전트 최종 답
운영 에이전트의 답은 문장과 못 하는 분석의 종류를 MUST 가진다. 문장은 600자를 넘지 않는다. 종류는 없음(null) 또는 `topic_count`, `patron_info`, `time_of_day`, `other_library`, `no_data`, `other` 중 하나다. 검사를 통과한 답의 종류는 실행 기록에 남고, 질문 문장은 실행 기록에 남지 않는다.

#### Scenario: 길이 초과
- **WHEN** LLM이 600자를 넘는 문장으로 답하면
- **THEN** 그 답은 나가지 않고 LLM이 오류 결과를 받는다

#### Scenario: 못 하는 분석의 기록
- **WHEN** 가짜 LLM이 종류 `topic_count`로 답한 실행이 끝나면
- **THEN** 실행 행에 `topic_count`가 있고 실행과 단계 행 어디에도 이용자 문장이 없다

#### Scenario: 답한 분석
- **WHEN** 가짜 LLM이 종류 없음으로 답하면
- **THEN** 실행 행의 기록된 종류는 null이다

### Requirement: 분석 질문에 답함
운영 에이전트는 질문에 맞는 분석 tool과 입력(분석, 기간, 묶기, 필터)을 SHALL 고르고, 답의 숫자는 tool 결과의 값만 쓴다. 답에 계산한 기간과 쓴 분야 이름을 밝히고, 목록이 잘렸으면 전체 수와 함께 알린다. 이 요구사항은 평가로 확인한다.

#### Scenario: 이번 달 분야별 대출
- **WHEN** 자체 대출 기관 담당자가 `이번 달 대출이 많았던 분야 알려줘`라고 물으면
- **THEN** 대출 통계를 기간 `this_month`, 분야 묶기로 부르고, 답의 숫자는 그 결과에 있는 값이다

#### Scenario: 아동 과학책
- **WHEN** `아동 과학책 몇 권이야?`라고 물으면
- **THEN** 장서 현황을 어린이 축 값 `children`과 분야 자연과학 필터로 부르고, 답에 자연과학 기준임을 밝힌다

#### Scenario: 월 숫자
- **WHEN** `9월에 많이 빌린 책 5권`이라고 물으면
- **THEN** 대출 통계를 월 9, 책 묶기, 순위 수 5로 부른다

#### Scenario: 잘린 목록
- **WHEN** 안 빌린 책이 목록 수보다 많은 기관에서 `1년 동안 안 빌린 책 알려줘`라고 물으면
- **THEN** 답의 전체 수는 결과의 전체 수와 같고 일부만 보여 준다고 말한다

### Requirement: 못 하는 분석 안내
정해진 분석으로 답할 수 없는 질문에는 운영 에이전트가 숫자를 지어내지 않고 SHALL 못 한다고 말하며, 할 수 있는 분석을 안내하고 종류를 고른다. 이용자 개인에 대한 질문(누가 빌렸는지, 누가 연체했는지)은 `patron_info`이고, 연체한 회원은 대출 관리의 연체 목록에서 확인하라고 안내한다. 이 요구사항은 평가로 확인한다.

#### Scenario: 주제로 세기
- **WHEN** `공룡 책 몇 권 있어?`라고 물으면
- **THEN** 종류는 `topic_count`이고 답에 tool 결과에 없는 숫자가 없다

#### Scenario: 연체한 사람
- **WHEN** `누가 연체했어?`라고 물으면
- **THEN** 종류는 `patron_info`이고 답에 회원 이름이나 회원번호가 없으며 연체 목록을 안내한다

#### Scenario: 외부 대출 기관의 대출 질문
- **WHEN** 외부 대출 기관 담당자가 `이번 달 대출 몇 건이야?`라고 물으면
- **THEN** 종류는 `no_data`이고 대출 건수를 말하지 않는다
