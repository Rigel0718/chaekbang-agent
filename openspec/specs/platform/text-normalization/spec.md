# platform/text-normalization Specification

## Purpose

출처와 입력 경로가 달라도 같은 글자·같은 이름·같은 분류가 같은 값으로 맞춰지도록, 저장용과 비교용 정규화 규칙을 한 곳에 두고 코드와 데이터베이스가 같은 결과를 내게 한다.

## Requirements

### Requirement: 저장용 정규화
시스템은 저장할 글자 값을 보여 줄 수 있는 깨끗한 값으로 MUST 다듬는다. 앞뒤 공백을 없애고, 겹친 공백을 하나로 줄이고, 보이지 않는 글자를 지우고, 유니코드를 NFC로 맞춘다. 대소문자, 문장부호, 낱말 사이 공백 하나는 바꾸지 않는다.

#### Scenario: 공백 정리
- **WHEN** `  공룡  백과\t2권 `을 저장용으로 다듬으면
- **THEN** `공룡 백과 2권`이 된다

#### Scenario: 분해형 한글
- **WHEN** 자모가 따로 저장된 분해형(NFD) `김영하`를 저장용으로 다듬으면
- **THEN** 완성형(NFC) `김영하`와 같은 문자열이 된다

#### Scenario: 표기는 그대로
- **WHEN** `J.K. Rowling`을 저장용으로 다듬으면
- **THEN** 대소문자와 마침표가 그대로다

### Requirement: 비교용 정규화
시스템은 글자 값을 맞춰 볼 때 비교용 키로 MUST 바꿔 비교한다. 비교용 키는 NFC로 맞추고, 전각 영문·숫자·기호를 반각으로 바꾸고, 모든 공백과 보이지 않는 글자를 지우고, 소문자로 바꾼 값이다. 비교용 키는 화면에 보이지 않는다. 한글 호환 자모(`ㄱ`, `ㅏ`)는 바꾸지 않는다.

#### Scenario: 띄어쓰기와 대소문자
- **WHEN** `Dinosaur ATLAS`와 `dinosauratlas`를 비교용으로 바꾸면
- **THEN** 두 키가 같다

#### Scenario: 전각 글자
- **WHEN** `ＡＢＣ１２３`과 `abc123`을 비교용으로 바꾸면
- **THEN** 두 키가 같다

#### Scenario: 분해형 한글
- **WHEN** 분해형(NFD) `공룡 백과`와 완성형 `공룡백과`를 비교용으로 바꾸면
- **THEN** 두 키가 같다

#### Scenario: 조합 중인 자모는 그대로
- **WHEN** `데미ㅇ`을 비교용으로 바꾸면
- **THEN** 호환 자모 `ㅇ`이 다른 글자로 바뀌지 않는다

### Requirement: 코드와 SQL의 일치
데이터베이스 안에서도 쓰는 정규화 규칙(비교용 키, 자모 키, 낱말 시작 키)은 코드와 SQL이 같은 결과를 MUST 낸다.

#### Scenario: 비교용 키 일치
- **WHEN** 공백 종류, 전각 글자, 분해형 한글, 대소문자가 섞인 문자열들을 코드 규칙과 SQL 식으로 각각 비교용 키로 바꾸면
- **THEN** 모든 문자열에서 결과가 같다

#### Scenario: 자모 키 일치
- **WHEN** 전각 글자와 분해형 한글이 섞인 문자열들을 코드 규칙과 SQL 함수로 각각 자모 키와 낱말 시작 키로 바꾸면
- **THEN** 모든 문자열에서 결과가 같다

### Requirement: 이름 맞춤 키
시스템은 사람 이름, 단체 이름, 시리즈명을 맞춰 볼 때 이름 맞춤 키를 MUST 쓴다. 이름 맞춤 키는 비교용 키에서 문장부호와 기호를 뺀 값(글자와 숫자만)이다. 음역이 다른 외국 이름과 동명이인은 이 규칙으로 풀지 않는다.

#### Scenario: 띄어 쓴 이름
- **WHEN** `김 영 하`와 `김영하`의 이름 맞춤 키를 만들면
- **THEN** 두 키가 같다

#### Scenario: 마침표와 대소문자
- **WHEN** `J.K. Rowling`과 `j.k.rowling`의 이름 맞춤 키를 만들면
- **THEN** 두 키가 모두 `jkrowling`이다

#### Scenario: 시리즈명
- **WHEN** `민음사 세계문학전집`과 `민음사  세계문학전집`의 이름 맞춤 키를 만들면
- **THEN** 두 키가 같다

#### Scenario: 음역이 다른 이름
- **WHEN** `조앤 K. 롤링`과 `J.K. 롤링`의 이름 맞춤 키를 만들면
- **THEN** 두 키가 다르다

#### Scenario: 기호뿐인 값
- **WHEN** `-`의 이름 맞춤 키를 만들면
- **THEN** 빈 문자열이다

### Requirement: KDC 키
시스템은 분류기호 표기를 KDC 숫자 문자열(세 자리 숫자와, 있으면 소수점 아래 숫자)로 MUST 맞춘다. 전각 숫자, 공백, 앞에 붙은 `KDC`, 뒤에 붙은 저자기호는 무시한다. 세 자리 숫자로 시작하지 않는 값은 KDC로 읽지 않는다.

#### Scenario: 표기가 달라도 같은 값
- **WHEN** `813.7`, `KDC 813.7`, `８１３．７`, `813.7-한232ㅊ`의 KDC 키를 만들면
- **THEN** 모두 `813.7`이다

#### Scenario: 소수점 없는 값
- **WHEN** `813`과 `813.`의 KDC 키를 만들면
- **THEN** 둘 다 `813`이다

#### Scenario: 읽을 수 없는 값
- **WHEN** `문학`, `81`, `아 813`의 KDC 키를 만들면
- **THEN** 모두 값이 없다

### Requirement: 서명 정렬 순서
시스템이 서명으로 순서를 정하는 모든 곳은 한국어 정렬 규칙 하나를 MUST 쓴다. 기호·공백, 숫자, 한글, 영문 순서이고, 한글은 가나다순이다. 영문은 대소문자를 가리지 않고 줄 세우며, 같으면 소문자가 먼저다. 숫자는 값이 아니라 글자 순서로 본다. 정렬 규칙이 같다고 보는 서명이 있어도 순서는 언제나 하나로 정해진다. 이 규칙은 순서에만 쓰고, 서명·저자를 맞춰 보는 비교(같음, 포함, 앞부분, 유사)는 바꾸지 않는다.

#### Scenario: 가나다순
- **WHEN** 서명이 `하늘`, `가나다`, `나비`인 책을 서명 순으로 줄 세우면
- **THEN** `가나다`, `나비`, `하늘` 순서다

#### Scenario: 숫자·한글·영문이 섞인 서명
- **WHEN** 서명이 `ABC 동화`, `하늘`, `10대`, `가나다`인 책을 서명 순으로 줄 세우면
- **THEN** `10대`, `가나다`, `하늘`, `ABC 동화` 순서다

#### Scenario: 영문 대소문자
- **WHEN** 서명이 `Banana`, `Apple`, `apple`인 책을 서명 순으로 줄 세우면
- **THEN** `apple`, `Apple`, `Banana` 순서다

#### Scenario: 숫자는 글자 순서
- **WHEN** 서명이 `가나다 2`, `가나다 10`인 책을 서명 순으로 줄 세우면
- **THEN** `가나다 10`, `가나다 2` 순서다

#### Scenario: 비교는 그대로
- **WHEN** 서명이 `Apple`인 책이 있고 `apple`로 서명·저자 찾기를 하면
- **THEN** 정렬 규칙을 더하기 전과 같이 서명 전체 일치로 맞는다
