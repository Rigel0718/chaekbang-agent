# catalog/book-embeddings Specification

## Purpose
기관 도서를 임베딩 벡터로 만들어 저장하고 바뀐 책만 다시 만든다. 텍스트 구성과 모델이 바뀌어도 같은 구조로 버전별 벡터를 함께 두어 비교할 수 있게 하고, 조회는 한 기관의 추천 가능한 책 안에서만 한다.

## Requirements

### Requirement: 임베딩 텍스트 구성
시스템은 기관 도서 하나의 임베딩 텍스트를 표시 값(연결된 공식 서지의 값이 먼저, 비어 있으면 기관 값)의 서명, 저자, 분류, 소개로 MUST 만든다. 비어 있는 값은 건너뛰고, 같은 값에서는 항상 같은 텍스트가 나온다. 텍스트 구성 규칙에는 버전 번호가 있고, 규칙이 바뀌면 번호가 오른다.

#### Scenario: 공식 값 먼저
- **WHEN** 공식 서지에 연결된 기관 도서의 기관 서명과 공식 서명이 다르면
- **THEN** 임베딩 텍스트에 공식 서명이 들어가고 기관 서명은 들어가지 않는다

#### Scenario: 빈 값 건너뛰기
- **WHEN** 소개와 분류가 없는 기관 도서의 텍스트를 만들면
- **THEN** 서명과 저자만으로 텍스트가 만들어지고 빈 줄이나 빈 항목 표시가 없다

#### Scenario: ISBN 없는 책
- **WHEN** 공식 서지가 없는 기관 도서의 텍스트를 만들면
- **THEN** 기관 값만으로 텍스트가 만들어진다

#### Scenario: 같은 값 같은 텍스트
- **WHEN** 값이 바뀌지 않은 기관 도서의 텍스트를 두 번 만들면
- **THEN** 두 텍스트와 그 해시가 같다

### Requirement: 문서와 질의 인코딩 구분
시스템은 도서(문서)와 검색 질의를 서로 다른 규칙으로 MUST 인코딩한다. 문서는 접두어 없이, 질의는 모델이 정한 질의 접두어(`query: `)를 붙여 인코딩한다. 두 벡터 모두 길이가 1이 되게 정규화하고 차원은 모델의 차원(1024)과 같다. 입력 길이 한도(기본 512토큰, 설정으로 바꿀 수 있다)를 넘는 텍스트는 오류 없이 앞부분만 인코딩한다.

#### Scenario: 질의 접두어
- **WHEN** 질의 `공룡 책`을 질의로 인코딩하면
- **THEN** 임베딩 서버에 `query: 공룡 책`이 전달된다

#### Scenario: 문서에는 접두어 없음
- **WHEN** 도서 텍스트를 문서로 인코딩하면
- **THEN** 임베딩 서버에 그 텍스트가 그대로 전달된다

#### Scenario: 정규화 요청
- **WHEN** 문서나 질의를 인코딩하면
- **THEN** 임베딩 서버에 정규화와 길이 한도 잘라내기를 요청한다

#### Scenario: 차원 불일치
- **WHEN** 임베딩 서버가 설정한 차원과 다른 길이의 벡터를 돌려주면
- **THEN** 인코딩이 오류로 끝나고 벡터는 저장되지 않는다

### Requirement: 인코더 교체
시스템은 임베딩 모델을 실행하는 방법을 적재·조회 코드와 MUST 분리한다. 적재와 조회는 실제 임베딩 서버 없이 다른 인코더로 바꿔 끼워도 동작하고, 벡터에는 만든 인코더의 모델 이름이 남는다.

#### Scenario: 가짜 인코더로 적재와 조회
- **WHEN** 임베딩 서버 없이 가짜 인코더로 적재와 유사도 조회를 실행하면
- **THEN** 벡터가 저장되고 조회 결과가 나온다

#### Scenario: 모델 이름 기록
- **WHEN** 이름이 다른 두 인코더로 같은 기관 도서를 차례로 적재하면
- **THEN** 그 기관 도서에 모델 이름이 다른 벡터 두 개가 있다

### Requirement: 벡터와 메타데이터 저장
시스템은 기관 도서, 모델 이름, 텍스트 버전마다 벡터를 하나만 MUST 저장한다. 벡터와 함께 임베딩한 텍스트의 SHA-256 해시, 만든 시각, 고친 시각을 저장하고, 텍스트 원문은 저장하지 않는다. 모델 이름이나 텍스트 버전이 다른 벡터는 같은 기관 도서에 함께 있을 수 있다.

#### Scenario: 같은 키는 한 행
- **WHEN** 같은 기관 도서를 같은 모델과 텍스트 버전으로 두 번 적재하면
- **THEN** 벡터 행은 하나이고 두 번째 값으로 바뀌어 있다

#### Scenario: 텍스트 버전이 다른 벡터 공존
- **WHEN** 텍스트 버전을 올린 뒤 같은 기관 도서를 다시 적재하면
- **THEN** 이전 버전의 벡터가 남아 있고 새 버전의 벡터가 더해진다

#### Scenario: 원문 미저장
- **WHEN** 소개가 있는 기관 도서를 적재한 뒤 저장된 행을 확인하면
- **THEN** 해시는 임베딩 텍스트의 SHA-256과 같고, 어느 열에도 소개 문구가 없다

### Requirement: 적재 대상
시스템은 추천 가능한 기관 도서(대출 가능이나 대출 중 사본이 하나 이상 있는 책)만 MUST 적재한다. ISBN이 없는 기관 도서도 대상이다. 기관을 지정해 실행하면 그 기관의 책만 다룬다.

#### Scenario: 제적·분실 사본만 남은 책
- **WHEN** 사본이 모두 제적이거나 분실인 기관 도서가 있을 때 전체 적재를 실행하면
- **THEN** 그 기관 도서의 벡터는 만들어지지 않는다

#### Scenario: ISBN 없는 책 포함
- **WHEN** ISBN과 공식 서지가 없고 대출 가능한 사본이 있는 기관 도서가 있을 때 전체 적재를 실행하면
- **THEN** 그 기관 도서의 벡터가 만들어진다

#### Scenario: 기관을 지정한 실행
- **WHEN** A 기관과 B 기관에 책이 있을 때 A 기관만 지정해 전체 적재를 실행하면
- **THEN** B 기관 도서의 벡터는 만들어지지 않는다

### Requirement: 전체 적재와 증분 적재
시스템은 전체 적재와 증분 적재를 MUST 제공한다. 전체 적재는 대상 도서를 모두 인코딩한다. 증분 적재는 현재 모델과 텍스트 버전의 벡터가 없거나, 지금 만든 텍스트의 해시가 저장된 해시와 다른 도서만 인코딩한다. 인코딩은 배치(기본 32권, 설정으로 바꿀 수 있다)로 하고 배치마다 저장을 끝낸다.

#### Scenario: 전체 적재
- **WHEN** 벡터가 없는 대상 도서 5권으로 전체 적재를 실행하면
- **THEN** 5권의 벡터가 저장되고 결과의 인코딩 건수가 5다

#### Scenario: 증분 재실행은 0건
- **WHEN** 전체 적재 직후 데이터를 바꾸지 않고 증분 적재를 실행하면
- **THEN** 인코딩 건수가 0이고 건너뛴 건수가 대상 도서 수와 같으며, 인코더는 한 번도 불리지 않는다

#### Scenario: 바뀐 책만 다시 인코딩
- **WHEN** 적재 뒤 한 기관 도서의 소개를 고치고 증분 적재를 실행하면
- **THEN** 그 한 권만 다시 인코딩되고 해시와 고친 시각이 바뀐다

#### Scenario: 새 책만 인코딩
- **WHEN** 적재 뒤 대상 도서 한 권이 새로 생기고 증분 적재를 실행하면
- **THEN** 새 책 한 권만 인코딩된다

#### Scenario: 배치 크기
- **WHEN** 대상 도서 5권을 배치 크기 2로 전체 적재하면
- **THEN** 인코더가 2권, 2권, 1권으로 세 번 불린다

#### Scenario: 전체 적재는 바뀌지 않은 책도 다시 인코딩
- **WHEN** 전체 적재 직후 데이터를 바꾸지 않고 전체 적재를 다시 실행하면
- **THEN** 대상 도서가 모두 다시 인코딩되고 벡터 행 수는 그대로다

### Requirement: 운영자 실행의 출력과 중단
적재는 운영자가 명령줄에서 MUST 실행할 수 있고, 진행률과 인코딩한 건수, 건너뛴 건수를 출력한다. 임베딩 서버에 닿지 않거나 서버가 오류를 돌려주면 이유를 출력하고 멈추며, 그 전에 저장을 끝낸 배치는 남는다. 종료 코드는 완료 0, 전제 조건·인자 문제 1, 임베딩 서버 장애로 중단 2다.

#### Scenario: 완료 출력
- **WHEN** 대상 도서 5권 중 3권이 이미 적재된 상태에서 증분 적재를 명령줄로 실행하면
- **THEN** 인코딩 2건, 건너뜀 3건이 출력되고 종료 코드가 0이다

#### Scenario: 임베딩 서버가 꺼져 있음
- **WHEN** 임베딩 서버에 연결할 수 없는 상태에서 적재를 실행하면
- **THEN** 서버에 닿지 않는다는 이유와 서버를 켜는 방법이 출력되고 종료 코드가 2다

#### Scenario: 중간 실패 뒤 이어 하기
- **WHEN** 배치 크기 2로 5권을 적재하다 두 번째 배치에서 임베딩 서버가 오류를 돌려주면
- **THEN** 첫 배치의 2권은 저장돼 있고 종료 코드가 2이며, 이어서 증분 적재를 실행하면 나머지 3권만 인코딩된다

#### Scenario: 잘못된 인자
- **WHEN** 전체와 증분을 함께 지정하거나 둘 다 지정하지 않고 실행하면
- **THEN** 사용법이 출력되고 종료 코드가 1이며 아무것도 인코딩되지 않는다

#### Scenario: 다른 모델이 떠 있음
- **WHEN** 임베딩 서버가 설정한 모델과 다른 모델을 제공하거나 입력 길이 한도가 설정과 다르면
- **THEN** 서버가 설정과 다르다는 이유가 출력되고 종료 코드가 1이며 아무것도 저장되지 않는다

### Requirement: 기관 범위 유사도 조회
시스템은 질의 하나를 질의 규칙으로 인코딩해, 지정한 기관의 추천 가능한 기관 도서 중 코사인 유사도가 높은 순서로 MUST 돌려준다(확인용 기본 5권). 다른 기관의 책, 추천 가능하지 않은 책, 모델이나 텍스트 버전이 다른 벡터는 결과에 섞이지 않는다.

#### Scenario: 유사도 순서
- **WHEN** 질의 벡터와 유사도가 다른 책 6권이 적재된 기관에서 조회하면
- **THEN** 유사도가 높은 순서로 5권이 유사도 값과 함께 나온다

#### Scenario: 다른 기관의 책
- **WHEN** B 기관에 질의와 가장 가까운 책이 있을 때 A 기관에서 조회하면
- **THEN** B 기관의 책은 결과에 없다

#### Scenario: 적재 뒤 제적된 책
- **WHEN** 벡터가 있는 책의 사본이 모두 제적된 뒤 조회하면
- **THEN** 그 책은 결과에 없다

#### Scenario: 다른 모델의 벡터
- **WHEN** 같은 책에 다른 모델 이름의 벡터가 함께 있을 때 조회하면
- **THEN** 조회에 쓴 인코더의 모델 이름과 현재 텍스트 버전의 벡터만 비교되고, 책은 한 번만 나온다

#### Scenario: 적재 전 조회
- **WHEN** 벡터가 하나도 없는 기관에서 조회하면
- **THEN** 빈 결과가 나오고 오류가 없다
