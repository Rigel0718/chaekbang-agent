# catalog/topic-recommendation Specification

## Purpose
주제로 찾기 요청("공룡 책", "가벼운 에세이")에 한 기관의 추천 가능한 책 중에서 후보 순위를 만든다. 키워드와 벡터 신호를 합치고 결과를 다양하게 하며, 기관 범위와 추천 가능·범위 조건은 코드로 강제한다. LLM을 쓰지 않는다.

## Requirements

### Requirement: 깊은 키워드 순위
시스템은 키워드 검색과 같은 점수와 같은 순서 규칙으로, 정한 깊이까지 키워드 순위를 MUST 만든다. 깊이는 키워드 검색의 결과 상한(10권)에 묶이지 않는다. 키워드가 하나도 맞지 않는 책은 순위에 없다.

#### Scenario: 상한보다 깊게
- **WHEN** 키워드가 맞는 추천 가능한 책이 30권인 기관에서 깊이 30으로 키워드 순위를 만들면
- **THEN** 30권이 나오고 앞의 10권은 같은 키워드의 키워드 검색 결과와 순서까지 같다

#### Scenario: 맞지 않는 책
- **WHEN** 키워드가 맞는 책이 3권인 기관에서 깊이 30으로 만들면
- **THEN** 3권만 나온다

### Requirement: 순위 합치기
시스템은 신호별 순위를 역순위 합(RRF)으로 MUST 합친다. 책의 점수는 신호마다 `가중치 / (k + 순위)`의 합이고, 그 신호에 없는 책은 그 신호에서 0이다. 점수가 같으면 가장 좋은 신호 순위, 그다음 기관 도서 id 순서다. 결과마다 신호별 순위를 근거로 함께 준다.

#### Scenario: 점수 계산
- **WHEN** k가 60이고 가중치가 모두 1일 때 키워드 1위, 벡터 3위인 책과 벡터 1위만인 책을 합치면
- **THEN** 앞 책의 점수는 1/61 + 1/63, 뒤 책은 1/61이고 앞 책이 먼저다

#### Scenario: 신호 가중치
- **WHEN** 키워드 가중치 0, 벡터 가중치 1로 합치면
- **THEN** 순서가 벡터 순위와 같다

#### Scenario: 근거
- **WHEN** 키워드 2위이고 벡터 순위에 없는 책이 결과에 오르면
- **THEN** 그 책의 근거에 키워드 2위가 있고 벡터 순위는 비어 있다

#### Scenario: 같은 점수
- **WHEN** 두 책이 같은 점수이고 가장 좋은 신호 순위도 같으면
- **THEN** 기관 도서 id가 작은 책이 먼저다

### Requirement: 시리즈 묶기
시스템은 상한을 받아 같은 시리즈의 책이 결과에 상한보다 많이 MUST NOT 나오게 한다. 같은 시리즈는 공식 서지의 시리즈 키가 하나라도 겹치는 것이다. 상한을 넘은 책은 결과에서 빠지고, 남은 책 중 순위가 가장 높은 같은 시리즈 책에 빠진 권수를 적는다. 시리즈 키가 없는 책은 묶이지 않는다. 상한이 없으면 순위를 바꾸지 않는다.

#### Scenario: 상한 1
- **WHEN** 같은 시리즈 키를 가진 책 3권이 1·2·4위인 순위를 상한 1로 묶으면
- **THEN** 1위 책만 남고 그 책에 빠진 권수 2가 적히며, 3위였던 책이 2위가 된다

#### Scenario: 시리즈 없는 책
- **WHEN** 시리즈 키가 없는 ISBN 없는 책 두 권이 순위에 있을 때 상한 1로 묶으면
- **THEN** 두 권 모두 남는다

### Requirement: 결과 다양화
시스템은 다양화 정도 λ를 받아 MMR로 결과 순서를 MUST 다시 정한다. 다음 책은 `λ × 관련도 − (1 − λ) × 이미 고른 책과의 최대 유사도`가 가장 큰 책이다. 관련도는 합친 점수를 후보 안에서 0~1로 맞춘 값이고, 책 사이 유사도는 기본 종류 벡터의 코사인 유사도다. 벡터가 없는 책의 유사도는 0이다. λ가 1이면 순서가 바뀌지 않는다.

#### Scenario: 비슷한 책 뒤로
- **WHEN** 1·2위 책의 벡터가 같고 3위 책의 벡터가 그와 직교하며 관련도 차이가 작을 때 λ 0.5로 다양화하면
- **THEN** 1위, 3위, 2위 순서가 된다

#### Scenario: λ가 1
- **WHEN** λ 1로 다양화하면
- **THEN** 순서가 합친 순위와 같다

### Requirement: 주제로 찾기의 범위
주제로 찾기는 그 기관의 추천 가능한 책 중 부르는 쪽이 넘긴 조건 안의 책만 MUST 돌려준다. 조건은 신호마다 순위를 매기기 전에 건다. 조건의 뜻(예: 어린이 도서)은 공통 코드가 모른다.

#### Scenario: 어린이 조건
- **WHEN** 키워드와 벡터 모두 1위인 일반 도서가 있을 때 어린이 도서 조건을 넘겨 주제로 찾으면
- **THEN** 그 일반 도서는 결과에 없고 결과는 모두 어린이 도서다

#### Scenario: 추천할 수 없는 책
- **WHEN** 키워드가 가장 잘 맞는 책의 사본이 모두 분실일 때 주제로 찾으면
- **THEN** 그 책은 결과에 없다

#### Scenario: 다른 기관의 책
- **WHEN** B 기관에 질의와 가장 잘 맞는 책이 있을 때 A 기관에서 주제로 찾으면
- **THEN** B 기관의 책은 결과에 없다

### Requirement: 같은 입력 같은 결과
주제로 찾기는 같은 데이터, 같은 질의, 같은 설정에서 MUST 같은 순서와 같은 점수를 돌려준다. 난수를 쓰지 않는다.

#### Scenario: 두 번 실행
- **WHEN** 같은 질의와 설정으로 주제로 찾기를 두 번 실행하면
- **THEN** 두 결과의 책 순서, 점수, 근거가 같다

### Requirement: 제품 경로의 주제로 찾기
AI 사서의 소장 도서 검색은 낱말이 있으면 주제로 찾기의 기본 설정으로 순위를 SHALL 만들고 앞의 10권을 낸다. 제품 경로는 순위 설정을 따로 고르지 않는다. 벡터 질의는 기본 설정의 벡터 질의 입력을 따르고, 이용자 문장은 이 경로에 넘기지 않는다. 낱말이 없으면 키워드 없는 둘러보기와 같다.

#### Scenario: 기본 설정과 같은 순서
- **WHEN** 같은 기관, 같은 낱말로 제품 경로와 기본 설정의 주제로 찾기를 부르면
- **THEN** 제품 경로의 결과는 주제로 찾기 결과의 앞 10권과 같은 책, 같은 순서다

#### Scenario: 낱말 없음
- **WHEN** 낱말 없이 제품 경로를 부르면
- **THEN** 결과가 키워드 없는 둘러보기 결과와 같고 인코더를 부르지 않는다

#### Scenario: 결과 수
- **WHEN** 키워드나 벡터로 맞는 추천 가능한 책이 30권인 기관에서 부르면
- **THEN** 10권이 나온다

### Requirement: 키워드 순위로 내려가기
제품 경로는 질의 인코딩이 실패하거나, 시간 제한을 넘거나, 서버가 설정과 다른 모델을 제공하거나, 인코더가 없으면 키워드 순위만으로 결과를 MUST 만든다. 이때 결과는 같은 낱말의 키워드 검색과 같은 책, 같은 순서다. 결과 모양은 바뀌지 않고, 로그에는 실패 종류만 남기며 낱말과 이용자 문장을 남기지 않는다.

#### Scenario: 서버가 꺼짐
- **WHEN** 임베딩 서버에 닿지 않는 상태에서 낱말 `공룡`으로 부르면
- **THEN** 결과가 낱말 `공룡`의 키워드 검색 결과와 같은 책, 같은 순서다

#### Scenario: 시간 제한
- **WHEN** 질의 인코딩이 시간 제한보다 오래 걸리면
- **THEN** 시간 제한이 지난 뒤 키워드 순위로 결과가 나온다

#### Scenario: 다른 모델
- **WHEN** 임베딩 서버가 설정과 다른 모델 이름을 알리면
- **THEN** 벡터 순위를 쓰지 않고 키워드 순위로 결과가 나온다

#### Scenario: 로그
- **WHEN** 인코딩이 실패해 내려가면
- **THEN** 로그에 실패 종류가 있고 낱말은 없다

### Requirement: 질의 인코딩 쉬기
질의 인코딩이 실패하면 시스템은 정한 시간(기본 30초) 동안 임베딩 서버를 MUST NOT 부르고 그동안의 요청은 바로 키워드 순위로 내려간다. 그 시간이 지나면 다시 부른다. 처음 쓸 때 서버의 모델과 입력 한도를 한 번 확인하고, 확인에 성공하면 다시 확인하지 않는다.

#### Scenario: 쉬는 동안
- **WHEN** 인코딩이 한 번 실패한 뒤 10초 안에 다시 부르면
- **THEN** 임베딩 서버에 요청이 가지 않고 키워드 순위로 결과가 나온다

#### Scenario: 쉬기가 끝남
- **WHEN** 인코딩이 실패하고 30초가 지난 뒤 다시 부르면
- **THEN** 임베딩 서버에 요청이 간다

#### Scenario: 모델 확인 한 번
- **WHEN** 서버가 정상일 때 제품 경로를 세 번 부르면
- **THEN** 모델 확인 요청은 한 번이다

### Requirement: 키워드 근거 없음 표시
제품 경로는 낱말이 있는데 키워드 순위가 비고 벡터 순위로만 결과가 나오면 결과에 키워드 근거가 없다는 표시를 SHALL 붙인다. 키워드 순위에 한 권이라도 있으면 표시하지 않는다. 결과를 비우는 유사도 문턱은 두지 않는다.

#### Scenario: 낱말이 맞는 책 없음
- **WHEN** 어느 책에도 들어 있지 않은 낱말로 부르고 벡터 순위에 책이 있으면
- **THEN** 결과에 벡터 순위의 책이 있고 키워드 근거 없음 표시가 있다

#### Scenario: 낱말이 맞는 책 있음
- **WHEN** 한 권에만 들어 있는 낱말로 부르면
- **THEN** 키워드 근거 없음 표시가 없다

#### Scenario: 내려간 결과
- **WHEN** 인코딩이 실패한 상태에서 어느 책에도 들어 있지 않은 낱말로 부르면
- **THEN** 결과가 비어 있고 키워드 근거 없음 표시가 없다

### Requirement: 제품 경로의 범위
제품 경로는 그 기관의 추천 가능한 책 중 부르는 쪽이 넘긴 조건 안의 책만 MUST 낸다. 벡터 순위로 내려가거나 키워드 근거가 없어도 같다.

#### Scenario: 다른 기관의 벡터 1위
- **WHEN** 질의 벡터와 가장 가까운 책이 B 기관에만 있을 때 A 기관에서 부르면
- **THEN** 그 책은 결과에 없다

#### Scenario: 조건 밖의 벡터 1위
- **WHEN** 벡터 1위가 일반 도서일 때 어린이 도서 조건을 넘겨 부르면
- **THEN** 결과는 모두 어린이 도서다

### Requirement: 주제로 찾기 API
직원 토큰으로 `GET /catalog/topic?q=`를 SHALL 쓸 수 있다. 키오스크 계정도 쓸 수 있고 기관은 토큰으로 정한다. 질의는 1자 이상 100자 이하다. 시스템은 질의를 공백으로 나눈 낱말로 제품 경로의 주제로 찾기를 부르고(순위, 내려가기, 범위 규칙은 제품 경로와 같다), 결과 항목은 서명·저자 찾기 결과와 같은 값이며 최대 10권이다. 비교용으로 정리한 뒤 남는 낱말이 없으면 둘러보기 대신 빈 목록이고 인코더를 부르지 않는다. LLM을 부르지 않는다.

#### Scenario: 제품 경로와 같은 결과
- **WHEN** 키오스크 토큰으로 `GET /catalog/topic?q=채식 소설`을 호출하면
- **THEN** 200이고, 결과가 같은 기관·같은 인코더로 낱말 `채식`, `소설`의 제품 경로 주제로 찾기를 부른 결과와 같은 책, 같은 순서다

#### Scenario: 인코더가 실패함
- **WHEN** 질의 인코딩이 실패하는 상태에서 호출하면
- **THEN** 200이고, 결과가 같은 낱말의 키워드 순위와 같은 책, 같은 순서다

#### Scenario: 낱말 없음
- **WHEN** 공백과 문장부호만 있는 질의로 호출하면
- **THEN** 200과 빈 목록을 돌려주고 인코더를 부르지 않는다

#### Scenario: 토큰 없음
- **WHEN** 토큰 없이 `GET /catalog/topic?q=채식`을 호출하면
- **THEN** 401을 돌려준다

#### Scenario: 잘못된 질의
- **WHEN** `q`가 비어 있거나 100자를 넘으면
- **THEN** 422를 돌려준다

#### Scenario: 요청의 기관 값 무시
- **WHEN** A 기관 토큰으로, B 기관에만 있는 책의 낱말과 `library_id`에 B 기관 id를 붙여 호출하면
- **THEN** B 기관의 책이 나오지 않는다

### Requirement: 주제로 찾기 API는 기록을 남기지 않음
주제로 찾기 API는 질의를 MUST NOT 저장한다. 실행 기록, 대화 기록, 노출 기록을 만들지 않는다.

#### Scenario: 호출 후 기록
- **WHEN** `GET /catalog/topic`을 호출하면
- **THEN** agent_runs, chat_messages, recommendation_events 행 수가 바뀌지 않는다
