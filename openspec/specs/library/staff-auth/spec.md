# library/staff-auth Specification

## Purpose

기관 직원이 비밀번호로 로그인해 받은 토큰으로 API를 쓰게 하고, 관리자와 도서관 PC용 키오스크 계정이 할 수 있는 일을 역할로 나눈다.

## Requirements

### Requirement: 직원 계정과 역할
시스템은 직원 계정을 SHALL 보관한다.
- 계정 정보: 로그인 아이디, 비밀번호 해시, 역할, 사용 여부, 소속 기관
- 로그인 아이디는 서비스 전체에서 유일하다.
- 역할은 `admin`(관리자) 또는 `kiosk`(도서관 PC 공용 화면)이다.
- 비밀번호는 원문으로 저장하지 않는다.

#### Scenario: 비밀번호 원문 미저장
- **WHEN** 비밀번호 `library-pass-1`로 계정을 만들면
- **THEN** 저장된 계정 데이터 어디에도 `library-pass-1`이 들어 있지 않다

#### Scenario: 허용되지 않은 역할
- **WHEN** staff_users에 역할 `owner`로 저장하려 하면
- **THEN** 데이터베이스가 저장을 거부한다

### Requirement: 로그인과 토큰
시스템은 로그인 아이디와 비밀번호가 맞고 사용 중인 계정이면 bearer 토큰을 SHALL 발급한다.
- 응답: 토큰, 역할, 만료 시각
- 토큰 만료 시간은 역할마다 설정으로 정한다 (관리자는 짧게, 키오스크는 길게).
- 아이디가 없거나, 비밀번호가 틀리거나, 사용 중지된 계정이면 모두 같은 메시지로 401을 돌려준다.

#### Scenario: 정상 로그인
- **WHEN** 사용 중인 관리자 계정의 아이디와 비밀번호로 `POST /auth/login`을 호출하면
- **THEN** 200과 함께 토큰, 역할 `admin`, 만료 시각을 돌려준다

#### Scenario: 틀린 비밀번호와 없는 아이디
- **WHEN** 틀린 비밀번호로, 또 없는 아이디로 각각 로그인하면
- **THEN** 둘 다 401과 같은 오류 메시지를 돌려준다

#### Scenario: 사용 중지된 계정
- **WHEN** 사용 중지된 계정으로 로그인하면
- **THEN** 401을 돌려준다

#### Scenario: 내 정보 조회
- **WHEN** 발급받은 토큰으로 `GET /auth/me`를 호출하면
- **THEN** 로그인 아이디, 역할, 소속 기관 이름을 돌려준다

### Requirement: 토큰 검증과 로그아웃
기관 데이터를 다루는 모든 API는 유효한 토큰을 MUST 요구한다.
- 토큰이 없거나, 모르는 토큰이거나, 만료됐거나, 로그아웃한 토큰이면 401을 돌려준다.
- 토큰을 발급한 뒤 계정이 사용 중지되면 그 토큰도 401이 된다.
- 비밀번호를 바꾸면 그 계정의 기존 토큰은 모두 끊긴다. 키오스크 비밀번호가 샜을 때 대응하는 방법이다.
- 역할은 토큰에 저장하지 않고 요청마다 계정에서 읽는다. 역할을 바꾸면 기존 토큰에도 바로 반영된다.
- 로그아웃하면 그 토큰은 더 쓸 수 없다.

#### Scenario: 토큰 없이 호출
- **WHEN** 토큰 없이 `GET /holdings`를 호출하면
- **THEN** 401을 돌려준다

#### Scenario: 만료된 토큰
- **WHEN** 만료 시각이 지난 토큰으로 호출하면
- **THEN** 401을 돌려준다

#### Scenario: 로그아웃한 토큰
- **WHEN** `POST /auth/logout` 후 같은 토큰으로 `GET /auth/me`를 호출하면
- **THEN** 401을 돌려준다

#### Scenario: 비밀번호 변경 후 기존 토큰
- **WHEN** 관리자가 `PATCH /staff/{id}`로 키오스크 계정의 비밀번호를 바꾼 뒤 그 계정의 기존 토큰으로 호출하면
- **THEN** 401을 돌려주고, 새 비밀번호로는 로그인할 수 있다

#### Scenario: 사용 중지 후 기존 토큰
- **WHEN** 관리자가 키오스크 계정을 사용 중지한 뒤 그 계정의 기존 토큰으로 호출하면
- **THEN** 401을 돌려준다

### Requirement: 역할별 접근 제한
키오스크 계정은 다음만 할 수 있어야 MUST 한다.
- 기관 정보 조회
- 도서·사본 조회
- 대출하기와 반납하기

그 밖의 쓰기(도서·사본·회원·직원 관리, 기관 수정)와 회원·대출 목록 조회는 관리자만 할 수 있다. 키오스크가 관리자 전용 API를 호출하면 403을 돌려준다.

#### Scenario: 키오스크의 도서 조회
- **WHEN** 키오스크 토큰으로 `GET /books`를 호출하면
- **THEN** 200을 돌려준다

#### Scenario: 키오스크의 관리 작업
- **WHEN** 키오스크 토큰으로 `POST /books`, `GET /members`, `PATCH /library`를 각각 호출하면
- **THEN** 모두 403을 돌려주고 데이터는 바뀌지 않는다

### Requirement: 직원 계정 관리
관리자는 자기 기관의 직원 계정을 목록 조회하고, 만들고, 수정할 수 있어야 SHALL 한다.
- 수정할 수 있는 것: 역할, 사용 여부, 비밀번호
- 로그인 아이디가 이미 있으면 409를 돌려준다.
- 비밀번호는 8자 이상이어야 한다.
- 관리자는 자기 계정을 사용 중지하거나 자기 역할을 키오스크로 바꿀 수 없다 (409). 기관에 관리자가 아무도 남지 않는 것을 막기 위해서다.

#### Scenario: 키오스크 계정 만들기
- **WHEN** 관리자가 `POST /staff`로 역할 `kiosk` 계정을 만들면
- **THEN** 201과 함께 비밀번호 해시가 빠진 계정 정보를 돌려주고, 그 계정으로 로그인할 수 있다

#### Scenario: 중복 아이디
- **WHEN** 이미 있는 로그인 아이디로 계정을 만들면
- **THEN** 409를 돌려준다

#### Scenario: 짧은 비밀번호
- **WHEN** 7자 비밀번호로 계정을 만들면
- **THEN** 422를 돌려준다

#### Scenario: 자기 계정 사용 중지
- **WHEN** 관리자가 자기 계정을 `PATCH /staff/{id}`로 사용 중지하려 하면
- **THEN** 409를 돌려주고 계정은 그대로다
