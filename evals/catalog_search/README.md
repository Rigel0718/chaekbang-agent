# 서명·저자 찾기 평가

이용자가 아는 책을 찾을 때(`GET /catalog/search`, `GET /catalog/suggest`, 대화의 찾은 책 카드) 얼마나 잘 찾는지 잰다. LLM과 외부 API를 부르지 않아 비용이 없다.

```bash
uv run python -m evals.catalog_search            # 지금 문턱으로
uv run python -m evals.catalog_search --sweep    # 문턱을 바꿔 가며
```

- YES24 표본(`evals/librarian/data/yes24_sample.json`, 저장소 밖)을 테스트 DB(`TEST_DATABASE_URL`)의 트랜잭션 안에서 가상 기관에 넣고 돌린 뒤 되돌린다. 개발 DB는 쓰지 않는다.
- 결과는 `evals/catalog_search/data/runs/<시각>/`에 쓴다(`summary.md`, 놓친 질의 `misses-*.json`). 질의에 표본 서명이 들어 있어 저장소에서 뺀 폴더다.
- 기관과 사본 상태는 가상이고 표본은 작은도서관 장서와 다르다. 수치를 실제 서비스 성능으로 쓰지 않는다.

## 질의

찾을 수 있는 책마다 이용자가 칠 법한 질의를 코드로 만든다(`queries.py`). 같은 책에서 늘 같은 질의가 나온다.

| 종류 | 만드는 방법 | 볼 지표 |
| --- | --- | --- |
| exact | 표시 서명 | 1위 |
| spacing | 공백을 지우거나 가운데에 넣음 | 1위, 5위 안 |
| prefix, word | 서명 앞 절반, 둘째 낱말 | 5위 안, MRR |
| author | 저자 원문의 첫 이름 | 5위 안 |
| vowel, final, key | 모음, 받침, 두벌식 옆 자판 오타 한 군데 | 5위 안, MRR |
| suggest | 입력 중인 글자(`데ㅁ`, `데미ㅇ`, `데미안`) | 8개 안 |
| found | `{서명} 있어요?` 같은 문장 틀 3개 | 찾은 책 카드에 있음 |
| unrelated | 서명을 담지 않은 주제·기분 문장 30개 | 카드가 뜬 비율(오탐) |

기준선은 지금의 키워드 검색(`search_collection`)에 질의를 키워드 하나로 넣은 결과다.

## 결과

2026-11-11, 표본 87권(받은 날 2026-11-07) 중 찾을 수 있는 책 79권, 질의 1,098개. 오타 문턱 0.7, 찾은 책 문턱 0.85. 판본·묶음 표기 무시를 넣은 뒤의 값이고, 괄호는 넣기 전 값이다.

| 종류 | 질의 | 1위 | 5위 안 | MRR | 결과에 있음 | 기준선 1위 | 기준선 5위 안 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| exact | 79 | 100.0% | 100.0% | 1.00 | 100.0% | 100.0% | 100.0% |
| spacing | 79 | 96.2% (98.7%) | 97.5% (100%) | 0.97 | 97.5% | 96.2% | 97.5% |
| prefix | 78 | 94.9% | 100.0% | 0.97 | 100.0% | 96.2% | 100.0% |
| word | 73 | 87.7% | 97.3% (100%) | 0.92 | 97.3% | 87.7% | 98.6% |
| author | 79 | 88.6% | 100.0% | 0.94 | 100.0% | 88.6% | 100.0% |
| vowel | 75 | 84.0% | 98.7% | 0.90 | 100.0% | 0.0% | 0.0% |
| final | 76 | 82.9% | 97.4% | 0.89 | 98.7% | 0.0% | 0.0% |
| key | 75 | 81.3% | 97.3% | 0.89 | 100.0% | 0.0% | 0.0% |
| suggest | 217 | 87.6% | 100.0% | 0.94 | 100.0% | - | - |
| found | 237 | 98.7% | 100.0% (88.6%) | 0.99 | 100.0% | - | - |
| unrelated | 30 | - | - | - | 오탐 0.0% | - | - |

- 오타는 지금 키워드 검색이 하나도 찾지 못하고(0%), 새 찾기는 5위 안에 97~99%다.
- word, author의 1위가 88% 안팎인 것은 같은 낱말·같은 저자의 책이 여럿이라서다.
- 오타를 놓친 5건은 긴 서명의 앞 두 음절에 오타를 낸 경우(`우이`, `사호`)로, 질의 자체가 애매하다.
- **판본·묶음 표기 무시**: 찾은 책 카드가 놓친 27건(모두 `[예스리커버]`, `(완전판)`, `(2026년)`, `+ 엽서 3종` 같은 표기가 붙은 서명)을 모두 찾게 됐다(88.6% → 100%).
- 그 대가로 `먼작귀 1 + 그림책 특별판`, `먼작귀 2 + 그림책 특별판` 두 권은 `+` 뒤가 묶음 표기로 지워져, `그림책`이나 공백 없이 친 `먼작귀1+그림책특별판`으로는 찾지 못한다(spacing·word의 차이). `먼작귀`로는 찾는다.
- 표기를 지우면 같아지는 판본(`… 그림책`과 `… 그림책 (완전판)`)은 원래 서명이 질의와 그대로 같은 책을 먼저 둔다.

## 문턱

`app/library/recommendation/lookup.py`의 `FUZZY_THRESHOLD`(0.7), `FOUND_THRESHOLD`(0.85)다.

- 오타 문턱 0.6~0.75에서 결과가 같고, 0.8에서 모음·자판 오타 5위 안이 89%로 떨어진다. 가운데인 0.7로 둔다.
- 찾은 책 문턱 0.8~0.9에서 오탐이 모두 0%다. 0.8에서 찾음이 89.9%로 조금 높지만, 짧은 서명의 오탐 여지를 줄이려 0.85로 둔다.
- 처음 잰 표에서 찾은 책 문턱 0.8·0.9의 오탐이 100%로 나왔다. `levenshtein_less_equal`이 상한을 넘으면 "상한+1"을 돌려주는데, 부동소수 오차로 상한이 한 칸 작아져 그 값이 문턱과 같아진 오류였다. 고치고 회귀 테스트를 두었다(`tests/library/test_book_lookup.py`).
