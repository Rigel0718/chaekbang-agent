# 운영 에이전트 평가

운영 에이전트가 분석 질문에 맞는 tool과 입력을 고르고, 결과의 숫자만 옮겨 말하는지, 큐레이션 요청에 검색한 책으로 승인 대기 초안을 만드는지, 연체 안내문 요청에 회원 값 없이 자리표시로 된 틀을 올리는지, 구매 요청서 요청에 구매 후보의 ISBN으로만 승인 대기 요청서를 만들고 금액을 말하지 않는지를 실제 LLM으로 잰다. 숫자 자체가 맞는지는 pytest(`tests/library/test_analytics.py`)가 본다. 이 평가는 고르기와 옮기기를 본다.

## 실행

실제 LLM을 부른다. **돌리기 전에 호출 수와 비용을 알리고 승인을 받는다.**

```bash
uv run python -m evals.admin_agent                        # 시나리오 36개
uv run python -m evals.admin_agent --only total,kids-science
uv run python -m evals.admin_agent --model gpt-6-luna --out /tmp/admin-eval
```

- 테스트 DB(`TEST_DATABASE_URL`)의 트랜잭션 안에 평가 기관을 넣어 돌리고 되돌린다. 개발 DB는 쓰지 않는다.
- 날짜는 2026-11-19(기관 시간대 14:00)로 고정한다.
- 임베딩 서버는 쓰지 않는다.
- 결과는 `evals/admin_agent/data/runs/<시각>-<모델>/`(저장소에서 뺀 폴더)에 시나리오마다 `NN-<id>.json`과 `summary.md`로 쓴다.
- 하나라도 틀리면 종료 코드 1이다.

## 구성

| 파일 | 내용 |
| --- | --- |
| `fixture.py` | 평가 기관(자체 대출: 기관 도서 48·사본 53, 그중 제적 2, 희망도서 5건(ISBN별 3종, 같은 ISBN 2건, ISBN 없는 1건), 승인 대기 구매 요청서 1. 외부 대출: 기관 도서 3), 큐레이션 평가 기관 둘(자체·외부 대출, 같은 책 10권: 공룡 5(제적 1)·우주 3·그 밖 2, 승인 대기 큐레이션 1. 외부 대출 기관에 희망도서 2건과 가져온 파일 기준 대출 중 사본 1)과 날짜 고정. 책마다 가상 ISBN(`eval_isbn`)이 있다 |
| `scenarios.py` | 시나리오 36개와 라벨(기대 호출, 있어야 할 값, 못 하는 분석 종류, 초안·안내문 틀·요청서 기대, 스펙 추적) |
| `runner.py` | 서비스와 같은 대화 경로로 한 시나리오를 돌린다. tool을 결과를 받아 두는 tool로 감싸, 입력을 남기지 않는 검색 결과도 채점에 쓴다. 안내문 틀 문장은 결과의 `template_id`로 저장된 행에서 읽는다 |
| `score.py` | 채점(LLM 없음) |
| `__main__.py` | 실행, 결과 파일, 요약 |

## 지표

| 지표 | 맞는 조건 |
| --- | --- |
| tool 선택 | 기대 호출이 실제 호출에 모두 있다. 적은 입력 값만 맞춰 보고(분야는 집합으로), 더 부른 호출은 상관없다 |
| 숫자 충실도 | 있어야 할 값이 답에 모두 있고, 답의 모든 숫자가 그 턴의 tool 결과·질문·KDC 주류 번호(000~900) 안에 있다. 줄 앞의 목록 번호는 숫자로 보지 않는다. 없어야 할 값(회원 이름·번호)이 답에 없다 |
| 못 하는 분석 분류 | 답의 `unsupported`가 라벨과 같다(분석으로 답했으면 null) |
| 초안 충실도 | 초안을 기대하면 성공한 `draft_curation`이 하나이고 승인 대기이며, 책이 모두 같은 턴의 `search_collection` 결과에 있고, 서로 다른 3~10권이고, 답에 "승인"이 있다. 기대하지 않으면 초안이 없어야 맞다. 안내문 틀을 기대하면 성공한 `draft_overdue_notice`가 하나이고 승인 대기이며, 틀 문장과 답에 평가 기관 회원 값(`평가회원`, `E000`)이 없고, 답에 "승인"이 있다. 기대하지 않으면 틀이 없어야 맞다. 요청서를 기대하면 성공한 `draft_purchase_request`가 하나이고 승인 대기이며, 항목 ISBN이 모두 같은 턴의 `list_purchase_candidates` 결과(wishes·popular)에 있고, 답에 회원 값이 없고 "승인"이 있다. 기대하지 않으면 요청서 초안이 없어야 맞다 |

## 라벨

라벨은 Claude가 평가 기관의 분석 결과를 보고 쓰고, 사람이 전부 확인한다(23개, 약 10분. 큐레이션 4개는 2026-11-21에, 연체 안내 4개는 같은 날 `add-overdue-notice`에서, 구매 요청서 5개는 2026-11-22 `add-purchase-request`에서 더함). 희망도서·ISBN을 더해도 분석 라벨의 숫자가 그대로인지는 `tests/evals/test_admin_agent_eval.py`의 `test_wishes_do_not_change_analysis_labels`가 본다. 평가 기관을 바꾸면 `scenarios.py` 머리말의 값과 `must_say`를 함께 고친다.

시나리오 묶음은 일곱 가지다.

- 질문 목록의 답할 수 있는 질문 14개
- 바꿔 말하기 4개: 과학, 9월, 아동, 작년
- 못 하는 분석 4개: 주제로 세기, 연체한 사람, 시간대, 최근 들어온 책
- 외부 대출 기관의 대출 질문 1개
- 큐레이션 4개(큐레이션 평가 기관): 공룡 만들기, 우주 이달의 추천, 승인 요청, 외부 대출 기관의 공룡 만들기
- 연체 안내 4개: 연체된 책(분석 평가 기관, 연체 2건), 안내문 만들기, 회원 이름을 말한 안내문, 외부 대출 기관의 안내문(큐레이션 평가 기관의 외부 대출 기관)
- 구매 요청서 5개: 희망도서 질문, 희망도서·인기로 요청서 만들기, 예산 질문(금액 숫자 없이 관리 화면 안내, `other`), 요청서 승인 요청(`other`), 외부 대출 기관의 요청서(큐레이션 평가 기관의 외부 대출 기관, 대출 수를 지어내지 않음)
