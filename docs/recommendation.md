# 추천 품질 평가

추천 품질이 이 프로젝트의 핵심 성과 지표다. 전체 설계는 `docs/design.md`, 확정된 기본값은 `docs/roadmap.md`에 있다. 세 층으로 나눠 측정한다.

| 층 | 지표 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| 반드시 지킬 것 | 미소장 도서 추천, 어린이 요청에 일반 도서 추천, 지어낸 정보 | 규칙 검사 (코드) | 각 0건 |
| 찾기 | 아는 책을 찾는가(정확, 띄어쓰기, 일부, 저자, 오타, 입력 중) | 표본에서 질의를 코드로 만들어 정답 대조 (`evals/catalog_search`) | 1위·5위 안 적중, 오탐 |
| 추천의 질 | 요청에 어울리는가, 다양성(한 분야·저자 쏠림) | 평가 세트 + 사람이 정한 어울림 라벨(Hit Rate·Recall), 다양성은 코드로 | 버전별 점수 비교 |
| 실제 효과 | 추천 → 대출 전환율, 희망도서 신청 수 | 서비스 로그 | 데모 데이터로 흐름 검증 |

- **평가 세트**: 가상 이용자 시나리오 30~50개. 예: "7살 아이 공룡 책", "퇴근 후 30분 읽을 에세이", "손주와 같이 읽을 그림책", 애매한 요청, 소장 도서가 없는 요청.
- **비교 실험**: 검색 방식(키워드 / 임베딩 / 혼합), 프롬프트 버전, 모델별로 점수를 비교해 README에 기록한다.
- **어울림 라벨**: 추천에 정답은 없다. 시나리오마다 "받으면 납득할 책"을 사람이 0·1·2로 정하고, 검색을 돌리기 전에 소개를 읽고 정해 키워드 쪽으로 기울지 않게 한다. 키워드가 약한 요청과 잘하는 요청을 나눠 점수를 낸다.
- **주제로 찾기 실험(2026-11-16, `add-recommendation-experiments`)**: `evals/recommendation`. 실험 장서 525권, 주제 질의 30개(조정 20, 확인 10), LLM 호출 없음.
  - 라벨: 결과를 보기 전에 관련 분야의 책 전체(1,384건)에 달고, 실행 뒤 상위 10권의 라벨 없는 책(583건)을 보충한다. 사람이 다 달기에는 많아 Claude가 초안을 달고 사람이 검수 화면에서 고쳤다(사람이 고친 것은 13건). 정답이 LLM 판단에 기대므로 방식끼리의 상대 비교에만 쓴다.
  - 지표: nDCG@5(주 지표), Hit@5, Recall@10, 상위 5권의 같은 지은이·시리즈 겹침, 규칙 위반 0건. 기준 변형과 질의별 차이로 이김·비김·짐과 고정 시드 부트스트랩 95% 구간을 낸다.
  - 채택 규칙: 조정 세트에서 평균 차이 > 0, 이김 > 짐, 구간 하한 > 0이면 채택하고, 아니면 단순한 쪽을 둔다. 확인 세트는 마지막에 한 번 본다.
  - 결과: 키워드 순위와 벡터 순위를 RRF(k 60, 1:1)로 합친 순위가 지금 키워드 검색을 이겼다(조정 nDCG@5 0.410 → 0.517, 확인 0.421 → 0.549). 벡터만으로는 차이가 뚜렷하지 않았다. 임베딩 텍스트는 저자 넣기·소개만·필드별 모두 기본(서명·분류·소개)을 이기지 못해 기본을 유지한다. 시리즈 묶기와 MMR은 품질은 같고 겹침만 줄어, 제품에 내보낼 때 다시 정한다. 표는 change의 design에 있다.
  - 서명 정렬을 가나다순으로 고친 뒤(키워드 동점 순서가 바뀜) 보충 라벨 37건을 달고 다시 쟀다: 조정 0.453 → 0.519, 확인 0.384 → 0.522. 채택은 그대로다.
- **비슷한 책·최근 기록 실험(2026-11-16, `add-related-book-experiments`)**: 같은 틀. 기준 책 20권(조정 14, 확인 6), 최근 기록 10개(조정 7, 확인 3). 기준 책의 저장된 벡터를 써서 임베딩 서버 없이 돈다.
  - 라벨: 비슷한 책 968건, 최근 기록 666건(실행 전 + 보충)을 Claude가 달았다. 사람은 등급별로 고르게, 해시 순서로 뽑은 고정 표본 45건만 보았고 고친 것은 0건이었다(전수 검수는 양이 많아 하지 않는다).
  - 비슷한 책: 벡터 이웃(임베딩 텍스트 기본 종류)을 채택 규칙으로 넘은 변형이 없다. 같은 시리즈·같은 저자 신호를 RRF로 합쳐도 14권 중 13권이 같은 점수였다(벡터 이웃이 이미 그 책들을 위에 둔다). 저자 넣기·소개만·필드별 벡터, 같은 외부 분류로 좁히기, 시리즈 묶기, MMR 모두 채택하지 않았다. 규칙 신호는 근거 표시("같은 작가의 책")용으로 남길지 제품에 내보낼 때 정한다.
  - 최근 기록: 기록 책 벡터의 평균이 책별 순위를 RRF로 합친 것을 모든 기록에서 이겼다(조정 nDCG@5 0.694 대 0.334). k 60에서는 여러 책의 목록에 중간 순위로 겹치는 책이 각 책의 가장 가까운 책보다 위로 오기 때문이다.
  - 같은 KDC 세목과 우리 도서관 인기는 실험 장서에 값이 없어 0건으로 보고했다. 코드와 테스트만 있고 평가는 정보나루 연동 뒤에 한다.
- **대출 신호(2026-11-17, `add-loan-signals`)**: 정보나루 이용 분석(함께 대출·마니아·다독자)과 연령 묶음별 인기를 실험 장서 469권 중 466권에 받아 쟀다. 같은 KDC 세목의 몫은 다시 확인됐고(조정 +0.053), 세 자리·계층 단위, 세목 안 벡터 순, 함께 대출(+0.017, 5·5·4), 최근 기록의 KDC·저자·함께 대출 신호는 채택 규칙을 넘지 못해 기본값은 그대로다(`sim-rrf`, `hist-mean`). 정보나루가 막혀 받지 못한 11회와 그것으로 할 다시 재기(인기 기간, 기준 책 `s10`)는 대출 테이블 change(`add-loan-signal-store`, 약관 확인 뒤)로 옮겼다.
- **남겨 둔 분야(2026-11-17, `add-related-books`)**: 조정에 쓰지 않은 종교·예술·건강 취미·여행에서 정해 둔 변형을 한 번 쟀다(모두 확인 항목, 주제 8·기준 책 8·최근 기록 4, 표본 20건 중 2건 고침). 주제로 찾기 `hybrid-k60`은 키워드 검색보다 높고(+0.097, 4·3·1, 방향 같음), 비슷한 책 `sim-rrf`는 벡터 이웃과 차이 없음(-0.004)이다. 그 분야에는 같은 KDC 세목 신호가 8권 중 1권에만 있어, 조정 세트의 몫이 KDC 세목에서 왔다는 것과 맞다. 설정은 바꾸지 않는다.
- **제품 연결(2026-11-17, `add-related-books`)**: 비슷한 책 API(LLM 없음, 근거 코드와 문구)와 AI 사서 관련 책 tool(책 id면 비슷한 책, 비우면 대화 세션의 책으로 최근 기록, 책이 없으면 우리 도서관 인기)을 실험의 기본 설정 그대로 이었다. 벡터 근거만 있는 책의 최소 유사도는 진단에서 0·2 라벨의 코사인이 겹쳐 두지 않는다. 주제로 찾기는 `add-topic-search-tool`이 잇는다.
- **LLM 채점**: 의도 일치, 추천 이유의 타당성은 최종 서비스 테스트에서 LLM 채점을 검토한다. 그때 채점 기준표를 고정하고 직접 채점한 샘플과 비교해 채점자를 검증한다.
- **관리자 에이전트 평가**: tool 선택 정확도, 자연어 SQL 정답률, 승인 없이 쓰기 실행 0건.
- **장서 가져오기 평가**: 기관마다 다른 열 구성의 가상 내보내기 파일로 ISBN 인식률, 어린이 분류 정확도, 확인 요청 비율을 잰다.
