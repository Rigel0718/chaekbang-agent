# 나중에 추가할 내용

현재 범위에는 넣지 않고, 필요할 때 꺼내 쓸 내용이다.

- **장서 데이터 정규화 고도화**: 작가명·제목 표기 차이, 권차 표기("2권", "Ⅱ", "하"), 개정판·리커버·재출간 같은 판본 문제, 재정가. ISBN이 없는 장서를 가져올 때 필요해지면 여기서부터 반영한다.
- **시즌·이벤트 큐레이션**: 원작 영화 개봉, 문학상 발표, 방학·독서의 달에 맞춘 큐레이션을 관리자에게 제안한다. 출처 없는 이벤트는 제안하지 않는다.
- **독립서점 모드**: libraries.type = bookstore일 때 대출 tool을 끄고 서가 안내·구매 문의 tool을 켠다. 회원 적립 등 가격 규칙은 코드로 처리한다.
- **다른 기관 유형**: 군 부대 진중문고, 학교. 이용자층과 추천 기준이 달라 평가 세트를 따로 만든다.
- **저자 구조화**: `add-book-contributors`에서 한다(공식 서지 기여자 표, 기관 도서 저자 키). 서명·저자 찾기는 지금처럼 원문의 자모 키를 쓴다. 못 푸는 것(외국 저자의 다른 음역, 동명이인)은 `add-bibliographic-sources`의 일반화 실험에서 얼마나 문제가 되는지 잰다.
- **기관별 기능 설정**: 어린이 구분처럼 기관마다 필요가 다른 기능은 지금 앱 전체 단위로 등록한다. 군부대·대학 같은 기관 유형을 더할 때 기관 설정으로 켜고 끈다.
- **공식 서지 정리와 갱신**: 어느 기관도 소장하지 않게 된 공식 서지의 정리 기준, 이미 만든 공식 서지의 갱신.
- **YES24 확인**: 여러 기관에 실제로 서비스하기 전에 공식 서지를 기관들이 함께 쓰는 것과 소개 문구를 LLM·임베딩 제공자에게 보내는 것, 평가 표본과 실험 장서(카테고리 스테디셀러 525권)를 로컬과 개발 DB에 두는 것, 소개글로 만든 임베딩 벡터를 저장하는 것(공식 서지 벡터는 여러 기관이 함께 쓴다)이 이용 조건에 맞는지 YES24에 확인한다. 지금 임베딩은 로컬 컨테이너에서 만들어 소개글이 외부로 나가지 않는다.
- **카카오·정보나루 확인**: 서비스 전에 카카오 운영정책(받은 데이터의 캐시는 사용자 환경 개선 목적으로만, 최신 유지)과 여러 기관이 함께 쓰는 공식 서지(정가·출간일)의 관계, 정보나루 사이트 이용약관(데이터 저장·재배포·출처 표기)을 확인한다. 함께 대출·인기 대출을 운영자 층 테이블에 저장해 제품에 쓰는 일(`add-related-books`)도 이 확인 뒤에 한다. 실험에서는 ISBN 순위와 수만 저장소 밖 파일에 둔다(`add-loan-signals`). 실험용 정보나루·카카오 원본 파일은 저장소 밖, 개발 DB에만 둔다.
- **미성년자 이용**: 어린이가 직접 쓰는 화면이므로 배포 전에 LLM 제공자의 이용 정책을 확인한다.
- **자동 채움**: 지금은 운영자가 스크립트를 돌린다. 스케줄러가 같은 실행을 부르게 하고, 채움 뒤 어린이 구분 갱신을 관리자 화면 버튼이나 기관 설정으로 줄인다.
- **세밀한 연령 구분**: 유아·초등 저학년·고학년처럼 나누는 것은 근거 데이터가 충분해질 때 검토한다.
