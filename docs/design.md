# 작은도서관 AI 사서 프로젝트 설계 v2

2026-11-07 기준

사서가 없는 작은도서관에 브라우저 하나로 AI 사서(이용자용)와 운영 에이전트(관리자용)를 제공한다. MVP 대상은 작은도서관이고, 독립서점은 확장 대상이다.

## 문제 정의와 방향을 바꾼 이유

작은도서관, 동사무소 문고, 군 부대 진중문고처럼 책은 있지만 사서가 없는 곳이 많다. 책이 납품돼도 추천하고 안내할 사람이 없어서 제대로 읽히지 않는다.

- **경험에서 나온 문제**: 작은 책방에서 일할 때 주 수입원이 이런 기관 납품이었다. 책을 넣어 주는 쪽에서 보면, 납품 이후 활용이 가장 약한 고리다.
- **이전 방향(무인 서점 에이전트)을 바꾼 이유**: 결제, POS, 입고 자동 처리는 웹만으로 풀기 어렵고, 키오스크 대여·POS·MARC·재고·매출 관리 서비스는 이미 여럿 있다.
- **새 방향**: 웹 브라우저에 로그인해 켜 두기만 하면 되는 AI 사서. 에이전트가 부가 기능이 아니라 서비스의 핵심이 된다.
- **원래 아이디어는 유지**: 처음 출발점이던 '재고 조회 → 발주 초안 → 사람 승인'과 자연어 SQL 분석은 관리자 화면으로 옮겨 그대로 살린다. 대상이 '소상공인 사장님'에서 '사서 없는 기관의 관리 담당자'로 바뀐 것이다.

## 대상과 범위

MVP는 작은도서관 하나에 집중하고, 독립서점은 같은 핵심 위에 '모드'로 더한다.

| 구분 | 작은도서관 (MVP) | 독립서점 (확장) |
| --- | --- | --- |
| 이용자 | 아이부터 어르신까지 주민 | 책에 관심 많은 방문객 |
| 관리자 | 주민센터 담당자, 자원봉사자 | 서점 사장님 |
| 추천 후 행동 | 대출 | 서가 위치 안내, 구매 문의 (결제는 매장에서) |
| 관리자 핵심 업무 | 장서·대출 현황, 연체, 보충 구매 요청 | 재고, 추천 카드, 입고 후보 |

**하지 않는 것**

- 결제, POS 연동, MARC 편목
- 학교 DLS나 공공도서관 대출 시스템을 대체하는 본격 대출 관리. 대출은 빌림·반납·대출 중 표시 수준으로만 만든다.
- 포지션은 '기존 시스템 위에 얹는 AI 사서'다.

## 기존 시스템과의 관계

작은도서관도 대부분 이미 대출·장서 관리 프로그램을 쓴다. AI 사서가 장서와 대출을 따로 관리하게 하면 담당자가 같은 일을 두 번 입력해야 한다. 그래서 **장서는 기존 시스템에서 가져오는 것을 기본 경로로 한다.**

| 운영 방식 | 대상 | 장서 | 대출 상태 |
| --- | --- | --- | --- |
| 가져오기 (기본) | 대출 프로그램을 이미 쓰는 기관 | 기존 시스템의 엑셀·CSV 내보내기를 가져온다. 다시 가져오면 바뀐 것만 반영하고, 파일에서 빠진 사본은 제적한다 | 가져온 파일의 대출 상태를 쓴다. 이용자 화면에는 마지막 갱신 시각을 함께 보여 준다 |
| 자체 대출 | 대출 프로그램이 없는 기관, 데모 | 관리자 화면에서 등록한다 | AI 사서가 빌림·반납을 직접 처리한다 |

- 기관마다 운영 방식(`loan_mode`: `imported` / `internal`)을 하나 고른다.
- 가져오기 기관에서는 이용자 화면의 대출 tool을 끄고 "대출은 데스크에서" 안내로 바꾼다. 추천·큐레이션·희망도서는 두 방식 모두 같다.
- 가져오기는 기관마다 다른 열 구성을 받아야 한다. 머리글 인식, ISBN 정규화(하이픈, ISBN-10, 엑셀 숫자 셀), 중복 사본 처리는 결정적인 코드로 한다.

## 전체 구조

하나의 FastAPI 백엔드 위에 두 화면과 두 에이전트가 올라간다. 두 에이전트의 tool과 REST API는 같은 Service Layer를 호출한다.

| 층 | 이용자 쪽 | 관리자 쪽 |
| --- | --- | --- |
| 화면 | 도서관 PC 브라우저 (기관 계정으로 로그인된 공용 화면) | 관리자 로그인 화면 (PC·모바일 웹) |
| 에이전트 | AI 사서: 검색, 추천, 큐레이션, 대출 | 운영 에이전트: 현황 분석, 초안 작성, 승인 후 실행 |
| 권한 | 조회 중심, 쓰기는 대출·희망도서 신청만 | 조회 + 초안 작성, 확정은 승인 후 |
| 공통 | Service Layer → PostgreSQL, 외부 도서 API, Langfuse 트레이싱 | 같음 |

**멀티 기관 구조**: 모든 데이터는 library_id로 분리한다. 로그인한 기관의 장서·대출·큐레이션만 보이고, 에이전트 tool도 해당 기관 범위 안에서만 동작한다.

**도서의 세 층**: 공식 서지와 기관의 값을 나눈다. 공용 도서 하나에 두 값을 함께 두면 한 기관의 수정이 모든 기관에 적용되고, ISBN 없는 책이 기관을 넘어 합쳐지기 때문이다.

| 층 | 주인 | 내용 |
| --- | --- | --- |
| books (공식 서지) | 서비스 운영자 | ISBN이 있는 책의 서지. YES24 값을 공식으로 본다. 기관은 쓸 수 없다 |
| library_books (기관 도서) | 기관 | 우리 도서관의 책. 파일·입력 값, ISBN 없는 책. 공식 서지 연결은 없어도 된다 |
| holdings (사본) | 기관 | 등록번호, 청구기호, 상태, 입수 구분 |

- 가져오기는 공식 서지가 없어도 끝난다. 파일 값을 기관 도서와 사본에 저장하고, ISBN이 같은 공식 서지가 있으면 연결한다.
- 화면과 검색은 공식 값을 먼저 쓰고, 없으면 기관 값을 쓴다. 연결된 도서의 서지 필드는 기관이 고칠 수 없다.
- 공식 서지는 운영자가 소장 도서의 ISBN만 채운다. 사람은 예외만 보고, 대부분은 자동으로 채운다.
- 운영자 실행은 공식 서지와 연결만 다룬다. 기관이 정한 값은 바꾸지 않는다.

**패키지**: 코드도 같은 경계로 나눈다. `app/central/`(운영자), `app/library/`(기관 공통), `app/features/`(기관 개별)이고, `features → library → central → core` 방향으로만 의존한다. 공통 코드는 기능을 이름으로 부르지 않고 훅으로 사건만 알린다. 어린이 구분은 `app/features/children/`에 있고, 등록하지 않아도 공통은 그대로 동작한다.

**공용 PC 고려**: 이용자 화면은 일정 시간 입력이 없으면 대화를 초기화한다. 개인정보는 대출할 때만 회원번호로 확인하고, 추천 대화에는 개인정보를 쓰지 않는다.

## 이용자 화면: AI 사서 에이전트

이용자가 "초등학생 아들이 공룡을 좋아해요", "요즘 마음이 지친데 가벼운 에세이 있어요?"처럼 물으면, 이 도서관에 있는 책 중에서 추천하고 대출까지 안내한다.

| Tool | 하는 일 | 종류 |
| --- | --- | --- |
| search_collection | 소장 도서 검색 (제목·저자·주제·어린이 도서 여부), 대출 가능 여부, 서가 위치 | 조회 |
| get_book_detail | 소개, 저자 정보, 같은 저자의 소장 도서 | 조회 |
| get_curations | 관리자가 승인한 이달의 추천과 주제별 큐레이션 | 조회 |
| get_popular_loans | 이 도서관의 인기 대출 도서 | 조회 |
| search_external_books | 소장하지 않은 책 검색 (희망도서 안내용) | 조회 |
| create_loan | 회원번호 확인 후 대출 처리 (자체 대출 기관만) | 쓰기 |
| return_loan | 등록번호로 반납 처리 (자체 대출 기관만) | 쓰기 |
| request_book | 희망도서 신청 남기기 | 쓰기 |

**원칙**

- **소장 도서만 추천한다**: 추천 목록은 항상 이 도서관에 있는 책이고, 대출 중이면 그렇게 표시한다. 없는 책은 희망도서 신청으로 연결한다.
- **추천 이유를 말한다**: 왜 이 책인지 한 줄로 설명한다. 근거는 도서 데이터에서만 가져온다.
- **어린이 요청에는 어린이 도서만 추천한다**: 나이를 세밀하게 나누지 않고, 책을 '어린이 도서'와 '일반 도서' 둘로만 나눈다. 어린이용 요청에는 어린이 도서로 분류된 책만 낸다. 분류가 확실하지 않은 책은 일반 도서로 두어 어린이 추천에서 빠지게 한다.
- **지어내지 않는다**: 줄거리·저자 정보·인용문을 LLM이 기억으로 만들지 않는다.
- **개인정보는 최소한으로**: 대화에서 이름·연락처를 묻지 않는다. 대출과 희망도서 신청에만 회원번호를 쓴다.

**에이전트 구조**: 공통 실행기 하나에 프로필만 갈아 끼운다. 에이전트마다 tool 호출 루프, 승인 대기, 실행 기록을 따로 만들지 않기 위해서다.

| 구성 | 역할 |
| --- | --- |
| `app/agent/` | 공통 실행기. 어떤 tool이 있는지 모르고 `core`만 의존한다 |
| 패키지별 `tools.py` | `central`, `library`, `features/*`가 자기 service를 tool로 감싼다 |
| 프로필 | 프롬프트, tool 묶음, 권한. `app/main.py`에서 조립한다. 기관 유형별 차이도 프로필로 푼다 |

- tool은 이름, 설명, JSON Schema로 정의하고 같은 프로세스에서 실행한다. 기관 범위, DB 세션, 승인 흐름을 코드로 지키기 위해서다. MCP와 모양이 같아서 필요하면 어댑터로 잇는다.
- `library_id`는 실행기가 주입한다. LLM이 정할 수 없다.
- 어린이 요청에 일반 도서를 내지 않는 규칙은 tool 선택에 맡기지 않는다. 프로필의 최종 추천 검사 단계에서 코드로 강제하고, 이 검사도 기능이 끼운다.

## 어린이 도서 분류

한국 서지 데이터에는 대상 연령이 비어 있는 경우가 많다. 나이를 특정하려 하면 대부분의 책이 '연령 정보 없음'이 되어 어린이 추천 후보가 거의 남지 않는다. 그래서 **어린이 도서인지 아닌지만** 나눈다. 어린이 도서는 영유아·초등학생 대상 도서다.

어린이 구분은 MVP 대상인 작은도서관에 필요한 **기관 개별 기능**이다. 군부대, 대학, 어르신 도서관처럼 필요 없는 기관도 있으므로 공식 서지와 외부 연동은 어린이를 모른다. 공식 서지는 YES24 분류 값을 원문으로만 보관하고, 기관 층이 이 원문을 근거로 쓴다. 어린이 구분은 기관의 요청(등록, 가져오기, ISBN 수정, 기관 관리자의 갱신)에서만 바뀌고, 운영자의 채움 실행은 바꾸지 않는다.

- 분류 값: `children`(어린이 도서) / `general`(일반 도서). 근거(`audience_source`)를 어린이 기능의 저장소에 함께 저장한다. 같은 책이라도 기관마다 다를 수 있다.
- 판단은 코드가 아래 순서로 한다. 앞의 근거가 있으면 그것을 쓴다.
  1. 관리자가 직접 지정한 값
  2. 가져온 파일의 별치기호·자료실·부가기호 (예: 아동 별치기호, "어린이자료실", 부가기호 첫 자리 6(초등 학습참고서)·7(아동))
  3. 연결된 공식 서지의 분류 원문 (YES24 `goodsSortNm`이 `국내도서-유아`, `국내도서-어린이`, `국내도서-초등학습서`인 경우)
  4. 위 근거가 없으면 `general`
- 관리자 화면에서 분류를 고칠 수 있고, 고친 값이 가장 우선한다.
- 어린이 구분은 기관의 요청(등록, 가져오기, ISBN 수정, 관리자의 갱신)에서만 바뀐다. 운영자가 공식 서지를 채운 뒤에는 기관 관리자가 갱신해야 외부 분류 근거가 반영된다.
- API는 `/children` 아래에 있고, AI 사서의 어린이 필터도 이 기능의 함수를 쓴다. 공통 API의 응답에는 어린이 값이 없다.
- 평가: "어린이 요청에 어린이 도서가 아닌 책을 추천한 건수"를 0건으로 유지한다. 어린이 도서인데 `general`로 분류된 책 비율도 함께 본다 (너무 많으면 추천 후보가 줄어든다).

## 관리자 화면: 운영 에이전트

처음 아이디어였던 매장 운영 에이전트를 도서관 운영에 맞게 옮긴 부분이다. 담당자가 "이번 달 대출이 많았던 분야 알려줘", "연체자 안내문 만들어줘", "아동 과학책이 부족하니 보충 구매 목록 짜줘"라고 말하면 처리한다.

| Tool | 하는 일 | 승인 필요 |
| --- | --- | --- |
| run_analytics_query | 자연어 질문을 SQL로 바꿔 장서·대출 현황 분석 (읽기 전용) | ✗ |
| get_collection_status | 분야별·어린이/일반별 장서 규모, 훼손·분실 현황 | ✗ |
| list_overdue_loans | 연체 목록 (자체 대출 기관) | ✗ |
| import_holdings | 기존 시스템의 엑셀·CSV로 장서 가져오기, 애매한 건 확인 요청. 공식 서지는 운영자가 따로 채운다 | 애매한 건만 |
| register_books | ISBN 목록이나 바코드로 장서 등록 (자체 대출 기관, 가져오기로 빠진 책) | 애매한 건만 |
| draft_curation | 이달의 추천·주제 큐레이션 초안 → 승인하면 이용자 화면에 게시 | ✓ |
| draft_overdue_notice | 연체 안내문 초안 | ✓ |
| draft_purchase_request | 부족 분야·희망도서·인기 대출을 근거로 보충 구매 요청서 초안 | ✓ |

**승인 흐름**: 초안(draft) → 승인 대기(pending_approval) → 승인(approved) → 게시·확정(published / confirmed). 승인 대기 상태는 DB에 저장하고, 승인되면 에이전트 실행을 이어서 진행한다. 서버가 재시작돼도 실행이 유지된다.

**자연어 SQL 안전장치**

- 읽기 전용 DB role과 분석용 view만 연다.
- sqlglot으로 SELECT만 통과시키고, statement_timeout과 LIMIT을 강제한다.
- library_id 조건을 코드에서 강제해 다른 기관 데이터에 접근할 수 없게 한다.

**구매 요청서의 의미**: 요청서를 받는 쪽은 납품하는 동네 책방이다. 금액은 코드로 계산한다.

## 추천 품질 평가

추천 품질이 이 프로젝트의 핵심 성과 지표다. 세 층으로 나눠 측정한다.

| 층 | 지표 | 측정 방법 | 목표 |
| --- | --- | --- | --- |
| 반드시 지킬 것 | 미소장 도서 추천, 어린이 요청에 일반 도서 추천, 지어낸 정보 | 규칙 검사 (코드) | 각 0건 |
| 추천의 질 | 요청 의도 일치, 다양성(한 분야·저자 쏠림), 추천 이유의 타당성 | 평가 세트 + LLM 채점 (채점 기준표 고정) | 버전별 점수 비교 |
| 실제 효과 | 추천 → 대출 전환율, 희망도서 신청 수 | 서비스 로그 | 데모 데이터로 흐름 검증 |

- **평가 세트**: 가상 이용자 시나리오 30~50개. 예: "7살 아이 공룡 책", "퇴근 후 30분 읽을 에세이", "손주와 같이 읽을 그림책", 애매한 요청, 소장 도서가 없는 요청.
- **비교 실험**: 검색 방식(키워드 / 임베딩 / 혼합), 프롬프트 버전, 모델별로 점수를 비교해 README에 기록한다.
- **채점자 검증**: LLM 채점과 직접 채점한 샘플 10개를 비교해 채점 기준이 믿을 만한지 확인한다.
- **관리자 에이전트 평가**: tool 선택 정확도, 자연어 SQL 정답률, 승인 없이 쓰기 실행 0건.
- **장서 가져오기 평가**: 기관마다 다른 열 구성의 가상 내보내기 파일로 ISBN 인식률, 어린이 분류 정확도, 확인 요청 비율을 잰다.

## 외부 데이터 API

장서 등록과 추천 근거에 쓴다. 각 API의 키 발급 조건, 호출 제한, 캐시·이미지 사용 조건은 시작 전에 확인한다.

| API | 쓰임새 | 비고 |
| --- | --- | --- |
| 도서관 정보나루 API | 인기 대출, 연령별 인기 도서, 도서 키워드 | 도서관 성격에 가장 잘 맞는 추천 근거 |
| YES24 API | 도서 검색·상세 조회, 카테고리·베스트셀러 등 제공 기능 전반 (예: GOODS API, CATEGORY API). 지금은 상품 상세 조회(`itemDetail`)만 쓴다 | 공식 서지 채움, 희망도서 안내 등. 표지는 저장하지 않고 원본 URL로 표시, 출처와 상품 링크 표기 |

외부 API는 위 두 개를 중심으로 쓴다. 표의 내용은 예시이며 두 API가 제공하는 기능을 여기에 적힌 것으로 한정하지 않는다. 쓸 기능은 각 change에서 API 문서를 보고 정한다.

**YES24 연동 구조**
- 호출 코드는 `app/central/external/yes24/`에 따로 둔다. 인증은 `X-Api-Key` 헤더이고 키 값은 `.env`의 `YES24_API_KEY`에만 둔다.
- 엔드포인트와 응답 필드는 코드 곳곳에 흩어 놓지 않고 정의 파일 한 곳에 모은다. 새 엔드포인트나 필드는 그 파일에 추가하는 것으로 끝나게 한다.
- API 묶음(GOODS, CATEGORY 등)별로 역할 함수를 나누고, 각 함수에 하는 일을 한국어로 적는다.
- 공식 서지는 운영자가 `scripts/enrich_books.py`로 채운다. 기관 API에는 실행 경로가 없고, 기관은 `GET /book-enrichment`로 처리 현황만 본다.
- 한도는 키 기준 하루 20,000회, 초당 10회다. 초당 5회 이하로 호출하고, 한도 초과나 외부 장애가 나면 실행을 멈춘다. 처리 상태가 기관 도서마다 저장돼서 다음 실행이 이어서 처리한다.

**YES24 이용 조건** (FAQ)
- 서비스 제공에 필요한 범위의 캐싱은 허용한다. 그래서 소장 도서의 ISBN만 조회해 저장한다.
- 전체 도서 정보의 자체 DB 축적과 제3자 재배포는 허용하지 않는다. 베스트셀러나 카테고리를 돌며 쌓지 않고, YES24 값을 내보내는 기능을 만들지 않는다.
- 가격·재고 같은 변동 정보는 갱신 주기를 짧게 유지해야 한다. 판매가와 판매 상태는 저장하지 않는다.

## 개발 단계와 일정

MVP는 약 8주다. 각 주차는 OpenSpec change 하나로 진행한다 (2주차는 외부 API 정보와 구조 변경 때문에 넷으로 나눴다). 이전 방향(무인 서점)의 1주차 결과는 저장소 기록에 남기고, 새 1주차 change에서 모델과 스펙을 새 도메인으로 정리한다.

| 주차 | OpenSpec change | 내용 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | add-library-core-domain | 이전 도메인 정리, 모델, 기관 분리, 관리자·키오스크 인증, 장서·대출 CRUD, 시드 데이터 | Swagger에서 대출·반납 동작, 다른 기관 데이터가 보이지 않음 |
| 2 | add-holdings-import | 기존 시스템 엑셀·CSV 장서 가져오기, 파일 근거 어린이 도서 분류 | 가상 내보내기 파일로 장서가 채워지고 어린이 분류 결과가 나옴 |
| 2 | add-library-catalog-layer | 공식 서지와 기관 도서 분리, 기관별 어린이 구분 | 한 기관의 수정이 다른 기관에 영향을 주지 않음 |
| 2 | add-book-enrichment | YES24 연동, 운영자의 공식 서지 채움, 기관의 외부 분류 근거 | 소장 도서의 소개·표지가 채워짐 |
| 2 | refactor-layer-packages | 운영자·기관 공통·기관 개별 패키지 분리, 어린이 기능 분리 | 의존 방향을 테스트가 강제하고, 어린이 기능 없이 공통이 동작함 |
| 3 | add-librarian-agent | AI 사서 v1: 조회 tool, tool calling 루프, 스트리밍, 추천 노출 기록 | "공룡 책 추천해줘"에 소장 도서로 답함 |
| 4 | add-recommendation-evals | 평가 세트, 규칙 검사, LLM 채점, 임베딩 검색 비교 | 버전별 점수표 |
| 5 | add-admin-agent | 운영 에이전트, 자연어 SQL 분석과 안전장치, 장서 등록 | 분석 질문 정답률 측정 |
| 6 | add-approval-flow | 큐레이션·연체 안내·구매 요청서 초안 → 승인 → 실행 | 서버 재시작 후에도 승인 이어짐 |
| 7 | add-web-ui | 이용자·관리자 화면 | 이용자 대화에서 추천·대출까지, 관리자 승인까지 화면으로 동작 |
| 8 | add-observability-deploy | Langfuse 트레이싱, 배포, README, 데모 | 데모 영상과 평가 결과표 |

**2단계**: 독립서점 모드(대출 대신 서가 안내·구매 문의), 시즌 큐레이션 제안, 대출 이력 기반 개인화(동의한 회원만).

## 나중에 추가할 내용 (메모)

현재 범위에는 넣지 않고, 필요할 때 꺼내 쓸 내용이다.

- **장서 데이터 정규화 고도화**: 작가명·제목 표기 차이, 권차 표기("2권", "Ⅱ", "하"), 개정판·리커버·재출간 같은 판본 문제, 재정가. ISBN이 없는 장서를 가져올 때 필요해지면 여기서부터 반영한다.
- **시즌·이벤트 큐레이션**: 원작 영화 개봉, 문학상 발표, 방학·독서의 달에 맞춘 큐레이션을 관리자에게 제안한다. 출처 없는 이벤트는 제안하지 않는다.
- **독립서점 모드**: libraries.type = bookstore일 때 대출 tool을 끄고 서가 안내·구매 문의 tool을 켠다. 회원 적립 등 가격 규칙은 코드로 처리한다.
- **다른 기관 유형**: 군 부대 진중문고, 학교. 이용자층과 추천 기준이 달라 평가 세트를 따로 만든다.
- **저자 구조화**: 공식 서지의 저자는 `앤디 위어 저/박아람 역`처럼 YES24 원문이다. 이름·역할을 나누는 `book_contributors`와 저자 검색은 표기 표본을 확인한 뒤 검토한다. `add-librarian-agent` 전에 어디서 할지 정한다.
- **기관별 기능 설정**: 어린이 구분처럼 기관마다 필요가 다른 기능은 지금 앱 전체 단위로 등록한다. 군부대·대학 같은 기관 유형을 더할 때 기관 설정으로 켜고 끈다.
- **공식 서지 정리와 갱신**: 어느 기관도 소장하지 않게 된 공식 서지의 정리 기준, 이미 만든 공식 서지의 갱신, 구매 요청서를 쓸 때의 최신 가격 조회.
- **YES24 확인**: 여러 기관에 실제로 서비스하기 전에 공식 서지를 기관들이 함께 쓰는 것이 이용 조건에 맞는지 YES24에 확인한다.
- **자동 채움**: 지금은 운영자가 스크립트를 돌린다. 스케줄러가 같은 실행을 부르게 하고, 채움 뒤 어린이 구분 갱신을 관리자 화면 버튼이나 기관 설정으로 줄인다.
- **세밀한 연령 구분**: 유아·초등 저학년·고학년처럼 나누는 것은 근거 데이터가 충분해질 때 검토한다.
