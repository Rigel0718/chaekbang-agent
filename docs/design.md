# 무인 책방 에이전트 프로젝트 설계

2026-11-02 기준

## 문제 정의

매장을 지키는 데 사람 한 명이 통째로 들지만, 그 사람이 정작 손님의 질문에는 답하기 어렵다. 이 프로젝트는 실제 작은 책방 근무 경험에서 출발했다.

1. **매출 구조가 특이하다**: 주 수입은 매장 판매가 아니라 기관(어린이집, 동사무소, 학교, 군 서점) 납품이다. 매장은 사업자 자격과 지역서점 가산점을 유지하려고 열어 두는 곳에 가깝다.
2. **방문객은 적지만 질문이 많다**: 하루 5~10명이 오고 구매는 5명 미만이다. 하지만 오는 사람은 책에 관심이 많아서 검색, 작가, 추천 질문이 몰린다.
3. **응대 공백이 생긴다**: 사장님은 배달로 자리를 비우고, 남은 직원은 책 지식이 부족해 질문에 답하기 어렵다.
4. **큐레이션은 반복적인 검색 작업이다**: 신간 정리, 추천 도서 글, 오늘의 글귀 모두 결국 찾아보고 정리하는 일이다.

그래서 에이전트를 손님용(A)과 사장님용(B) 둘로 나누고, 실제 매출 업무인 기관 납품(C)을 더한다. C는 핵심 흐름만 MVP에 넣는다.

## A. 매장 큐레이터 에이전트 (손님용)

손님이 매장 태블릿이나 QR 웹으로 직접 물어보고, 에이전트가 매장 재고와 외부 도서 데이터를 근거로 답한다.

| Tool | 하는 일 | 종류 |
| --- | --- | --- |
| search_store_books | 우리 매장에 있는 책인지, 어느 서가에 있는지 | 조회 |
| search_external_books | 매장에 없는 책 검색 (알라딘 / 카카오 책 검색 API) | 조회 |
| get_author_info | 작가 정보와 다른 작품 | 조회 |
| get_today_picks | 사장님이 승인한 오늘의 추천 | 조회 |
| get_today_quote | 오늘의 글귀 | 조회 |
| request_book_order | 매장에 없는 책 주문 요청 남기기 (연락처 포함) | 쓰기 |
| leave_message_for_owner | 에이전트가 답하기 어려운 질문을 사장님께 전달 | 쓰기 |

**설계 원칙**

- **매장 재고 먼저 추천한다**: "따뜻한 그림책 추천해줘"에는 우리 서가의 책부터 보여준다. 결국 매출로 이어져야 한다.
- **책 정보는 API 데이터로만 답한다**: LLM이 기억으로 줄거리나 작가 정보를 말하면 틀릴 수 있다. tool 결과만 근거로 삼는다.
- **글귀는 LLM이 지어내지 않는다**: LLM은 그럴듯한 가짜 인용문을 만들기 쉽다. 사장님이 등록한 글귀 중에서만 고른다.
- **모르는 건 넘긴다**: 답이 불확실하면 사장님께 메시지를 남기도록 안내한다.

## B. 사장님 운영 에이전트 (관리자용)

사장님이 배달 중에도 휴대폰으로 확인하고 승인만 하면 되게 만든다.

- **신간 큐레이션**: 매일 신간을 수집하고 책방 성격에 맞는 후보를 고른다. 사장님이 승인하면 추천 목록에 오른다.
- **추천 카드 초안**: 추천 도서 POP 문구를 초안으로 쓰고, 사장님이 수정하거나 승인하면 매장 화면에 게시된다.
- **손님 질문 요약**: "이번 주 손님들이 많이 찾았지만 매장에 없던 책" 같은 보고서를 만든다. 그대로 입고 결정에 쓴다.

**승인 흐름**: 초안(draft) → 승인 대기 → 승인(approved) → 게시(published). 승인 대기 상태는 DB에 저장해 두고, 승인되면 에이전트 실행을 이어서 진행한다. 서버가 재시작돼도 실행이 유지된다.

## C. 기관 납품 에이전트 (핵심은 MVP)

실제로 매출이 나는 기관 납품 업무를 자동화한다. 학교나 어린이집에서 받은 도서 목록(엑셀/PDF)을 올리면 에이전트가 ISBN을 찾아 맞추고, 절판이나 품절을 확인하고, 견적서 초안을 만들고, 납품 일정을 관리한다.

| 단계 | 범위 |
| --- | --- |
| MVP (핵심) | 도서 목록(엑셀) 업로드 → ISBN 매칭 → 애매한 결과는 사장님께 확인 요청 → 견적서 초안 |
| 2단계 | PDF 목록, 납품 일정 관리, 절판·품절 시 대체 도서 추천 |

**Tool (MVP)**: parse_order_list, match_book, check_availability, request_match_confirmation(승인 필요), create_quote_draft

- 견적 금액은 LLM이 아니라 코드로 계산한다. LLM은 "같은 책인가" 같은 애매한 판단에만 쓴다.
- 평가 지표: ISBN 자동 매칭 정확도, 사람 확인 요청 비율, 견적 금액 오류 0건.
- 실제 기관 자료 대신, 실무에서 본 형식(열 구성, 제목만 있는 행, 오타)을 재현한 가짜 목록을 만들어 쓴다.
- "매장 무인화 + 실제 매출 업무 자동화"로 포트폴리오 이야기를 완성한다.

## 외부 데이터 API

책 정보의 근거는 아래 API에서 가져온다. 각 API의 키 발급 조건과 호출 제한은 시작 전에 확인해야 한다.

| API | 쓰임새 | 단계 |
| --- | --- | --- |
| 알라딘 Open API | 도서 검색, 신간, 베스트셀러, ISBN 조회 | MVP |
| 카카오 책 검색 API | 검색 보조, 매칭 후보 보강 | MVP |
| 도서관 정보나루 API | 인기 대출 도서, 연령별 추천 (어린이 도서 추천에 유용) | MVP |
| 네이버 검색 API (뉴스) | 문학상, 작가 소식, 원작 영상화 보도 수집 | 추가 기능 (메모) |
| 영화진흥위원회(KOBIS) 오픈 API | 개봉 예정작 목록 | 추가 기능 (메모) |

## 추천 범위와 일정

MVP는 약 6~7주, 2단계는 2~3주로 잡는다. C의 핵심 흐름을 MVP에 넣고, 이벤트·시즌 알림은 범위에서 빼서 메모로 옮겼다.

| 단계 | 범위 | 기간 |
| --- | --- | --- |
| MVP | A 전체 + B(신간 큐레이션, 추천 카드 승인) + C 핵심(목록 업로드 → ISBN 매칭 → 확인 요청 → 견적서 초안) | 6~7주 |
| 2단계 | C 기관 납품 에이전트 고도화: PDF 목록, 납품 일정 관리, 대체 도서 추천 | 2~3주 |

**공통**: FastAPI, Langfuse 트레이싱, eval 시나리오. 예를 들어 "그림책 추천해줘"에서 매장 재고를 먼저 조회했는지, 작가 정보가 API 결과와 일치하는지 채점한다.

## 나중에 추가할 내용 (메모)

현재 범위에는 넣지 않고 나중에 추가할 내용을 모아 둔다.

### 실무 데이터 문제와 규칙 (C 고도화)

| 문제 | 성격 | 처리 방향 |
| --- | --- | --- |
| 작가명 표기 차이 ("J.K. 롤링" / "조앤 K. 롤링") | 정규화 | 공백·마침표 정리 규칙 → 그래도 다르면 API 저자 데이터로 확인 |
| 제목 표기 차이 (부제, 띄어쓰기, 특수문자) | 정규화 | 규칙으로 정리 → 후보가 여럿이면 LLM이 판단 |
| 권차 표기 ("2권", "Ⅱ", "II", "제2권", "하") | 정규화 | 규칙 코드로 숫자 하나로 변환 (LLM 불필요) |
| 개정판·리커버·신장판·재출간 | 판본 관계 | "작품"과 "판본"을 분리한 데이터 모델 |
| 재정가 (가격 변경) | 가격 이력 | ISBN은 그대로, 가격 이력 테이블 추가 |
| 회원 2% 적립, 기관 할인 한도 | 정책 | LLM이 아닌 코드로 계산 |

**용어와 규칙**

- **리뉴얼 용어**: 개정판·개정증보판(내용 변경), 리커버(표지만 변경), 신장판(판형·장정 변경), 특별판·한정판, 재출간(출판사 변경).
- **ISBN**: 내용·제목·출판사가 바뀌면 새 ISBN, 가격만 바뀌면 같은 ISBN. 리커버는 출판사마다 다르다.
- **재정가**: 발행일부터 12개월이 지나면 고지 후 정가 변경 가능 (출판문화산업진흥법 제22조 제2항).
- **도서정가제 할인**: 가격 할인 10% + 적립 등 간접 할인 5%, 최대 15%. 회원 2% 적립은 간접 할인에 해당.
- **기관 구매**: 2020년 개정 방향에서 공공기관은 적립 없이 정가 10% 할인만 허용. 현재 적용 여부는 구현 전 확인 필요.

**매칭 파이프라인 초안**

1. ISBN이 있으면 바로 확정
2. 정규화 후 정확히 일치하면 확정
3. API로 후보 검색 → 유사도 점수 계산
4. 애매하면 LLM이 판단하고 신뢰도를 매김
5. 신뢰도가 낮거나 개정판과 구판이 둘 다 있으면 사장님께 확인 요청

회원 가입, 결제, POS 연동처럼 에이전트와 무관한 운영 기능은 이 프로젝트 범위에서 뺀다.

### 이벤트·시즌 알림 (B 확장)

베스트셀러에 더해, 책 판매가 몰리는 시즌을 미리 잡아 사장님께 알린다. 원작 영화 개봉, 문학상 발표, 방학 같은 시점이다.

| 이벤트 유형 | 예시 | 알릴 시점 | 데이터 출처 |
| --- | --- | --- | --- |
| 원작 영화·드라마 | 원작 소설의 영화 개봉 | 개봉 2~3주 전 | 개봉 예정작 API + 뉴스 검색 |
| 문학상 | 노벨문학상(10월), 부커상, 국내 문학상 | 발표 당일 | 뉴스 검색 + 시즌 캘린더 |
| 작가 소식 | 신작 출간, 방한, 수상 | 보도 당일 | 뉴스 검색 |
| 학사·계절 시즌 | 방학 권장도서, 입학, 독서의 달(9월), 연말 선물 | 4주 전 | 사장님이 등록한 시즌 캘린더 |

**흐름**

1. 매일 아침 스케줄러가 뉴스, 개봉 예정작, 시즌 캘린더를 수집한다.
2. 에이전트가 이벤트와 관련된 책을 찾고 매장 재고를 확인한다.
3. 사장님께 알린다: 이벤트 요약, 출처 링크, 관련 도서와 재고, 할 일 제안(발주, 추천 카드, 기관 제안).
4. 사장님이 승인하면 추천 카드 초안이나 발주 초안으로 이어진다.

**Tool**: collect_news, get_upcoming_movies, get_season_calendar, match_books_to_event, create_owner_alert

**원칙**

- 출처 링크가 없는 이벤트는 알리지 않는다. LLM이 지어낸 뉴스를 막기 위해서다.
- 같은 이벤트는 한 번만 알린다(중복 제거).
- 하루 알림은 최대 3건, 중요도 순으로 보낸다. 알림이 많으면 사장님이 안 본다.
- 방학 권장도서 같은 시즌은 기관 납품(C) 영업 기회로도 알린다.
